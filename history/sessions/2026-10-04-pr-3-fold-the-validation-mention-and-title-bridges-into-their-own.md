## Description

First of a stack of four PRs that retires the bridge modules, so that `Package.swift` says which way each dependency goes.

## What changes

Four bridges joined a concern to a surface it shows itself on, or to Validation. Their code now lives in the module that owns its meaning:

| Was (bridge module) | Now | Edge in `Package.swift` |
|---|---|---|
| ValidationDetails | Validation (`IssuesTab.swift`) | Validation → DetailPanel |
| ValidationContents | Validation (`IssueMarks.swift`) | Validation → TableOfContents |
| MentionValidation | Mentions (`MentionValidation.swift`) | Mentions → Validation |
| TitleValidation | Titles (`TitleValidation.swift`, with its `TitleIndex`) | Titles → Validation |

This is how Titles, Locking, Mentions and Boards already reach the panel and the table of contents. Validation was the only concern that went through bridges to do the same.

**Plugin values are unchanged.** `ValidationDetailsPlugin`, `ValidationContentsPlugin`, `MentionValidationPlugin` and `TitleValidationPlugin` keep their names and ids, and now live in their owners' modules. The registry refuses a contribution to a point whose owner isn't installed. Keeping each face a separate plugin value means a plugin list can still install Validation without the panel, or Mentions without Validation. Only the module boundary moved.

The shipped list, the registry report and behavior are unchanged.

**Tests moved, not rewritten:**
- ValidationDetailsTests and ValidationContentsTests now live in ValidationTests (`IssuesTabTests.swift`, `IssueMarksTests.swift`).
- MentionValidationTests now lives in MentionsTests. Four helpers it duplicated byte for byte (`SplitMix`, `idA`, `idB`, `keptAside`) are dropped.
- TitleValidationTests now lives in TitlesTests.

The suites are the same and each owner's `main.swift` runs them.

The docs (CLAUDE.md, `docs/plugin-system.md`, README) now say how a concern reaches the surfaces it shows on: the owning module imports the surface, and a face a plugin list should be able to leave out is a plugin value of its own in the owner's module. Four guide headings were retitled, with their links updated.
