# Find (⌘F) and Jump To (⌘K): the plan (settled)

The owner asked for two navigation features, distinct:
- **Find (⌘F)** searches the board and all subboards for text that fuzzy-matches the query, case-insensitive and somewhat tolerant of typos; highlights matching text in any shape; shows results in the right-hand panel, nearly taking over the detail panel. UX inspiration: ⌘F in browsers.
- **Jump To (⌘K)** is loosely a command palette. It looks only at titles and the containment tree (Topology's: subboards and frames), never at contents. VS Code's file switcher is the model: name one subboard, skip one, name another two levels down, then something like the shape's name, and the candidate list narrows.

Background: survey reports in this folder (`understand-*.md`) and critiques (`critic-*.md`). Where this plan and those disagree, this plan wins.

## Modules (Package.swift, one line each, `// layer:`)

### FuzzyMatching — foundation, no dependencies (new)
- Move `CaretListMatcher`, `CaretListMatch`, `CaretListRanking` out of TextEditing into it, renamed `FuzzyMatcher`, `FuzzyMatch`, `FuzzyRanking` (no compatibility aliases: there are no users to keep). Importers switch: Mentions (`MentionState.swift`, `MentionCatalog.swift`, `MentionMatching.swift`), SlashCommands (`SlashCommandPicker.swift`), DetailPanel (`CodeCompletions.swift`, comment in `TextViews.swift`); TextEditing's comment in `CaretList.swift`. Their Package.swift lines gain `FuzzyMatching`. The matcher's tests move from `Tests/TextEditingTests/CaretListTests.swift` to a new `FuzzyMatchingTests` (layer test, deps FuzzyMatching + TestKit).
- No public type may be named `FuzzyMatching` (the audit).
- Add **`TextSearch`** (Find's matcher): fold per Unicode scalar (case, diacritics, width; as the matcher folds) into UTF-16 units, with a map back to the original's UTF-16 offsets kept only when folding changed lengths (an ASCII fast path, as the matcher's). A query is a phrase: its words in a row, whitespace runs equal. Hits, in text order:
  1. exact folded substring matches, every occurrence (mid-word too);
  2. then fuzzy: word-anchored (a hit starts at a word start); each query word of ≥ 4 folded letters may differ from its text word by one Damerau edit (an adjacent swap is one edit), shorter words exact; the last query word may match a text word's prefix (typing mid-word keeps hits); the first letter of each word exact; a fuzzy hit overlapping an exact one dropped.
  - Each hit: UTF-16 range in the original text, and whether exact. At most a cap of hits per text (100, a constant); cancellation hook (a closure checked every 64K characters).
  - Pure, nonisolated, `Sendable` inputs/outputs.
- Add **`PathMatcher`** (Jump To's matcher), built on `FuzzyMatcher.match(Query, in: Label)`:
  - Query split on whitespace into pieces. A path is segments root-side first, the last the shape's own title (the leaf). Pieces go in order into segments in order: contiguous groups of pieces, one group per segment, segments may be skipped, the last group goes in the leaf. Several pieces in one segment are one `Query` of the joined words (hits the word-prefix tier).
  - Ancestor groups may score only exact, prefix, word-prefix, substring or typo tiers (no bare subsequence); the leaf any tier.
  - Score: leaf group's score weighted above ancestors', plus ancestors' scores, less a small penalty per skipped segment; ties broken by the caller.
  - Returns the score and per-segment matched ranges (Character offsets as the matcher's, plus a helper to UTF-16) for bolding.
  - Built to run as a DP over a tree: an API that scores a container's segment given its parent's row (best score for the first g pieces placed along the chain root→container), so a caller memoizes a row per container per query and a leaf costs O(pieces). A single-piece query is just `FuzzyMatcher` on the leaf.

### Find — layer **surface** (new): Canvas, Geometry, Keyboard, Selection, DetailPanel, Topology, TextEditing (only if used), FuzzyMatching
Knows no concern and no kind. Plugin id **`"find-in-boards"`** (never `"find"`: that's the command's string).
- **Point `FindableTexts`** (declared in Find): contributions keyed per kind, or for every shape with `where:` over a kind (asked once per kind; never `{ _ in true }` from a shipped plugin). Sugar on `PluginRegistrar` (`registrar.findableTexts(...)`) and on `ShapeRegistrar` for a kind's own. A contribution has:
  - `texts: @MainActor (AnyShapeRecord, FindContext) -> [FindableText]` — `FindableText(field: String, text: String)`: what the shape shows, as plain text. Cheap; read into the index.
  - `rects: @MainActor (AnyShapeRecord, String /*field*/, [Range<Int>] /*UTF-16*/, FindContext) -> [[CGRect]]` — **box-relative** world units (from the shape's frame origin), one array of line rects per range, as the render lays the text out; asked lazily, only for shapes in view with hits, and cached by the contributor's own layout cache (text + width), never per query.
  - `zoomedOut: @MainActor (AnyShapeRecord, String, FindContext) -> CGRect?` optional (a title's cover), else the shape's bounds.
  - `affected: @MainActor (ChangeSet, FindContext) -> Set<ShapeID>` optional: shapes whose texts a commit changes without changing them (a note showing another shape's live name).
  - `FindContext` lends services (`service(_:)`) and the editor where needed, as `ContentsContext` does.
  - Conform contributions/services in extensions (CLAUDE.md).
- **Contributors** (each a plugin value of its own in its owner's module, after `FindPlugin()` and its owner in the shipped list, so a list without Find leaves them out; the registry refuses a contribution whose point's owner isn't installed):
  - Mentions' `MentionFindPlugin`: kinds that list `MentionTexts` placements (notes' `text`, schema cards' `prompt`); `texts`: plain text with live names (`MentionLabels`/`plainText`, read after Mentions has heard the commit: call `rowsAffected(by:)` first); a pill's name maps to its one U+FFFC in the drawn string, so a hit inside a name highlights the whole pill; `rects` from the render's layout (`MentionTextLayout`), keeping a layout per (text, width) in `MentionTextMemo` (beside the pills' `laidOut`), so a hit's rects are a glyph-range lookup; `affected`: `rowsAffected(by:)`.
  - Titles' `TitleFindPlugin`: kinds that hold `TitleProperty` or derive a title (`registry.titleIsDerived`); text `registry.title(of:)`; field `"title"`; `rects`: the pill's frame (Adornments' `adornmentFrames(of:)` for the `TitlePill`), the whole capsule (a pill truncates), box-relative; `zoomedOut`: `editor.titleCover(of:)`'s rect.
  - Connections' `ArrowFindPlugin`: the arrow kind; text its label; `rects` from the label's layout (`ArrowLabels`, string drawing with `.usesLineFragmentOrigin`, centered).
  - A string-drawing range→line-rects helper (attributed string + width → per range, line rects, matching `NSAttributedString.draw(with:options:.usesLineFragmentOrigin)`) goes in **TextEditing** (foundation; Mentions and Connections import it already); Mentions keeps its pill stand-ins on top.
- **`FindState`** (service, `editor.find`, `@Observable` where views read it): `isActive`, `query`, `results`, `current`, `focusRequest` (a counter: each ⌘F bumps it, the field focuses and selects its text, the host shows the inspector), whether it showed the inspector.
- **`FindIndex`** (inside Find): per shape, its fields' texts, folded. Built on the first ⌘F, in main-actor slices of ~2 ms (`editor.scheduler`), walking every board the editor can show, none kept aside; a spinner in the field until built. Before the first ⌘F a commit costs O(1) (a revision noted, a dirty flag). After: per commit O(changed): `removed`; `added` and `changed` minus `moved`; `elsewhere` (dropping ids no longer in the file; iterate the smaller set, as `TitleIndex.catchUp`); contributions' `affected`; a commit heard out of turn, or a file put in place, reads everything again. Never stores file order (swap-remove is fine).
- **Search**: off the main actor over a `Sendable` snapshot of the index (mirror Queries' small pieces: a handover, a detached `@concurrent` task), cancel-and-restart per keystroke, results tagged by generation (stale ones dropped), cancellation checked every 256 shapes and inside long texts. Results are compact: per shape `(id, field, hitCount, firstHit)`, in scope order; a shape's ranges are recomputed on demand (in view, the current hit, a listed row) by matching that one text again. While Find is open, a commit patches the results for the shapes it changed (O(changed)), never a full search for a move.
- **Scope**: the board shown when the query last changed (or ⌘F opened Find) and every board under it. Stepping and clicking rows don't re-scope. **Order**: the scope board's shapes in file order (frames' contents in file order within it), then each board under it, depth-first in file order. The panel groups rows under board headers in the same order.
- **Overlay** (world space), drawn only while active (no `paintOrder(in:)` call otherwise): for shapes in view with hits, per shape by `drawsSkeleton(of:)`:
  - in full: the contribution's rects offset by the shape's frame origin and `worldDrawingOffset(of:)`, filled as a highlighter (multiply blend over notes and cards; source-over translucent where text sits on the canvas, an arrow's label), every hit in `FindStyle.hit`, the current one in `FindStyle.current` plus a thin outline (view points ÷ zoom); a title hit rings its pill rather than multiplying. Colors chosen so a hit reads on a yellow note (a yellow on a yellow note vanishes: use an orange-leaning hue), in a `@MainActor enum FindStyle`.
  - a layout budget per frame (~2 ms; the editor asks for another frame while any wait), shapes not yet laid out showing the zoomed-out tint meanwhile.
  - zoomed out (skeleton): a batched tint of each matched shape's bounds (or its title cover's rect), by `Silhouettes.form`'s rule for tiny shapes, the current one stronger; one path per look.
  - A hit under a shape in front shows through (accepted for now).
- **Panel** (`FindPanel`, a SwiftUI view in Find using DetailPanel's styles): Find's own header, no Back button: a search field (magnifier; the query; a spinner while indexing), the count "3 of 12" (hits, exact and fuzzy alike), previous/next buttons (tooltips via `registry.help(_:forCommand:)`: "Previous (⇧⌘G)", "Next (⌘G)"), Done. Rows one per shape, lazily (a `LazyVStack`, a window of ~200 rows around the current one): the kind's symbol tinted as its contents row is (`registry.label(of:)`), a one-line snippet around its first hit with hits in semibold, its hit count when more than one; board headers (name and symbol from a closure Composition passes, as the TOC's heading; `editor.name(of:)` there). The current row tinted. Empty query: nothing listed. No hits: "No Results". Quiet copy, no explanations.
- **Behavior**:
  - ⌘F: opens Find (or, open, focuses the field and selects the query); shows the inspector if hidden (and hides it again on close if Find showed it); ends editing (committing it), and a note's selected text, if any, becomes the query; refused mid-gesture (a session under way). Reopening keeps the last query, selected.
  - Typing: results live; the current hit is the first on the board shown that's in view, else the first on the board shown (revealed, `reveal`, if out of view), else the first anywhere (not revealed: typing never switches boards).
  - Return / ⇧Return in the field, ⌘G / ⇧⌘G anywhere, the buttons: step through hits in order, wrapping; a hit elsewhere shows its board; each step reveals the hit. ⌘G/⇧⌘G enabled while there's a query with hits; with Find closed and a last query, they reopen Find and step.
  - Clicking a row: makes its shape's first hit current and reveals it; the keyboard stays in the field.
  - Stepping, typing and rows never change the selection. The whole Find session's navigation is **one Back step** (Back after Find returns to where Find began), as `SelectionState.asOneStep` groups `goInto`.
  - Closing: Escape or ⌘. in the panel (the takeover's `onEscape`, ahead of the panel root's `exitByKey`), or Done: highlights go, the panel shows what the selection says again, the keyboard goes to the canvas, selection and camera untouched. Escape on the canvas is the canvas's own (Find stays open).
  - Clicking a shape on the canvas while Find is open: Find stays open, results kept.
  - Edits while open: results patched; the current hit kept as (shape, ordinal) clamped to that shape's surviving hits, else the next hit; the camera doesn't move.
  - ⌘K while Find is open: Find stays; ⌘F with the palette open closes the palette.
  - No commands leave empty undo steps (check `perform`'s group).

### JumpTo — layer **vertical** (new): Canvas, Keyboard, Selection, Topology, Titles, Boards, TextEditing, FuzzyMatching
A feature no kind opts into (Reordering's precedent); nothing imports it. Plugin id **`"jump-to"`** (the command's string is `"jumpTo"`).
- **`JumpToState`** (service, `editor.jumpTo`): `isOpen`, `query`, rows, `focusRequest`, recent picks (this window, newest first).
- **Candidates**: titled shapes (`registry.title(of:)`, named or derived) on every board the editor can show, none kept aside. Its own lazy catalog (Mentions' catalog's shape: entries, folded keys in one buffer, swap-remove, a stale set refreshed lazily), built on the first ⌘K (slices if a 10k board needs them), kept current per commit as Find's index is (pre-first-⌘K commits O(1)). Don't promote `TitleIndex`.
- **Paths**: containment ancestors (Topology; frames and board owners, nearest first), reversed; the root is never one (not shown). An untitled ancestor shows its placeholder dimmed in the path and is never matched. Container labels folded once per query, cached per container; never `ancestors(of:)` per candidate during ranking — walk/memoize over the tree (PathMatcher's row per container); build path strings only for rows shown.
- **Ranking**: a single piece: `FuzzyMatcher.rank` over leaf labels (the @ picker's workload). Several pieces: prefilter leaves by the last piece, then the per-container DP rows. Ties: fewer segments skipped, shallower, recent picks, file order. Budgets: single piece ≤ 2 ms at 10,000 shapes on main; several pieces ≤ 4 ms on `generatedFile(depth: 10)`.
- **Empty query**: "Recent" (up to 5 picks) then "Nearby" (titled shapes in view on the board shown, nearest the view's center, up to 5), headers as the @ picker's.
- **Palette**: a SwiftUI overlay placed by Composition's `boardChrome` (below), top middle, at a fixed offset below `coveredTop` taken as it opens; a capsule holding the field, an `EditingTextView` in an `NSViewRepresentable` of JumpTo's own, placeholder "Jump To"; its rows in the app's one caret list: the `CaretList` model and `CaretListWindow`, which gains an anchor-rect form (a closure giving a rect in screen coordinates, so the list sits under the capsule at its width) beside its text-range anchor, with the list's `close` closing the palette (one state); `CaretListItem` gains `detailMatched` ranges (drawn semibold, spoken as before); metrics ~560 wide, 10 rows. A row: the kind's symbol tinted as its contents row, the title with matched letters semibold, the path ("Alpha › Beta") as detail with matched letters semibold. Keys: ↑ ↓ ⌃P ⌃N Page Up/Down move; Return and Tab pick; Escape and ⌘. close; a click outside the palette closes it and isn't passed on (a clear scrim over the canvas while open). The keyboard returns to the canvas on close.
- **Pick**: Boards' rule, exposed once in Boards as `editor.follow(_ id:)` (goInto for a shape whose kind opens its board, else goTo), which the crumb menus' `pick` then calls too; one Back step. A frame is fitted (`goTo`'s rule), never forced to 70%.
- ⌘K: opens (or, open, focuses and selects the query); ends editing; refused mid-gesture.

## Host and composition (prep, before the features)
- Commands named in the core (`Sources/Canvas/Model/Identity.swift`, beside `.enclosingBoard`): `.find` = "find", `.findNext` = "findNext", `.findPrevious` = "findPrevious", `.jumpTo` = "jumpTo". Claimed by Find and JumpTo with Keyboard's `registrar.command(_:shortcuts:isEnabled:_:)`: ⌘F, ⌘G, ⇧⌘G, ⌘K.
- Menus (`Sources/CanvasUI/BoardMenus.swift`, `BoardWindowController.swift`): Edit › Find (a submenu: Find… ⌘F, Find Next ⌘G, Find Previous ⇧⌘G) after Select All; Go › Jump To… ⌘K. Custom selectors on `BoardWindowController` in its `commands` table (dimmed by `canPerform`), never AppKit's find actions (a note's text view would take them), not in `textKeys`, so they work from the canvas, a note being edited, a panel field and the list.
- `DetailPanelView(editor:onExit:overview:takeover:)`: a `DetailTakeover` slot (isActive, content, onEscape) that, while active, outranks the "No Details" branch and the selection; the root's Escape/⌘. call its `onEscape` first. Composition fills it with Find's panel; DetailPanel never learns Find.
- Composition: `ShippedPlugins.boardChrome` — a modifier over the canvas view adding the path overlay, Jump To's palette overlay, the inspector with `detailPanel`, and the inspector shown on Find's `focusRequest` — taking bindings and closures (`showsDetails: Binding<Bool>`, `rootName`, `onExit`), never CanvasUI types. The app's `ContentView` keeps its toolbar and frame around it; CompositionTests' `InspectorHost` applies the same modifier, so the tests run the app's wiring.
