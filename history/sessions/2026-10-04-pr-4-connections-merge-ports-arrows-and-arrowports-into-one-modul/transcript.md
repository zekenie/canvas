## Description

Second step of retiring the bridge modules, after #3. The Lexicons and Tiers PRs follow.

## Why
Ports and Arrows were one concept split across a horizontal, a vertical and a bridge:
- **Ports needed Arrows.** Its `Connectors` point takes at most one contribution, and without one no shape shows ports. ArrowPorts was the only one.
- **Arrows needed Ports.** Since the arrow tool went, arrows have no tool and are only drawn from ports. `beginArrow` existed for that one caller, and the only shipped `ArrowBindingRules` rule was ArrowPorts'.
- **The bridge hid the cycle.** Two inversions, filled by one bridge, so neither module imported the other.

The split dates from when notes mustn't import Arrows (a vertical). Connections is a horizontal, which keeps that true.

## What changes
- **One module.** `Sources/Ports`, `Sources/Arrows` and `Sources/ArrowPorts` are now `Sources/Connections`, a horizontal on Canvas, Geometry, Selection, TableOfContents, TextEditing and Topology. It is the first horizontal to own a kind: the arrow, the shape a connection is drawn as.
- **Importers.** StickyNotes, Schemas, PortEdges, Composition and the tests import `Connections`.
- **Plugin values are unchanged.** `ArrowsPlugin`, `PortsPlugin` and `ArrowPortsPlugin` keep their names and ids, so a list can still have arrows without ports (ArrowsTests) or ports with a connector of its own (PortsTests). The shipped list and the registry report are unchanged.
- **Re-encapsulation.** `beginArrow`, which only `ArrowPortsPlugin` called, is internal now. `ArrowBindingRules`, `arrowMayBind`, `canBindArrow` and `ArrowEdge` stay public because tests use them.
- **One visible side effect.** A shared schema definition is named after its module, so the arrow's terminal is `connections.terminal` in its kind's schema (`canvas kinds --schema`) instead of `arrows.terminal`. No board stores it. SchemaTests' two pinned strings are updated.
- **Tests.** ArrowsTests, PortsTests and ArrowPortsTests stay separate targets, so they still run in parallel. PortsTests' recording connector class was called `Connections`, the module's new name. It is now `ConnectionLog`, to rule out any lookup confusion.
- **Docs.** CLAUDE.md, the guide and the README come in a follow-up commit on this PR.
