# Infinite Canvas

Native macOS infinite canvas (an AppKit document app, SwiftUI windows around an AppKit canvas), built from compiled-in plugins.

## Build and test

- `./build.sh && open build/InfiniteCanvas.app`. It calls `swiftc` directly and wraps the binary in an `.app`, because SwiftPM (`swift build`) is broken with this machine's Command Line Tools. Each module is compiled with only its dependency closure on `-I`, as many at once as there are cores (`BUILD_JOBS=N`), each once its dependencies are built, and only when what it's built from changed: its sources, its command, its dependencies' `.swiftmodule`s. A module's `.swiftmodule` is a job of its own (function bodies skipped, as in the job swiftc splits off itself), so what imports it starts compiling long before its code is done, and in release other modules can't inline its functions whatever cross-module optimization makes of them (nothing is `@inlinable`, and the benchmarks measured no difference). A module's code compiles to an object per source at fixed paths (`-num-threads 4`, through an output file map), so the same inputs make the same bytes, and what comes out the same isn't replaced: an edit inside a function recompiles only its module and links the executables again, and a touch or a checkout that changes nothing links nothing. In debug an executable's object job emits its module too, which its link hands the debugger (`-add_ast_path`), as a one-step `swiftc -g` does. A build fails, saying so, if a module's sources change while it builds (an interface and an object from different edits would link). Builds of one configuration wait for each other (`build/.debug.lock`), and however build.sh or test.sh ends (^C, a TERM), what it started stops with it. The app bundle's files change only when they do: macOS checks each new executable the first time it runs (about 0.3 s each, one at a time). The app carries its command line, `canvas` (`Contents/Helpers/canvas`; `build/canvas` links to it): with the app open, `build/canvas help`.

- `./test.sh` builds every module but the app (debug, `-D DEBUG`) and runs the test executables, as many at once as there are cores (`TEST_JOBS=N`), slowest first, printing each one's output whole, in order. `TEST_FILTER=substring ./test.sh` runs the matching tests, and fails if none match. `TEST_UI_MENUS=1` adds the tests that open real (on-screen) menus, and runs the executables one at a time. Run by hand, a test executable takes `TEST_TIMES=1` (each test's seconds, on standard error). A time budget in a test measures the test thread's CPU time (TestKit's `threadCPUTime`), never the wall clock, which counts whatever else the machine runs. Every `Suite` a test target declares must be passed to `runTests` in its `main.swift`; test.sh fails otherwise.
- `Package.swift` is the module graph: one target per line, each tagged `// layer:`. Its header lists the layers and what each may use (wire, foundation, ui, horizontal, vertical, bridge, composition, app, cli, testsupport, test). Non-test modules live in `Sources/X`, or `Examples/X` with `path:`; test modules in `Tests/X`.
- Every build.sh mode audits first; `./build.sh audit` does only that. What it reads of each module is kept in `build/audit` and read again only for a module that changed, and a pass is kept by every input's name, size and mtime, so auditing what already passed costs one stat. It fails on a cycle or a forbidden layer edge; on any difference between that table and SwiftPM's own evaluation of `Package.swift`; on a module whose imports, as the compiler parses them, aren't exactly its declared dependencies; on an import inside `#if`, `canImport(<project module>)`, `@_exported`, `@_implementationOnly` or `@testable`; on a public type named like a module, or `Task` or `Span` (either would shadow Swift's in every importer: a query's place in its text is a `QuerySpan`); and on a module writing another module's `ShapeKind`, `PluginID`, `ToolID`, `PropertyKey`, `ChannelID` (Ports') or `EdgeTypeID` (Topology's) string without depending on it (a string two modules declare is both's, so an id that must equal another module's is made from that module's constant, as `ArrowEdge.id` from `Arrow.kind`; a name in a property list, `Property("…")`, is exempt, and so is a JSON member named by a JSON Schema keyword, a subscript's key, `json["title"]`, or a key before a colon where a member's name starts, but not in a `case`'s patterns or `where` or a ternary, even across lines: the `title` keyword is also Titles' property key; any other member's name, `json["locked"]`, counts; `frame`, the core's own member every box has, which Frames' kind is spelled as, is an ordinary word that no module owns, `ORDINARY_IDS`). The graph (the `-I` closure plus MemberImportVisibility) keeps the core from referencing plugin types; the id check keeps any module from writing another module's kind, tool, plugin, property, channel or edge type id as a literal. The editor's host API (input, cursor, drawing, delegate) is `@_spi(Host)`, and only the ui, testsupport and test layers may import it.
- `./build.sh graph`, `dot`, and `api <Module>` (a module's public interface) are for reading the graph.
- If the build fails with "this SDK is not supported by the compiler", a stale newer SDK is being picked. Prefix the command with `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk`.
- Sources compile in Swift 6 language mode. Keep them free of warnings (build.sh passes `-warnings-as-errors`).

## Architecture

Read `docs/plugin-system.md` first; it's the guide to the plugin system, with the examples.

- `Canvas` (the core) knows no particular shape or concern (its one tool is Hand), and must stay that way. A concern like validity is declared by a plugin (an `ExtensionPoint` in its own module) and other plugins opt in; if the core seems to need to know about one, add a generic extension point instead.
- A plugin is a value (`CanvasPlugin`) that registers into a frozen `Registry`, which refuses a plugin list with a duplicate plugin, a contribution whose owner isn't installed or whose kind nobody registers, or two claims to one key. A rule spanning a point's contributions that keys can't express goes in that point's `static func check(_ registry:)`, which throws `RegistryError.invalid` or any error (reported as `invalid` for the point; the core runs it without knowing what it checks). A kind is its props type (`static let kind`, defined by its list of properties); its behavior is a stateless `ShapeDefinition` (only `render` is required for box kinds, and `geometry` drives hit testing and outlines); more comes from capability protocols (`Editable`, `CustomTranslation`, which moves a kind by its own rules through `beginTranslation` when a `TranslatingSession` moves it, `PaintOrderAnchored`, `DerivedProps`, whose `derive` puts what follows from the rest of the props in step, as the kind's setters would, in a shape made from properties, `registry.shape(_:properties:)`: a schema card's height, a note's from its text, `CustomSkeleton`: `renderSkeleton`, drawn in `render`'s place zoomed out (below the editor's `skeletonZoom`, 35%) but for the shape being edited, fills and greeked text bars (`context.fillSkeletonText`, as long as their text's columns, `SkeletonText`), no text, shadows or pictures of its own (a picture only through `RenderContext`, a subboard's board preview), reading the shape, its kept geometry, `context.zoom` and what its plugin already keeps of the shape if it's there, never parsing or laying out text (a paragraph's lines are counted, `SkeletonTextBars`), and outlined there by its kept geometry, as a kind without one is (drawn as the default skeleton, its geometry in gray, `context.drawSkeleton(of:color:)`), unless it adopts `CustomSkeletonOutline` (`skeletonIndicatorPath`, its outline there, nil for its kept geometry's: an arrow's arc; found once, so no other kind's shape is asked), and `BoardOwning`: each shape of the kind owns a board, a subboard, with nothing to implement; boards in a file, below; and `ShapeContaining`: each shape of the box kind holds shapes on its own board, a frame, with nothing to implement; containers, below). Escape on a `TranslatingSession` puts back only what the drag moved (a box's origin; a `CustomTranslation` kind's whole record from before its begin), so a plugin's write to a shape while it moves (a model's answer landing) stays. A `TranslatingSession` carries what a container it moves holds, read-only or not (in `TranslationStart.ids` too), outlines past the drag threshold the container a drop would go into (the hint, never a read-only one), and on a release past the threshold settles what was dropped (`Transaction.settle`, a container dropped taking in what it lands on) in the press's step (`end` runs before `undoHistory.pressEnded()`), gliding what's nudged; a read-only container refusing the drop sends what was dragged back, gliding from where it was dropped, and the press leaves no step. A shape just placed (`editor.place`) follows the pointer while the press that placed it lasts, whatever its placement (`place(_:in:)` puts one down with a given frame, as with no press under way, never following: what a tool that draws its shape's rect puts down at the release, the Frame tool) (`PlacingSession`, a `TranslatingSession` inside), settles on the release (at once, in the same step, placed with no press; refused by a read-only container, it's taken away and the container hears it, `didRefuseChanges`), an editing placement's shape is edited on the release, unglided, and Escape before that takes the shape away and puts back what the undo participants kept before the press (what was selected), so the press comes to nothing; placed with no press, an editing placement's is edited at once. Selection declares two more: `HandleProviding` (handles on the only selected shape), and `BrushHitTesting`, which the marquee asks only when it overlaps a shape without strictly containing it (default: `ShapeGeometry.isHit(byBrush:)`, from `geometry`). Behavior intrinsic to a kind is a capability; behavior any plugin can add is an extension point. Conform to `ShapeDefinition` (and capabilities), `Tool`, `Session`, `EditorService`, `MentionScope` and any extension point that implements `check` or `summary` (how the registry's report shows a contribution) in an extension: only there does the compiler flag a near miss on a defaulted requirement.
- A kind's props, and any struct stored in them, are a list of properties (`SchemaDefined`): `static let properties = Properties<StickyNote>(title: "Sticky note") { Property("frame", \.frame).required(); Property("text", \.text).description("…") }`, with `init()` giving the defaults. The list is the type's `Codable` (a member missing from a board reads as its default; a `required()` one has none) and its JSON Schema (2020-12): each property's type from its member's (`SchemaDescribed`: the core's geometry and `ShapeID` as `core.*` definitions, `SchemaCases` for a string enum, a nested struct in place or, with `definition:`, shared and named after its module, `canvastesting.memo-note`), its default, and what its modifiers add (`PropertyModifiers`: `minimum`, `maxLength`, `pattern`, `examples`, `keywords` for any other). A type that codes itself by hand writes `schema(in:)` by hand (`ArrowTerminal`). The registry describes every kind's and added property's schema as it's built, and refuses a list of any struct those reach that misses a stored member (a board wouldn't save it), names a non-member or has a key path that isn't its member (a computed view), lists one twice, writes one member twice, has an optional that's required or defaults to non-nil, or holds optionals in a collection (nor may an added property's value); the first problem is the one reported, a property value's against its declarer; and two types under one definition name, or a struct that holds itself with no name. `registry.schema(for: kind)` is the kind's whole schema, its added properties included, and marked `x-canvas-board` for a `BoardOwning` kind. `registry.schemaViolations(of: shape)` checks a shape against it (its own and added properties as one object, `record.propertiesJSON`, through a fast `JSONValueEncoder`; each kind's schema compiled as the registry is built, `SchemaValidator`, which checks any JSON against any schema, strings code point for code point and patterns as ECMA-262 reads them; and a schema it couldn't check, a `$ref` to nowhere or back to itself before going into the value, a pattern ICU can't read, refuses the plugin list, a kind's or an added property's): typed props always have the schema's shape, so what breaks it are bounds (`maxLength`, `minimum`) and numbers that aren't finite. A bound is a guideline, never a refusal: Validation warns about each violation. Agents get the schemas from the command line (`canvas kinds --schema`). Text reads a kind's schema through the core's `KindSchema` (`Sendable`, holding the schema's JSON and no registry, so it reads anywhere, following its `$ref`s): which properties hold a place (`holdsPlace`: the core's rect or point, or what holds one), what each property's values are (`shape(of:)`, a `KindSchema.PropertyShape`), what each takes said briefly (`compactType(of:)`, `canvas kinds`' and a query's vocabulary's words), and a literal read as the property's JSON (`value(ofLiteral:quoted:for:)`, `forItemOf:` for a list's item), refused with a `KindSchema.Refusal` that holds no words, which each command says in its own (`draw` through Automation's `KindVocabulary`, a query through its resolution); so `canvas draw` and `canvas query` read a value alike.
- Added properties are what a plugin adds to the kinds that opt in: something the shapes know that their kind doesn't declare (a title). The type is the key: `enum TitleProperty {}` with `extension TitleProperty: ShapeProperty { static let key: PropertyKey = "title"; static var defaultValue: String? { nil } }` (a nil default: only the shapes it's set on have one), and `static var keywords: PropertyKeywords<Value>` for what its schema says beyond its type (Titles' title: `.minLength(1).maxLength(80)`), and `static func isNone(_:)` for a value that's no value at all (Titles' blank title), which no shape holds: a shape set to one, or read from a board with one, holds nil, or the default for a property that has one (which can't be none). A value a board writes as null, added, kept or handed over, is none too. Its owner declares it (`registrar.declare(P.self)`); a kind opts in through the owner's sugar (`ShapeRegistrar.optIn(to:)`, as `note.title()` does), a bridge's `registrar.optIn(Kind.self, to:)`, or `optInEveryShape(to:where:)`. The registry refuses an opt-in to a property nobody declares, a key declared twice, a kind opted in twice, and a key that's one of the kind's own property names; its report lists `property title` and `property title → sticky-note`. Read and write `shape[P.self]` (`record[P.self]`), in a transaction like the props; a write the shape can't hold (its kind doesn't opt in, nil for a property with a default, a value kept aside) is dropped. A placement sets one on what it places with `.setting(P.self, to:)`. Defaults are filled where shapes enter an editor (inserted or placed, `CanvasEditor.init` and `replaceFile` on every board, `replaceDocument`, a board read; `registry.fillingDefaults`); filling never marks a board edited by itself. In a kind's schema each one is a property marked `x-canvas-owner`. What a shape knows is a property; what a plugin keeps about a shape (the one it was copied from) is `ShapeMeta`, never a property.
- Layers: horizontals (Keyboard, Selection, Validation, Titles, DetailPanel, ContextMenus, SlashCommands, TableOfContents, Adornments, Clipboard, Locking, Ports, Mentions, Topology, Queries, Automation, QueryCommands, LanguageModels, Boards, Snapping) declare extension points and import no vertical, though one may build on another (Queries on Topology; QueryCommands on Automation, LanguageModels and Queries, and the wire; Boards on ContextMenus, DetailPanel, Keyboard, Selection, TableOfContents and Titles; Clipboard on Keyboard, Selection and ContextMenus; Locking on Adornments, ContextMenus, Selection, SlashCommands and TableOfContents; Ports on Selection and Topology; Mentions on ContextMenus, DetailPanel, Selection, SlashCommands, TableOfContents, TextEditing, Titles and Topology; Titles on Adornments, DetailPanel and TableOfContents; Adornments, DetailPanel, ContextMenus and TableOfContents on Selection; DetailPanel and SlashCommands also on TextEditing; Selection on Keyboard); verticals (Arrows, StickyNotes, Schemas, Subboards, Frames, Reordering) import no other vertical (StickyNotes, Schemas and Arrows import TextEditing, for the text view their editors are; StickyNotes and Schemas import Ports, each for a channel of its own, and StickyNotes, Subboards, Frames and Schemas import Mentions, notes and schema cards to hold mentions and all four to be mentioned; Subboards builds on Boards; Frames on Selection, for its marquee and its resizing); bridges (ValidationDetails, ValidationContents, MentionValidation, TitleValidation, ArrowPorts, TitleNames, PortEdges, ValidationChecks, TitleQueries, BoardQueries, MentionQueries, ValidationQueries, SelectionQueries) connect them, even two horizontals (ValidationDetails joins Validation and DetailPanel, ValidationContents Validation and TableOfContents, MentionValidation Mentions and Validation, TitleValidation Titles and Validation; TitleNames, PortEdges and ValidationChecks join Automation to Titles, Ports and Validation, for `canvas draw`; TitleQueries, BoardQueries, MentionQueries, ValidationQueries and SelectionQueries join Queries to Titles, Boards, Mentions (and Topology), Validation and Selection, for `canvas query`), and ArrowPorts joins Arrows, Ports and Topology, the only code that knows both arrows and channels. The foundation is Geometry, Canvas, DrawScript, QueryLanguage and TextEditing (the last three libraries beneath the plugins that know no canvas, registry or plugin: the languages `canvas draw` and `canvas query` read, and draw's solver, pure; and the app's text editing, the text view and caret list every editable text is built on). The shipped list is `ShippedPlugins.plugins(pasteboard:model:)` in Composition (and `registry(pasteboard:model:)`, `makeEditor(document:scheduler:pasteboard:model:)`); the app passes `ShippedPlugins.anthropicModel`.
- TextEditing (a foundation module that depends on no other of the project's, so it knows no canvas, registry, plugin or panel; `docs/plugin-system.md`, "TextEditing") is the text under every editable text in the app (a note's editor, a schema card's description, an arrow's label, the detail panel's boxes) and the one list shown at a caret. `EditingTextView` is an open `NSTextView` with what a host needs and `TextEditor` doesn't give, which a plugin subclasses for text of its own (the panel's `DetailTextContent`s, Mentions' `MentionTextView`): `onCommit`, `commitsOnReturn`, `onExit`, `onLeave` (the keyboard leaving, whatever for) and `placeholder` do nothing until set, so without them it's a plain text view, and `commitsOnLeaving` off leaves only ⌘↩ to `onCommit`, as a note's editor on the canvas, whose ⌘↩ ends editing; `commitsWhileReadOnly` lets ⌘↩ commit read-only text, for a commit that only ends editing (a schema card's description while the model writes it); it draws its placeholder in `drawBackground`, since AppKit gives a class that overrides `draw(_:)` TextKit 1, in the view's font or else `TextEditingStyle.placeholderFont` (the system's, 11 pt); `showEnabled(_:)` dims it, by default by its text's color, the label's or the secondary label's. A subclass that shows a list at its caret keeps its window, `caretListWindow` (a `MentionTextView`'s `@` picker or slash commands' list, a code editor's completions), and `EditingTextView` does the rest for every such list alike: while one's open it `holdsKeys`, so the list's commands (`CaretList.perform`) are the list's, before the delegate's turn (through the window's `pickHighlighted()` and `closeList()`, which run the owner's), and Return and Escape are never `onCommit`'s nor `onExit`'s, while ⌘↩, where the text commits, closes the list and commits, as with none; the keyboard leaving, the view leaving its window and its being made read-only close it; what's left to the subclass is when it opens, what it lists and what a pick puts in (a subclass may `holdsKeys` for something else too). ⌘., which the window sends up the responder chain as `cancelOperation:`, closes an open list (the view's `cancelOperation(_:)`, answered only while one is open, so with none it goes on up the chain as though the view weren't there). Tests read a list through `caretListWindow`. Such a list is the app's one caret list, whatever text it's over (Mentions' `@` picker; slash commands' list; a code editor's completions): `CaretList`, the model, headless (`CaretListRow`s: headers, items and one empty state; a `CaretListItem` is a title with its `matched` characters semibold, in an optional `font`, an optional symbol and `tint` before it, a `trailingSymbol` after it, a `detail` at the trailing end, which takes what the title leaves, or `TextEditingStyle.caretListDetailShare` of the row where both are long, and what VoiceOver says, `spoken`, the title and detail by default; the first item highlighted, ↑ ↓ wrapping and a page, `rowsShown`, stopping at the ends; `perform(_:)` takes the text view's commands: ↑ ↓ ⌃P ⌃N, Page Up and Down, Return and Tab pick, but not with nothing highlighted, Escape, ⌥⎋ and F5 close), sized by its owner's `CaretListMetrics` (width, row height, rows shown, offset below the anchor; its look is `TextEditingStyle`'s), and shown in a `CaretListWindow(list, accessibilityLabel:over:anchor:pick:close:post:)`, a borderless child window that never takes the keyboard (not deferred: a click's events name it, shown or not, and a board's window leaves clicks in its children alone, so a pick with the mouse is part of the typing), placed under the anchor range's `firstRect` (its rows' text under the anchor's start, above the line where there's no room below, on screen), following every ancestor's frame and bounds, asking its owner to `close` once the anchor leaves the text's visible rect or the window resigns key, and telling VoiceOver through `post` (Mentions routes it through `MentionAccessibility`); its owner calls `listDidChange()` after each change and `dismiss()` as it closes, and decides when it opens and closes, what the query is and what a pick inserts. - Slash commands (SlashCommands, a horizontal, on TextEditing; `docs/plugin-system.md`, "Slash commands") let a line of a shape's text run a command the shape offers: a `/` typed on an empty line lists them, and a line that is `/name` and what the command takes, entered with Return, runs the command and goes from the text, leaving only what the command did. A command is contributed as a context menu item is (the `ShapeSlashCommands` point, keyed by target and name): `x.slashCommands { SlashCommand("turn-on", when: { !$0.isOn }) { lamp, _ in lamp.isOn = true } }` over the kind's props, `x.slashCommands(of: P.self) { … }` over an added property's value on the kind's shapes that hold one, `registrar.slashCommands(K.self) { … }` for a bridge, `registrar.slashCommands(of: P.self) { … }` on every shape that has the property, and `registrar.slashCommandsForEveryShape(where:) { … }` over the record, where `where` gets a `SlashCommandKind` (the kind, its definition, the registry and `holds(P.self)`, asked once per kind, so a feature's every-shape command goes only on the kinds that opted into it: `$0.holds(LockedProperty.self)`); a horizontal's opt-in sugar may call these, so opting in brings its commands; the builder is `MenuBuilder`'s. A `SlashCommand<Value>` is a name, an `argument` (the hint beside the name in the list, `"title"` or `"@shape"`, which also says it takes one; nil for none), `when:` (the shapes that offer it, always by default), `accepts:` (which arguments it can run with: by default none for a command without an `argument` and anything but nothing for one with; given, it replaces that rule entirely) and an action in the forms of `MenuItem`'s: `edit: { value, arguments in … }` on the shape's live value in one transaction (setting what's there commits nothing), or `perform: { id, arguments, editor in … }` for what editing can't do (locking, moving, putting somewhere), which changes the document only through `editor.transact`. A name is lowercase ASCII letters and digits, words joined by single hyphens (`set-title`, `h2`: `SlashCommandLine.isName`, what can be typed and completed), else `ShapeSlashCommands.check` refuses the plugin list (`invalid`); two claims to one name for one target (a kind, or every shape) are a `conflict`, and a kind's own command takes the place of an every-shape one of the same name, offered or not. `SlashArguments` is what's typed after the name, trimmed at both ends, adjacent text merged: `runs` (`.text`, `.shape(id, label:)`), `text` (each shape "@" and its label: "near @Groceries"), `shapes` (in order, each once) and `isEmpty`; the module knows no mention, so a pill is a shape only because the host reads it so. Arguments a command doesn't accept leave the line as text and the command never runs (`/lock foo`, `/set-title` given none). `SlashCommandState` (`editor.slashCommands`, a service; nil without `SlashCommandsPlugin`) says what a shape offers now (`commands(for:)`: its kind's own in builder order, then those over a property it holds, then every shape's that its kind lets in, each whose `when` holds for the shape as it is, an `OfferedSlashCommand`; none for a shape that isn't on the board shown or is kept aside) and runs one (`run(_:on:with:)`, or by name folded to lowercase): in `undoHistory.group(title)`, one step named for the command in words (`/set-title` is "Set Title"), none if it commits nothing; false, doing nothing, for a shape that's gone or kept aside, a name the shape doesn't offer now, and arguments it doesn't accept (an `OfferedSlashCommand` is run as it was found, `when` not asked again). It keeps nothing per shape (each kind's commands gathered once, the registry being frozen), so `boardDidChange` is overridden with nothing. A text view takes part by hosting `SlashCommandTyping(over:owner:commands:arguments:)`, which holds the view and the state weakly, belongs to one shape's text (`owner`) and writes the text only through the view: the host tells it what's typed (`didType`), where the text and the caret go (`didChange(isEdit:)`) and asks it first about each key (`takesKey(_:)`, a plain Return), and shows its list as its own (`caretListWindow` returns its `window`), so the list's keys and its closing as the keyboard or the window goes are every caret list's (TextEditing's); `arguments` reads a range of the text as runs (default: plain text). A `/` typed (not pasted, not composed, not an undo) on an empty line, at the text's start or right after a line break and with nothing after it, opens the list while the view is editable, no other caret list is open and the shape offers a command; at the start of a line that has text (the line is evaluated whole, so a command chosen there would take that text with it), mid-line, or where nothing is offered, a slash is a slash. The list is `SlashCommandPicker`, headless, built on `CaretList` as Mentions' picker is and shown in a `CaretListWindow` under the `/` (240 wide, rows 24 tall, 8 shown, 4 below, "Commands" to VoiceOver): what's typed after the `/` is the query; an empty one lists every offered command in the order offered, else those whose names it matches ranked with `CaretListMatcher` (best tier first, then as offered), each row the name with its matched characters semibold and the `argument` as its detail, or the one row "No matches" with nothing highlighted; the first is highlighted. It closes when the caret leaves the name (before the `/`, past what was typed, or a selection), the `/` is deleted, what's typed holds what a name can't (whitespace, a line break, a pill, punctuation: ASCII letters, digits and hyphens, matched folded) or is past 40 characters (`SlashCommandPicker.Closing`), and on Escape or ⌘., leaving the `/` as typed; the text's substitutions are off while it's open (`CaretListSubstitutions`). The keys are every caret list's, and Tab, or a click on a row, completes: the `/` and the whole name token it is in (the caret may be in the middle of one) become `/` and the command's name, and a space if it takes an argument and no whitespace follows on its line (a line break doesn't count), one step of the text's undo, running nothing. Return is the list's own: a highlighted command that accepts nothing runs at once if nothing but whitespace follows its name on the line, else Return completes it as Tab does, so its argument can be typed; with nothing highlighted it's a new line, which closes the list. A plain Return (⇧↩, ⌥↩ and ⌘↩ are not) with the list closed, no selection, no text being composed and the caret after the `/` on a line that is `/name` and what follows, where the shape offers a command of that name now (folded to lowercase) and it accepts what follows (trimmed), takes the line's text out of the text, from its `/` to its end but not its line break, leaving the caret at its start on the now empty line, and runs the command; anything else (not a command, one not offered, arguments not accepted) is Return as ever, a new line or a box's commit (a command line runs and doesn't commit; anywhere else commits). The line goes first, as an edit of the person's (undoable, heard by the host through `shouldChangeText` and `didChangeText`, its own steps of the text's undo, its list closed before), because a command that makes the shape read-only (`/lock`) would refuse the text's write after it; the command is asked of the shape when Return is pressed (one not offered by then, or not accepting what was typed, takes nothing out), then run as it was found once the line is gone (`when` isn't asked again, so a command that reads the text still runs). While the shape is edited the line's removal is in the editing session's step and the command's commit closes it, so the command is a step between the typing before and after: the board's Undo takes it back by its name ("Undo Lock"), the typing next, and typing after it is a step of its own; the text's own undo (⌘Z while typing) brings the line's text back and leaves the command done; a command that ends editing (a lock) ends it as the core does. Mentions' `MentionTextView` hosts it (`slashCommands`, made for a view with an owner when the editor has `SlashCommandState`, else nil; its `caretListWindow` is the `@` picker's or the slash list's), so every text where mentions are typed takes slash commands (a note's editor, a schema card's description's, the panel's `MentionTextArea`), a pill in a command line is a shape it's given, the `@` picker's keys come first while it's open (Return picks the shape; Return then runs the line), opening the picker closes the slash list, and `show(_:)` closes both. Mentions contributes no command and needs no `SlashCommandsPlugin()`: the plugins that offer commands do, since the registry refuses a contribution whose owner isn't installed. `SlashCommandsPlugin()` is right after `ContextMenusPlugin()` in the shipped list; it contributes nothing and claims no key. The one command that ships is Locking's `/lock`, below.
- Locking (a horizontal, on Adornments, ContextMenus, Selection, SlashCommands and TableOfContents): any shape can be locked, from the context menu (Lock, or Unlock once every shape the menu is for is locked, as tldraw's toggle; items for the canvas in `LockMenuGroup`, order 300; no key; each goes by the shapes' own locks, of those whose lock can change: a shape in a locked frame, at any depth, is locked with it (the core makes it read-only) and can't change its own lock either, so neither item is for it: a menu for only such shapes has neither, and one for some of them and others acts on the others, trying none of them, `isLockedByContainer`) or with `/lock` (below), and unlocked from the menu or with a click on its chip (`LockChip`, a clickable adornment). Once a shape is unlocked, however, its chip shows the lock open for 1.5 s, more while the pointer's on it, then fades over 0.3 s; a click on the open lock locks the shape again, so a click by mistake can be taken back. Locked is something the shape knows: `LockedProperty` (`locked: true`, nil when unlocked), an added property every kind opts into (`optInEveryShape`), read as `record.isLocked`, set with `editor.lock(ids)` and `editor.unlock(ids)`; a locked shape's copy is locked. Locking tells the core locked shapes are read-only (`registrar.readOnlyShapes`), so nothing changes, moves, restacks, edits or deletes one (a drag moves the rest of the selection, Delete and Cut take the rest, the panel is disabled, there are no handles), while it's still selected, copied, listed and bound to. Each try shakes it (`LockState` hears `didRefuseChanges` and plays `editor.setDrawingOffset`: 5 points side to side, 3 times over 360 ms, dying away; a try while it plays doesn't start it over; a click doesn't count); every refused shape on the board shown shakes, so a shape whose board holds a locked shape, which isn't deleted either, shakes too, and a container shakes with what it holds. A locked shape that owns a board is entered like any other. On another board, `LockState` takes back its locked shapes as it kept them (a `BoardStash`, while the board's revision is unchanged; else it finds them again, one pass; `boardsScannedForLocks`, debug builds, counts the passes) and drops the shakes and open locks of the board left. A chip (`LockChip`: an 18-point disc with a lock, on the kinds that hold `LockedProperty`, at the right end of the row above the top edge, order 300, so a title's pill stops 4 points short of it; lighter hovered, darker pressed; below 35%, on a shape drawn as a skeleton (a locked shape always is: it can't be edited), a blank disc, locked or open and fading, which a click works as ever) marks it, and so does a lock at the end of its row in the table of contents (a `ContentsMark` with `symbol: "lock.fill"`, "Locked", on the kinds that hold `LockedProperty`, read from the record alone), so the list shows which are locked: a shape's own lock, so what a locked frame holds shows neither, the frame alone does; its open, fading lock is a label `LockState` keeps (`openLockOpacity(of:)`, with `editor.adornmentsDidChange`). `/lock` is a slash command every kind that holds `LockedProperty` offers (`registrar.slashCommandsForEveryShape(where: { $0.holds(LockedProperty.self) })`, offered `when` the shape isn't locked, running `editor.lock([id])` with `perform`): typed on a line of its own in a shape's text (a note's), with Return, it takes the line out, locks the shape and ends its editing, one step named "Lock" like the menu's, after the typing that has the line's removal in it; there's no `/unlock`, since a locked shape's text can't be edited and so nothing could be typed (the report shows it as `/lock → every shape`). A plugin list with Locking needs `SlashCommandsPlugin()` (the registry refuses a contribution whose owner isn't installed), which the shipped list has. Core and horizontal tests use CanvasTesting's `FreezingPlugin` and `Frozen` for read-only shapes, never Locking.
- Ports (a horizontal, on Selection and Topology; data-canvas's) are dots just outside a shape's sides, from which a drag draws a connection (an arrow) that may end only on a shape that takes its channel. A channel is a kind of connection, a type (`Channel`: `static let id: ChannelID`, `static var color` for its dots, computed, gray by default, and `static var summary`, nil by default, its edge type's), declared by the plugin that owns what it means (`registrar.channel(NoteLink.self)`, the `Channels` point; one declaration per id), which declares Topology's edge type of the same name too, under the connector's family (a root without a connector). `ChannelID` is what a connection keeps, so it never changes once shipped, and the id audit holds its literal to the module that declares it. A kind has ports on a channel with `x.ports(C.self, sides:role:)` (`registrar.ports(K.self, on: C.self, sides:role:)` from a bridge; the `ShapePorts` point, one per kind and channel, and a kind may have ports on several): a dot at the middle of each of `sides` (`PortSide`, all four by default), and a `PortRole`, `.both` (the default), `.source` (dots; nothing ends on it) or `.target` (connections end on it; no dots). `ShapePorts.check` refuses ports on a channel no installed plugin declares, or on the connector's own kind. One plugin draws connections, the connector (`registrar.connects(K.self, edgeType: F.self, canConnect:make:ends:begin:)`, the `Connectors` point, at most one): `F` is the family of edges connections are (an `EdgeType` it declares; with `ends`, a connection bound at both ends is one edge, of its channel's type, else `F`'s, and `F`'s too for a channel that names a declared type that isn't a channel's; a free end, none), `K` opts into `ChannelProperty` (key `channel`, nil by default, so only a connection drawn on a channel has one; one `canvas draw` makes with `channel: none` has none), `canConnect` says which shapes one may start from and end on in a `ShapeContext` (the editor's for the dots, a transaction's for a connection made by name: `registry.canConnect(_:in:)`), `begin` gets the `Connection` (`shape`, `side`, the dot's `channels` in the port table's order, `origin`, where it was pressed, world units) and returns the session the press hands the drag to (nil: nothing), and the optional `make` and `ends` connect shapes without a drag: `registry.connection(_:existing:in:)` makes a `ConnectionRequest` (ends, optional sides, channel, both heads) into a connection, not inserted, or changes `existing` (only named sides and the heads; `existing` itself when nothing would change, so `==` tells unchanged), and `registry.connectionEnds(of:)` is which shapes one joins. Without a connector no shape shows ports. Every question about ports reads one port table per kind (`KindPorts`, PortTable.swift: plugin order, a kind's first contribution on a channel its only one there), the registry's lookups too (`connectorKind`, `makesConnections`, `dotChannels(of:side:)`, `takes(_:_:as:side:)`, …), so a drag and a connection made by name pick channels alike. `editor.channel(of:endingAt:)` is the first of a connection's channels a shape's kind takes as a target (nil for the shape it starts from, or one kept aside); `registry.accepts(shape, on:as:)` and `registry.declares(_:)` are what rules for connections already drawn go by. The dots are Selection's canvas buttons, dragged (`PortDot`, from `PortState.dot(atViewPoint:)`), shown for one shape, the host: the one whose dot the pointer is on (any shape's, so a dot reached straight from empty canvas shows its shape's, as data-canvas's halo does), else the shape with dots under the pointer, kept while the pointer stays within reach of its dots (its view bounds grown by 24 points) over empty canvas or a shape without ports; none while a handle is under the pointer (it takes the hover), and none once the tool changes or the shape is deleted. A shape has dots when its kind has a side that isn't `.target`, it isn't kept aside, and `canConnect` allows it. They show in the select tool only, at 25% zoom and up (`PortStyle.minZoom`), while the pointer's over the canvas (`editor.pointerOverCanvas`) and, where it is now (`editor.pointerWorldLocation`), within reach of them, and nothing is under way but a dot's press: each 12 view points out from the middle of its side of the shape's bounds, a disc 8 points across in its first channel's color at 60% in a white 1.5-point ring, and hovered or pressed 10 points across at full color in a halo 24 points across at 24% (`PortStyle`'s radii: 4, 5, 12); constant on screen, following the host's drawing offset (a locked shape's shake). A dot shows, and is hit, only while no selectable shape painted above its own covers its center (an arrow leaving the shape there, a neighbor on top; `PortState.liveDots(of:)`), so a shape lying on a bigger one shows its dots over it. The nearest showing dot within 12 view points is pressed (none where the select tool hasn't seen the pointer move, just after a tool change or a first click into the window, since none shows there); past the drag threshold the connector draws, and while it does each shape in view the connection could end on is outlined faintly, as a hover (the one it would end on now gets the hint). `PortsPlugin` comes after `AdornmentsPlugin` in the shipped list, so a dot is found before a lock chip (a clickable adornment) and draws above it. Locked shapes keep their ports: connecting doesn't change them. ArrowPorts makes arrows the connector (its family `ArrowEdge`, `arrow`, its id made from `Arrow.kind`; `canConnect` is `shapes.canBindArrow(to:)`, `begin` is `editor.beginArrow(from:at:canBind:complete:)`, `canBind` a shape that takes one of the port's channels (`editor.channel(of:endingAt:)`), and `complete` sets the arrow's `ChannelProperty`; `make` binds both ends, an unnamed side at the center (imprecise) and a named one at its middle (precise, not exact), its channel set before `registry.arrowMayBind` asks the rules), and its `arrowBindingRule` keeps an arrow with a channel some installed plugin declares to shapes that take it at that end (the start as `.source`, the end as `.target`), re-aimed or moved; one without (`channel: none`'s), or with an undeclared channel, binds wherever an arrow can. Shipped: notes have ports on `NoteLink` (`note-link`, a brown amber) on every side but the top, where a titled note's pill is (`NoteLinks.swift`), and schema cards on `SchemaLink` (`schema-link`, the card's accent) on every side but the top too, where a titled card's pill is (`SchemaLinks.swift`), each declared by its kind's plugin, so a note links only to a note and a schema card only to a schema card.
- Topology (a horizontal on the core alone; `docs/plugin-system.md`, "Topology") is what connects and contains what, whatever is where: edges, a typed graph (an arrow bound at both ends, a mention), and containment, one tree of two kinds of link (the container a shape is in on its board, a frame, else the board it's on); spatial relations (a note within another shape's bounds) are geometry, not Topology's. The carrier shape is the system of record (an arrow's bound ends and `channel` are its edge, a note's text its mentions): `TopologyIndex` (`editor.topology`, a service) derives the whole file's edges from the records, by carrier, by each end and by type, in memory, never saved (nothing in props, meta or the file: tldraw's binding records would be a second truth to keep in step, and a mention outlives what it names), and never transacts. An `Edge` is its `type` (the most specific), `source`, `target`, `carrier`, `slot` ("" for the carrier itself, else the property's name) and `count` (repeats in that slot); only a connection bound at both ends is one (no loose edges), and a shape kept aside, or on a board the editor can't show, carries none. Edge types are types (`EdgeType`: `static let id: EdgeTypeID`, `parent` and `summary` nil by default: a lowercase line, no period, saying what it joins and which way, which a query's vocabulary shows, `EdgeTypeTree.summary(of:)`, a channel's through `Channel.summary`) declared by the plugin that owns the meaning (`registrar.edgeType(T.self)`, or `edgeType(_:parent:summary:)` with a parent resolved from the frozen registry; the `EdgeTypes` point, one per id, whose `check` refuses an undeclared parent and a loop), a tree (`EdgeTypeTree`: `registry.edgeTypes`, or `topology.types`, kept); shipped: `arrow` (ArrowPorts' `ArrowEdge`) with each channel's type (`note-link`, `schema-link`) under it, and `mention` (Mentions' `MentionEdge`, a root). A type nobody declares (a newer app's channel) is kept as written, with no parent. Queries filter by `EdgeTypeFilter`: `.all`, `.within(t)` (t and every type under it), `.only(t)`, each also over a sequence (an empty one admits nothing). Sources (the `EdgeSources` point; several per kind add up) say what a record carries: `x.edges { shape, registry, sink in … }`, `registrar.edges(K.self) { record, registry, sink in … }`, `edgesForEveryShape(where:)` (asked once per kind), and the property rule `registrar.edges(in: P.self, as: T.self)` (every shape a `ShapeNaming` added property's value names, slot its key, on the kinds that opt in; it doesn't declare `T`); `sink.emit(type, from:to:slot:)` counts repeats and keeps the order of first emission. A source is a pure function of one record and the registry (never other shapes, geometry, services or time, nor where a box is), so each commit reads again only what it removed, added, changed other than by moving (`ChangeSet.moved`), or touched `elsewhere`, and undo is exact; `registry.edges(of:)` is one record's. Queries cost what they return: `edges(of:_:types:)` (`.outgoing`, `.incoming`, `.either`; an edge to itself once; `hasEdges(of:_:types:where:)` stops at the first, making nothing), `neighbors(of:_:types:)` (the other ends by type: what's connected, and how), `edges(ofType:)`, `edges(carriedBy:)`, `end(_:)` (`EdgeEnd`: `.live(board)`, `.unavailable`, `.missing`), `revision(of:)` (observed per shape, counted from its first read) and `touched` (the last commit's; `touched(types:)`, of some types). Containment, never an edge, reads boards and containers on them as one tree, with no index of its own (the boards keep who's in which container, and only containers the core goes by count, `document.container(of:containingKinds:)`, nonisolated): `parent(of:)` (the container a shape is in on its board, else its board's owner; nil on the root in no container), `children(of:)` (what a container holds, back to front, then, for an owner, its board's shapes in no container), `ancestors(of:)` (nearest first), `isInside(_:_:)`, only on boards the editor can show, one piece of code (`Containment`, a value over a `CanvasFile`, the kinds that own boards and the containing kinds) for the index and its snapshot; `containerKinds` (on `Registry`, the index and the snapshot) is which kinds contain: those that own boards and `registry.containingKinds` (a kind that's both lists what it holds before its board); a move costs it nothing, and a board without containers what it did before there were any (`CanvasDocument.namesContainers`, O(1)). `topology.snapshot()` is Topology as it is now for any thread (`TopologySnapshot`, `Sendable`, O(1), reading no record and observing nothing: it shares the index's tables, `EdgeTables`, and the file, read without observing it, and answers through the same code, so it answers as the index would have as it was taken, though not what changed: no `revision(of:)` or `touched`), with more reads of the whole file: `forEachShape(inFileOrder:)` (every shape on a board the app can show, kept-aside ones too, with its board: the root's shapes in no container back to front, each followed at once by what's inside it, what it holds then, for an owner, its board's, before the next; iterative, so a chain of any depth; an error its body throws stops it, as the body's own type, `throws(E)`), `fileOrderKey(of:)` (a key that sorts as that walk visits, each ancestor's place among what's directly inside its parent, root down; O(depth), nil off the boards the app can show), `topLevel` (the root's shapes in no container) and `isTopLevel(_:)`, `container(of:on:)` (the container a record is directly in on its board, O(1), with no lookup for one in none: a query's walk), `descendants(of:)` (file order), `shape(_:)` (kept-aside ones too) and `presentTypes`. Hold one for a task, never past it: a commit copies each table it changes, once, while one's held; and one taken by a service hearing a commit before Topology holds that commit's file with the commit before's edges (`catchUp` first). It reads every board the editor can show as it opens (a kind with no source costs a lookup), again for `replaceFile` and `replaceDocument`, and nothing on a switch. `TopologyPlugin()` is right after `SelectionPlugin()` in the shipped list, so its service hears each commit before those that read it; a service that may hear first calls `topology.catchUp(changes)` (nothing once heard). Every plugin list with Ports or Mentions needs it (and one with Queries, whose every query is `no_topology` without it). `canvas query` reads it through a snapshot, and `canvas draw` matches an edge by its ends, not its type.
- Queries (a horizontal on Topology; `docs/plugin-system.md`, "Queries") finds the shapes of a file a query matches. The language is QueryLanguage's (a foundation module that knows no canvas, registry or plugin: `SelectorList(parsing:)`, a tree whose parts know their places, `QuerySpan`s in characters of the query as sent, and `canonical`, the one form it prints, which an answer says ran), CSS's where CSS has a meaning: a compound is at most one head (a kind, `*`, a title in quotes, a kind with a title right after it, `sticky-note"Checkout"`, the kind's shapes with that title, refused as a title head is, or `#` and an id) and tests with no space (`[a]`, `[a=v]`, `^= $= *= ~= |=`, `< <= > >=`, `i` and `s`; `:not`, `:is`, `:where`, `:has`), a space is inside at any depth, `>` directly inside (a container's own shapes, an owner's board's in no container), a comma either; its own words (`Word`) are those, `:inside`, `:top-level`, `:current-board`, the edge words (`:edge-to`, `:edge-from`, `:connected-to`, one edge either way, `:downstream-of`, `:upstream-of`, `:component-of`, any number either way, `:starts-at`, `:ends-at`, `:between`, each taking edge types after a comma, `a|b`, `only t` for a type alone, a type taking in those under it), `:dangling` and `:contains("x")`; `QueryLimits`: 8,192 characters, 1,024 in a string, 32 levels, 256 compounds, 20 problems said. The canvas skill teaches it (`reference/query.md`). Every kind is selectable unless it opts out (`x.unselectable()`, or `x.selectable { ... }` per shape); the select tool sees through such shapes, nothing else does. A `LabeledShape` (Selection's capability, an `Editable` kind with text on part of it, `labelFrame(of:in:)`: an arrow's label) is edited by a click on the only selected shape only on its label, and a drag from its label, past the threshold, is its `labelDragSession`'s (the shape selected alone, ⇧ adding it), not the selection's; a read-only shape's is the selection's, refused. The shape being edited shows no handles (its editing view is over them, as tldraw's). A read-only shape (a locked one) is selected, hovered and outlined as any other, but shows no handles, so a press there presses the shape. A plugin can put buttons on the canvas (the `CanvasButtons` point: where they are, in view points, and what they do), clicked (`registrar.canvasButtons(at:click:)`, Adornments' clickable adornments: the lock chip) or dragged (`registrar.canvasButtons(at:drag:)`, Ports' dots): in the select tool only, they win over handles and shapes (the later plugin's first, as its overlay draws on top); a press and a release on a clicked one click it (dragged off, nothing), with the pointing hand over one (`CanvasCursor.pointingHand`); a dragged one's press, past the drag threshold, hands the drag to the session `drag` returns (given the button and where it was pressed, world units; nil ends the press), and released without a drag does nothing, with the open hand over one and the closed hand while it's pressed; Escape lets go of either. `editor.hoveredButton` and `editor.pressedButton` say what to draw hovered and pressed (both cleared as a drag hands over), a plugin whose buttons change without a commit calls `editor.canvasButtonsDidChange()`, and `editor.pointerOverCanvas` is where the pointer is over the canvas in the select tool (view points, as it last moved with nothing under way; nil once it's left the canvas or gone over the minimap or the editing view, another tool is current, or Escape let go of a dragged button's press, until it moves again), for buttons that show only while it's near (a port's dots). Something drawn for a shape outside it (`registrar.decorationHits`, the `DecorationHits` point: every adornment) is that shape for the select tool (a press, a drag, the release, a double-click), hover and the context menu: `editor.selectableShape(at:)` asks it first, the last plugin's first, with `isSelectable` as its `include`, so an unselectable shape's is seen through; buttons still come before it, and the core's `shape(at:)`, the marquee and an arrow's end never see it. - Going to shapes is Selection's, one way for every plugin: `editor.reveal(ids)` only moves the camera (centers the shapes' bounds in `unobscuredViewport`, below the path over a subboard's canvas, fitted with 100 points of margin, no closer than 120%, over 200 ms: `SelectionStyle.reveal*`, data-canvas's zoomToBounds), and is what selecting table-of-contents rows does. `editor.goTo(ids)` is following a link (a mention): it ends editing, selects the selectable ones (a Back step only when that changes the selection; to what's selected already, or to unselectable shapes, it only moves the camera), and reveals unless they're all in view, where the camera is headed (`cameraTarget`), at a readable zoom: `SelectionStyle.readableZoom` (70%: a note's 16-point text reads at 11.2 points there, just over `NSFont.smallSystemFontSize`), or a kind's own, closer, for text set smaller (`x.readableZoom(_:)`, `registrar.readableZoom(K.self, _:)`, Selection's `ReadableZoom` point, above zero and at most 120%, `ReadableZoom.maximum`, as close as `reveal` brings shapes, `editor.readableZoom(of:)`: 11-point text reads at 100%; no shipped kind says one; the closest of the shapes' kinds counts), or as close as fitting them would bring them (a shape too big for 70% that's all in view stays put). The shapes may be on any board of the file: it goes to the board of the first of them on a board it can show, and to those of them there, showing that board and selecting them as one Back step (`showBoard(_:selecting:)`), then revealing them. `reveal` is the board shown's alone. Nothing mid-gesture, or when none of the shapes is on a board it can show. `editor.goInto(id)` is following a link into what it names (a mention of a subboard): `goTo`, then `open` there (`canOpen`), as one Back step to where it was followed from, whatever boards it went through (`SelectionState.asOneStep`: nothing inside records a step of its own); nothing for a shape whose own board is shown.
- Faces (Selection's `ShapeFaces` point, `registrar.shapeFaces(at:click:doubleClick:hovering:)`) are parts of a shape's content that answer a click without taking the shape's press: a mention's pill in a note, a link, a checkbox on a card. `at` is asked only for a plain press (no ⇧, ⌘ or ⌥, not a Control-click) on the shape the select tool would press, selected or not, at a world point on that shape itself (a point on what `DecorationHits` draws for a shape is no face's), after canvas buttons and handles, and looks at that one shape; the last plugin's first. Never on a shape drawn as a skeleton (`editor.drawsSkeleton(of:)`, zoomed out), which shows none of its content: there a click, a double-click (which edits an `Editable` one from where it's pressed, then drawn in full, and is a refused edit on a read-only one) and the pointer are the shape's, and a lone box follows the pointer at once; as the level changes, Selection's `drawsSkeletonsDidChange` looks again under a still pointer, so a face's hovered target gives way to its shape; a face pressed in full whose shape is a skeleton by the release (a pinch past 35% mid-press) isn't clicked: the release is the shape's, as a canvas button gone by the release isn't clicked (`PointingShapeSession.end` checks `drawsSkeleton(of:)` again). The press is the shape's: it selects the shape as any press does and, past the drag threshold, moves the selection from the press; on a lone box it waits for the threshold too (an intended deviation from the lone box's press, pinned in SelectionTests). Released within the threshold, the shape is selected alone and `click` runs; Escape lets go first. A double-click whose press lands on one selects the shape alone and runs `doubleClick` in place of editing it, a read-only shape's too; without `doubleClick`, a double-click there edits an `Editable` shape and is otherwise one more click. The pointer over one hovers the shape `hovering` names (`editor.hovered`, so hover keeps one path), or its own shape when it names none, or one that isn't there or can't be selected; hover asks whatever keys are held, and the cursor stays the arrow. `click` runs once the press is over, so it may `goTo` or go back, and what it selects is a Back step of its own; it isn't given the press, so a face that needs a point carries it in its value (a pill edits its note from there, `editor.beginEditing(id, at:)`), and a click that begins editing leaves the pointer over the editing view, which ends the hover. CompositionTests' canvas view tests hold these pieces together with `pillsPlugin`, a pill-like face in a note: edited from the pill on a click, not hovered under its text, and gone to (`goTo`) from a locked note's double-click; Mentions' pills are faces built on them. A face that edits its shape checks `editor.isReadOnly` first (as `pillsPlugin` does): a refused edit is a try, which Locking shakes, and a click on a locked shape isn't one. A click on a face that goes somewhere (it changes the selection or moves the camera: a link's `goTo`) makes the rest of its double-click its own: the select tool ignores each press after it with a click count of 2 or more, until one of 1 (`ignoresPress`), so the camera goes on to where the click sent it and nothing is placed, edited or pressed where it has got to; a click that goes nowhere (a pill's) leaves the double-click to `doubleClick`.
- Boards are files, one per board, with the boards inside it (`docs/plugin-system.md`, "Boards on disk"): `BoardDocument` (CanvasUI, an `NSDocument`, autosaved in place) saves `editor.file`, every board of it, with `BoardCodec` (Canvas), and opens one with `replaceFile`. The app is AppKit-run: `InfiniteCanvasApp` sets `BoardDocument.configuration` (the shipped registry, the window's SwiftUI content) and installs `BoardMenus`; the Info.plist that `build.sh` writes exports the `.canvasboard` type (not `.board`: Freeform owns it). Order in the stack is each record's `stackingKey`. A kind's props are versioned by its append-only `static let migrations`: changing how they encode needs a migration and a new fixture in `Tests/CompositionTests/Fixtures/kinds` (never edit a fixture), even a new member with a default (`PropsMigration("name")`, which rewrites nothing). An added property's value is versioned by its own (`PropertyMigration`, over the value's JSON), whatever kinds opt in, with fixtures in `Fixtures/added` (`expectPropertyFixtures`); `PropsMigration.handOver("title", to: TitleProperty.self)` hands a kind's own member over to one. Shapes the app can't use are kept aside (`AnyShapeRecord.isOpaque`) and saved back as they were; a horizontal that goes through every shape skips them. A record's metadata is saved beside its props (`meta`), members no plugin knows included, and its added values in `added`, by key; those the app can't use (not declared, not opted into, newer, unreadable) in `kept`, with their versions, saved back as they were and listed in `LoadReport.keptValues` (the alert never offers to delete them). A board is written in the oldest format that holds it: 5 when a shape on any board is in a container (its `container`, beside its props, read only from 5; reading drops one not on the shape's own board or in a loop, `LoadReport.Repair.droppedContainer`, and keeps one that can't hold, kept aside or of a kind that holds nothing here, as written), else 4 with any board besides the root (`BoardCodec.encode(CanvasFile)`: `boards`, one flat map by owner id, never nested (Foundation's JSON reader stops at 512 levels), each `{ "shapes" : [...] }`, under the root's `versions`; read only from format 4), else 3 with added values (the envelope's `versions` has `kinds` and, when any, `added`), else 2 with metadata, else 1 (both with `schema`), so an older app refuses what it would save without. `LoadedBoard.file` is every board (`document` its root); reading walks the boards in tree order with one set of ids, so a repeated id is the first holder's, with the board it owns, and keeps the boards it can't show (`LoadReport.keptBoards`, `KeptBoard`: an owner kept aside, of a kind that owns none, inside such a board, unreachable, or an entry that isn't a board, kept verbatim in `CanvasFile.unreadableBoards`), writing them back; `KeptShape` and `KeptValue` name their `board`. The camera on each board, the board left open, and whether the details and the minimap show are remembered per file (`BoardViewMemory`: `View`'s `board` and `boards`, read with `decodeIfPresent`, so an older entry is the root's; saved for the boards the file can still show, `editor.boardCameras`: the one shown and those above it, then those shown most lately, up to `BoardViewMemory.boardLimit`, 50, by `editor.boardsLeft` and the last session's `recent`), never in the file; a file opens on the board left open if it can still show it, through `replaceFile(with:showing:)`, so it's no step back nor an edit, each board with its camera (`rememberedCameras`). A board document has no undo manager (`hasUndoManager = false`): it counts its changes by its history's events (`undoHistory.didChange`, host API: a step began, came to nothing, was undone or redone), at once, so undoing to what was saved reads unedited. Every save closes the open step (`breakStep`), so undo returns to exactly what was saved; a periodic autosave during a press, or while a key is held whose repeats are one step (`undoHistory.isKeyHolding`: an arrow key's nudges), gives way (`userCancelled`) and runs once it's let go (`snapshot(implicitlyCancellable:)`). Its window is a `BoardWindow`, which answers Edit › Undo and Redo: the text's own while text has the keyboard (its `textUndo`, the only undo manager text views see, or a field's; forgotten when the text loses the keyboard; after each, the text says it changed, so a note or a field's binding writes it), else the board's `.undo`/`.redo`, named ("Undo Move"); it seals a run of panel writes on a click, a key on a control, or the keyboard moving, and every board's window seals on a click in a window that isn't a board's (the color panel), but not in a board's child window (the `@` picker beside a panel's text, whose pick is part of the typing).
- Change documents only with `editor.transact`, and name the step a user would call it (`transact("Name")`, `undoHistory.group("Name")` around several). A body that throws commits nothing and opens no step, and the error comes out untyped. Tools see `Pointer` values, never `NSEvent`; timers go through `editor.scheduler`. Model positions are world units; overlay sizes (handles, outlines, hit margins) are view points, divided by `zoom` in world space.
- Boards in a file (`docs/plugin-system.md`, "Boards in a file"): a file is a tree of boards, `CanvasFile`: the root board, and `children`, a board for each shape of a `BoardOwning` kind, keyed by the owner's `ShapeID` (a board is named by a `BoardID`, `.root` or `BoardID(owner:)`, written "root" or the id), never in the owner's props (its schema is marked `x-canvas-board`). So the tree is a function of where shapes are: a board has one owner, a copy (a new id) has a board of its own, and nothing done in the app makes a loop or an orphan (only a file edited by hand, which reading keeps and reports). Shape ids are unique across the file (`file.board(containing:)`, `file.record(_:)`); a board with no shapes isn't kept, so placing an owner makes only the shape; each board has a revision (`file.revision(of:)`) that changes with its shapes and never comes back, which is what anything kept about a board (an index, rows, issues, locks, a preview) is checked against. One editor holds a whole file (`editor.file`) and shows one board of it (`editor.board`) as `document`: what's local to a board comes from reading `editor.document`; never list shapes from `editor.file`. `editor.contents(of:)` and `editor.owner(of:)` read any board. A transaction is on the board shown and reads the file through the editor, never holding a copy; deleting a shape takes its board and every board under it in the same commit (the cascade, `ChangeSet.boardsRemoved`, in `Transaction.delete`, one undo step that undo puts back whole, every id), unless a read-only shape is on any of them, which keeps the owner from being deleted; `transaction.insert(_:contents:)` brings a shape in with its boards (a paste, `boardsAdded`). A commit says what it did beyond its board in `ChangeSet.elsewhere` (every shape of the boards it took or brought, those it changed on another board, and, for a file put in place over the board shown, those its other boards changed), for what reads shapes anywhere in the file. Only `editor.transact(on: board, "Name") { … }` edits a board that isn't shown (what lands late: a sync's answer): its commit changes that board in the file, is an undo step of its own made on that board (undoing it shows the board first; a step open on the board shown stays open, after it), and services hear it as `boardsChanged` with its shapes `elsewhere`; it can't take the board shown or one above it, shakes nothing, and returns nil for a board `canShow` refuses. Core and horizontal tests nest boards with CanvasTesting's `PocketsPlugin` (a `pocket` kind that's `BoardOwning`, apart from `FixturesPlugin` so the reports tests pin don't change), never with Subboards.
- Showing a board: `editor.showBoard(board)` (true once it's shown; false while a session runs, or for a board `canShow` refuses: one whose owners, root down, aren't all in the file, of a `BoardOwning` kind, none kept aside: the file's rule, `file.canShow(_:boardOwningKinds:)`, nonisolated, which the editor's calls) makes it `document`, and `editor.board` and `editor.boardPath` (root first) say where the editor is. It's not an edit. In order: services hear `boardWillChange(from:to:)` while the old board is shown (save what's its: a draft, state in a `BoardStash`), editing ends, the default tool comes back, camera motion stops, the old board keeps its camera (`cameraTarget`) and index, the new board takes back its `ShapeIndex` if its revision (`file.revision(of:)`) hasn't changed since (the last 8 boards; those on the path are kept longest), `revision` bumps once, the camera is the one the board was left with, else the host's `rememberedCameras`, else a first visit's fit (inset 64, no closer than 100%, into what the host leaves clear of the view on that board, `coveredTop`), else `Camera()`; then services hear `boardDidChange(BoardChange)` (`from`, `to`, `leftCamera`, and `changes`, worked out only if read: by default a service hears it as `documentDidChange` of every shape of one board gone and every shape of the other come, right for per-shape state; one that keeps state per board overrides it, and reads no other service there; one that keeps nothing per shape overrides it with nothing, as ContextMenus, Keyboard, Clipboard, DetailPanel, LanguageModels and Arrows do; the table of contents, Validation and Locking keep each board's rows, issues and locked shapes in a `BoardStash`, Selection makes the board left a step back, Boards makes the path again, Ports lets go of the dots it showed, Adornments drops its labels (made again only for what a frame draws), the schema cards' sync keeps every card of the file by id, and Topology's index and Mentions' resolutions and catalog are the file's, so no shipped service works out the change set; CompositionTests' BoardsTests hold the shipped list to that), and the host `editorBoardDidChange`. Arrows stop aiming in `boardWillChange`. `replaceFile(with:showing:)` stays on the board shown if the new file can show it, else goes to the nearest board above it, or the root, as a switch does (and `CanvasEditor(registry:file:showing:)` opens on one). A `BoardStash<State>` is a service's state per board, taken back only while the board's revision is unchanged; `BoardChange.isFileReplaced` says a `replaceFile` came with the switch, so what a service keeps across the file by shape id is taken afresh. Damage marks are per index (`DamageMark`, host API; `editor.isCurrent(mark)`), so a picture kept for a board (the minimap's) is current only while the editor kept that board's index. A render may read `context.shapeCount(inBoardOwnedBy:)` and `context.shape(inFile:)` (a shape on any board the editor can show: a mention's pill; `editor.shape(inFile:)` elsewhere), and draw `context.drawBoardPreview(ofBoardOwnedBy:in:)` (only on `RenderContext`: geometry and hit tests never read another board). The command names `.openSelection` and `.enclosingBoard` are the core's, for plugins to claim (Selection claims `.openSelection`, Boards `.enclosingBoard`). - Moving arrows is `ArrowDefinition: CustomTranslation`. Alone (or with unrelated shapes) it is the POC's translation exactly; moved with a shape it's bound to, it keeps every binding, as tldraw. Its ends probe at the full delta (tldraw: half), a known deviation the transcript pins.
- What an end may bind to is tldraw's canBind, from any plugin: `ArrowBindingRules` (`registrar.arrowBindingRule { query in … }`, over `ArrowBindingQuery`: the arrow as it is, the end, a shape under it, the registry). An end binds only to a shape every rule allows, looking through the rest to the shapes behind, wherever an end binds: `ArrowTargeting.bindTerminal` (a port's drag, re-aims, the precise timer, a modifier's change) and a lone arrow's translation probe (`beginTranslation`); rules are asked only of the shapes the point hits, and with none nothing is filtered. Arrows knows no channel: ArrowPorts' rule does, and lets an arrow without one bind to anything, as arrows always did (the transcript holds them). `shapes.canBindArrow(to:)` is whether an arrow can bind to a shape in a `ShapeContext` (there, closed, not an arrow; `editor.canBindArrow(to:)` in the editor's), `registry.arrowMayBind(arrow, end, to:)` asks the rules for an arrow made without a pointer (ArrowPorts' `make`), and `editor.beginArrow(from:at:canBind:complete:)` draws one for another plugin's gesture (a port's drag): it inserts an arrow, its start bound to the shape at its center (imprecise) and its end free at `origin`, and returns an `ArrowHandleDragSession` dragging the end (`connecting`), which binds by tldraw's rules (fast to the center, slow or after a 320 ms dwell precise, ⌥ exact, ⌘ or ⌃ nothing, ⇧ snaps the angle) only to shapes `canBind` and the rules allow, seeing through the rest; released bound, `complete(&record, target)` finishes it in one transaction. `BindingHintsOverlay` draws for the arrow being dragged (the session's `arrowID`), else the selection, so re-aims and a port's arrow hint alike.
