# Testing

Writing tests: the headless harness, views in unshown windows, and the board documents a test must close. Each subsystem's own test guidance is in the Testing section of its topic file (listed at the end).

Related: [build](build.md), [drawing](drawing.md), [editing](editing.md), [undo](undo.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Testing plugins](../../docs/plugin-system.md#testing-plugins).

## Verifying UI changes

- Screen capture isn't permitted here. Benchmarks and most tests draw into bitmaps, while the app's `CanvasView.draw` records a display list (AppKit's context isn't a bitmap: its `bitsPerComponent` is 0) that Core Animation renders on the GPU while the window is on screen and the display awake (headless, or with the display asleep, it replays it on the CPU), so what a drawing change costs on screen is seen only in the app on screen, and a clip of many rects is the known trap (the dot grid's, some 400 ms a frame, is why it clips only into a bitmap).
- Drive a headless editor with `EditorHarness` (CanvasTesting), with `KeyboardPlugin()` and `SelectionPlugin()` first in its plugins when the test presses, drags or selects as a user does (without Selection the default tool is Hand, and without Keyboard no key does anything). `EditorHarness(plugins:file:)` starts on a file of boards (with `PocketsPlugin()` for a kind that owns them), and `h.enter(owner)` shows the board a shape owns; `openingPockets()` (in SelectionTests, TableOfContentsTests and CompositionTests) makes pockets open onto their boards (`registrar.opens(Pocket.self, …)`). `h.key("v")` presses a key on the canvas (with what `h.hold` holds); CanvasTesting's fixture tools have no keys, so pick them with `h.editor.setTool`. One clock drives event timestamps and the `ManualScheduler`, so pointer speed, the arrow timers and the hand tool's slide (inertia) behave. Check drawing with `renderBitmap`, `pixel` and `changedPixels`.
- A shape laid out larger than it stores (`LaidOutBox`) is tested without Types or StickyNotes: CanvasTesting's `StretchesPlugin(log:)` registers `Stretch`, a box laid out by the `Gauge` it names (a layout input it provides, `Stretches.room`), a service that announces a gauge's change, and a `StretchLog` of every size and provider call asked (apart from `FixturesPlugin`, so the registry reports tests pin don't change). KindSchemaTests and ValidationTests have a `Gauge` kind of their own: CanvasTests refer to the fixture's as `StretchGauge`.
- A card (`editor.showCard`, [editor](editor.md)) is tested with CanvasTesting's `CardProbe` (an `NSView` that is flipped, takes the keyboard, logs the keys it takes, wants a settable size cut to the room it is asked about, and logs those rooms) and `probeCard(_:about:anchor:stepName:probe:closings:)`, whose `ClosingLog` holds the reasons it closed with. CanvasTests' `CardTests` run it headless over a counting `CanvasEditorDelegate`; CanvasUITests' `CardViewTests` put a `CanvasView` in an unshown window and call `pressBeganInWindow` (the press monitor's body; `NSApp.sendEvent` runs the monitor itself), `canvas.cardFrame` and `canvas.hitTest`.
- The gallery (CompositionTests' `GalleryKit.swift`, the harness, and `GalleryTypesLook.swift`, the states of the types cut: `galleryTests`) renders states of the app's look offscreen, light and dark, as PNGs named for the plan's board panel each answers (`Flow2-p1-list-types-dark.png`) with an `index.txt`, and a menu as its `outline` in a `.txt`: `GALLERY_DIR=/some/dir TEST_FILTER=Gallery ./test.sh`. A tool for design review, not the tests: with `GALLERY_DIR` unset it is one quick test (a state in both appearances, not blank, the two differing, no file named twice). It draws the canvas with `cacheDisplay` (editing view and all) at 2x and lays an open caret list's visible rows over it under the caret (its blur isn't drawn offscreen); the model is scripted and answers a type's highlights only, the pasteboard is private, a type's id (so its color) is fixed. A new state is a `GalleryState` in the list; other tracks add their own beside it. A type's rows are `GalleryRows.swift` (`rowStates`; `rows-read-failed`, `-no-key`, `-too-long` and `-failed-zoomed-out` are a failed read said at the foot of a type's rows), a note that is one's `GalleryValues.swift` (`valueStates`: its values, the row typed in, a choice focused and its menu, the marks' look alone through `rowBook.checks`, a value found, zoomed out and many), the types sitting far off the stage so a note is alone in view.  The panel's (`GalleryPanel.swift`, `panelStates`) hang the Types tab over the same fixtures. `GalleryCards.swift` (`cardStates`) holds the card's: board 5's Order from `FieldFixtures`, each card opened by a click on its real row (`click`: the stage's press and release on the row's value or the fold's words, which begins the note's editing there and asks for the card on the next turn; on a type's note and a locked note it opens at once), so it hangs from the row and the row is outlined, and a wrong cell is red from the real check; each kind's card, the fold (`+12 more`, `from Person`), a type's note, a locked note, a type deleted under an open card, the note low in the window and at the right edge, two zooms, a wide table, forty lines and a fold scrolled. `GalleryPointers.swift` (`pointerStates`: the Order's pill, a list's pills and `+N`, a target that is gone, one that is no longer a Person, a type that is gone, an untitled target, a locked note, each pointing at Persons off the stage (`offstagePeople()`)). `GalleryChecks.swift` (`checkStates`) draws needed and wrong from the real check, ring and all, never `rowBook.checks`: `Flow5-p6-needed-and-wrong`, `Flow5-p2-gift-note-needed`, `Flow3-p3-wrong-value`, and the states no board draws (an empty Order, the caret in a wrong value, a fold marked red, a note of a gone type and the type that refers to it, a rule across fields). A state that shows a wrong value stages a type the value is wrong for (`FieldFixtures.person`, whose email has the format; `personThree`'s is plain text), and the caret's state begins the note's editing in the row itself, since the render draws no value under the row's field.
  The list's rows are drawn under the plain appearance, not the list window's vibrant one, which draws a translucent line (a separator) as a blend and so dark.
- The tests of what ships (CompositionTests, BenchmarkTests) get the product's plugins from ShippedTesting's `ShippedPlugins` (`plugins`, `registry`, `makeEditor`, each taking `pasteboard:` and `model:`): the list the app is made of, each plugin made by its name, with a clipboard and a language model of the test's own ([build](build.md), What ships). Their lines in `Package.swift` end `+ shipped`, so they import whichever shipped modules they call.
- For focus, key routing and the editing view, put a `CanvasView` in an unshown `NSWindow` and send it synthesized `NSEvent`s (see CompositionTests).
- Each test runs in an autorelease pool of its own (TestKit's `runAsTest`, which `runTests` runs each test with), as the app handles each event in one, so what a test lets go is gone as it ends: its windows, their views and what those scheduled (a panel's keyboard handed back a turn later, `reclaimSoon`) never act in a later test. A closure a test hands a view (a panel's `onExit`) captures the test's own objects weakly, since the view may call it a turn after the test let them go; and a window a test closes is `isReleasedWhenClosed = false`, which ARC needs, else it's released once too often when the pool drains. DetailPanelTests' "a panel let go by its test goes with it" holds the pool.
- A test closes the `BoardDocument`s it edits (`defer { board.close() }`). AppKit autosaves an edited document 15 s after its last change (or after the last event sent through `NSApp`, if later), in whatever test is running then, and a test's board has no file type, so one given a `fileURL` throws "inTypeName is nil" and ends the run, only when the run is slow enough to get there (under load). After each test (`runTests(_:afterEach:)`), CompositionTests' `closeBoardsLeftOpen` fails one that left a board open with changes, and closes every board it left open (`BoardDocument.unclosed`, debug builds).
