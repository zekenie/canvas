# Keyboard shortcuts

Keyboard: one shortcut per chord, who registers which, how a key reaches the canvas, AppKit's key bindings, the menu bar (made from the commands' declarations), and the Keyboard Shortcuts window, generated from what's registered.

Related: [selection](selection.md), [keyboard navigation](keyboard-navigation.md), [editor](editor.md), [undo](undo.md), [boards](boards.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Keyboard shortcuts](../../docs/plugin-system.md#keyboard-shortcuts).

## Architecture

- Keyboard shortcuts (Keyboard, platform, a horizontal in the window, first in the shipped list): every key the canvas answers is registered with it, one shortcut per chord (`KeyChord`: `"v"`, `KeyChord("a", .command)`, `.escape`), by the plugin that gives it its meaning: `x.tool(label:systemImage:shortcut:placing:)` and `registrar.tool(descriptor, shortcut:)` for a tool's key (`x.tool(label:systemImage:shortcut:placing:_:)` for a kind's tool of its own that still says what it places, the core's `ShapeRegistrar.tool(_:label:systemImage:placing:_:)`: the Frame tool, which draws, while `registry.placement(for:)`, what `canvas draw` places, is its placement), `registrar.command(.group, title: "Group", in: GroupingSection.self, shortcut: KeyChord("g", [.command, .option]), runs: .whenIdle, isEnabled:) { … }` for a command, declared once with its key (`shortcuts: [...]` for several: Delete's ⌫ and ⌦; Go › Back's ⌘[ and VS Code's ⌃-, and Forward's ⌘] and ⌃_, which ⌃⇧- types), its title, its menu bar item and its rule: the core's `registrar.command(_:title:…)` and the key in one call ([editor](editor.md), Commands) (its keys pass while it can't run, as its items dim: ⌘[ and Go › Back, ⌘↓ and `.openSelection`), `registrar.shortcut(chord, "Title", when:, repeats:) { editor in … }` for anything else, and `registrar.shortcut(chord, forTool:)` for another plugin's tool, `registrar.shortcut(chord, forCommand:, repeats:)` for another's command, and `registrar.shortcut(chord, "Title", forCommands: [...])` for one key that runs the first of several commands that can (Locking's ⇧L, `[.lock, .unlock]`, never both possible: each command's items show the key, and the Keyboard Shortcuts window lists one row under the title said, "Lock or Unlock", filed as the first command) (Keyboard gives the core's Hand H, Space held its pan (`registrar.shortcut(chord, "Title", whileHeld:released:)`: down, `editor.isHandHeld`; up, or every key let go, not), unless Space pressed what has the keyboard first (`PressFocused`, a keyed point Keyboard owns, at most one claim, `registrar.pressFocused { editor in Bool }`: Selection's presses a shape's focused part, [selection](selection.md#parts-of-a-shape), and then no Hand is held; the report says "press focused"), Undo ⌘Z and Redo ⇧⌘Z, held again and again, Escape and ⌘. `editor.cancel()`, Q the tool lock (`editor.isToolLocked`), and ⌘= and =, ⌘- and - (held, again and again), ⌘0 and ⇧0, and ⇧1 the zoom commands, and Page Up and Page Down (held, again and again), Home and End the core's paging commands, which have no menu item ([editor](editor.md)); `KeyChord.pageUp`, `.pageDown`, `.home` and `.end`, written ⇞ ⇟ ↖ ↘). The other keys the canvas's drags have (P10): the arrows pan with nothing selected and nudge a selection (Selection's one "Nudge or Pan" shortcut a chord), a nudge across a frame's edge settling as the key is let go; ⌥ and an arrow resize the selected box ("Resize"); Return with a placing tool picked places its shape (Selection's Return, `editor.placeAtKeyboard()`), and with shapes waiting to be placed (`editor.placeLater`, `/bulk-create`'s notes) puts them down, ⌥↩ in a row (Selection's ⌥↩ is Return with ⌥: `returnKey()`, which reads the keys held); ⇧↩ on the canvas is Insert › Note (StickyNotes gives the core's `.insert(ToolID(placing: StickyNote.kind))` the key, `registrar.shortcut(chord, forCommand:)`): a note beside the selection, in the color of the one shape it's beside, or with none somewhere clear in the middle of the view, edited (`editor.insert`, [editor](editor.md)), as ⇧↩ in a note's words puts one beside that note: [selection](selection.md). The core knows no key: `CanvasView.keyDown` hands every key to the editor as a `KeyStroke` (host API `editor.keyDown`), which passes it to the plugin that claims key strokes, and so does `CanvasView.performKeyEquivalent` for a ⌘ key while the canvas has the keyboard, before the menu bar (so ⌘A is Keyboard's there; with a field focused, the menu's). A held key's repeats run a shortcut again only with `repeats:`, and only while the canvas has seen the key go down (one held down in the table of contents, whose pick gives the canvas the keyboard, repeats there as nothing). A key no shortcut takes goes on to AppKit's key bindings, and the standard actions they send that have a key of their own (`deleteBackward:`, `deleteForward:`, `insertNewline:`, `cancelOperation:`) come back to the shortcuts as ⌫, ⌦, ↩ and ⎋, so ⌃H does what Delete does; the moves they send (`moveLeft:`, `scrollPageDown:`) and typing (`insertText:`) stop at the canvas, so a stray key doesn't beep. ⇧ counts when a chord asks for it; a key held with ⇧ answers the chord without it too when ⇧ may be only what typed it (⇧ alone, or punctuation, a symbol or a digit: ⌘? is ⇧⌘/), never for a letter with ⌘, ⌥ or ⌃ (⇧⌘Z isn't ⌘Z). A digit's chord is its key on the number row, whatever the layout types with it (`KeyStroke.numberRowKey`, from the key code: ⇧1 is the key that types "!" on a US keyboard), and the menu bar (`MenuBar`) answers a View item's ⇧1 and ⇧2 the same way, and never takes a key without ⌘ from text, where it types (below; one held with fn, 🌐E's Emoji & Symbols, is AppKit's as ever). The table of contents' list runs the `.delete` command on Delete, as the canvas does. Every plugin with a key imports Keyboard, so any plugin list with Selection or a shipped tool needs `KeyboardPlugin()`. A kit switches its plugins' keys (`KeyboardShortcuts: KitSwitched`, [kits](kits.md)): `KeyboardState` gathers its table of chords through the editor, again as `editor.kits` changes, so an off kit's keys pass (its tools' and commands' pass by `isToolEnabled` and `canPerform` too), while their chords stay claimed; the Keyboard Shortcuts window's rows are `keyboardHelpRows(kitsOn:)`. A tool's key is taken only while the editor takes the tool (`Shortcut.applies`: `editor.isToolEnabled`, false for a tool that places shapes on a board that takes none: a locked subboard's, `editor.isBoardReadOnly`), so there the key goes on as a command's does while it can't run, and the tool stays. The toolbar's picker (`ToolPicker`, `SwiftUIBridge.swift`) is an AppKit segmented control in an `NSViewRepresentable`, since SwiftUI's segmented `Picker` dims none of its segments (`.disabled` on a segment's content does nothing there, tried): a segment a tool, its symbol and tooltip, selected as `editor.currentToolID` is, dimmed as `editor.isToolEnabled` says (observed through `isBoardReadOnly`, so a board shown or a lock landing above redraws it, never a commit), the whole control's `isEnabled` following the environment's, and a click on a segment the editor refuses (it can't be made by hand, the segment is dimmed) leaving the selection on the current tool; CanvasUITests' `ToolPickerTests` host it in an `NSHostingView` in an unshown window and read the `NSSegmentedControl` (a segment each tool with its tooltip and symbol, the selection following a switch, a click picking a tool, the tools that place dimmed on a frozen pocket's board and as a lock lands above, a refused click leaving the selection), and KeyboardTests the key passing there. The toolbar's tooltips ("Note (N)") are Keyboard's, given to the host's slot for them (`registrar.toolTips { tool, registry in registry.help(for: tool) }`, read by `ToolPicker` as `registry.toolTip(for:)`: [host slots](host-slots.md)), since CanvasUI can't see Keyboard, and a list without Keyboard shows each tool's label; a button that runs a command names its key the same way (`registry.help(_:forCommand:)`: Find's "Next (⌘G)"; a command with no key, the table of contents' `.goUpBoard`, is its title alone). The keys a menu item has for a command are Keyboard's too, given to the host's slot for them (`registrar.menuKeys { command, registry in … }`: every key that runs it, in the order registered, Delete as Backspace's character, `KeyChord.menuKey`; read as `registry.menuKeys(of:)`, and `registry.menuKey(of:)` the first): the menu bar's items and a context menu's that run a command show the first, the menu bar answers each other one held with ⌘ or ⌃ too (below), and a list without Keyboard shows none. The toolbar's buttons for the sidebar and the inspector are Sidebar and Inspector, each with a tooltip titled as its View item is: "Show Sidebar" or "Hide Sidebar" as View › Show Sidebar (⌃⌘S) is, "Show Inspector" or "Hide Inspector" as View › Show Inspector (⌃⌘I) is.
- The Keyboard Shortcuts window (Help › Keyboard Shortcuts, ⌥⌘/, `BoardMenus.showKeyboardShortcuts`, answered by the app's delegate with CanvasUI's `KeyboardShortcutsWindow(registry:menu:autosaveName:)`, made afresh each time it opens, as Settings is) is generated, never written by hand (the owner's call): it reads `registry.keyboardHelp` ([host slots](host-slots.md): `KeyboardHelp`, at most one, and `KeyHints`, any number) and the menu bar as it is when it opens (`NSApp.mainMenu`; a test hands `BoardMenus.make`'s). Keyboard gives the rows (`registrar.keyboardHelp { $0.keyboardHelpRows }`): each shortcut in registration order under its tool's label, its command's title (a `.command(c)` place) or its own title (`.canvas`), shortcuts under one name in one row (⌘↓, ↩ and ⌤ are Open Selection; a custom shortcut sharing a command's name is filed with the command; a tool's keys never share a row with what isn't a tool, so the Note tool's N stays under Tools while Insert › Note's ⇧↩ is filed under Insert), the four arrows held with the same modifiers written as one key (`KeyChord.written`: "←↑→↓", "⇧←↑→↓"; three arrows stay three). A key no shortcut has is a hint, said beside the code that reads it with the core's `registrar.keyHint(keys, title, while: .pointer | .text)`, so no plugin imports Keyboard for one: Keyboard says the core's (⇧ Drag, ⌘ Scroll), Selection the select tool's and resizing's, Snapping its ⌘ or ⌃, Arrows an end's ⌥, ⌘ or ⌃ and ⇧ and the hover's ⌥, Mentions the hover's ⌃⌥, Types the hover's ⌥ on a type ([neighbors](neighbors.md)), Frames the Frame tool's ⇧ and ⌥, StickyNotes ⌘↩ or ⎋, ⇧↩ and ⇥ in a note, Mentions @, SlashCommands /, Types a note's rows' ⇥. `KeyboardShortcutSection.sections(menu:rows:)` (public, pure over its inputs) files them: Tools; each menu-bar menu in order (a submenu's items in its menu; a hidden item, another key of the item before it, passed over), an item's own key and, where the item runs a command (`BoardMenus.command(of:)`: the command a plugin's item carries, or the one that answers one of AppKit's own, Edit's Undo, Redo, Cut, Copy, Paste, Delete and Select All), the registered keys of that command under its title; then Canvas (commands no item runs, and the canvas's own), Pointer and Editing Text (`ShortcutsStyle`); a key listed once, where it first comes, a row left with none and an empty section dropped. A menu item's key is written as menus write it (`KeyboardShortcutSection.key(of:)`: ⌃⌥⇧⌘, a capital key equivalent held with ⇧, fn as 🌐). CanvasUITests' `keyboardShortcutsTests` hold the filing over a menu and rows of their own; KeyboardTests the rows (names, merging, arrows, the core's hints after); CanvasTests' `hostSlotsTests` the slot and the hints; CompositionTests' `keyboardShortcutsShippedTests` hold every shipped shortcut, every menu-bar key and every hint listed exactly once, each named, and where a few are filed (the four restacking keys under Arrange with their fixed items; Lock's ⇧L and Create Frame's ⇧⌘F under Canvas, since no fixed menu item runs them: the Shape menu is empty at rest, and its items are the selection's menu's, not a menu bar item the window reads).
- The menu bar (CanvasUI's `BoardMenus.make(appName:registry:)`, which the app installs with the shipped registry) is the window's own items and the commands placed in it (`registrar.command(… in:placed:…)`, read as `registry.menuBarCommands`: [host slots](host-slots.md)), in sections, a line between two and nowhere else: no number places anything. A section is a type (the core's `MenuBarSection`, `Sources/Canvas/Plugins/MenuBarSections.swift`) that says its menu (`MenuBarMenu`: one by its title, `"Arrange"`, or a submenu, an item of another section, `.submenu("Find", in: EditMenu.FindAndSpelling.self, placed: .first)`, made with the first section in it) and its place among the menu's sections (`Order`: [plugins and kinds](plugins-and-kinds.md)); an item is placed among its section's items by naming the item that runs a command (`placed:`, an `Order<CanvasCommand>`: `.after(.paste)` is right after Edit › Paste, which runs the command that answers it, so an item of the window's that runs none, Copy as Image, can't be named; one placed beside a command that isn't there goes where one that says nothing would). What says nothing goes where it first appears: the window's own in the order it lists them, then the commands' in plugin order (CanvasUI's `MenuLayout` gathers the sections and their items, then arranges each with `OrderRule.arranged`). The window's own items are in the core's sections where commands go beside them (`EditMenu.Undo`; `EditMenu.CutCopyPaste`, Cut, Copy, Copy as Image, Paste, Delete and Select All; `EditMenu.FindAndSpelling`, Spelling and Grammar; `ViewMenu.Panels`, Show Toolbar, Show Sidebar, Focus Sidebar, Show Inspector and Focus Inspector, then, placed last, Focus Next Pane, Focus Previous Pane and Show Minimap, so a plugin's item that says nothing goes after the inspector's and one placed last after the minimap's; `ViewMenu.Zoom`, the core's zooms) and in its own otherwise (`FileMenu.Open` and `.Save`, `ViewMenu.FullScreen`, `.last`, so a plugin's section in View comes before Enter Full Screen, `WindowMenu.ThisWindow` and `.AllWindows`, `HelpMenu.Shortcuts`). The shipped bar's rules: Paste at Pointer after Paste and Duplicate after it, Remove Mention after Select All, Find's submenu first, Forward after Back and Enclosing Board after Forward, Jump To… first in Boards' `PathSection`, the window's panes' focus and Show Minimap last among View's panels, and Enter Full Screen's section last; the rest is the window's listing and plugin order (Grouping's section before Reordering's, Selection's in Go before Boards', the inspector's tab commands after Focus Inspector, the mentions' after Open Selection). The registry refuses (`invalid` for `Commands`) an item placed in no section, a submenu inside itself, a submenu its sections place two ways, sections or items placed beside each other in a circle, a section placed beside one of another menu, and an item placed beside a command whose item is in another section; one placed beside the window's own, which the registry doesn't see, is the window's to place. The menus come in the Mac's order by title (`BoardMenus.menuOrder`: File, Edit, Insert, Shape, Format, Arrange, View, Go, Insert after Edit as Keynote's and Freeform's), then any only commands name, in the order they first do, then Window and Help; a menu with nothing in it isn't there (a list without Grouping and Reordering has no Arrange, one without Selection, Boards and JumpTo no Go). A command's item is titled as the command is, shows the key `registry.menuKey(of:)` gives, carries its command (`representedObject`, read as `BoardMenus.command(of:)`) and sends the controller's one action, `runCommand:` (`editor.perform`, on the selection); each other key of the command held with ⌘ or ⌃, which type nothing (`registry.menuKeys(of:)` past the first), is a hidden item right after it, the same title, command and action (`isHidden`, `allowsKeyEquivalentWhenHidden`; `BoardMenus.addOtherKeys`, once the bar is made), so AppKit's menus and `MenuBar` answer that key wherever the item's own works, text being typed included, and the controller's validation dims it with the item (Go › Back's ⌃- beside ⌘[, Forward's ⌃_ beside ⌘]); a key held with neither types, and is the canvas's alone, no item taking it (= and -, which zoom again and again while held); CanvasUITests' `menuBarTests` hold the hidden items and CompositionTests' `goingBackShippedTests` the keys through them, from a note being typed in; the controller's one validation dims it while `canPerform` says no, and while text has the keyboard (`window.firstResponder is NSText`) for a command that runs `.whenIdle`, so a disabled item leaves the key to the text (⌘↑ and ⌘↓ move the caret, ⌘D and ⇧⌘V are the text's, `]` types), and retitles it for a command named for its step (`menuTitle`). Edit's Undo, Redo, Cut, Copy, Paste, Delete and Select All are AppKit's own items, with AppKit's actions and keys, which text answers first, so every field has them whatever is installed; each carries the command that answers it (`registry.command(answering:)`), which the window (`undo:` and `redo:`, `BoardWindow`), the controller (`cut:`, `copy:`, `paste:`) and the canvas (`delete:`, `selectAll:`) run on the board where nothing nearer took them (`editor.perform(answering:)`), as the canvas runs a trackpad's smart zoom. The window and the app name no plugin's command. CanvasUITests' `menuBarTests` hold the making over fixtures; CompositionTests' BoardDocumentTests the shipped bar, item by item.
- Find and Jump To's commands and menu items (Find's `.find`, `.findNext` and `.findPrevious`, [find](find.md); JumpTo's `.jumpTo`, [jump to](jump-to.md), each declared in its plugin): Edit › Find, a submenu after Select All (a separator before it) of Find… (⌘F), Find Next (⌘G) and Find Previous (⇧⌘G) (`FindSection`, its submenu first in `EditMenu.FindAndSpelling`), and Go › Next Issue (⌘'), Previous Issue (⇧⌘'), Ignore Issue (⌥⌘') and End Issue Walk (Validation's `IssuesSection`, `.after(NavigationSection.self)`: after Navigation's items and Mentions' that join them, before Boards' section; ⌘' and ⇧⌘' repeat while held, the second `KeyChord("\"", .command)`, the ⌘? convention: [validation](validation.md); the Keyboard Shortcuts window lists them as ⌘' and ⌘", End Issue Walk, which has no key, only in the menu bar; KeyboardTests hold ⇧⌘' reaching the `"` chord and not ⌘', CompositionTests' `keyboardShortcutsShippedTests` the rows), and Go › Jump To… (⌘K) after them, past a separator (first in Boards' `PathSection`, before Board Path, the section after Selection's `NavigationSection` by plugin order). Each runs through the controller's one action, never AppKit's `performFindPanelAction:` or `performTextFinderAction:`, which a text view answers, dimmed while `canPerform` says no, and none runs `.whenIdle`, so they work from the canvas, a note being edited, a panel's field and the list (the canvas answers their keys first, the menu bar elsewhere). `MenuBar` hands a ⇧⌘ letter to the item that names ⇧ (⇧⌘G is Find Previous, not Find Next, whichever item comes first). Find's plugin claims the first three (⌘F refused mid-gesture; ⌘G and ⇧⌘G while there are hits, or with Find closed and a query) and JumpTo's the last, ⌘K (refused mid-gesture).
- Walking issues' commands and menu items (Validation's `IssuesSection`, in Go right after Navigation's items, before Jump To's section; [validation](validation.md)): Next Issue (⌘'), Previous Issue (⇧⌘', the `"` chord with ⌘), Issue List (⌃⌘', `KeyChord("'", [.command, .control])`, declared by `IssueWalkPanelPlugin` since the list is the panel's, and placed `.after(.previousIssue)`; Ignore Issue is placed after it and, in a list without the panel, goes where an item that says nothing would), Ignore Issue (⌥⌘') and End Issue Walk (no key). Next and Previous repeat while held, Issue List does not (one press toggles the list); all three run between presses, and each only when it can (`IssueWalk.canStep`, and Issue List not while another takeover covers the list) (no gesture, no shapes waiting to be placed); the Keyboard Shortcuts window lists the four with keys under Go.
- Arrange (between Shape and View): Group (⌥⌘G) and Ungroup (⌥⇧⌘G), Grouping's `.group` and `.ungroup` ([grouping](grouping.md)), placed there by their declarations (`GroupingSection`, before Reordering's by plugin order), `.whenIdle`, so dimmed while text has the keyboard and the key is the text's; `MenuBar` hands ⌥⇧⌘G to Ungroup (the item that names ⇧) and AppKit ⌥⌘G to Group, never to Find Next's ⌘G. CompositionTests' BoardDocumentTests hold the items and keys, `groupingShippedTests` the routing.
- Arrange (continued): after Ungroup and a separator, Bring to Front (`]`), Bring Forward (⌥]), Send Backward (⌥[) and Send to Back (`[`), Reordering's own `.bringToFront`, `.bringForward`, `.sendBackward` and `.sendToBack` (`ReorderSection`; on their shapes, while there are some and none is painted by anchor; `.whenIdle`, so dimmed while text has the keyboard). The same commands are the context menu's Arrange ▸ items, and are left out of the Shape menu, whose Arrange submenu would hold nothing. A key without ⌘ is filed with the item that has it, in the Keyboard Shortcuts window, as the others are.
- Insert (between Edit and Shape) is the core's: an item for each tool that places a shape, in plugin order (Note, Subboard, Frame, Reference; a kit's tools in a submenu named for the kit, Insert ▸ Stickers, hidden while the kit is off in the key window's file: [kits](kits.md)), each the core's `.insert(tool)` titled as the tool, `.whenIdle` and dimmed on a board that takes nothing, which puts the tool's shape down without the pointer, beside the selection or in the middle of the view, and edits it if its placement edits ([editor](editor.md), Insert); Insert's first item is the core's New (kind) Beside (`.insertBeside`, `.whenIdle`, titled for what it will make: "New Subboard Beside", "New Note" with nothing selected) and it shows ⇧↩, which Keyboard binds (`registrar.shortcut(KeyChord(KeyChord.return.key, .shift), forCommand: .insertBeside)`, as it binds ⌘Z): a shape of the selection's kind beside it, else a note (StickyNotes claims its Note tool with `insertsBesideByDefault`, and no longer binds the key itself); the Keyboard Shortcuts window files ⇧↩ there, and Insert › Note shows no key. A note's own ⇧↩ in its words is the note editor's, unchanged ([editor](editor.md), Insert beside). CompositionTests' BoardDocumentTests hold the items and the key, `keyboardShortcutsShippedTests` the filing, `keyboardCreationShippedTests` what ⇧↩ and Insert › Frame put down and the item's title through the controller, `insertBesideShippedTests` ⇧↩ beside a subboard, a frame and a note, a note for nothing or mixed kinds, a kit's kind with the kit off, and the note editor's ⇧↩; KeyboardTests' registration tests hold the key on the registry.
- Shape (between Insert and Arrange) is the selection's context menu in the menu bar, less what the menu bar already has ([context menus](context-menus.md): `registrar.menuForSelection`, `editor.menuForSelection(omitting:)`). `BoardMenus.make(appName:registry:editor:)` makes it a `ShapeMenu` (`BoardMenus.swift`: an `NSMenu` that is its own delegate, `autoenablesItems` off), whose editor is the key window's board (`BoardMenus.keyBoardEditor`: the key window's, else the main window's, if a `BoardWindow`; a test hands its own). It holds nothing at rest, so the Keyboard Shortcuts window drops its section and no key reaches a stale item; `menuNeedsUpdate` fills it each time it opens with the items of the selection, moved out of the menu the plugin made, leaving out every item whose command an item of the menu bar runs (`ShapeMenu.omitting`, every command `BoardMenus.commands(in:)` finds in the bar as it's made: Cut, Copy, Paste, Duplicate, Delete, Select All, Group, Ungroup, the four restacking items, and the rest of the menu bar's) so that nothing is in two menus; nothing selected, nothing in it (an empty menu), and no window with a board, nothing. Its items show their commands' keys (⇧L, ⇧⌘F) but they are not live there: `menuHasKeyEquivalent` says no, so a key never makes AppKit fill it to look, and `menuDidClose` empties it (after the chosen item's action, which AppKit sends after the delegate hears the close). The items are the ones the plugin made, with the editor they were made for, so a pick reaches that window's editor, and they enable and dim as their commands do (the rule over the selection, which is the menu's, and the moment), a pick ending editing first. The shape commands with keys: Locking's `.lock` and `.unlock` (⇧L runs whichever can), Frames' `.createFrame` ⇧⌘F, and Reordering's four, which are also items in Arrange.
- Plain keys stay out of text. `MenuBar` never takes a key held without ⌘ or ⌃ from text, where it types: not ⇧L, `]` or `[` (nor ⇧1), and not ⌥] or ⌥[ either, which type a quote on a US layout; AppKit's menus would take a key equivalent without ⌘ before the text view sees it. A key held with ⌃ types nothing, so in text it goes on to AppKit's menus as it did (Window's ⌃⇥, a service's key), then to the text's own bindings (⌃A). Not in text (`NSApp.keyWindow`'s or the event's window's first responder an `NSText`), and only where the key is the board's (the first responder the canvas, the window itself, or an `NSTableView` or `NSOutlineView`, the table of contents; a panel's checkbox or button with the keyboard takes `]` or ⇧1 as its own and the menu bar answers nothing): such a key is answered by the item that names it (the exact key and modifiers, a digit by its number-row key code), and while that item is dimmed the key goes on (AppKit's own menus take a dimmed item's key and beep); otherwise the item runs, once: a held key's repeats are taken and run nothing, as the canvas's shortcuts for those keys don't repeat (a held ⇧1 would flip between the fit and back, a held ⌥[ send a shape back a step a repeat). A key without ⌘ that an item names only with other modifiers is taken by none (`MenuBar` returns false rather than ask AppKit, whose own matching hands Return to an item on ⇧↩, Insert › Note, and the number row's 1 to ⇧1's): it goes on to what has the keyboard, so Return still opens the selection, a row of the table of contents and a crumb of the path. A key held with fn is AppKit's as ever. A ⇧⌘ letter goes to the item that names ⇧; where none does but one names the letter without ⇧ (⇧⌘F, and Edit › Find's ⌘F), the menu bar takes it for none (`MenuBar` returns false: AppKit would have run Find, which CompositionTests' `shapeMenuShippedTests` show).
