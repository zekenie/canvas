# The engineering kit

The engineering kit (`Sources/Engineering`, product): database tables, their enums and the databases that hold them, and REST APIs; the module and its parts, the kinds and what they keep, the column, enum, endpoint, header and server grammars, a table's columns, an enum's values and an API's server and endpoints written a line each (what a line offers, its steps), an endpoint's body and responses as type notes, the looks at rest and zoomed out, the ways in (the tools, `/table`, `/api`, `/database`, Create Database, ⇧↩), what an API does (writes, reads and calls: channels with pills, its endpoints' ports, its card's relations, ⌘L from an endpoint), how an API changes and retires (Change Method from its chip, Deprecate Endpoint, New Version, Group by Prefix) and an endpoint of its own (the `endpoint` kind, one row taken out), `canvas draw`'s `columns:`, `values:`, `server:` and `endpoints:`, ⌘V of SQL and of OpenAPI (and the YAML subset it reads), what agents read of it (`:route`, the rows at an arrow's ends, tests inside its lists, `--ask`'s `<tables>` and `<apis>`), and what VoiceOver says.

## Architecture

- **The module** is one product, in parts (`Package.swift`'s table): `Model` (the kinds' props, `TypeRef`, `KitStyle`, how a row is drawn on the paper, `RowText`, `RowMarks`, `KitPaper`, `KitRows`, `MoreLine`, and the file's tables and enums by name, `KitNames`: what the Tables and APIs parts share, so neither uses the other), `Grammar` (the line grammars, pure; uses Model), `Tables` (the three kinds drawn, laid out, placed and written, and their rows written as lines through LineRows; uses both), `APIs` (the API, the same; uses both; it imports Types for its bodies) and `Readers` (what's pasted: the SQL reader, the YAML subset and the OpenAPI reader, and the draw program a paste of each is; uses Model, Grammar, for `APIGroups`, and APIs, for the width an API's rows show whole at, and the module imports Clipboard for the paste readers, Draw for the programs they write and Types for the ordered values YAML and JSON read into) and `Agents` (what agents read: `RoutePattern`, pure, and `KitAskFacts`, `--ask`'s blocks; uses Model, Grammar, Tables, for the key index and a key's written target, and APIs, for an endpoint's relations' names; the module imports Queries for it). One module, not a product for tables and one for APIs: an API's grammar will offer tables and its writes reach tables, and no product sees another. The module's own source (`Engineering.swift`) is the kit (`EngineeringKit`, id `engineering`, "Engineering") and its plugin (`EngineeringPlugin`, `engineering`, shipped last), which joins the kit: its tools, their Insert items (Insert ▸ Engineering: Table, Enum, API, Database), `/table`, `/api`, `/database` and Create Database are the kit's and gone from a file with it off; its kinds, looks, the title field and its draw words are never switched ([kits](kits.md)).
- **The kinds**, each complete at version 0, a fixture each in `Tests/CompositionTests/Fixtures/kinds` holding every member: `table` (`DatabaseTable`: `frame`, `columns`, a `Column` each: `id` a `PartID`, `name`, `type` a `TypeRef`, `nullable`, `unique`, `primaryKey`, `default`, `onDelete`, `onUpdate`, `unread`, the words its line held that no part reads, kept as written), `enum-type` (`DatabaseEnum`: `frame`, `values`, an `EnumValue` each: `id`, `text`; `enum` is a word other modules write, so the kind isn't it) and `database` (`Database`: `frame`, `ShapeContaining`, a region that holds shapes as a frame does, its hollow hit test and marquee rule Frames'). Their names are Titles' (`title`). A new table holds `id uuid pk` (`DatabaseTable.starter()`). A table's and an enum's frame keeps only its width as theirs: the height is laid out from the rows (`LaidOutBox`, 8 above, 24 a row, 12 below, `KitStyle.height(rows:)`, a row's room with none), so a row added or (later) folded writes no box; `DerivedProps` keeps the stored height in step where a shape is made from properties (`canvas draw`), so draw places it at its true size, and `CustomSizing` takes a resize's or `size:`'s place and width and keeps the height its rows'. `api` (`API`: `frame`, `server`, an `APIServer`, `host` and `auth`, one value since its line is written whole, `version`, `deprecated` and `endpoints`, one flat list of `APIRow`s, each a header, `PathHeader`, coded `{"id", "header": "/orders"}`, or an `Endpoint`: `id`, `method`, `path` under the header above it, `name` (its operationId), `summary`, `authScope`, `parameters` (`PathParameter`s, a path parameter's type by name), `body` a `TypeRef?`, `responses` (`EndpointResponse`s: `status`, `type` a `TypeRef?`), `deprecated`, `unread`; schema definitions `api-row` (one of the two), `path-header`, `api-endpoint`, `api-server`, `path-parameter`, `endpoint-response`), its height laid out from its server's band (34) and its rows as a table's are (`APIRows`). `TypeRef` is the words as typed and the shape they name once one matches (a column's enum, an endpoint's type note), a name not a binding (`ShapeNaming`: on any board, kept when its shape goes, renamed by a copy), coded `{"words", "shape"}`, its schema `engineering.type-ref`. And `endpoint` (`StandaloneEndpoint`: `frame`, `endpoint`), one endpoint taken out of an API, standing alone (K16, below).
- **Parts.** A table's columns and an enum's values are their parts (`PartedShape`, the core's, [plugins and kinds](plugins-and-kinds.md)): each by its id and name, "Column" or "Value", a key's symbol leading a primary key and a "1" a unique column; none stands alone. Each row's rect is in the kind's geometry (`ShapeGeometry.parts`), as wide as the paper, 24 tall.
- **The grammars** (`Grammar`, pure): `ColumnGrammar` reads a line `name type [null] [unique] [default …] [pk]` (a `?` after the type is null, `not null` and `primary key` read too, the grammar's words in any case, a quoted or parenthesized run one word, as SQL writes `numeric(10, 2)` and `'a b'`; a quote opens a run only where a word starts, so an apostrophe in a name is a letter, and a quote or parenthesis never closed is a letter too, the line's other words staying words; `null`, `unique`, `pk` and `default` are read once, said again they stay with the unread words, in order) and prints a column back as it reads, `name type null unique default … pk unread`; what it can't place stays in `unread`, a key's `→ table.column` (`->` typed for it) among it as read. `key(in:)` says a key's words apart (`KeyWords`: `→` and the word after it, the table, the column, nil for a table alone, and the unread words without them), `target(_:)` reads `table.column`, `table` or `"a table".column` (the column after the last dot), and `written(table:column:)` writes one back, quoting a table's name that holds a dot, a space or a quote. `read(lines:)` reads a block, a column a line, each a new id; `merge(_:onto:)` joins what a statement wrote onto what a table holds by name: a column it names takes its line, keeping its id, on delete, on update and its type's bound shape while its words say the same; a new name goes after the nearest column written before it, else last (`after:` names the one a join written in pieces wrote before); one it leaves out stays. `EnumGrammar` is a value a line, joined by text, a new value placed the same way. Typing, `canvas draw`'s `columns:` and `values:`, and a paste of SQL join by these, one join for all. The tests hold that printing what was read reads back as the same column and keeps every word of the line.
- **Looks at rest** (`KitStyle`, shared, in Model; `TableStyle`, `EnumStyle`, `DatabaseStyle` in Tables, a skeleton's constants beside the full look's): the paper #EBEBEB at radius 6 with the note's shadow, the same in both appearances, so its inks are fixed: names 15 points at 35 in, in #111113; types monospaced 13 points, right-aligned 14 from the edge, in the frames' grey made to read on the paper at 4.5 (`Swatch.reading`); a nullable's `?` after its type in the names' ink (the brief's "at full ink"); in the gutter a primary key's key (`key.horizontal`, the frames' gold made a line color on the paper: it measured 2.9) else a unique column's `1.square` in the grey; an enum-typed column's type as a pill (Adornments' `draw(at:in:)`) saying the enum's name now, in Palette's swatch of the frames' purple on the paper (a light tint, its ink at 4.5). An enum's values monospaced 14 points at the names' inset. Text is set once a string and role as a Core Text line (`RowText`, kept to 8,192) and drawn from it; a render draws only the rows its clip reaches. Title pills: a table's `tablecells`, an untitled one's dimmed "Table"; an enum's solid purple (`Swatch(purple)`'s solid, its text the swatch's `onSolid`) after `list.bullet`; a database's `cylinder` in a tab on its top edge, as a frame's (`titleTab`, its surface and border). The database is a region as a frame is: white, or 0.15 grey in the dark, a hairline border (black 12%, white 14%), radius 12, no shadow.
- **Zoomed out** (below the skeleton zoom): the paper square, ringed in black 16% on the light canvas, a bar a name and a bar a type (x-height bars, 0.52 em a column for names and 0.6 for types, at most 40 columns) in the canvas's text-bar fill, an enum-typed column's bar in the purple, a second fill; the database its surface and its border's ring, its tab over it. A column's type is a pill when the enum it names is still in the file, the same test as at rest. Where a row is under 2 view points (`TableStyle.skeletonLeastRow`, far out: 6% and less) no bars are drawn for the rows, only the paper and the title's bar, so a board of thousands of tables costs a card each (`TableBenchmarks`: 10,000 tables, some 4,000 in view at 6%, 20 ms with the bars and 10 without). Their titles are bars where their pills are (Titles' `title(bars: true)`, [titles](titles.md)), the enum's in its purple, never a cover printed over the rows (E8's 30%).
- **Edited**, a table or an enum is LineRows' editing view ([line rows](line-rows.md)): its name typed in its pill (Titles' `TitleField`, its first stop; `editingFrame` the paper and the pill's row above it), then a line a row and the waiting line. Put down by its tool, by Insert or by ⇧↩ (each an editing placement), untitled, the caret is in its name (the pill the glyph and the caret, no placeholder, and ringed only while its text has the keys) and what's typed joins the step that placed it ("Add Table", "Add Enum"), Return going on to its empty row; `/table orders` puts down a titled one with the caret on its empty row (T1, panel 2); Return on one selected, a double-click, edits it at its empty row, ↑ from its first row back to its name, a name typed again its own step ("Rename Table", "Rename Enum", `editingStepName`).
- **Room below** (U3; the core's push, [containers](containers.md)): the table, the enum and the API adopt `MakesRoomAsItGrows`, so a step that writes one taller at rest (a column typed, pasted, moved in (cut and pasted, dragged) or dropped, Paste SQL or Paste OpenAPI again, draw's `columns:`, `values:` and `endpoints:`) pushes what's below it in its database (or on the board) that its new bottom comes within the reach of down by its growth, and the database grows to hold what the push takes past its bottom, pushing on the board in turn. A locked table stops it, and the person lays out the rest. A database grows only so; it never shrinks to fit. A draw's grown table is left to the push (draw's settling skips it), so one at the bottom of a database grows the database and is never nudged up over the table above; `canvas apply` and the digest make no room (their plan has put every shape at the size it will have). The reach is in world units: it clears a title's row at 84% zoom and up, and a person laying tables out closer than that at a lower zoom has their gap. EngineeringTests' `roomTests`; CompositionTests' `makingRoomShippedTests` (the walk's structure steps, Paste SQL again with a table more, Paste OpenAPI again, draw's `columns:` in a database and above one, draw's `moved` and its rows, `canvas apply` pushing nothing); EngineeringTests' `roomTests` also a column cut and pasted or dragged into a table above another, which pushes it in the move's step.
- **Rows written as lines** (`Tables/Lines.swift`): the kinds opt in with `lineRows(TableLines())` and `lineRows(EnumLines())`. `ColumnLineGrammar` reads a line through the Grammar part's `ColumnGrammar.scan` (the column, and each word's role and UTF-16 range: name, type, keyword, a default's value, the arrow, unread), drawn as the frames draw a focused line: the name in the names' font, the type in code, an enum's name in its purple pill (the at-rest pill's color at 0.14 behind the purple's ink) standing for that enum, the grammar's words and the arrow grey code, a default's value code, what nothing reads plain; the gutter a primary key's key or a unique column's "1". A type's words that a printed or picked run stands for name that enum whatever else is so called; typed afresh they're found by name, the nearest first (on the shape's board, else anywhere in the file: `KitNames`, a service keeping the file's enums by name until `editor.revision` moves), so the column's `TypeRef` binds its enum and its pill says the enum's name now. It prints a column as `ColumnGrammar.print` does, an enum's name as it's called now. A line's key (K5): the first `→` and the word after it name a key once that word names a table's row on the shape's board: the run's reference (printed, or picked from the list), on the whole target or on the column after its dot, else by name (`KitNames.tableNamed(_:besides:)`, the board's tables by title; a table alone is its primary key's first column), and only where something draws connections (`registry.drawsConnections`). The row read is a `ColumnLine` (public: the `Column` and a `ColumnKey`, `.stored` for a column as the board has it, `.none`, or `.to(PartAddress)`), and a key read leaves the column's `unread` without its words; a `→` that names nothing stays there, plain. Its target is drawn in the link blue's pill (`LineLooks.keyFill`, `keyInk`; `TableStyle.keyPillFill` 0.14), the table's name already as `customers.` is typed, and the gutter shows the link while the line has a key. A focused line prints the key the line holds, or for a column as stored the key index's, `→ customers.id` by the far table's and column's names now (a reference to the row), so a rename follows with nothing written; VoiceOver's help says "key to id in customers". Offers: after a name, SQL's types (Postgres's, the common first: `in` lists int, int8, integer, interval, inet first) and the file's enums, each a purple chip lit on the board while highlighted; after a type and a space, null, unique, default, pk and → (what the line says already left out); right after the `→`, the tables on the shape's board Mentions' search finds for what's typed (`candidates(…kinds: [table], admitting:)`, nearest and recent first with nothing typed), each one's key columns as `customers.id` with its type (a key column is its primary key's or a unique one; all of a table's where it has none), and after `customers.` that table's key columns by name, the offer's range what follows the dot; each lit while highlighted (its row's rect: LineRows' light); nothing after `default`, a key's target or words nothing reads. `->` typed becomes `→`. `EnumLineGrammar` is a value a line, as typed, trimmed. `TableLines` (made with the table and the key index for a session, `TableLines(table:keys:)`) keeps what a line doesn't say (on delete, on update), writes its changes itself (`apply`: the columns, then each line's key with its column in the row's one transaction, `KeyArrows.write`: the arrow made by `registry.drawConnection(…parts:)`, re-aimed by moving its far end with `movingParts` so it keeps its id and bend, or the column's arrows deleted where the line names none; a column as stored writes no key; a key that can't be drawn refuses the commit and the table shakes) and names its steps Add Column (a new row, with its key or not), Paste Columns, Rename Column (the name alone changed), Add Key, Change Key and Delete Key (the key alone made, re-aimed or taken out, judged against the board's for a row as stored), Change Column, Delete Column, Move Column; `EnumLines` Add Value, Paste Values, Rename Value, Delete Value, Move Value (`TableStyle`, `EnumStyle`). Their style is the kit's at rest (`LineLooks`): names 15 points at 35 in, types 13 monospaced, an enum's values 14 monospaced. `EngineeringLines` gives the two grammars to what reads lines as typing does (the tests' corpora).
- **While edited**, a table and an enum read LineRows' layout inputs (`KitRows`): laid out a line taller while the waiting line has the caret, the rows after it a line down, in their render, geometry and skeleton, and the row the field draws not drawn.
- **Ways in**: the Table, Enum and Database tools (no keys; the kit's toolbar segment, Insert ▸ Engineering; the database's a plain placement, 640 × 400, least 96 × 64, a click putting one down); `/table NAME` (a command about the bar's target, `SelectionSlashCommand.atOnce` with its step "Add Table": the starter titled NAME, put down beside the selection or in view through `editor.insert(_:named:beside:)`, the table tool's editing placement, selected and edited at its empty row); `/database NAME` ("Create Database": round the selection; with nothing selected round every shape on the board in no container, the bar's rule; on an empty board an empty one in view); Create Database (`.createDatabase`, run when idle, in the canvas's menu of shapes that hold a table or an enum, `DatabaseMenuGroup`, after Transform's as Create Frame's is, so the two sit together), all through `editor.createDatabase(named:around:)`: the core's `place(_:around:)`, 32 past them, never under its least size, selected, all or nothing, a locked shape among them shaking. ⇧↩ on a table makes a table beside it (the core's insert beside, the table tool's editing placement).
- **`canvas draw`**: `columns:` and `values:` take text, a row a line in the grammars (or the rows as JSON: an id given to an item with none, and only the members an item names joined onto the column of its name, so a restated column keeps the rest, its on delete and on update unless it gives them, and a new row whose id another has is given one of its own), through Draw's value writers that take text (`drawValueWriter(for:describes:…)`, [command line](command-line.md)); `canvas kinds` says `lines (name type [null] [unique] [default …] [pk] [→ table.column]) or JSON [{…}]`. A line's `→ customers.id` is an edge the value implies (`implies:`, `RowsDraw.keys`): `edge "orders".customer_id -> "customers".id channel: foreign-key` on the statement's line, so the column keeps none of its words; a table alone (`→ customers`) is its primary key's row for a table the file has (one the same script draws needs its column named, `invalid_value` otherwise); an explicit edge between the same rows is that edge; a line without `→` leaves a key alone, and a `→` that aims a column elsewhere than its key is that key re-aimed, as the line and ⌘L's pick do (a column has the one key its line says: the run deletes the column's other edges of the `foreign-key` type, `DrawImpliedEdge.replacesType`, but an `edge` the script writes itself stays; `delete edge "orders".customer_id -> "customers".id` takes one). `→ customers` alone is refused for what is wrong, an ambiguous table's name as any, or a table the file doesn't have yet (name the column). A column's type whose words are an enum's title in the file (found as draw finds a title) is bound to it; one that is called by two enums is refused, `ambiguous_title`, as any such name is, not left words without a word, while a type of SQL's own, or a table's title, stays words. Joined by name, so a run again says `unchanged`; an enum's box that grows a row says `moved`, as a note's does with its text. A database is drawn with `size:` and its tables `in` it in a later run. The canvas skill's `reference/engineering.md` teaches it, its blocks run by SkillTests.
- **Keys** (`Tables/Keys.swift`): a key is its arrow and nothing else, on the kit's channel `ForeignKey` (`foreign-key`, no title so no pill, `isOnEveryChannel` false so a subboard takes none, its dots the frames' link blue, its edge type under `arrow`). A table's columns take it both ways (`table.partPorts(ForeignKey.self)`): a dot at each end of the hovered row, a drag drawing a key bound to both rows ("Add Arrow"), the far tables outlined and never an enum or a database (they have no ports). `KeyIndex` (a service) keeps each table's keys, the far row of each column that starts one, read from Topology's `foreign-key` edges with their parts, resolved, so a key into a pill for a table on another board is a key to the column its binding names, of that table (`forEachEdge(of:.outgoing…view:.resolved)`), worked out when asked and forgotten only for the tables a change to those edges touched (`topology.follow`), all of them on a rebuild or a new file: a frame asks it once a table with rows in view. The render reads it for the gutter's link (`TableStyle.linkSymbol`, `linkColor`, the link blue made to read on the paper), a primary key's key before it and a unique's "1" after. The table, the enum and the database adopt the core's `TakesBoundShapes`: deleting one takes its keys ("Delete Table and 3 Arrows"), a column taken out (⌘⌫ then ⌫, LineRows' `removeParts`) its keys ("Delete Column and 1 Arrow": LineRows counts even one), a copy of tables the keys among them. A key to a column on another board ends at a reference pill for its table, the column on the arrow's binding (K10, the plan's "Through a pill", decided 12: the arrow meets the pill whole, Topology reads the column as the edge's end, the key index and the line say `→ customers.id`): ⌘L's pick and a typed `→` put the pill down beside the table, or reuse the board's pill for that table in the table's container, in their step (T6 panel 3, "Add Column" for a typed one); a move keeps keys that cross through pills ([moving](moving.md), T6 panel 2); deleting or moving the column on its board reaches the arrow through the pill in the same step (the core's `removeParts` and `moveParts`, [shape references](shape-references.md)). A table's pill takes `foreign-key` on its parts, as the table does (`KindPorts.standing(for:)` keeps part entries: [connections](connections.md)), so it shows no key dots and no drag ends a key on it; the ways to a key through it are the line, ⌘L and `canvas draw`, which name the column. A table and an enum take rows out by id (`PartedShape.removing`, `derive`d to their rows' height) for draw's `delete "orders".x`. `KeyIndex` keeps each key's arrows too (`arrows(of:in:)`), for a line that re-aims or takes its key out and a pick that replaces it. No `→ customers.id` chip at rest: the frames draw none; the focused line prints the key (above).
- **How a key looks** (K4, `KeyLooks` in `Tables/Keys.swift`, the kit's answer to Connections' `ConnectionLooks`, [connections](connections.md)): for an arrow on `foreign-key`, from the column its start is at, a crow's foot at that end (`many`), two bars when the column is unique (`one`: it says `unique`, or it is its table's one primary key column; one of two isn't), and at the row it references two bars (`one`), a bar and a circle when the column may be null (`zeroOrOne`); the line `KitStyle.keyLineWidth`, 2.5, and ink as every line is (the colors of marks, pills and dots elsewhere are Palette's swatches, decided 25). A key whose start is at a table as a whole has a plain column's marks. Nothing is stored: Arrows asks when it works out the key's geometry, and the column is read through the shapes it is handed, so a column made unique or nullable (its line, draw, an undo) redraws its keys' marks with nothing written to them (T3 panel 4, T4 panel 2). Every key is a level curve, its ends at its rows' sides ([arrows](arrows.md)).
- **Where a line to a table meets it**: the table's geometry gives its first shown row's two sides as its entries (`ShapeGeometry.entries`, `ShapeEntry.sides(of:)`, the core's), so a level arrow bound to the table as a whole (a row's arrow to a table, E8 panel 2) meets that row at the side facing it; a table with no rows gives none, and an enum or a database none.
- **VoiceOver** (`x.accessibility`, Titles naming it): "orders, Table, 5 columns", "order_status, Enum, 7 values", "shop, Database, 4 shapes"; the title field is "Table name" or "Enum name".
- **Folded** (LineRows' folds, [line rows](line-rows.md)): ⌃⌘↑ folds a table to the columns its model marks (`TableLines.marked`: a primary key, a column that starts a key, read from the key index, a unique column: T6's products to `id` and `sku`), an enum to its first two values (it marks none: `pending`, `paid`, "+4 ›"); `KitRows` reads `LineRowsLayout.shown` and lays the kind out at the height of its shown lines, draws them and a "+N ›" line (`MoreLine`: the names' font in the types' grey, `KitStyle.moreChevron`; zoomed out a bar in the text fill), and puts a hidden row's part rect at that line, marked not shown (`PartFrame.isShown` from `KitRows.isShown`), so a key bound to it ends there and the ports, the row stepping and a drop on "+N ›" meet the columns that show. The key index tells the folds which tables a change to the keys touched (`marksMayHaveChanged`), so a key drawn shows its column on a folded table at once and one undone hides it. `KitRows` also reads `LineRowsLayout.width`: a line typed wider than the table lays it out that wide (T2 panel 3), the stored width kept.
- **Find** (`Tables/RowFind.swift`, `EngineeringFindPlugin`, `engineering-find`, shipped after the kit's plugin, a plugin value of its own so a list without Find leaves it out): a text a column (`name type`, its name alone where its type is an enum's pill) and a text an enum value, by the row's id, marked where the row draws it (`ColumnRow`, the one layout of a column's row the render draws by); an enum-typed column's pill ringed, its text the enum's name now, read again, with the column's plain type words, for every table of the file that names an enum a commit adds, removes, changes or reaches elsewhere (`EnumUsers`, a service of the plugin: which tables name which shapes in a column's type, built from the file when Find first asks and followed by each commit after, so it costs what the commit touched).
