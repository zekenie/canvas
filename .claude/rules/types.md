# Types

Types: a shape that holds a JSON Schema is a type, named by its title; making one (`/type`) and taking it back (Remove Type); the file's types and what is what (`TypeIndex`); what a shape is (`is`, the `is-a` edge); its words and its schema kept saying the same thing by the model (`TypeSync`); references between types; the Schema tab's JSON, its completions and issues; highlights of its words, and their popovers; and their tests.

Related: [language models](language-models.md), [prose maps](prose-maps.md), [mentions](mentions.md), [titles](titles.md), [publishing](publishing.md), [detail panel](detail-panel.md), [validation](validation.md), [slash commands](slash-commands.md), [editing](editing.md), [shape references](shape-references.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Types](../../docs/plugin-system.md#types-shapes-that-hold-a-schema).

## Architecture

- Types (a concern, on Canvas, DetailPanel, LanguageModels, Mentions, ProseMaps, Publishing, Selection, SlashCommands, Titles and Validation; `docs/plugin-system.md`, "Types") knows no kind. A kind opts in with sugar its plugin calls: `typeWords(_:drawnIn:fitting:)` hands Types its words (a key path to its `MentionText`, the placement its render draws them in, and what a write of them changes besides: a note's height), a contribution to the `TypeWords` point (one per kind, its `words`, `placement` and `write`, the last a transaction's update that fits the shape as the kind fits it), and `canBeType()` opts the kind into `TypeSchemaProperty` (key `schema`, a `SchemaText`), which the registry refuses without `typeWords` (`TypeWords.check`). StickyNotes calls both, so a note is the shipped type; TypesTests' `Memo`, a box of words of the tests' own, shows Types needs no note. A shape is a type exactly while it holds `schema` (`record[TypeSchemaProperty.self] != nil`); nothing else marks it, and Type is in no list of a shape's types. Its name is its title (Titles' `TitleProperty`, `registry.title(of:)`): a type's schema keeps no root `"title"` of its own, and one the person types in the JSON is kept as typed and never the name. `SchemaText` is one string in a board, kept as typed (its order and half-typed text survive), and `ShapeNaming` through `urn:uuid:` `$ref`s (`SchemaReferences.refs(in:)`, `uri(of:)`, `target(of:)`, read in any case, whole or with a fragment), so a copy of a type with the types it refers to refers to the copies and one alone to the originals, and `canvas draw` warns of a `$ref` to a shape not in the file; the key `schema` is an ordinary id to the audit (`ORDINARY_IDS`), a board's own old member. `Fixtures/added/schema.v0.json` is its fixture.
- Making one: `/type` (`registerTypeCommands`, every shape that holds the property, `when` it holds none, no argument) runs `editor.makeType(_:)`, one step "Make Type": the starter schema (`TypeSchemaProperty.starter`, an object with no properties) and `public: true` in the same transaction, through Publishing's `PublicProperty` (a type starts public, so what stands for a type elsewhere can; the person may make it private after; a list without Publishing makes it all the same, not public). `editor.removeType(_:)`, one step "Remove Type", takes the schema away and leaves the words, the title and whether it's public; undo brings the schema back. Its chip and menu are a later slice's. An agent makes a type with draw's `schema:` (an added property's attribute, as every one is): a note drawn with it, named by its title.
- The file's types: `TypeIndex` (`editor.types`, an `EditorService`) reads every board's types as the file opens (the kinds that `canBeType` only, a lookup a shape), then keeps them by each commit's `ChangeSet` alone (added, removed, changed, `elsewhere` with the kind first, `replacedDocument`, and a whole file put in place, `boardDidChange`'s `isFileReplaced`): `isType(_:)`, `types`, `name(of:)` (its title), `revision(of:)` (moves when its schema or its name does) and `onChange(_:)` (the ids that came, went or changed, after each commit that did). It reads nothing per frame and nothing on a move. `referenceTargets(from:)` is a `$ref`'s completions: every other titled type, by name, its fields counted, in the order of the names. `popover(at:on:origin:)` is an editing view's way to its highlights' popovers.
- What a shape is: `is`, an added property (`IsAProperty`, key `is`, an ordered `[TypeLink]`, none twice: `uniqueItems`; empty is none, so emptying it takes the property off), on the kinds that call `typeable()` (it needs `typeWords`, `TypeWords.check`): a note and an arrow. `TypeLink` is a one-field wrapper of a `ShapeID`, `ShapeNaming`, coded by hand as the bare uuid string, `contentMediaType` `text/x-canvas-type` (`TypeLink.mediaType`, what draw and queries read the entries by, later): a name, not a binding, so a copy of an instance copied with its type is an instance of the copy, one copied alone stays an instance of the original, and a type that is deleted leaves its name behind (its chip dashed) until the delete is undone. `ShapeID` itself must not be `ShapeNaming` (an arrow's bindings are ids). The order is the order added: a later entry wins where two say the same (a later slice reads it). `Fixtures/added/is.v0.json` is its fixture. Types declares the `is-a` edge type (`IsAEdge`, a root, "from a shape to each type it is, in the order of its list") and derives it with Topology's property rule (`registrar.edges(in: IsAProperty.self, as: IsAEdge.self)`: slot `is`, from the instance to each type, a name of a pill forwarded to what it stands for, a move reading nothing). `build.sh`'s `ORDINARY_IDS` holds `is`. A kind that is `typeable()` says where its words are, as one that `canBeType()` does: an arrow's `typeWords` places its label against the shapes around it (`typeWords(_:drawnIn:fitting:)` has an overload whose `drawnIn` is given the `ShapeContext`; the contribution's `placement` takes it).
- What is what: `TypeIndex` (`@Observable`, `editor.types`) also keeps `links(of:)` (a shape's types, in the order of its list; a name of a shape that is gone included), `instances(of:)` (the shapes whose list names it, directly), `lineage(of:)` (what a shape's types lead to, level by level, nearest first: its own types later first, then those types' own, each once, never the shape itself, a cycle stopping where it comes back; the one place the order is decided is its private `parents(of:)`, which the custom shapes of a later slice extend with a template and what it builds on), `affected(by:)` (the instances of the shapes, near and far, each once: what a change to a type changes) and `name(of: TypeLink)` (`TypeLinkName`: `.live(title)` while the shape is a type, else `.missing(lastKnown:)`, the last title it was known by in this session; observed per type). Kept by each commit's `ChangeSet` as the types are (a shape that only moved reads nothing: `recordsRead` in debug builds), read again for a file put in place and for a commit heard out of turn (`heardRevision`, as Titles' index does; `boardDidChange` always catches up), and it tells Adornments (`editor.adornmentsDidChange(for:)`) to make the chips of the instances of every type again whose name or being a type changed (renamed, deleted, brought back, no longer one).
- The sync: `TypeSync<Schema>` (`editor.typeSync` for a type's, `TypeSync<TypeSchemaProperty>`) keeps a shape's words and a `SyncedSchema` property (one whose value is a `SchemaText`: the property it writes, the prompts it sends, `SchemaSyncPrompts`, its update step's name, and whether the shape's name is the schema's, `namesTheShape`) in step through `editor.languageModel`, as the schema card's did: only the person's edits sync (not its own write, a board read again, a move, a lock, a rename, an agent's write, `ChangeSet.byAgent`, which is taken as in step), on a commit (editing the words ended however it ended, `editingDidEnd`, an edit still waiting committed the next turn; ⌘↩ or the keyboard leaving in the panel's JSON) or 3 s after the last (`TypeSync.idleDelay`, `editor.scheduler`), the wait held while the JSON's completion list is open (`completing`); words that changed rewrite the schema (whole: past 34 KB never sent, "Schema too long to rewrite", `TypeSyncFailure.tooLongMessage`), else a schema changed in meaning (its root `"title"` left out of the comparison) rewrites the words; never for text that isn't a JSON object, a read-only shape (`editor.isReadOnly(inFile:)`, asked as the sync starts and as an answer lands), a shape with no fields and no words, or without a model. A shape seen for the first time is in step, but words over a schema with no fields, never answered, are ahead; a shape the person makes a type (`/type`) waits as an edit does, so the next commit asks for its schema. The name: the type's title goes in as the root `"title"` of each schema sent (`TypeNaming.titled`, unless the schema has one the person typed), the model's comes out of what it writes back (`TypeNaming.untitled`), and an untitled shape is named by it in the same step. While a call is out the side it writes is read-only (the JSON, `detailUpdating`; the note's editor, read-only and faint, showing what lands); its answer is dropped if that side changed. Its write is a step of its own ("Update Schema", "Update Text"), on the shape's board shown or not (`transact(on:)`), the words through the kind's `TypeWords.write`; undo and redo start nothing (`restoredStep`) and the pair last synced goes back with the steps (`UndoParticipant`). Its status (`TypeSyncStatus`, `TypeSide` `.words`/`.schema`, `TypeSyncFailure` and its remedy) shows under the JSON ("Updating schema…", "Updating text…"). What it asks is `SchemaPrompts` (the file name, constant names and prompt literals byte for byte, since `scripts/schema-prompts` parses them; they still say "prompt" for the words): Haiku 5.5 at `medium`. The model never sees an id: each type the texts name is `@` and a word (`SchemaReferenceNames(words:schemas:name:isType:)`), a mention of a type its word and a `$ref` that word as its URI; a mention of a shape that isn't a type reads as its label, words.
- Readings: `SchemaReadings` keeps a reading per shape and text (`versionsPerShape`, 4; past 4,096 those used longest ago go; `TypesPlugin.schemasRead` counts reads in debug builds), its `shown` the last that was a JSON object while the text isn't one; `issues` are Validation's (`TypeValidationPlugin`, `validateEveryShape`): not JSON or not an object an error; `required` naming no property, a `type` that isn't JSON Schema's, and whatever else the meta-schema refuses (`MetaSchema` through the core's `SchemaValidator`, its own sentences, a `type` left to the rule of its own), warnings, 20 at most. `SchemaDocument`, `JSONReader`, `JSONCaret`, `JSONCompleter`, `JSONPointer` and `MetaSchema` came over from Schemas as they were.
- The panel (`TypeDetailsPlugin`): every shape that holds the property has the Schema tab (`TypeSchemaTab`), its JSON section (`TypeSchemaCode`): `SchemaCodeEditor` (public, for any schema kept as a shape's text: colored by `JSONReader.tokens`, `SchemaCodeColors`; completed by `TypeCompletions.completions(in:at:types:extra:)`, the meta-schema's keywords with no root `title`, a `required` list's names, a `$ref`'s targets, its own definitions then the file's other titled types, and what a caller adds where a value goes, `extra`), its issues a status line each, and the sync's line (`TypeSyncLine`: Retry, Open Settings…, or nothing). Writes through it are one step a run, "Change JSON". The header is the kind's (a note's title).
- Highlights: a prose map of the words into the schema (`SchemaTarget`, its guide `SchemaPrompts.highlightsGuide`, `highlightsReferences` its context when the words name types), asked once the shape is drawn in full and in step, read through `ProseHighlights` (generic over a target whose addresses are JSON Pointers, keyed by shape and target: the texts as the model reads them, made once per text, and the map moved onto the drawn text, `MentionReading.drawnRange`; `forget(_:)`, `forgetEverything()` in debug builds). A kind's render calls `context.fillTypeHighlights(of:in:)` with the placement it draws its words in, between its fill and its text (a note's), which costs one added-value lookup on a shape that isn't a type: a field's pale blue, a rule's pale amber (`TypesStyle`). Resting the pointer on them shows that part of the schema, or of the type a `$ref` names, in the core's popover: on the canvas through Selection's `shapePopovers` (`TypeHighlights.popover(at:on:in:)`), in a note's editor through `EditContext.hoverPopover` (the editor asks `editor.types`). `TypeHighlights.placed(for:in:)` and `lines(for:in:)` read them for tests.
- StickyNotes: the note's render fills the highlights under its text; its editor (`NoteEditor`) follows the sync, read-only and faint while the model writes the words, showing what lands (`MentionTextView.show`, typing's undo dropped), ⌘↩ ending editing while read-only, and asks for the highlights' popovers as the pointer rests. Every list that installs `StickyNotesPlugin` installs `TypesPlugin` (the registry refuses an owner not installed).
- Composition: `TypesPlugin(), TypeValidationPlugin(), TypeDetailsPlugin()` right after `PublishingPlugin()`, so a note's commands list `title`, `lock`, `public`, `type`, then Moving's. The schema card, its tool, its `schema-link` channel and Schemas are gone: a board that holds a card keeps it aside.

## Testing

- TypesTests: every test over `Memo` (`MemosPlugin`: titled, mentionable, `typeWords`, `canBeType`) with `typePlugins(model:)` (a scripted model always; `SCHEMA_LIVE=1`, which test.sh never sets, runs `liveTests` against Claude), `typeRecord`, `addType`: the JSON reader, caret, completer and meta-schema as they were (`readerTests`, `caretTests`, `completionTests` with a type's `$ref` targets and `extra`, `metaSchemaTests`, `fieldTreeTests`); the sync (`syncTests`: both ways, timers, completing, failures, too long, read-only, an agent's write, the name put in and taken out, an untitled type named, a typed root title kept, a rename asking nothing, `/type` waiting, an agent's or undo's type in step, Remove Type dropping its call), the prompts (`promptTests`), undo (`undoTests`), boards not shown (`schemaBoardsTests`), the panel (`panelTests`, `panelCompletionTests`, `TypePanelWindow`), highlights (`highlightTests`, `highlightShownTests`), references (`referenceTests`, `referenceNameTests`, `referenceSyncTests`, `referenceShownTests`), `/type` and Remove Type (`commandTests`, with `Slip`, a kind that can't be one and one refused without `typeWords`), the index (`indexTests`), the rules and reading (`ruleTests`) and the words' write (`wordsTests`).
- TypesTests' `isAPropertyTests`, `isAEdgeTests` and `typeLinkTests` (over `Memo`, which is `typeable()` too; `instanceRecord`/`addInstance(_:of:)`, `typesOf`; a local `Echo` that stands for the shapes it cites; a `ChaserPlugin` before Types that commits while hearing a commit): the property (declared, opted in, the report line, `typeable()` refused without `typeWords`, the schema's `text/x-canvas-type` and `uniqueItems`, saved as the bare ids in order and read back, empty is none, `ShapeID` not `ShapeNaming`, a copy renaming the ones copied along and keeping the rest, a delete leaving names dangling and undo whole), the edges (one per entry in the order of the list, slot `is`, followed commit by commit, forwarded through a stand-in, a move reading no record), and the index (three boards, each commit, a move reading nothing, a shape moved to another board and a board taken and brought back, the lineage level by level with cycles and a deleted type, `affected(by:)`, names live and missing and heard by their readers, a file put in place, a commit heard out of turn).
- StickyNotesTests' `typeNoteTests`: a type note's highlights under its text, and under its editor pixel for pixel but anti-aliasing; words kept and typed over; the editor's popover over it, typing taking it down; the editor read-only and faint while the model writes, showing what lands; ⌘↩ ending it; editing ending asking for the schema.
- CompositionTests' `typesShippedTests`: `/type` typed in a note's editor in the app's canvas view (one step, public, editing going on, the model asked once it ends, the note named), a mention of a type a `$ref`, copy and paste remapping both (a private pasteboard), `canvas draw` with `schema:` over a socket of its own and a query finding it; the story's W, S and V are type notes (`sticky-note[schema]`), the eval board's records and boxes too; `PersistenceTests` its fixture; `FramesShippedTests` the frames file's card kept aside.
