# Types

Types: a shape that holds a JSON Schema is a type, named by its title; making one (`/is-a type`) and taking it back (Remove Type); the file's types and what is what (`TypeIndex`); what a shape is (`is`, the `is-a` edge); its words and its schema kept saying the same thing by the model (`TypeSync`); references between types; the Schema tab's JSON, its completions and issues; highlights of its words, and their popovers; and their tests.

Related: [adornments](adornments.md), [topology](topology.md), [language models](language-models.md), [prose maps](prose-maps.md), [mentions](mentions.md), [titles](titles.md), [publishing](publishing.md), [detail panel](detail-panel.md), [validation](validation.md), [slash commands](slash-commands.md), [editing](editing.md), [shape references](shape-references.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Types](../../docs/plugin-system.md#types-shapes-that-hold-a-schema).

## Architecture

- Types (a concern, on Adornments, Canvas, ContextMenus, DetailPanel, LanguageModels, Mentions, Placing, ProseMaps, Selection, SlashCommands, Titles, Topology and Validation; `docs/plugin-system.md`, "Types") knows no kind. A kind opts in with sugar its plugin calls: `typeWords(_:drawnIn:fitting:)` hands Types its words (a key path to its `MentionText`, the placement its render draws them in, and what a write of them changes besides: a note's height), a contribution to the `TypeWords` point (one per kind, its `words`, `placement` and `write`, the last a transaction's update that fits the shape as the kind fits it), and `canBeType()` opts the kind into `TypeSchemaProperty` (key `schema`, a `SchemaText`), which the registry refuses without `typeWords` (`TypeWords.check`). StickyNotes calls both, so a note is the shipped type; TypesTests' `Memo`, a box of words of the tests' own, shows Types needs no note. A shape is a type exactly while it holds `schema` (`record[TypeSchemaProperty.self] != nil`); nothing else marks it, and Type is in no list of a shape's types. Its name is its title (Titles' `TitleProperty`, `registry.title(of:)`): a type's schema keeps no root `"title"` of its own, and one the person types in the JSON is kept as typed and never the name. `SchemaText` is one string in a board, kept as typed (its order and half-typed text survive), and `ShapeNaming` through `urn:uuid:` `$ref`s (`SchemaReferences.refs(in:)`, `uri(of:)`, `target(of:)`, read in any case, whole or with a fragment), so a copy of a type with the types it refers to refers to the copies and one alone to the originals, and `canvas draw` warns of a `$ref` to a shape not in the file; the key `schema` is an ordinary id to the audit (`ORDINARY_IDS`), a board's own old member. `Fixtures/added/schema.v0.json` is its fixture.
- Making one: `/is-a type` (the `Type` row of `/is-a`'s list, below) or `editor.makeType(_:)` (`makeTypes(_:)` for several, one transaction), one step "Make Type", on a shape that holds the property and none yet. Its schema is the starter (`TypeSchemaProperty.starter`, an object with no properties) unless the shape's words are a JSON object (`TypeWordsSchema.schema(fromWords:)`: nil if the words hold a mention, are empty, or trimmed are not an object; an array, a number or text get the starter; `{}` is a schema), in which case the schema is the words, trimmed of whitespace at both ends and otherwise as written, with no model call, and the sync then writes the words from the schema: `TypeSync.changed`, on a shape made a type by the person, sets the last-synced sides to the words and `{}` when the words equal the schema, so the next commit finds the schema ahead of the words and asks for the words (the `toWords` direction), and with `{}` words, which say nothing, nothing is asked. A type does not start public (it is found by `/is-a` and by its title; `/public` is the person's to say, on a type as on any shape). `editor.removeType(_:)` (`removeTypes(_:)`), one step "Remove Type", takes the schema away and leaves the words, the title and whether it's public; undo brings the schema back. Each plural form leaves out the shapes that cannot take the change and transacts nothing when none is left; a read-only shape stays in, so the core refuses it and it shakes while the rest change. Is a ▸ in a shape's menu is the other way. An agent makes a type with draw's `schema:` (an added property's attribute, as every one is): a note drawn with it, named by its title.
- The file's types: `TypeIndex` (`editor.types`, an `EditorService`) reads every board's types as the file opens (the kinds that `canBeType` only, a lookup a shape), then keeps them by each commit's `ChangeSet` alone (added, removed, changed, `elsewhere` with the kind first, `replacedDocument`, and a whole file put in place, `boardDidChange`'s `isFileReplaced`): `isType(_:)`, `types`, `name(of:)` (its title), `revision(of:)` (moves when its schema or its name does) and `onChange(_:)` (the ids that came, went, or whose schema, name or own types changed, after each commit that did), `schemaText(of:)` and `chainRevision` (internal: the stamp the field book keeps its resolutions by, moved when a type comes, goes, its schema's text changes or its own `is` list does, at one integer add; not for a rename, an instance's list or another shape's text). It reads nothing per frame and nothing on a move. `referenceTargets(from:)` is a `$ref`'s completions: every other titled type, by name, its fields counted, in the order of the names. `popover(at:on:origin:)` is an editing view's way to its highlights' popovers.
- What a shape is: `is`, an added property (`IsAProperty`, key `is`, an ordered `[TypeLink]`, none twice: `uniqueItems`; empty is none, so emptying it takes the property off), on the kinds that call `typeable()` (it needs `typeWords`, `TypeWords.check`): a note and an arrow. `TypeLink` is a one-field wrapper of a `ShapeID`, `ShapeNaming`, coded by hand as the bare uuid string, `contentMediaType` `text/x-canvas-type` (`TypeLink.mediaType`, what draw and queries read the entries by, later): a name, not a binding, so a copy of an instance copied with its type is an instance of the copy, one copied alone stays an instance of the original, and a type that is deleted leaves its name behind (its chip dashed) until the delete is undone. `ShapeID` itself must not be `ShapeNaming` (an arrow's bindings are ids). The order is the order added: a later entry wins where two say the same (a later slice reads it). `Fixtures/added/is.v0.json` is its fixture. Types declares the `is-a` edge type (`IsAEdge`, a root, "from a shape to each type it is, in the order of its list") and derives it with Topology's property rule (`registrar.edges(in: IsAProperty.self, as: IsAEdge.self)`: slot `is`, from the instance to each type, a name of a pill forwarded to what it stands for, a move reading nothing). `build.sh`'s `ORDINARY_IDS` holds `is`. A kind that is `typeable()` says where its words are, as one that `canBeType()` does: an arrow's `typeWords` places its label against the shapes around it (`typeWords(_:drawnIn:fitting:)` has an overload whose `drawnIn` is given the `ShapeContext`; the contribution's `placement` takes it).
- What a shape holds for its types' fields: `fieldValues`, an added property (`FieldValuesProperty`, a `FieldValues`: one JSON object over `JSONObject`, coded as the bare object) on the kinds that call `typeable()` (it opts in beside `is`; `isTypeable` still means "holds `is`"). A value that is empty is not kept, at any depth (`FieldValues.pruned`, the one rule: null, text with no characters, a list left with no items and a group left with no members once their own empties are dropped; `false`, `0` and text of spaces are values), and every way in prunes (`init(_:)`, `init(from:)`, the subscript; `values` is `private(set)`), so `isNone` is `isEmpty` and a board read, a draw or a set that is only empties holds none. Written by people and agents, never `readOnly`; `canvas draw`'s `fieldValues:` replaces the whole object (a statement naming it), `null` takes it off, an edge takes it; a query reads a path into it (`[fieldValues.status="paid"]`). Nothing reads a type for it: it knows no field, so a value no type names is kept. Not `ShapeNaming` yet. `Fixtures/added/fieldValues.v0.json` is its fixture. Beware `JSONValue` is `ExpressibleByNilLiteral`: a `nil` beside a `JSONValue` in a ternary is `.null`.
- `/is-a` (`registerIsACommand`, every shape that holds `is`: a note, an arrow in its label; Types' one command, after `title` and the other plugins' every-shape commands): a slash command that takes one choice (`SlashCommand(_:argument:choices:step:perform:)`, [slash commands](slash-commands.md); `argument` `type`). Its rows (`TypeChoices.rows(for:in:)`, in `TypeChoices.swift`, asked once when the list opens) are `Type` (group 0, title `TypesStyle.typeChoice`, symbol `curlybraces`, step "Make Type") only while the shape can be a type (`registry.canBeType`) and is not one, never on an arrow's label or a type, then the file's types the shape may be (`TypeIndex.choices(for:)`, group 1, the same symbol, step "Add Type"): every type for which `TypeIndex.admits(_:for:)` is true (a type, never the shape itself, one it is already, one that reaches the shape (`reaches`: no cycles), a pill (a stand-in kind), a shape that isn't there; the one private `mayBe` is where the custom shapes of a later slice join), on any board, ordered by name (lowercased once and compared as plain text, the id the tie: the locale's collation cost most of opening the list), an untitled one last and called `Untitled`; the first type is `isPreferred`, so with nothing typed it is the highlight, and `Type` is when there are none. A row's id is `type` or the type's uuid (`TypeChoice`). A pick runs at once: `Type` calls `makeType`, a type `addTypeLink(_:to:)` (the type goes at the end of the list, a later line wins, one step, "Add Type", on a shape on any board; `addTypeLink(_:to: [ShapeID])` for several shapes in one step); a read-only shape is offered nothing (the state), and the core refuses and shakes the one that became so. `editor.removeTypeLink(_:from:)` is the one way an entry goes (one step, "Remove Type", the property off with the last; the plural form for several), the chips' and the panel's Remove call it, so what a later slice settles when a type is given or taken back is settled inside these, in the person's own step. `@` typed on `/is-a`'s line is a letter (Mentions asks `listsChoices(at:)`). `/type` is gone.
- New type (`/is-a company`, TypesStyle `newType`, "New Type"): for what was typed, `/is-a`'s `otherwise:` offers the row `New type “Company”` (`TypeChoices.newRow(typed:owner:editor:)`, `TypeChoice.new(name)` in the row's `id`), which the list puts last, after the ranked matches, and not at all where a row is titled what was typed (`/is-a type` on a shape that has the `Type` row, `/is-a company` with a type called Company: case aside, spaces folded) or nothing is typed ([slash commands](slash-commands.md)); where nothing matches it is the only row and highlighted, with matches the best match stays the highlighted row (`/is-a co` with a Company lists Company and then `New type “Co”`, and Return picks Company). The name is the typed text folded to one line (`TitleProperty.folded`) with its first letter capitalized and the rest as typed, in the typographic quotes; none for nothing typed, a name over a title's 80 characters, the list's own word (`type`, case aside: on a shape that is a type already `/is-a type` offers nothing), no kind that can be a type, or one with no placement (`registry.placement(for:)`, read from a kind's tool). The pick is `editor.newType(named:besides:)` (public, discardable result): in `undoHistory.group("New Type")` it takes the kind (the owner's if it can be a type, else the first in registry order that can and has a placement), reads the board shown once for the landing beside the owner (`Surroundings(on:moving:in:).near(owner)`, as `/move-near` places one: right if free, then below, left, above), puts the placement down titled with the starter schema (`Placement.setting`, and `mapping` to learn the new record's id: the core's `place` is unchanged) and then links the owner (`addTypeLink`). The note is selected and edited as any placed note is, which ends the owner's editing, and the step stays open while the new note is edited, so words typed into it before that ends are in New Type and one undo takes them with the note and the link; a read-only board or a container that refuses it puts nothing down (the core refuses; nil, no link, no step, and the board's owner or container shakes), as does an owner not on the board shown. The new type is not public and its words are empty, so the sync has nothing to read until the person writes. TypesTests' `newTypeTests` (`IsALine`, Support.swift: `IsAView`, a text view that hosts slash commands over a memo, in an unshown window, so the real list is typed into and picked from) and CompositionTests' `typesShippedTests` hold it, and the gallery's `Flow2-p4-list-match-and-new-type`; `Budget.newTypePick` ([benchmarks](benchmarks.md)).
- Is a ▸ (`TypeMenus.swift`, `registerTypeMenus`: an item for the canvas, `MenuItems(in: StateMenuGroup, id: "is-a")`, so in Lock's group with no line between them, after it in plugin order): a submenu `Is a` in the menu of every shape the selection holds, made when the menu opens (`IsAMenu`). Items: `Type` (group `ShapeMenuGroup`, only when every selected shape can be a type), a line (the group `IsATypesMenuGroup`, order 1), then the types some selected shape is or may be (`TypeIndex.menuChoices(for:)`, in `choices(for:)`'s order), each titled by its name or `Untitled`. A check by an item every selected shape has (`Type`: all are types); there is no mixed state, so a type some have is unchecked and choosing it gives it to the rest. An unchecked item calls `makeTypes` or `addTypeLink(_:to:)` (steps "Make Type", "Add Type": one step for the whole selection), a checked one `removeTypes` or `removeTypeLink(_:from:)` ("Remove Type"). Never dimmed: a read-only shape is refused by the core and shakes while the rest change in the one step. The submenu is left out for a selection with a shape that holds no `is` (a frame, a subboard), and where it would hold nothing (an arrow in a file with no types). An arrow's menu has it with the file's types and no `Type`. A list that installs `TypesPlugin` installs `ContextMenusPlugin` too (the registry refuses a contribution whose owner isn't installed).
- A type's note is white paper (StickyNotes': `NoteStyle.typePaper`, white in the light appearance and 0.92 in the dark, the plain yellow note unchanged in both; the text's ink is the note's on both): its render and its skeleton fill it, the skeleton resolving the dynamic color once for the appearance drawn (`NoteStyle.typePaperCG`; [benchmarks](benchmarks.md)), and its cover's ink is chosen for it (`titlePillLook` with `coverSurface`). It is yellow again once the schema goes.
- A type's color (`TypeColors`, public; the table is `TypesStyle.colorTable`): one of eight by the id, never stored, so two types can share one; the index is the first eight bytes of the id's UUID, each summed with its position, modulo eight (never `hashValue`; TypesTests' `typeColorsTests` hold a table of ids that never changes, the spread, and the validator: white on each `base` at 4.5:1, each ink on its 14% tint over the light canvas (0.965) and the dark (0.11) at 4.5:1, none within 0.05 of red's hue, the eight distinct). `base` is fixed in both appearances; the ink follows the appearance. `TypeColors.solid(id)` is the pill's tint, `light(id)` the chips', `base(id)` the color alone, `gray` (0.40, `TypesStyle.grayChip`) what has no color. `/is-a`'s rows are chips (`SlashChoice.chip`, [slash commands](slash-commands.md)): `Type` and an untitled type gray, the others in their color, white on it, the `{}` first. A type's pill is Titles' (`registrar.titlePillLook(forShapesHolding: TypeSchemaProperty.self)`, [titles](titles.md)): its title after `curlybraces`, solid in its color; untitled, a dimmed gray `Untitled` placeholder (the neutral look every placeholder pill has); a note that holds no schema keeps the plain pill; Remove Type and its undo switch it.
- Chips (`TypeChips`, an `Adornment` and `ClickableAdornment`, aboveTopLeft, order 100, on every kind that holds `is`; a group, tagged): one chip per entry of `is`, in order, light (Adornments' `tinted(_:)`) in the type's color (`TypeColors.light`) with its type's live title (`TypeIndex.name(of:)`; an untitled type a gray placeholder "Untitled", no color), `.missing()` (dashed, italic, gray) for a type that is gone or no longer a type, with the last title it was known by, else "Deleted"; the ones that don't fit whole fold into Adornments' "+N" (gray). A type's note shows its own pill and then the chips of the types it builds on; there is no Type chip (Is a ▸ Type in the menu makes and unmakes one). The index tells Adornments to make the chips of a type's instances again when it is renamed, deleted, brought back or no longer one. A click (`TypeChipMenus.menu(for:in:)`, popped up below the chip's rect with `editor.popUpMenu`): on a type's chip `Go to “Person”` (`editor.goTo`, left out for a type that isn't in the file) and `Remove “Person”` (`removeTypeLink`, left out while the shape is read-only); on "+N", those for every type, a separator between types. Nothing is shown on a shape drawn as a skeleton. On an arrow the row sits above its label (Adornments' anchor).
- The panel's Types tab (`TypesTab`, order 50, a section "types" over `IsAProperty`, `enabledWhileReadOnly`): a row per type in order, a click on it goes to the type (`editor.goTo`, on the scheduler), a minus removes it (`removeTypeLink`; off while the shape is read-only), the row dimmed with the last title once the type is gone. A type that has supertypes has the Schema tab and this.
- Duplicating a typed shape (⌘D, a ⌥-drag, copy and paste, cut and paste: [clipboard](clipboard.md)) keeps `is`; copied with its type, the copy's names are renamed among the copies by the paste's one map (`TypeLink` is `ShapeNaming`), so the copies are the copy's instances and the original keeps its own; pasted into another file the names point at shapes it lacks (dashed chips).
- What is what: `TypeIndex` (`@Observable`, `editor.types`) also keeps `links(of:)` (a shape's types, in the order of its list; a name of a shape that is gone included), `instances(of:)` (the shapes whose list names it, directly), `lineage(of:)` (what a shape's types lead to, in the one order they are read in, `TypeOrder.linearized`: a type before every type it builds on, and where a list leaves a choice the later added first, which is C3, Python's method resolution order; where C3 has no order, as when a note was given Employee and then Person, a depth-first walk breaks the ties and the rule still holds, so Person never beats Employee; each once, never the shape itself, a cycle stopping where it comes back; a list is read latest first, `TypeGraph.parents(of:)`), `TypeGraph.reaches(_:from:)` (reachability alone, no order: what `admits` and the query ask), `affected(by:)` (the instances of the shapes, near and far, each once: what a change to a type changes) and `name(of: TypeLink)` (`TypeLinkName`: `.live(title)` while the shape is a type, else `.missing(lastKnown:)`, the last title it was known by in this session; observed per type). Kept by each commit's `ChangeSet` as the types are (a shape that only moved reads nothing: `recordsRead` in debug builds), read again for a file put in place and for a commit heard out of turn (`heardRevision`, as Titles' index does; `boardDidChange` always catches up), and it tells Adornments (`editor.adornmentsDidChange(for:)`) to make the chips of the instances of every type again whose name or being a type changed (renamed, deleted, brought back, no longer one).
- The chain (`Chain.swift`, pure: `Chain.resolve(types:in:)` over a `ChainCatalog` of `ChainNode`s, so one answer serves a shape, every shape with the same types, and a test with no editor): what an instance's types give it, as a `Resolved`. `order` is `TypeOrder.linearized` of the instance's list read latest first, less the shapes the catalog has nothing for (a gone name, or a shape that is no longer a type, ends its branch: its notes keep their words and show a dashed chip, while `:is-a` still follows its list). A field's winner is the first type in `order` to name it, and its whole `ChainField` is used (nothing merged, `required` with it, which is the root's own; a `required` name with no property names no field). `fields` is in row order: `order` reversed, each type's fields in the order written, a name taking the place it first appears at, so a field a more specific type restates keeps the more general type's place with the restater's definition (`source` the winner, `introducedBy` the type whose block the row sits in). A type cannot take a field away. `rules` are every type's root keywords across fields (`allOf anyOf oneOf not if then else dependentRequired dependentSchemas`, none overridden, in row order of their types), `directives` the root's `$title`-like properties, raw, one per name, the first in `order` (so an Employee gets Person's `$title`; nothing reads them yet). The root's `patternProperties`, `$ref`, `additionalProperties`, `unevaluatedProperties`, `propertyNames`, `minProperties` and `maxProperties` are none of these: they speak of the whole object, which holds every type's fields and values no field names, and those are never wrong. `schema` is the as-written composition (`properties`, the winners' `required`, `allOf` of the rules; what is empty is left out) for the check a later slice makes. A level is read from a type's JSON (`ChainLevel(schema:)`) with every `#` reference written out at the reading (`SchemaInliner`, over `SchemaPositions` alone: `enum`, `const`, `default`, `examples`, `contentSchema` and what is no schema are copied as written; siblings win over the target, the target's order kept; a reference to nowhere is dropped; one that leads back into itself or past six deep is dropped and the field's `holdsItself` set; `$defs`, `definitions`, `$schema`, `$id` and `$anchor` are left out of what is written). A `urn:uuid:` `$ref` (another type, bare or into a part of it) is kept as written: a bare one is "another type's fields", one with a fragment gives no rows (rows read it as Other), and the check answers both with the type's own composed schema. `Resolved.Field.field.schema` is a `SchemaValue`, so a group's rows and a type's card have their order.
- The field book (`FieldBook`, `editor.fieldBook`, an `EditorService` registered right after the index; it reads nothing as it is made, so `typeIndex10k` does not see it): `fields(types:)` (and `fields(of:)`, a record's `is` list) is the chain's `Resolved` for a list, resolved once for each distinct list as the shape holds it (the same types in another order are another list: the order decides who wins) and kept while `revision` (the index's `chainRevision`) stands. A list is resolved when first asked, never eagerly, so a type's edit costs the lists asked afterwards, not all: each valid keystroke in a type's Schema tab drops every kept list (the plan's named risk, held by `Budget.fieldListsResolved`'s second figure). A type's own note asks `fields(types: [itsID])`, the list an instance of it asks too. `members(of:)` gives the fields a group holds in order (its `properties`, its own `required`) or, for a field that is a bare `urn:uuid:` `$ref` to a type, that type's fields with their own sources, inherited first (empty for a type that is gone, a part of one, a pointer, anything else; a `$ref` with `properties` beside it shows the type's only), and `item(of:)` the field for a list's `items`, named "" (nil for none and for tuples); both are given a `Resolved.Field`, so slices that unwrap a schema (a "may be null" dropped) can ask of what they built. `ChainBook` (internal) is the catalog under it: each type's level read once per text through `SchemaReadings`' `shownRoot`, so a type whose JSON is broken mid-edit keeps the rows of its last good JSON (this session's: a file opened with a broken schema has none until it's mended, and undo back to a good text is that text's rows) and a type whose text was never an object has none; `prune()` forgets the levels of shapes no longer types. `resolutionsMade` (debug builds) counts resolutions, as `TypesPlugin.schemasRead` counts reads. It keeps nothing per shape or per board, so it hears a board switch with no change set (`boardDidChange` empty; the default would work one out, which BoardsTests refuses of every shipped service) and follows a file put in place through the index's stamp. A type that is gone, its name and its color are the index's, not the book's. Nothing here draws; the check is [Checks](#checks).
- The sync: `TypeSync<Schema>` (`editor.typeSync` for a type's, `TypeSync<TypeSchemaProperty>`) keeps a shape's words and a `SyncedSchema` property (one whose value is a `SchemaText`: the property it writes, the prompts it sends, `SchemaSyncPrompts`, its update step's name, and whether the shape's name is the schema's, `namesTheShape`) in step through `editor.languageModel`, as the schema card's did: only the person's edits sync (not its own write, a board read again, a move, a lock, a rename, an agent's write, `ChangeSet.byAgent`, which is taken as in step), on a commit (editing the words ended however it ended, `editingDidEnd`, an edit still waiting committed the next turn; ⌘↩ or the keyboard leaving in the panel's JSON) or 3 s after the last (`TypeSync.idleDelay`, `editor.scheduler`), the wait held while the JSON's completion list is open (`completing`); words that changed rewrite the schema (whole: past 34 KB never sent, "Schema too long to rewrite", `TypeSyncFailure.tooLongMessage`), else a schema changed in meaning (its root `"title"` left out of the comparison) rewrites the words; never for text that isn't a JSON object, a read-only shape (`editor.isReadOnly(inFile:)`, asked as the sync starts and as an answer lands), a shape with no fields and no words, or without a model. A shape seen for the first time is in step, but words over a schema with no fields, never answered, are ahead; a shape the person makes a type (`/is-a type`) waits as an edit does, so the next commit asks for its schema. The name: the type's title goes in as the root `"title"` of each schema sent (`TypeNaming.titled`, unless the schema has one the person typed), the model's comes out of what it writes back (`TypeNaming.untitled`), and an untitled shape is named by it in the same step. While a call is out the side it writes is read-only (the JSON, `detailUpdating`; the note's editor, read-only and faint, showing what lands); its answer is dropped if that side changed. Its write is a step of its own ("Update Schema", "Update Text"), on the shape's board shown or not (`transact(on:)`), the words through the kind's `TypeWords.write`; undo and redo start nothing (`restoredStep`) and the pair last synced goes back with the steps (`UndoParticipant`). Its status (`TypeSyncStatus`, `TypeSide` `.words`/`.schema`, `TypeSyncFailure` and its remedy) shows under the JSON ("Updating schema…", "Updating text…"). What it asks is `SchemaPrompts` (the file name, constant names and prompt literals byte for byte, since `scripts/schema-prompts` parses them; they still say "prompt" for the words): Haiku 5.5 at `medium`. The model never sees an id: each type the texts name is `@` and a word (`SchemaReferenceNames(words:schemas:name:isType:)`), a mention of a type its word and a `$ref` that word as its URI; a mention of a shape that isn't a type reads as its label, words. A rewrite of the words that reads like a preamble, a fence or `NO_CHANGE` inside text is unusable, unless the words it replaces read so themselves (`SchemaPrompts.parse(_:_:words:)`): a note that begins "Here are the fields" is a note.

## What rows, cards and the panel share

The vocabulary the rows, the card, the panel's Fields section and the check all speak, in `Sources/Types`, so they cannot disagree. All pure but the services; each file is small.

- `FieldPath` (`steps`: `.key` by the field's key, never its title, `.index` by the *stored* index; the list is dense, empties are pruned, so a card maps its display line to the stored index by counting the non-blank lines before it): `field`, `parent`, `isPrefix(of:)` (equal counts), `isRoot` (a problem across fields), `pointer` (JSON Pointer's escapes), and `init(violation:)` from a `SchemaViolation`'s path (the root is `FieldPath()`; `FieldPath([])` is ambiguous). `FieldName`: `words(of:)` is the field's own `title` trimmed of surrounding spaces, else its key in lower-case words (`lineItems`, `line_items`, `postalURL` is `postal url`), `stepName(of:)` the undo step of every write of that field, whatever the surface: `Change Line Items`. `FieldWords`: every string a row, card or panel says (`add gift note`, `No fields`, `+12 more`, `from Person`, `from 2 types`, `4 fields`, `2 items`, `edited as JSON in the panel`), beside `FieldKind.typeLabel`'s.
- `FieldKind` (`FieldBook.kind(of:)`, a pure function of the field's schema: it reads no other type, so a gone type still reads as `typeFields(target)`; a reader that wants it often keeps it): the first that fits, after a "may be null" is dropped: `holdsItself` is `other`; a pointer (`type: string`, `contentMediaType: "text/x-canvas-link"`, `contentSchema.$ref` a bare `urn:uuid:`; an array of them is `pointers`); a bare `urn:uuid:` `$ref` is `typeFields` (a fragment is `other`); `enum` of scalars or a `const` is a choice (a non-scalar one is `other`); an array (`choices` for `uniqueItems` over an `enum`, `pointers`, `listOfTypeFields`, `listOfGroups`, `list(of:)`, else `other`: no `items`, tuples, `prefixItems`, a list of lists); an object (`group` for `properties`, then `other` for `patternProperties`, `allOf`, `not`, then `pairs` for a plain `additionalProperties`); `boolean`, `integer`/`number`, a `date` format as `date`, a `date-time` one as `dateTime`, any other string as `text`; two branches (a `type` list, `anyOf`, `oneOf`) each a kind but `other` as `either`, three or more `other`; anything else `other`. `hasMore` is whether a row on a note ends in `›` and opens a card (everything but `plain`, `pointer` and an either of those); `opensOnType` is the type's note's own column, board 5 panel 7 cell for cell (`Choices`, `List of Text` and the links have no `›` there). `typeLabel(memberCount:)` is the kind's words on a type (`Either` past 22 characters or with a branch that is not plain). `field(at:types:)` names the field of a value path (`members(of:)`, `item(of:)`, `pairValue(of:)`, an either's first branch that has the step), `branches(of:)` an either's.
- `FieldValues.value(at:)` and `setting(_:at:)`: the pruning rule at any depth (setting empty takes the element out and the rest shift up; an index at or past the count appends; a parent that holds the other shape of value is replaced, but removing from under one changes nothing, and a path that starts with an index changes nothing). `keys(unnamedBy:)` is the members no field names, the panel's dimmed values.
- `FieldText`: what typed text is stored as, and how a value shows; every function takes a defaulted `locale:`. A number is stored as one only when it reads back as typed (`9.50` is 9.5, `12.00` is 12; `02134`, `1e3`, `1.`, `-`, a 17-digit id are text); a date is a full date however it is written (`2026-03-03`, `Mar 3, 2026`, `3 Mar 2026`, `3/3/26` in the locale's order), stored `2026-03-03`, and in a `dateTime` field (`format: date-time`) as UTC midnight, `2026-03-03T00:00:00Z`, which a date-time format check accepts; both forms show as the day; a part of a date stays text; nothing is refused. The locale's formatters are made once per locale and kept (a `DateFormatter` costs far more to make than to use), since rows draw dates every frame in view. `shown` of a value of another JSON type shows it as its own type would (the check is what calls it wrong). `value(from:asOneOf:)` and `shown(_:asOneOf:)` are for a field that takes either of two plain kinds.
- `FieldSummary.of(_:field:in:types:)`: what a row with more in it reads (a group leaves out a member edited as JSON: a sentence is not a value) (`empty`, `value`, `items`, `count`, `pair`, `json`; `pills` is slice 14's), `text` the same as one string. `FieldCheck`, `FieldProblem` and `FieldClass`: the check's answer as a value (`mark(at:)` the worst at or under a path, `problems(at:)` exactly there, `leaving(out:)`). `RowList` (`init(_:own:)`, `count(of:own:)`): nine fields or fewer all show; past nine, two rows or more inherited (introduced by a type not on the shape's own list) fold into one `from Person` row in the place of the first, and of what is left nine or fewer show, else eight and `+N more`: a fold shows only when it hides two rows or more, so a note has at most ten rows.
- The services other tracks fill started as stubs, each registered after `TypeSync`, each with an empty `boardDidChange` in its `EditorService` extension (the default works out a switch's change set, which BoardsTests refuses of every shipped service), each reached through an accessor (`editor.fieldWriter`, `fieldChecks`, `fieldCards`; nil without `TypesPlugin`): `FieldWriter` is [the one writer](#the-one-writer) and `FieldChecks` the check ([Checks](#checks)), neither a stub now; `FieldCards.open` answers false; `FieldForm` shows the summary and `›`. `FieldCardRequest` is the card's whole request, a public init with `folded` and `rowRectNow`.
- The shared fixtures are `FieldFixtures` in CanvasTesting (strings and fixed ids only, so every test target reads the same: Person, Address, Employee, Order as board 5 draws them, `everyKind` with nine fields in each of two types, `wide(_:)`); `fieldEditor()` in TypesTests (a free function, also `FieldFixtures.fieldEditor()`) puts them in an editor (Employee a Person). The gallery's states are one array a track (`rowStates`, `valueStates`, `cardStates`, `checkStates`), beside the look's.

## The one writer

`editor.fieldWriter` (`FieldWriter`, `FieldWriter.swift`) is the only thing that changes a shape's `fieldValues`: a row, the card, the fold and the panel all go through it, so a field is changed one way and its step is named one way. Called from key and mouse handlers, never inside a transaction or while an undo is applied (`transact` refuses both).

- Its door. `set(_:at:of:step:)` (`setTyped` is `set(FieldText.value(from:as:), …)`, `remove(at:)` is `set(nil, …)`), `rename(_:to:under:of:)` (a pair's value moves to its new key in one commit; false for an absent, empty, same or taken name and for the root) and `removeUnnamed(_:of:)`. All five end in one `apply`: a path that starts with no key (the root included), a shape not on the board shown and a kind that is not `typeable()` are false; a shape that can't change is `editor.refuseChanges(to:)` (services hear it, Selection shakes it) and false, before any transaction, so no empty step; else one `transact` with one `update` of the record. A write that changes nothing is true, and `Transaction.update` keeps a record only if it differs, so there is no commit, no step, and what there was to redo stays. `editor` is internal: the panel builds a `FieldFormContext` from it.
- Its steps. `.ownRun` is named `FieldName.stepName` of the field the key names on the shape's types (`Change Shipping Address`; a key no field names by the same word split, `Change Nickname`) and coalesces by `FieldRunKey { shape, field }` of the top-level field: typing in one field, however many commits and at whatever depth under it, is one step; another field, `UndoHistory.seal()` (the host seals on every mouse-down and move of the keyboard) or a commit from elsewhere ends the run. `.card(key:)` is nameless and joined by the card's key. `removeUnnamed` is `Remove Nickname` (the key's words, capitalised) and never coalesced.
- Slice 15 sets the title in the same `update`; nothing else belongs in it.
- TypesTests' `fieldWriterTests` hold the door, the steps and runs, pruning, the no-op, the refusals (frozen, another board, no values, no key), `setTyped`'s forms, `rename`, `removeUnnamed`, the title's name and a field taken out of its type; `Budget.fieldKeystroke` ([benchmarks](benchmarks.md)) holds a keystroke to one commit on one shape.

## Checks

What a note's values are checked against, and what the check says. The whole answer is a `FieldCheck` (above); `FieldChecks` (`editor.fieldChecks`) makes and keeps it; two rules in `TypeValidationPlugin` and the word `:incomplete` read it. Needed is amber and is no issue (no ring, no Issues line, no table-of-contents dot, not `:invalid`); wrong is red and an error.

- The one pure part is `FieldChecker` (internal; one for each distinct list of types, over a `FieldBook` and a `TypeIndex`, no editor): it runs the core's validator (`SchemaValidator`, `formats: .standard`) over the list's composed schema without its `allOf` (`main`) and over each type's rule object (one validator each, so a problem on the root names the rule's type), each made checkable first, and says each violation as a problem of a class. A `$ref` to a type is served by a resolver (`Resources`): `urn:uuid:T` is T's checkable resolved schema with T's own root `$defs` and `definitions` laid in (read from the last good JSON), so a ref with a fragment and the `#/` refs inside are checked too; a type that is gone is served as nothing and recorded as gone (a type that comes back makes the checker stale). `isCurrent()` re-reads the list's resolution and each served input and compares them: an edit that changes nothing the check reads (a root `description`, whitespace, text broken mid-edit) leaves the checker and every answer it made standing.
- `FieldSchemas.checkable` (public, pure) rewrites a schema on a copy, at every place that holds a schema: T1 drops a `pattern` or a `patternProperties` entry ICU cannot read (the type's fault, not the note's); T2 drops `additionalProperties`, `propertyNames`, `patternProperties`, `unevaluatedProperties` and `maxProperties` from an object with `properties` (a value no field names is never wrong, at any depth; `minProperties` stays, as an unnamed member can only help meet it), and T2b an `additionalProperties: false` from anywhere (a pairs field's schema `additionalProperties` and its counts are its own rules); T3 turns `dependentSchemas` into an `if/then` (the core ignores it); T4 rewrites an `if` that has `properties` into `{if: presence, then: {if: X, then: T, else: E}}`, so a condition asks only once the fields it tests have values (an empty Order is not asked for a gift note, and its `else` is not applied to a note that never said; an `if` with only `required` is the author's); T5 turns an `anyOf` or `oneOf` of required-only branches into "if none holds, ask for every field of them" (and for a `oneOf`, the author's `oneOf` only when one holds, so two is the validator's own violation at the node). Limits: an `if` through `anyOf`, `not` or `$ref`, and an applicator's branch under an object that has no `properties` of its own, keep the validator's reading.
- Classes. `required` and `dependentRequired` are needed, at the missing member, dropped when no field is there (a name no type has, a path under an `Other`) and for a yes or no (an unticked box is a value); inside an absent group nothing is asked. `type`, `enum`, `const`, the bounds, lengths, `pattern`, `format`, the list limits, `minProperties`, `propertyNames`, `not`, `anyOf`, `oneOf` and `false` are wrong, at the value's path (the list's, the object's, the member's); a path no row has is clamped to the deepest row above, and dropped when even its first step names no field. A needed list is needed while empty (never `minItems`: an empty list is no value); one filled short of `minItems` is wrong. A violation at the root is a rule across fields: wrong, keyword `rule`, no row. `$ref` (a gone type, a loop) is dropped. Problems are deduped (a field asked for by the root and by a rule is one; two wrongs at one path are two), capped at 100 keeping at least one of each class (so `isWrong` and `isIncomplete` never change), and sorted by row, then path (a key by its text, an index by its number, the root last).
- Words (`FieldCheckWords`): a wrong problem is its place and the validator's own tail (`line items › Plate › quantity is 0, and should be at least 1`: one wording across the app; the place is the rows' names, an item named by its first plain value cut to 24 characters, else `item 2`, a pairs key as written), a needed one `<place> is needed`, a root one `Order rule: the note <tail>`, a refused pair name `labels › Size 2 isn’t a name labels allows`. `SchemaViolation.detail` is the tail.
- `FieldChecks` (`@Observable`, `revision` is what a view tracks; an `EditorService` in an extension with its own `boardDidChange`): `check(of:)` is the answer with `typing`'s path left out, `fullCheck(of:)` the whole (queries); both `.clean` for no `is`, a type's own note, an opaque shape, and a list none of whose types is a type. It keeps one `FieldChecker` for each distinct list (at most 1,024, then all dropped) and one answer for each shape asked. An answer is never invalidated; it is trusted while the record's own list and values are the ones it was made from (two compares that end at the storage's identity) and its checker is current (`FieldBook.revision` against the checker's stamp, rebased when a re-read finds it equal). A note with no values takes the checker's one check of no values, kept with the rename count it was made at: one that holds a root problem (a rule across fields that fails on an empty note) says its rule's type by name, so a rename makes it again. `documentDidChange` reads no record and checks nothing: it forgets what left the file, moves `revision` if a changed shape has an answer (a move changes no answer), and clears everything for a document put in place.
- `typing` (`(shape, path)?`): set by whoever has the caret in a field when it gets it and cleared by them when it leaves, one at a time. The field's path and below are left out of `check(of:)`, so a half-typed value is never red and never rings. Setting it moves `revision`, has Validation check the old and the new shape again (`ValidationEngine.recheck`) and redraws. It is also cleared when its shape goes from the file, when that shape's editing ends (the ring is Validation's, drawn once editing ends) and on a board switch or a file put in place; a board switch tells Validation too (`recheck`), which files the shape under the board it keeps, so the answer stashed with that board, made with the path left out, is made again when the board is taken back.
- A type's change reaches shapes through `TypeIndex.onChange`, which runs after the index has taken the commit in (a rule's `affected:` would hear it first, from an index a commit behind): if only names changed (`chainRevision` stands) only the answers that name a type (a root problem) are checked again, so a rename costs what its chips do; otherwise `TypeReferences` (the types each type's text refers to, both ways, a gone target kept so its return reaches the types waiting for it) is updated, and the reached set is the changed types, their instances, the types that refer to them, and so on to a fixpoint; Validation is told with `recheck` (and the table of contents rows are made again), but not of an instance whose answer's checker is still current once asked (the edit changed nothing the check reads of it: a description, whitespace, a field it doesn't have) and whose answer names no type: each reached list is made current inside the commit and the instance keeps its answer, so an edit that reads nothing costs the types alone (2.7 ms over 10,000 instances, against 57 to 73 when all were named). Which shapes are reached matters only to Validation: the answers are found stale by themselves. `goneReferences(of:)` is a type's refers-to-a-gone-type list.
- The rules (`TypeValidationPlugin`) have no `affected:`: a wrong value is an error with the problem's message and the row's key as `field` (nil for the root); a type whose JSON refers to a gone type carries a warning, `Refers to “Address”, which is gone.`, never the instances. Draw's check is lent no editor, so these say nothing there until slice 16.
- Not here: a pointer's problems (slice 14), `--ask` and draw learning the check (16), a title from a field (15), the Issues tab refreshing when a caret leaves a row (the ring and the dot do, immediately; the tab on the next time the panel is made).
