# Schema cards

Schema cards: a JSON Schema kept as text with its description in words, kept in step by the model; references between cards, the panel's JSON and its completions, highlights, and their tests.

Related: [language models](language-models.md), [mentions](mentions.md), [detail panel](detail-panel.md), [text editing](text-editing.md), [editing](editing.md), [connections](connections.md), [titles](titles.md), [validation](validation.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Schema cards](../../docs/plugin-system.md#schema-cards).

## Architecture

- Schema cards (Schemas, a vertical; `docs/plugin-system.md`, "Schema cards"): a `SchemaCard` (kind `schema-card`, the Schema tool, S, `curlybraces`) is a JSON Schema kept as its text (`schema`: order and half-typed text survive) and what it holds in words (`prompt`, its description, mention text of other schema cards, `SchemaPromptText`), named by its root `"title"` (a derived title, `x.title(symbolInPill: true) { … }`, never Titles' `TitleProperty`, so it's said in one place; `setTitle` rewrites only that member), which its title's pill shows (`TitlePill`) after the kind's `{}` (`curlybraces`, its tool's symbol), as a note's pill shows a note's name; an untitled card has no pill, as an untitled note has none. The card is white, with a note's corners (`SchemaStyle.cornerRadius`, 4), and shows its description, set as a note's text is (16 points in 19-point lines, 16 in from its edges: `SchemaStyle.text`, a `MentionTextStyle`, `SchemaCardMetrics`), each mention a pill (`drawMentionText`, its placement `mentionPlacement`, so pills are faces), and nothing of its schema, which is its panel's; with no description it's blank, and it has no hue (the kind's magenta is its row's symbol and its ports' dots). Its description is typed on it (`Editable`: `SchemaDescriptionEditor`, a `MentionTextView<Only<SchemaCard>>` laid over the card as a note's editor is, its lines and pills on the render's, `SchemaStyle.editorInset`; `@` lists the file's titled schema cards, every board's, the card itself too): the Schema tool places a card being edited (an editing placement, so placing and typing are one step, "Add Schema"), and Return, a double-click or a click on the only selected card edits one; Return is a new line, as in a note; ⌘↩ or Escape is done and ends editing (read-only too, while the model writes the description: `EditingTextView.commitsWhileReadOnly`), and so does the keyboard going to a view outside the canvas (the panel's JSON, heard through `onLeave`). Its description's words are highlighted where they say a part of its schema (`SchemaHighlighter`, asking Sonnet 5.5, `SchemaPrompts.highlightsModel`, once the card is drawn in full and in step; answers kept by the pair's text, `SchemaHighlightAnswers`, never saved): a field's pale blue, a rule's pale amber, filled by the render under its text, also while it's edited (the editor draws no background), where the canvas draws the words, pills and all (`MentionTextStyle.lineRects`; the model's words found in the description as it read it, each mention `@` and its word, then moved onto the drawn text, a word its pill: `SchemaModelText.shownRange`), and resting the pointer on them, on the canvas (Selection's `ShapePopovers`) or in the editor (`EditContext.hoverPopover`), shows that part of the schema in the core's popover (`CanvasPopover`, `editor.hoverPopover(_:)`: shown after `Style.popoverDelay`, 500 ms, at once while one shows or just went; a press, a key, the camera, editing or another board takes it down; `CanvasView` hosts it over everything, taking no clicks), colored as the panel's JSON (`DetailStyle.code(_:spans:)`), or, for words that say a `$ref` to another card, that card's schema (the part its fragment points to); the evals are `scripts/schema-prompts/highlight_evals.py`. Write the description only with `setPrompt` (`prompt` is `internal(set)`), which fits the height to it at the card's width in the same transaction (a note's measure, `SchemaStyle.fittedHeight`, pills by the names they hold, a line at least: a new card is 240 × 52; the editor's `setPrompt(_:shown:)` measures its text as it shows it); the editor writes it with each change, the card growing in the typing's step, and grows a card too short for it as editing begins; the width is the person's; a card made from properties, or given a description that way (`canvas draw`, `registry.shape(_:setting:)`), is fitted too (`DerivedProps`), and placed at that height, unless `size:` says otherwise. The schema is a plain `var` (`SchemaText`, one string in a board), and sizes nothing. References: a card refers to another's schema with a `$ref` to its URI, `urn:uuid:` and its id, lowercase (`SchemaReferences.uri(of:)`; read in any case, whole or with a fragment, `target(of:)`), so it survives a rename and finds a card on any board of the file; `SchemaText` is `ShapeNaming` (each `$ref` to a card anywhere in the JSON, `SchemaReferences.refs(in:)`, found only in text that says `urn:uuid:`), so a copy of a card with the cards it refers to refers to the copies, in its schema as in its description, and one alone to the originals, a cut and paste keeps them, and `canvas draw` warns of a `$ref` to a card not in the file; a mention in the description says in words what a `$ref` says, and the sync writes one from the other (a `canvas draw` script writes the mention as `@[Title]`, the card called that, and the `$ref` by id: [command line](command-line.md)). The model never sees an id: each card a card's texts name is `@` and a word of its name (`SchemaReferenceNames`: its words run together, each after the first capitalized, only letters, digits and `_`, a number for a second card of one word; `@LineItem`, `@Address2`), a mention that word, a `$ref` that word as its URI (a fragment kept), each named as the card is now (else as its mention holds it; a `$ref` to a card with neither stays as written, and a mention of a shape that isn't a schema card is words), listed first in the request (`<schemas>`), and what it writes read back: a `$ref` to a word the card's URI, an `@` and word (any case, the longest, not inside a word) a mention of its card, named as it is. What the prompts say of other schemas (`toSchemaReferences`, `toPromptReferences`, `highlightsReferences`) goes after them only for a request that names some, so a card that names none is sent exactly what it always was (the evals held that: added to every request, the same words cost three old cases). In the panel, ⌃Space at a `$ref`'s value lists the file's other titled cards by their titles (`SchemaSync.referenceTargets(from:)`, `SchemaCompletions.completions(in:at:cards:)`, asked only there), each written as its URI. A card is mentionable (by its title, in its magenta; an untitled one isn't offered), so its panel has the Mentioned In tab (the cards whose descriptions mention it) and its menu Show What Mentions. `JSONReader` reads JSON in order, with ranges, line and column, tokens, and a depth limit; `SchemaDocument` reads the title and the top-level fields, and each `SchemaField` its type and fields a level at a time (`$ref`s within the document, bounded). `SchemaReadings` keeps a reading per card and text, read again only when the card's text changes (its name, row, rules, header and sync read the one text; drawing a card reads none); a card keeps up to 4 texts' (`versionsPerCard`: ids are unique within a file, not across files, so a file duplicated in Finder and opened beside its original has the same cards, and each window's reading stays beside the other's; typing adds one, the card's used longest ago going); the sync drops a card's once it's deleted or its board is read again, and past 4,096 those used longest ago go (`SchemasPlugin.schemasRead` counts reads in debug builds). Zoomed out the card is its skeleton (SchemaSkeleton.swift: white with a light gray edge half a view point inside its frame (`SchemaStyle.skeletonEdge`) where its shadow showed, square, no shadow, and its description greeked as a note's text is, each mention as wide as its pill, the core's `SkeletonTextBars`: three fills, its name Titles' cover over it, and its outline its frame's). While a card's text isn't a JSON object, what it shows of it is its last reading that was (`shown`, since its board was read): its name, its row and badge, its panel's header, so typing doesn't flicker (Validation's outline says it's broken); what acts reads the text (`document`: the rules, the sync, the colors, a rename). `SchemaCard.untitled`, "Untitled", is its name in its header and its row. Its panel is where its schema is written: the header renames the root `"title"` (`setTitle`; dimmed while the model writes the schema, text, not a field, `isRenamable: false`, while the text isn't a JSON object), over the count of its fields (none for none); the Schema tab has the JSON (a `DetailCodeEditor` colored by `JSONReader.tokens`, the token where it stops being JSON marked, with the card's Validation issues under it, a status line each, in their words and tones). `SchemaSync` (`editor.schemaSync`) keeps the two in step through `editor.languageModel` (`SchemaPrompts`): only the person's edits to the two sides sync (not its own write, a board read again, a move or a lock, nor an agent's write, `ChangeSet.byAgent`, `canvas draw`'s, which is taken as in step), on a commit (the card's description done, editing it ended however it ended, which services hear, `EditorService.editingDidEnd`, an edit still waiting then committed the next turn, so an undo, a draw or a file put in place that ended it asks nothing; ⌘↩ or the keyboard leaving in the panel's JSON) or 3 s after the last (`editor.scheduler`), the wait starting only once the JSON's completion list closes; a changed prompt rewrites the schema (whole: past `SchemaPrompts.toSchemaMaxLength`, 34 KB, it's never sent, and the status says `SchemaSync.tooLongMessage`, "Schema too long to rewrite"), else a schema changed in meaning rewrites the prompt; never for text that isn't a JSON object, a read-only card (locked, in a locked frame, or on a locked subboard's board, on whichever board it is: `editor.isReadOnly(inFile:)`, asked as the sync starts and as an answer lands, so a lock that lands while the call is out drops the answer, writing nothing and refusing nothing), an empty new card, or without a model; a card first seen is in step, but for a prompt over a schema with no fields, which was never answered; the side being written is read-only (the panel's JSON `.detailUpdating`; the card's description, typed into, read-only and dimmed as mention text is, `MentionTextView.showEnabled`, showing the answer once it lands) and its answer dropped if it changed; edits to the other side sync once it lands; `NO_CHANGE` (the first word, or the last line) writes nothing. Its write is an undo step of its own ("Update Schema", "Update Description", with the pair it leaves in step), on the card's board whether it's shown or not (`transact(on:)`: it keeps every card of the file, so a card's commit, timer and call go on while another board is shown, and undoing an answer that landed there shows its board; a card whose board goes with its owner drops its call, and a file put in place takes every card afresh); undo and redo start no sync (`ChangeSet.restoredStep`) and drop a changed card's timer and call, and the pair each card last synced goes back with the steps, for the cards a step brings back or changes (`SchemaSync: UndoParticipant`). Its status (`SchemaSyncStatus`: "Updating schema…" or "Updating description…", or a `SchemaSyncFailure`, a fragment in the warning's tone, red being the schema's own errors: the model's error, "Claude declined", "Unusable answer", or too long to rewrite for a schema cut off; with its remedy: Retry, Open Settings… alone (saving a key retries), or `editByHand`, no button, where asking again would repeat the answer: a schema cut off, or Claude declining) shows under the JSON, whichever side it writes, and a key saved in Settings retries the cards that failed for want of one. The quick evals are `scripts/schema-prompts` (they read the prompts, their settings, the model and the starter out of the Swift). Validation: not JSON ("Invalid JSON: expected a value at line 1, column 1.") or not an object is an error; `required` naming no property, or a `type` that isn't JSON Schema's (read as written, `SchemaFieldType.unknown`), a warning. Validation messages are short sentences with periods; process status (the sync's, Settings') is fragments without. The table of contents' badge is the top-level count. Ports on all four sides, on a channel of its own (`SchemaLink`, `schema-link`), as notes have theirs: a schema links to a schema or to a subboard, which takes every channel. Its JSON completes as VS Code completes a JSON Schema: ⌃Space (⌥⎋, F5) in the panel's JSON lists what can be typed at the caret, the code editor's `completions:` (`SchemaCode` maps the card's into `DetailCodeCompletions`, candidate for candidate), each keyword with its description, and a pick is typing, one step of the "Change JSON" run that the sync hears as the person's, reopening where it leaves the caret among more (`type`'s names), the sync's idle wait held while the list is open (`SchemaSync.completing`, from the editor's `onCompleting:`: a pick that reopens leaves whole JSON waiting for a value, `"type": ""`); nothing opens while the model writes the schema (`docs/plugin-system.md`, "Completing the JSON"): `JSONCaret.at(_:in:)` reads half-typed JSON leniently and says where a caret is (the path, a key, a value or an element, what's typed and what a pick replaces, the members around it, a missing comma), and `JSONCompleter`, generic over any JSON Schema, walks the schema along that path (`patternProperties` read as the validator reads them, `SchemaValidator.regex(for:)`) and offers the object's keys (in the schema's order, described, none deprecated or there already) or the place's values, each written as it goes in (a key with a value to type into, commas, `reopens`), and matches nothing against what's typed (the list does). What it knows of JSON Schema is data, `MetaSchema`: the 2020-12 meta-schema flattened, its keywords in the order offered, each described, the type names, formats and encodings as described consts, and `x-canvas-when`, the app's one annotation, which leaves a keyword out beside a `type` it doesn't matter for until something's typed, then ranks it last; `SchemaCompletions.completions(in:at:cards:)` is the card's, in UTF-16, adding in code only a `required` list's names, a `$ref`'s targets (its own definitions, then the other cards), and that `$schema` and `$vocabulary` go only at a root.
