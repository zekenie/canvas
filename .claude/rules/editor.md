# The editor

What `CanvasEditor`, the headless core, lends every plugin: how a board holds its shapes (a value that costs what a change reaches), labels and symbols, the default tool, outlines and their standoff, read-only shapes, drawing offsets, the glide, skeleton levels, cards, commands (each declared once by its plugin, what it acts on and when) and zoom, shapes placed later, keys, the hand and the middle button, the translation adjuster, service and session hooks and the order services hear a change in, edge scrolling.

Related: [plugins and kinds](plugins-and-kinds.md), [undo](undo.md), [editing](editing.md), [drawing](drawing.md), [keyboard](keyboard.md), [selection](selection.md), [snapping](snapping.md), [locking](locking.md), [boards in a file](boards-in-a-file.md), [types](types.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [The editor, the document, and drawing](../../docs/plugin-system.md#the-editor-the-document-and-drawing), [Outlines](../../docs/plugin-system.md#outlines), [Skeletons](../../docs/plugin-system.md#skeletons).

## Architecture

- The document's storage (the core's, `ShapeStack.swift`, `ShapeMap.swift`, `CanvasDocument.swift`; [the guide](../../docs/plugin-system.md#the-editor-the-document-and-drawing)): a board is a value that costs what a change reaches, never what it holds. `document.shapes` is a `ShapeStack`, a `RandomAccessCollection` of `AnyShapeRecord` (`Int` positions, the bottom shape first, `Equatable`, `Sendable`, `ExpressibleByArrayLiteral`), held in chunks of 128 records (`ShapeStack.chunkSize`; debug builds', the tests', is 4, so a few shapes meet every edge between chunks, as `ShapeMap`'s shards are 4 to 16 entries there) in an array of them, each a Swift array that is copied when written to while another copy holds it, with a table of where each shape is (`ShapeMap<Int>`: a dictionary in shards, the shard picked by the id's `ShapeID.spread` bits and not by hashing it, a power of two of them, the map spreading over more when it has grown fourfold, so a shard holds some 128 to 1,024 entries). So a copy shares every chunk and shard with the board it was made from until one of them writes, and a write copies the list of chunks (782 references at 100,000 shapes), the one chunk it reaches and the one shard its shape is in: a shape changed in place (`replace(at:with:)`: a keystroke, a drag event's moves, undo and redo of those) or put on top (`append`) costs that, a shape moved in the stack (`move(from:to:as:)`) the chunks between where it was and is, each passing a record on to the next, a block of shapes (a container restacked with what it holds, `move(_:above:as:)`) the chunks from the first place that changes to the last in one pass, a removal or an insertion below the top (`remove(_:)`, undo of one, `replaceSubrange(_:with:departing:)`, `CanvasDocument.apply`) the stack from the first shape it moves to the top, each shape whose place changed written again in the table (linear in what is above it, as an array's removal was), and every chunk below stays shared. The cost of a commit is therefore what the commit changes and the list of chunks, never a copy of the board: what it holds of the board it began from (`ChangeSet.priors`, which `before(_:)` reads), every board an undo step reached whole (`DocumentDelta.boards`) and a transaction's `contents(of:)` are such copies, sharing what the commit did not write, and releasing one frees the chunks it alone held. `==` on two boards passes over the chunks they share (`CanvasDocument`, and `ChangeSet(from:to:)`, which compares only the chunks two boards do not share, `ShapeStack.differences(from:)`), so a board and the one a few commits made from it compare in the chunks those wrote. `CanvasFile` keeps which board each shape is on (`locations`) in a `ShapeMap` too, so a commit that adds or removes shapes writes one shard per shape and not a table of the whole file, however many copies of the file a query or a save holds. Reading: `document[id]` and `index(of:)` are constant time (a shard's lookup and a chunk's); `shapes[i]` and walking `shapes` with `for` copy a record out as an array's do (a pass over every shape that reads a field or two of each, as the core's settling and letting go of a deleted shape do, goes through `shapes.forEach { … }`, which lends each record in place); whatever needs an `Array` makes one (`Array(document.shapes)`, which costs the board, as `sorted` and `filter` do); a slice (`shapes[a..<b]`) is a view of the stack, not a copy of it. `shapes.sharedChunkCount(with:)` and `chunkCount` (host SPI) say how much two boards share, for the tests and benchmarks that hold a commit to what it changed. CanvasTests' `ShapeStackTests` hold it: boards from 0 to 41 shapes (the edges between chunks) reading as the lists they were made from, a seeded run of 260 commits of every kind (insert, in-place update, delete, every restack, undo and redo in bursts) after which each place, each lookup and each way of walking the board agree with a list, and each undo and redo restores the records exactly; a board holding what it was while the editor's changes; a commit sharing all but the chunks it wrote with the board before (a shape changed in place, three far apart, one put on top, an undo, a shape near the top brought to the front, a deletion), a document put in place naming what differs from the one it replaces whether or not the two share shapes, and the file's table following shapes put in, deleted and moved between boards; BenchmarkTests' `StorageBenchmarks` hold a commit of a few shapes to `Budget.storageCommit` and to costing no more on ten times the shapes.

The service keeps a cursor with the `runID` it read and applies `changes[cursor...]` on the next ask, so a run of n shapes settled one at a time costs n applications and not n squared; a different `runID` is a log to read from its start. The core names no shape and no plugin in it (CanvasTests' `layoutReadingTests`).
