# Slash commands

Slash commands: a line of a shape's text that runs a command the shape offers; registering and offering them, the list at a `/`, Return, undo, and hosting them in a text view.

Related: [text editing](text-editing.md), [mentions](mentions.md), [titles](titles.md), [locking](locking.md), [context menus](context-menus.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Slash commands](../../docs/plugin-system.md#slash-commands).

## Architecture

- Slash commands (SlashCommands, a surface, on TextEditing; `docs/plugin-system.md`, "Slash commands") let a line of a shape's text run a command the shape offers: a `/` typed on an empty line lists them, and a line that is `/name` and what the command takes, entered with Return, runs the command and goes from the text, leaving only what the command did. A command is contributed as a context menu item is (the `ShapeSlashCommands` point, keyed by target and name): `x.slashCommands { SlashCommand("turn-on", when: { !$0.isOn }) { lamp, _ in lamp.isOn = true } }` over the kind's props, `x.slashCommands(of: P.self) { … }` over an added property's value on the kind's shapes that hold one, `registrar.slashCommands(K.self) { … }` for another plugin's kind, `registrar.slashCommands(of: P.self) { … }` on every shape that has the property, and `registrar.slashCommandsForEveryShape(where:) { … }` over the record, where `where` gets a `SlashCommandKind` (the kind, its definition, the registry and `holds(P.self)`, asked once per kind, so a feature's every-shape command goes only on the kinds that opted into it: `$0.holds(LockedProperty.self)`); a horizontal's opt-in sugar may call these, so opting in brings its commands; the builder is `MenuBuilder`'s. A `SlashCommand<Value>` is a name, an `argument` (the hint beside the name in the list, `"title"` or `"@shape"`, which also says it takes one; nil for none), `when:` (the shapes that offer it, always by default), `accepts:` (which arguments it can run with: by default none for a command without an `argument` and anything but nothing for one with; given, it replaces that rule entirely) and an action in the forms of `MenuItem`'s: `edit: { value, arguments in … }` on the shape's live value in one transaction (setting what's there commits nothing), or `perform: { id, arguments, editor in … }` for what editing can't do (locking, moving, putting somewhere), which changes the document only through `editor.transact`. A name is lowercase ASCII letters and digits, words joined by single hyphens (`set-title`, `h2`: `SlashCommandLine.isName`, what can be typed and completed), else `ShapeSlashCommands.check` refuses the plugin list (`invalid`); two claims to one name for one target (a kind, or every shape) are a `conflict`, and a kind's own command takes the place of an every-shape one of the same name, offered or not. `SlashArguments` is what's typed after the name, trimmed at both ends, adjacent text merged: `runs` (`.text`, `.shape(id, label:)`), `text` (each shape "@" and its label: "near @Groceries"), `shapes` (in order, each once) and `isEmpty`; the module knows no mention, so a pill is a shape only because the host reads it so. Arguments a command doesn't accept leave the line as text and the command never runs (`/lock foo`, `/set-title` given none). `SlashCommandState` (`editor.slashCommands`, a service; nil without `SlashCommandsPlugin`) says what a shape offers now (`commands(for:)`: its kind's own in builder order, then those over a property it holds, then every shape's that its kind lets in, each whose `when` holds for the shape as it is, an `OfferedSlashCommand`; none for a shape that isn't on the board shown or is kept aside) and runs one (`run(_:on:with:)`, or by name folded to lowercase): in `undoHistory.group(title)`, one step named for the command in words (`/set-title` is "Set Title"), none if it commits nothing; false, doing nothing, for a shape that's gone or kept aside, a name the shape doesn't offer now, and arguments it doesn't accept (an `OfferedSlashCommand` is run as it was found, `when` not asked again). It keeps nothing per shape (each kind's commands gathered once, the registry being frozen), so `boardDidChange` is overridden with nothing. A text view takes part by hosting `SlashCommandTyping(over:owner:commands:arguments:)`, which holds the view and the state weakly, belongs to one shape's text (`owner`) and writes the text only through the view: the host tells it what's typed (`didType`), where the text and the caret go (`didChange(isEdit:)`) and asks it first about each key (`takesKey(_:)`, a plain Return), and shows its list as its own (`caretListWindow` returns its `window`), so the list's keys and its closing as the keyboard or the window goes are every caret list's (TextEditing's); `arguments` reads a range of the text as runs (default: plain text). It marks the command as it's typed, as a mention's pill is marked (`EditingTextView.highlights`, in the text's own color so it follows the surface, `SlashCommandStyle.commandFill` 18% and `argumentsFill` 8%, a pill's being 10%): the `/name` on the line the caret is on, while the list lists a command for it (not "No matches") and, with it closed, while the shape offers the command now (`SlashCommandLine.nameRange`), and what it's given in the lighter shade, only if the command accepts it (`/lock now`, which stays text, marks `/lock` alone); so a line Return would run looks unlike one that is only text; nothing is marked in a view that can't be written. A `/` typed (not pasted, not composed, not an undo) on an empty line, at the text's start or right after a line break and with nothing after it, opens the list while the view is editable, no other caret list is open and the shape offers a command; at the start of a line that has text (the line is evaluated whole, so a command chosen there would take that text with it), mid-line, or where nothing is offered, a slash is a slash. The list is `SlashCommandPicker`, headless, built on `CaretList` as Mentions' picker is and shown in a `CaretListWindow` under the `/` (240 wide, rows 24 tall, 8 shown, 4 below, "Commands" to VoiceOver): what's typed after the `/` is the query; an empty one lists every offered command in the order offered, else those whose names it matches ranked with `CaretListMatcher` (best tier first, then as offered), each row the name with its matched characters semibold and the `argument` as its detail, or the one row "No matches" with nothing highlighted; the first is highlighted. It closes when the caret leaves the name (before the `/`, past what was typed, or a selection), the `/` is deleted, what's typed holds what a name can't (whitespace, a line break, a pill, punctuation: ASCII letters, digits and hyphens, matched folded) or is past 40 characters (`SlashCommandPicker.Closing`), and on Escape or ⌘., leaving the `/` as typed; the text's substitutions are off while it's open (`CaretListSubstitutions`). The keys are every caret list's, and Tab, or a click on a row, completes: the `/` and the whole name token it is in (the caret may be in the middle of one) become `/` and the command's name, and a space if it takes an argument and no whitespace follows on its line (a line break doesn't count), one step of the text's undo, running nothing. Return is the list's own: a highlighted command that accepts nothing runs at once if nothing but whitespace follows its name on the line, else Return completes it as Tab does, so its argument can be typed; with nothing highlighted it's a new line, which closes the list. A plain Return (⇧↩, ⌥↩ and ⌘↩ are not) with the list closed, no selection, no text being composed and the caret after the `/` on a line that is `/name` and what follows, where the shape offers a command of that name now (folded to lowercase) and it accepts what follows (trimmed), takes the line's text out of the text, from its `/` to its end but not its line break, leaving the caret at its start on the now empty line, and runs the command; anything else (not a command, one not offered, arguments not accepted) is Return as ever, a new line or a box's commit (a command line runs and doesn't commit; anywhere else commits). The line goes first, as an edit of the person's (undoable, heard by the host through `shouldChangeText` and `didChangeText`, its own steps of the text's undo, its list closed before), because a command that makes the shape read-only (`/lock`) would refuse the text's write after it; the command is asked of the shape when Return is pressed (one not offered by then, or not accepting what was typed, takes nothing out), then run as it was found once the line is gone (`when` isn't asked again, so a command that reads the text still runs). While the shape is edited the line's removal is in the editing session's step and the command's commit closes it, so the command is a step between the typing before and after: the board's Undo takes it back by its name ("Undo Lock"), the typing next, and typing after it is a step of its own; the text's own undo (⌘Z while typing) brings the line's text back and leaves the command done; a command that ends editing (a lock) ends it as the core does. Mentions' `MentionTextView` hosts it (`slashCommands`, made for a view with an owner when the editor has `SlashCommandState`, else nil; its `caretListWindow` is the `@` picker's or the slash list's), so every text where mentions are typed takes slash commands (a note's editor, a schema card's description's, the panel's `MentionTextArea`), a pill in a command line is a shape it's given, the `@` picker's keys come first while it's open (Return picks the shape; Return then runs the line), opening the picker closes the slash list, and `show(_:)` closes both. Mentions contributes no command and needs no `SlashCommandsPlugin()`: the plugins that offer commands do, since the registry refuses a contribution whose owner isn't installed. `SlashCommandsPlugin()` is right after `ContextMenusPlugin()` in the shipped list; it contributes nothing and claims no key. The two commands that ship are Titles' `/title` ([titles](titles.md)) and Locking's `/lock` ([locking](locking.md)).

## Testing

- For slash commands, SlashCommandsTests use fixtures only (CanvasTesting's boxes, discs and cards, and chores' added `Flagged`; `Lamp`, a kind of the target's own that offers commands every way a kind can, its own and over the flag it holds, `LampsPlugin`; `CardCommandsPlugin(log:)` gives cards commands to type: `grow` and `width` edit, `log` and `ping` perform, `wide` is offered only while the card is wide, `any` accepts even nothing; `slashHarness` is an `EditorHarness` with the fixtures and `SlashCommandsPlugin()`): registration (every form of the sugar and the report's summary of each, `where` with `holds`, a kind's own command over an every-shape one, conflicts, the names refused, `ownerNotInstalled`, `unknownKind`), resolution (`commands(for:)`'s order, `when`, a shape gone, off the board or kept aside offering none, `accepts` by default and given, an edit command in one transaction and one undo step named for it, a `perform` command, `run` false), `SlashCommandLine`, `SlashArguments` and `SlashCommandPicker` headlessly (the line breaks, the rows and their ranking, each closing), and the typing object over `SlashTextView`, an `EditingTextView` of the target's own that forwards to `SlashCommandTyping` as `MentionTextView` does, in an unshown window over a card being edited (`SlashSession`: `type`, `down`, `tab`, `returnKey(_:)`, `set(_:caret:)`, `list`, `rows`; its `SlashHost` is the card's editor, writing the text to the board and counting `commits`): where the list opens and where a slash is a slash, narrowing and closing, the substitutions off while it's open and back, completing, Return from the list and on a whole line, what isn't a command being Return as ever, ⇧↩, the text's undo bringing the line back and the board's undo undoing the command by name, a box that commits on Return not committing, and the marks (`view.highlights`: the `/name` while the list lists a command, a line the shape offers with what it accepts in the lighter shade, the caret's line alone, none in a view that can't be written). MentionsTests' `slashTests` (`SlashFixturesPlugin(log:)`: `ping` and `near` for jots, which are titled, so their list ends with Titles' `title`, and `ping` for briefs, which aren't) hold a mention text view hosting it in `EditedJot` and the panel's box in `MentionPanel`: the view's list and keys, a pill in a command line as a shape, the `@` picker's Return picking and a second running the line, `show(_:)` and the keyboard leaving closing the list, no hosting without an owner, a slash that is a slash where the shape offers nothing (the brief's box; every list there has Titles, so `SlashCommandsPlugin()`, and a text with an owner always hosts slash commands), and a box with `onCommit` not committing a command line. A plugin list with Titles or Locking needs `SlashCommandsPlugin()` (LockingTests' `lockingHarness` and TitlesTests' `titleEditor` have it, and so do `mentionPlugins` and every other target's list with `TitlesPlugin()`): `lockSlashTests` hold `/lock` offered only where a shape can be locked and isn't, run as one step named "Lock", and TitlesTests' `titleSlashTests` `/title` offered on the kinds that keep a title (not on a box, nor on a card titled only by derivation) and not accepted with nothing typed, run as one step named "Title" that undo takes back, a pill in the line as "@Label", and Titles refused without SlashCommands. CompositionTests' `slashCommandsShippedTests` type `/lock` and `/title` into a note's editor in the app's canvas view (a slash mid-line is a slash; on a new line it lists `title` and `lock`; Return locks the note, ends editing and takes the line out, and Undo Lock is followed by the typing; `/title Groceries` names it, editing goes on, and Undo Title is followed by the typing, while `/title ` alone is a new line), and the registry report (`ShippedTests`) pins `slash-commands`, Titles' `/title → every shape` and Locking's `/lock → every shape`.
