# FuzzyMatching

FuzzyMatching, the core library that matches what's typed against text: `FuzzyMatcher` (the tiers every list ranks by), `TextSearch` (Find's matcher, over folded texts) and `PathMatcher` (Jump To's, over containment paths), and `BoundedHeap` (the best few of many matches).

Related: [text editing](text-editing.md), [mentions](mentions.md), [slash commands](slash-commands.md), [detail panel](detail-panel.md), [build](build.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [FuzzyMatching](../../docs/plugin-system.md#fuzzymatching).

## Architecture

- FuzzyMatching (a core module that depends on no other of the project's, so it knows no canvas, registry, plugin or TextEditing; `docs/plugin-system.md`, "FuzzyMatching"): pure, nonisolated and `Sendable`, so a background task runs it and an index holds what it prepares. No public type may be named `FuzzyMatching` (the audit). It was TextEditing's `CaretListMatcher`, moved and renamed (`FuzzyMatcher`, `FuzzyMatch`, `FuzzyRanking`) with no aliases: TextEditing's caret list takes a `matched` array of `Character` ranges and knows nothing of how they're found, and what imports the matcher imports FuzzyMatching (Mentions, SlashCommands, DetailPanel).
- `FuzzyMatcher` is every list's ranking, unchanged by the move: a `Query` folded once per keystroke and a `Label` once per label (or its keys back to back in a list's buffer, `appendKeys`), the tiers in `FuzzyRanking` (exact 1000, prefix 800, word prefixes 600, substring 400, subsequence up to 300, one typo 100 for a query of 4 or more that matched nothing above), `match`, `matches`, and `rank`, the two passes (every tier but the typo's, then the typo's over the rest when fewer than 8 matched), and `ranking`, the same saying whether the second pass ran (what it found was read from every label, so a list that ranks a narrowed set gets the same list only when it did not: Mentions' `forgave`). Two entry points serve `PathMatcher`: `match(_:in:allowSubsequence:)` (public: the brute force in the tests uses it) and the internal `score(_:in:allowSubsequence:)` (no ranges, no allocation), which leave the bare subsequence out, and then a query that's a subsequence and a typo gets the typo's tier. A change to the tiers is a change to every list (Mentions' `MentionWeights` take theirs from `FuzzyRanking`).
- `TextSearch` and `FoldedText` (Find): fold per Unicode scalar into UTF-16 units (case, diacritics and width through Foundation's folding, once per distinct scalar per text; whitespace a plain space; a combining mark Foundation folds into the scalar before it dropped, its original units joining that scalar's hit), with a map back to the original's units (`FoldedText.sources`) kept only if some scalar's folded length differs from its own: ASCII is one pass over the bytes, nothing kept. A hit is a `TextHit` (original UTF-16 `Range<Int>`, `isExact`), in text order, at most `TextSearch.hitCap` (100), none inside another (two hits on one `ß` are one). Exact hits first and non-overlapping (as a browser's: "aa" in "aaaa" is two; mid-word included, whitespace runs equal); then fuzzy hits from a word start (not between two letters or digits) where each query word of `typoMinimumLetters` (4) letters or more takes one edit, shorter words exact, the first letter of every word right, the last word a prefix; the edit's end is the nearest the query word's length (changed or swapped), then one short, then one long; an edit never covers a space of the text; a fuzzy hit overlapping an exact one is dropped, and a fuzzy pass runs only if a word can have an edit. The cap is the first 100 in text order of both kinds. `isCancelled` is asked every `cancellationInterval` (64K) units, in each pass, and what's found comes back. The search was written to be the matcher Find's index can use off the main actor: no shared state, no allocation but the hits and the ranges found on the way.
- `BoundedHeap` (Mentions' `@` picker and Jump To's list): the best `capacity` of what's inserted, a heap with the worst on top (`isWorse`), so an insert costs a logarithm of the capacity; `sorted()` gives the best first. One public type, so neither module keeps its own.
- `PathMatcher` (Jump To): pieces of the query (at most `PathRanking.maximumPieces`, 8, the last taking the rest) placed in order along a path's segments, a group of neighbors to a segment (one `FuzzyMatcher` query of their words joined, prepared for every group once), skips allowed, the last group in the leaf; a container's group may score only the tiers above a bare subsequence, the leaf's any. The formula is documented on `PathRanking`: `leafWeight` (2) × the leaf's score + the containers' scores − `skipPenalty` (25, less than a tier's smallest step, 100) per skipped segment, where a skipped segment is one without a group after a piece has been placed (the containers above the first group cost nothing). `Row` is what a caller keeps per container to rank a tree without walking each path: `best[g]` for g pieces placed along the chain to the container, g up to `pieceCount - 1` (the leaf takes the last piece); `advance` takes the parent's row through one label (nil, an untitled container, is a skip) in O(pieces²) matches, and `leafScore(after:label:)` is O(pieces). `match(path:)` is the same recurrence over a whole path with the way back for the matched ranges, and `PathMatcher.utf16Ranges` converts `Character` offsets to UTF-16. Single-piece queries are `FuzzyMatcher.rank` over leaves, not this: the leaf's weight makes its scores not tiers.

## Testing

- For fuzzy matching, FuzzyMatchingTests (on TestKit alone, no pasteboard, socket or document): the matcher's Suite (moved from TextEditingTests), Text search (folding with offsets for `ß`, `é`, decomposed accents, `İ`, emoji, CJK, full-width; every exact occurrence; swap, add, leave out, change; short words exact; last-word prefix; overlap dropped; the cap; cancellation; a seeded fuzz of texts and queries against `naiveHits`, written in the test with a full edit-distance table where the search reasons about the one edit, over an alphabet whose folding is one unit a character, so offsets line up; a second seeded fuzz over `ß`, emoji, CJK, combining marks and `İ`, whose hits must be in bounds, whole, and an exact hit's text must fold to the query; a CPU-time check at 10,000 texts, wide because the tests are debug builds) and Path matcher (skips, groups, last piece in the leaf, tiers allowed in a container, the ranking of a small story, `leafScore` over memoized rows and `match(path:)` on seeded random trees each against `bruteForce`, written in the test: every placement of the pieces, scored by the stated formula, the match's ranges and skips one of the best placements; ranges). A new tier or edit rule changes the naive implementation too, never the other way round. Each `Suite` is in `main.swift`'s `runTests`. The bounded heap's Suite: the best capacity of random inserts, best first, fewer than capacity, capacity zero.
