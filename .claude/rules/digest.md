# canvas-digest

The canvas-digest skill: a large body of connected information (a codebase, an org, notes, a plan) laid out as boards by a tool outside the app: it reads a graph document, measures it with `canvas measure`, decides where everything goes, and the app draws the result with `canvas apply`. The driver, the tool, the graph document, the plan, pills and private shapes, drawing again in place, and the tests. The codebase ingestion built on it is [ingest](ingest.md)'s.

Related: [ingest](ingest.md) (the codebase ingestion, which makes a graph document and draws it through this skill), [command line](command-line.md) (`canvas apply`, `canvas measure` of a document, `canvas kinds`, `:drawn-by`, which the skill is built on), [types](types.md) and [relationships](relationships.md) (what a typed document draws), [references](references.md) (the pills it promotes hubs into), [publishing](publishing.md) (what public means), [queries](queries.md) (what it asks the file for) ([every topic](../../CLAUDE.md#map)).

## Architecture

Three layers, each passing the rest through unread. The app owns every rule about shapes (what a kind takes, titles, types, channels, values, names, order of drawing). The render layer, this skill, owns only where things go. Ingest, or any producer, owns what the things are. The tool therefore **names no kind, attribute or channel** (it reads `canvas kinds`: what a kind holds, `shapes` or `board`, whether it is drawable, and the pills that can stand for it, `via`), never looks inside `props`, checks no value and decides no order of drawing. `tool/test/names.js` (`names-lib.mjs`, and a test in `run.js`) fails if any name `canvas kinds` lists is a quoted string literal in `tool/lib/*.mjs`; a build step may run it under jsc or node.

- **The driver** (`.claude/skills/canvas-digest/digest`, sh) is the only thing that runs `canvas`; the tool (JavaScript, run by the system `jsc`, else node) reads and writes files. Commands: `check GRAPH` (`canvas kinds` kept in `OUT/kinds.json`, then the tool's check), `measure GRAPH` (`canvas measure -` of the document as given, with `--board` and `--on` as apply takes them, so a pill is measured where it is drawn, kept as `OUT/measure.json`), `plan GRAPH [--view WxH] [--mess ..] [--promote off] [--prefer N] [--cap ..] [--margin ..] [--popular ..] [--ranks ..] [--current FILE]` (measures first when there is no measurement or the document is newer; writes `OUT/drawing.json` and `report.json`), `apply [--dry-run] [--on NAME] [--board ID]` (`canvas apply -` with drawing.json on standard input; the answer in `OUT/results/apply.json`, or `apply.dry.json`; a refusal, exit 1 and `{"error": {..., "refusals": [...]}}` on standard error, is printed by key with the app's message and hint, an edge by its ends, since the app counts edges by drawing.json's list; only a refusal says "nothing was changed", and a timed out apply says the app may still be applying it), `all GRAPH` (check, measure, the current query, plan, `apply --dry-run`, apply), `ready` (canvas found, the app answering with a board open, `canvas help apply` known). `--out DIR` (default: the document without `.json`, plus `.out`), `--board ID` (reaches `measure`, the warm-start query and `apply`), `--timeout S`. Exit 0 done, 1 refused or failed, 2 usage. It warns when the skills are from another build than the app (`build-id`).
- **The graph document** (`reference/graph.md`; the contract is the spec's §1). `drawing` (the app's record is by it), top-level `layout` (`mess`, `promote`, `ranks`), `nodes: [{key, kind, in, props, layout: {rank, pill}}]`, `edges: [{from, to, key?, props, layout: {weight, direct}}]`. The tool reads `key`, `in`, `kind` and `layout`; `props` and an edge's `props` pass through to drawing.json as parsed. Keys are the layout's identity (nodes are sorted by key, so a row keeps key order); titles matter to the tool nowhere and may repeat.
- **The checks** (`check.mjs`, over `model.mjs`'s `readGraph`): structure the layout needs, and nothing the app owns. A key a non-empty string and unique (and not `root` on a node that holds a board: the layout's name for the drawing's own board), a kind `canvas kinds` lists as drawable, `in` naming a node whose kind holds shapes or a board, no cycle in `in`, edge ends naming nodes, the layout hints' types, `layout.pill: true` only on a kind some pill stands for, not on a node that holds shapes. Messages name keys. A refusal the app has (a title, a value, a type, a channel) comes from the app, when it measures or applies.
- **Measure** (`sizes.mjs`). `canvas measure -` answers `nodes[key]` (`size`, `above`, `titleWidth`), `pills` (`for`, `from`: the key of the frame or subboard that holds the other end, null for the top of the drawing's board, with `size`), `edges` (those the app would refuse, by place in the list, with reason, message and hint) and `constants`. `sizesFrom(model, measure)` is what the layout reads: each leaf's size, each frame's smallest and **title width** (a frame is never narrower than its title), a pill's width by `pillKey(for, container id)`, the constants (pill height, step and gap, the frame inset, the smallest frame). An edge the app refuses is left out of the layout and of drawing.json, with a warning quoting its message and naming both keys. A node the measurement has no size for is an error naming the key.
- **The model** (`model.mjs`). Nodes by key with `holds`, `parent`, `chain`, `board`, `frames`, `container` (`b:root`, `b:<subboard key>`, `f:<frame key>`), `pin` and `never` (`pin` from `layout.pill: true`; `never` from `layout.pill: false` or a kind no pill stands for), `rank`; boards (root first, then subboards by depth); edges between one pair are one edge to the layout (weights added, `items`: the document's edges it stands for); `direct` is `layout.direct`, or an end that holds shapes. Left out with a warning (in `model.warnings`, `model.dropped`): the app's refusals, an edge between boards at a shape that holds shapes, an edge between boards to a kind no pill stands for. `forcedTargets`: the far end of an edge between boards, and pinned nodes.
- **The layout** (`layout.mjs`, `promote.mjs`, `cost.mjs`, `elk.mjs`, `moves.mjs`, `noise.mjs`, `stress.mjs`, `geom.mjs`, `dial.mjs`; unchanged by the rewrite). Each board is laid out a container at a time (ELK layered down and across, stress as it comes and stretched, trees, rectpacking), every leaf with the column of pills it will have beside it reserved; a loop (`runBoard`) promotes hubs many point at, fans out nodes that point at many, sets apart arrows too long, splits a shared pill far from some users, and stops when the board is good enough under the dial, when the best candidates gain no more than the margin (the layout's measured noise), or at the cap. The mess dial (`dial.mjs`, one number, `cli.mjs`'s usage has the table) sets the price of a pill, the cap, the margin, how many arrows make a node popular, how long an arrow may run, and what good enough is. **Spines** (a frame or board of two to six leaves that don't point at each other and share two or more targets: two columns facing a column of the shared pills, no search), **ranked** children (rows or columns, whichever the view shows larger, `layout.ranks` and `--ranks` over it), **the view** (every container aims at the view's shape; `aspect` is how far off it is; `--view`, else 1440 x 960, said by the summary), and **crowded boards** (a container of more than 150 children, or a board of more than 1,000 shapes, is laid out once and not searched; its pills are those between boards; the report's warnings say to split it) are as they were.
- **The plan** (`plan.mjs`, `emit.mjs`). `planGraph(graph, sizes, options, elk)` builds the model, lays out every board (inner boards first), and returns the plan (`buildBoards`: each board's shapes and pills in board coordinates, the layout's own record the tests read), **`drawing`** (`buildDrawing`) and the report. drawing.json is the document as given (every field of every node and edge, in the order given) with `place`: a node's `at` is its box's top-left from its frame's top-left when its `in` is a frame, else from its board's origin, `size` its box's (a frame's the layout's; any other node's the measured size, rounded up); nothing is shifted and a number may be negative. An edge the layout draws through a pill has `place.pill`: the host's own edge (the first edge of the pair) `{at, in?}`, the pill's top-left from its frame's top-left (`in` the frame's key) or the near end's board origin; every other edge of that pair, and every user of a pill someone else makes, `{share: <the host's node key>}`. A pill stands for the `to` end beside the `from` end (an edge between boards is a pill for its end on the other board, beside the end on this one). The makers come before the sharers in the list; every other edge keeps its place in the list. A self edge and an edge with no pill stay unplaced (the app draws an arrow). Edges the model left out are not in it.
- **Pills and private shapes.** Every shape is public unless a person made it private (`private: true`), and the tool makes nothing public or private: a pill can stand for any shape it draws but a private one, which the tool can't tell (it reads no `props`), so a document that makes a node private keeps it off pills with `layout.pill: false` and draws no edge to it from another board, else `canvas apply` refuses the pill by the node's key ([drawings](drawings.md)). The report names the moves (`promotions`: promoted, fanned out) and the long arrows; a spine's targets and the far ends of edges between boards are pills by the layout. `layout.pill: false` means never a pill target, `layout.pill: true` pins one, `layout.direct: true` that an edge is never a pill.
- **Drawing again in place** (`plan.mjs`'s `currentFrom`/`currentFor`, `layout.mjs`'s `keepCurrent`). `digest all` writes `canvas query ':drawn-by("NAME")' --brief` as `OUT/current.json` (rows `{id, key, at: [[x, y], [w, h]], board, inside, in}` in world units: `inside` the names of the subboards and frames the shape is inside, outermost first, which is not read, and `in` the key of the drawing's shape that holds it; a list or `{rows, absent}`; no rows when the file lacks the drawing, which starts the plan afresh; any other failure of the query stops the driver, saying what canvas said) and `plan --current` starts from it. The search for pills runs afresh, so the same document decides the same; the board is then laid out once more with `current` set. A container (a board, a subboard's board, a frame) whose members are exactly the keys the file holds in it now (none added, removed, or moved between containers) **keeps** each member where it is (the row's box, made relative to the container's current top-left; a frame at its current place and at least its current size); any other container, and one with shared spine pills, is laid out afresh; so is one whose kept members now overlap (a pill column that no longer fits, a frame that grew). A row's container is its `in` (the key of the drawing's shape that holds it); a row with none is on the drawing's board. Only the document's nodes are a container's members: the rows of the pills and arrows the drawing's edges drew (`pill …`, `edge …`) are its too, and hold no place (counted, they made every frame with a pill in it look changed, so it was laid out afresh on every redraw). A container of ranked children (the bands) is laid out by its ranks, as the document and `--ranks` say, wherever they are now, and what each band holds is kept, so `--ranks rows` over a drawing of columns turns it. Its `at` is the frame each shape is laid out in (`canvas query`'s, [queries](queries.md)), which `canvas apply` places, so a relationship type's pill, drawn about the middle of a taller box, is read where it is drawn and drawing again doesn't move it. `report.boards[b].kept` lists the containers that kept. A pill the plan puts elsewhere than it is, or in another frame, is moved there by `canvas apply` ([drawings](drawings.md)), and an edge the plan draws straight that went through a pill, or the other way round, is drawn anew.
- **The commands of the tool** (`cli.mjs`, `main.js`): `check`, `check-text`, `plan`, `name`, `drawn-by` (the query that finds the drawing's shapes, `:drawn-by("NAME")`; once `query`, a word `canvas kinds` lists as an attribute, which the names rule refuses as a literal), `view` (the room `canvas boards` says a board's window has, `WxH`), `count`, `refusals`, `applied`, `extract kinds|errors`; the usage lists them with the dial and the view.

## Testing

- `tool/test/run.js` (under jsc and node; `K/N` runs every Nth test from the Kth, and says how many of how many it ran; `node tool/test/run.js record` prints the fixtures' hashes) holds the tool's unit tests: the dial, the layout, the pill loop, spines, ranks, the view, the crowd, drawing.json (places, pass-through, shares, determinism, a hash of each fixture's drawing), drawing again in place, check, sizes and the edges the app refuses, the commands (on in-memory files) and the names rule. Fake `canvas measure` answers are built from the fixtures (`helpers.mjs`'s `estimateMeasure`, sizes per key). Fixtures in `tool/test/fixtures`: graph documents (`acme`, `tree`, `flat60`, `spine`, `frames`, `typed`), `kinds.json` (the tool's reading of `canvas kinds`, `extract kinds`) and `kinds.answer.json` (the answer whole, which the names rule reads every name of the app from), both written by CompositionTests' `kindPagesTests` (`mise run skill:kinds`) and never by hand; `DigestTests`' kinds suite holds `extract kinds` of the shipped answer to `kinds.json`. The warm start's tests hold the rows of pills and arrows a drawing's edges drew as no member of a frame, and a ranked board drawn as columns drawn again as rows, each band keeping what it holds.
- `tool/test/names.js` (`jsc` or `node`, from the tool's folder) is the names rule alone, for a build step.
- `tool/test/driver.sh` runs the driver against a fake `canvas` (`fake-canvas.mjs`): its commands, what it asks the app, the dry run first, `--on`, the warm start's query (no rows starts afresh, a failure stops), `--board` on measure, query and apply, a relative graph path given to `apply`, a timed out apply's wording, a refusal printed by key. Run by hand; it needs node (`DRIVER_JSC=<path to jsc>` runs the tool under jsc).
- `Tests/SkillToolsTests/DigestToolTests.swift` runs `run.js` in parts under jsc. `Tests/CompositionTests/DigestTests.swift` runs `digest all` against the built `canvas` and a `CommandServer` of the test's own, and holds each run to the document: exit 0, every verdict and its id, every node where drawing.json puts it (its frame's top-left, or the board's origin, within a unit), frames at their planned size, every edge an arrow or through a pill where `place.pill` says, the pills where the plan puts them and no other pill or arrow and one undo taking the drawing back. `digestSmallTests`: acme, tree (a subboard's description mentioning notes by key), frames (the edge the app refuses: `measure` lists it, the plan leaves it out naming both keys), spine (one shared pill) and typed, each drawn into a subboard drawn first (`--on Home`). `digestBoardTests`: acme on an empty board with no `--on`, flat60 into a new file (`canvas new`, then `--board`). `digestRedrawTests`, over tree with a note of the test's own beside it: the same document again every verdict `unchanged`, the board as it was and no new undo step; a node's text changed `updated` alone; a node gone `deleted` with its edges and pill, no arrow left bound to it, the test's note still there. `digestFieldsTests`: a node's, a frame's and an arrow's `color`. `digestRefusalTests`: an unknown kind (by `check` and by `all`, naming the key and the kind), a `props` member no kind takes and a malformed `fieldValues` (the app's refusal by key, exit 1, the board as it was, no step), a value its type refuses (a warning, not a refusal), an `in` cycle (`check`, `measure`, `plan` and `all` naming the keys), a title holding "error: ". `digestReadyTests`: `ready` against the app, a `canvas` without `apply` refused with `canvas install`'s hint, `canvas` found on the PATH, and each command with no `canvas`. `digestKindsTests`: `extract kinds` of the shipped answer is `kinds.json`.

## Not built

- Drawing part of a document: `canvas apply` is all or nothing.
- A view for each board (a subboard's has a little less room); a board laid out again when the window changes.
- Matching pills in a kept container to the pills already drawn: a pill has no key, so the pills are decided and placed afresh beside the kept shapes.
- A frame as a hub, or at a pill.
- The layout's tuning by eye (layered against stress) and benchmarks. `longest` is the dial's alone: it doesn't grow with the view.
