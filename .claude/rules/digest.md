# canvas-digest

The canvas-digest skill: a large body of connected information (a codebase, an org, notes, a plan) laid out as boards by a tool outside the app, measured with `canvas measure` and drawn with `canvas draw`; the driver, the tool, the digest format, the plan, the public rule, and the tests.

Related: [command line](command-line.md) (`canvas draw`, `share:` on an edge and `canvas measure`, which the skill is built on), [references](references.md) (the pills it promotes hubs into), [publishing](publishing.md) (what public means), [queries](queries.md) (what it asks the file for) ([every topic](../../CLAUDE.md#map)).

## Architecture

- **Where the layout lives.** Layout and promotion are the skill's, in `.claude/skills/canvas-digest/tool` (JavaScript, no dependency but ELK, vendored unmodified in `tool/vendor`: elkjs 0.12.0, whose `README.md` says where from, with its EPL-2.0 licence and an entry in `THIRD_PARTY_NOTICES.md`). The app measures (`canvas measure`) and lands shapes (`canvas draw`); `draw` never chooses an arrangement, and nothing in `Sources` knows the skill. The runtime is the system jsc (`/System/Library/Frameworks/JavaScriptCore.framework/Versions/Current/Helpers/jsc`), node as a fallback; the tool is plain ES modules that touch files only through the `io` main.js hands them, so one code base runs in both (jsc cannot make a folder: the driver makes `<out>/runs`, and hands the tool absolute paths, since jsc reads a relative one from where the tool is).
- **The driver, `digest`** (POSIX sh), is the only file that runs `canvas`: `check`, `measure`, `plan`, `draw`, `verify` and `all`, each taking the digest and a target (`--board <id> --into "Title"`: a new subboard of an open board; or `--new-file <path>`: `canvas new`). It finds `canvas` as `$CANVAS_CLI`, else `build/canvas`, else PATH (looked up when it starts, and before the driver's own functions are in play: they are `run_canvas`, `canvas_try` and `canvas_to`, never a name `command -v canvas` would find), and sets `CANVAS_FORMAT=json` and a `--timeout` (120 s) on every call. It never parses JSON in sh: the tool does that (`extract titles|kinds|id|count|errors`, `into`, `clashes`, `check-text`, `runs`, `compare --text`, `replay`); `check` reads the tool's JSON (`extract errors`), never its words. **Errors reach the user:** the driver's own standard error is file descriptor 3 (`exec 3>&2`), and `die`, a tool that fails (`tool` sends jsc's and node's complaints there, and drops jsc's `Exception:` echo on standard output) and a missing canvas write to it, whatever a command's output was redirected to. `tool_to FILE ...` stops the driver when the tool fails. One query lists at most 10000 titles and can't be paged: a file with more titles than it lists is refused (`extract titles`) rather than checked against some.
- **The digest** (`reference/graph.md`): `title`, `policy: {mess, promote}`, `nodes: [{title, kind, in, text, public}]` (flat, `in` names the parent), `edges: [{from, to, weight, text, via, direct}]`. `check` refuses duplicate folded titles, titles over 80 characters, titles already in the file (one `canvas query`) and the header notes' titles, kinds `canvas kinds` doesn't list, an unknown `in`, an edge to nothing, and `public: true` on a frame; it warns past 15 shapes in a frame and 150 on a board, and for an edge dropped because it names a frame (a frame has no ports).
- **The plan.** `plan` reads `measure.json` (the answer of `canvas measure` to the script `measure-script` writes: every note, subboard and board header, then one `edge A -> T via: reference` per end something points at, so a pill's width is measured, not guessed; the constants the layout places with, `referenceStep`, `defaultGap`, `frameInset`, `smallest.frame` and the gaps, come from its `constants`, with draw's numbers as defaults only when a key is missing) and lays out each board, inner boards first (what is public inside costs less outside). A hub is promoted by measured cost over a structural prefilter: every user of a promoted hub gets a pill, those in one frame sharing one by preference, a far group splitting off its own shared pill only when it saves at least `--prefer` (2) pills' prices, each shared pill beside its host, the user that keeps its group's arrows shortest. One dial, `mess` (0 tidy to 1 loose, default 0.1), sets a pill's price, the cap and the good-enough thresholds together; the order of promotions is the same at every setting. Output: `plan.json` (each board's shapes at exact offsets from its header note, its pills, its edges in drawing order, `share` and `host`, `into`, `runs`), `report.json` (promotions with costs, why each board's loop stopped, the public set with a reason for each) and `runs/NN-<board>-<step>.draw`, shapes first (a board's top level, then each depth of frames), then each board's edges: a shared group's host first and the others saying `share: "<host>"`. With `--into`, `runs/00-into.draw` makes the subboard and every shape of the root board is `in` it; compare reads that board as `root`.
- **What is public.** Only shapes the run creates, in their own shape statements (`public: true`, so before any edge through them), and the report names them with why: pinned in the digest, an edge from another board points at it, `via: reference`, or promoted. `public: false` in the digest means never promote it; `direct: true` on an edge means never a pill. The canvas skill carves this out of "making a shape public is the user's call"; a shape that was on a board is never touched (v1 draws a new file's board or a new subboard, never among a board's shapes, and `digest draw` refuses a plan made without `--into` onto an open board).
- **The gate.** Every run is a dry run first: `compare` holds each shape row's `at` (relative to its board's header) to the plan within a unit, and fails the run on a push (`pushedPast`), an unorderable placement or a pill pushed past a shape; the driver stops before drawing that script, naming the shape, exit 4. A shape the plan creates must come back `created`: one found `unchanged` is a plan drawn before (or a title taken), and fails the run. Pills are held as shapes are: a pill more than a unit off its planned spot fails compare and replay. Then the real run is compared again. A warning that shapes landed outside the window's view is not a failure (a big drawing outgrows the window; the camera is the user's). `verify` replays every saved real result in order (`replay`), checking each planned shape, pill and arrow landed, none was restated, and the file's titles hold them. Neither reads positions from the file: `canvas query` doesn't read where a shape is, so the result rows of the runs are the evidence.
- **Standalone steps.** `digest draw` checks the plan's titles against the file again (`clashes`: a title the plan draws, or the `--into` title, that the file holds stops it before the first script), and refuses a plan with a saved result (`results/NN-....json`): a plan is drawn once, and `plan` starts the results afresh. `digest plan --board` re-runs the title check (quietly unless it finds an error). When a draw stops after something was drawn, the driver says which scripts are on the board and how to take them back, for the target: one undo (Edit > Undo Draw) a script, or delete the subboard `--into` named; for `--new-file`, close the file's window without saving and delete the file. A cycle in `in` is refused by `check`, `plan` and `measure`, naming the titles (`buildModel`).
- **Hubs and frames.** An edge that names a frame is dropped with a warning (a frame has no ports), so a frame is never a hub or an end of an edge; subboards and notes can be hubs (D9, narrowed).
- **Known and left.** `canvas measure` runs on the main actor (a `run:` command), so measuring a very large digest holds the window for as long as it takes. A promoted hub is measured without its Public chip, which it will have once drawn, so its `above` and chip width in `plan.json` are the unpromoted ones; positions are still held by the shapes' own rows.

## Testing

- `Tests/CompositionTests/DigestTests.swift` (`digestTests`): the tool's unit tests under jsc (`tool/test/run.js`, which also runs under node; its tests cover the dial, the layout, the measure script and sizes, check, compare, replay, extract and the three fixtures `acme`, `tree` and `flat60` in `tool/test/fixtures`); then `digest all` as an agent runs it, with `canvas` as built (`CANVAS_CLI` = `builtExecutable("CanvasCLI")`) against the test's own `CommandServer` (`CANVAS_SOCKET`), on Acme drawn into a subboard of an open board and again with `--promote off` on another, a 3-level tree, and the flat 60 notes into a new file (`canvas new` through a server whose `show` keeps the board). Each run is held to its plan by the tool's own `verify` over rows read from the editor (every shape and pill within a unit, pills as wide as planned, in their frames, every arrow drawn, no extra pill), to no warning but the out-of-view one, to the public set being exactly the report's, and, for each promoted hub, `canvas query`'s `:edge-to("Hub")` rows being the same promoted and not, and the digest's own edges. Refusals (a title the file has, an unknown kind, a plan made for another target, `--board` without `--into`) and a tampered script that stops the run before it draws (into a subboard, and into a new file, where the advice differs) are held too, and so are the standalone steps: a draw whose title the file has, a plan drawn twice, `plan --board` over a drawing, a missing canvas and a cycle (said on standard error, status 1), canvas found only on the PATH (a copy of the driver in a folder with no `build/canvas`), and a title with "error: " in it passing `check`. The test closes the boards it opens and uses its own socket; `DIGEST_DUMP=1` prints what `digest` said in each run.
- `canvas measure` and `share:` are held in MeasureTests and DrawShareTests ([command line](command-line.md)).
- A change to `measure`'s answer or to how `draw` places a pill or a frame changes what the tool plans: run `DigestTests` (and `tool/test/run.js` under jsc and node) with it.

## Not built

- Updating a board the digest drew earlier: plan again into a new place.
- A frame as a hub or an end of an edge.
- The layout's tuning (steady landscape boards, layered against stress by eye) and benchmarks.
