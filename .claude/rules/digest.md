# canvas-digest

The canvas-digest skill: a large body of connected information (a codebase, an org, notes, a plan) laid out as boards by a tool outside the app, measured with `canvas measure` and drawn with `canvas draw`; the driver, the tool, the digest format, the plan, the public rule, drawing again in place, the codebase ingestion built on it, and the tests.

Related: [command line](command-line.md) (`canvas draw`, `share:` on an edge and `canvas measure`, which the skill is built on), [references](references.md) (the pills it promotes hubs into), [publishing](publishing.md) (what public means), [queries](queries.md) (what it asks the file for) ([every topic](../../CLAUDE.md#map)).

## Architecture

- **Where the layout lives.** Layout and promotion are the skill's, in `.claude/skills/canvas-digest/tool` (JavaScript, no dependency but ELK, vendored unmodified in `tool/vendor`: elkjs 0.12.0, whose `README.md` says where from, with its EPL-2.0 licence and an entry in `THIRD_PARTY_NOTICES.md`). The app measures (`canvas measure`) and lands shapes (`canvas draw`); `draw` never chooses an arrangement, and nothing in `Sources` knows the skill. The runtime is the system jsc (`/System/Library/Frameworks/JavaScriptCore.framework/Versions/Current/Helpers/jsc`), node as a fallback; the tool is plain ES modules that touch files only through the `io` main.js hands them, so one code base runs in both (jsc cannot make a folder: the driver makes `<out>/runs`, and hands the tool absolute paths, since jsc reads a relative one from where the tool is).
- **The driver, `digest`** (POSIX sh), is the only file that runs `canvas`: `check`, `measure`, `plan`, `draw`, `verify`, `all` and `ready` (whether a draw could start, for a caller with slow work to do first: canvas found, the app answering and both new enough to measure (one note measured: an app or a `canvas` from before `measure` is said here, not after the read), a board fit to be drawn as, the `--into` title free, a new file's path free and its folder there, and, with `--replace`, the take-back as a dry run, so a shape of the last drawing the app won't delete is said now (a window inside a drawing that is the board is shown its root first, as `draw` does); its GRAPH needn't exist yet), each taking the digest and a target (`--board <id> --into "Title"`: a new subboard of an open board; `--board <id>` alone: the board itself, which must be empty; or `--new-file <path>`: `canvas new`; `--board front` is the board in front, resolved to its id once, by `canvas boards`). It finds `canvas` as `$CANVAS_CLI`, else `build/canvas`, else PATH (looked up when it starts, and before the driver's own functions are in play: they are `run_canvas`, `canvas_try` and `canvas_to`, never a name `command -v canvas` would find), and sets `CANVAS_FORMAT=json` and a `--timeout` (120 s) on every call. It never parses JSON in sh: the tool does that (`extract titles|kinds|id|count|errors`, `into`, `clashes`, `check-text`, `runs`, `compare --text`, `replay`); `check` reads the tool's JSON (`extract errors`), never its words. **Errors reach the user:** the driver's own standard error is file descriptor 3 (`exec 3>&2`), and `die`, a tool that fails (`tool` sends jsc's and node's complaints there, and drops jsc's `Exception:` echo on standard output) and a missing canvas write to it, whatever a command's output was redirected to. `tool_to FILE ...` stops the driver when the tool fails. One query lists at most 10000 titles and can't be paged: a file with more titles than it lists is refused (`extract titles`) rather than checked against some.
- **The digest** (`reference/graph.md`): `title`, `text` (the first board's header note), `policy: {mess, promote}`, `nodes: [{title, kind, in, text, public, rank}]` (flat, `in` names the parent; a subboard's `text` is its board's header note; `rank` stacks a container's ranked children in rows, lowest on top, title order in a row, and a frame alone in its row is stretched to the widest row with what it holds centred, `Layouter.ranked`: no ELK, whatever the arrows ask), `edges: [{from, to, weight, text, via, direct}]`. `check` refuses duplicate folded titles, titles over 80 characters, titles already in the file (one `canvas query`) and the header notes' titles, kinds `canvas kinds` doesn't list, an unknown `in`, an edge to nothing, and `public: true` on a frame; it warns past 15 shapes in a frame and 150 on a board, and for an edge dropped because it names a frame (a frame has no ports).
- **The plan.** `plan` reads `measure.json` (the answer of `canvas measure` to the script `measure-script` writes: every note, subboard and board header, then one `edge A -> T via: reference` per end something points at, so a pill's width is measured, not guessed; the constants the layout places with, `referenceStep`, `defaultGap`, `frameInset`, `smallest.frame` and the gaps, come from its `constants`, with draw's numbers as defaults only when a key is missing) and lays out each board, inner boards first (what is public inside costs less outside). The loop's moves (`moves.mjs`, `promote.mjs`), each of which turns arrows into pills: **promoting** a node many point at (it is made public, and every user of it gets a pill, those in one frame sharing one by preference, a far group splitting off its own shared pill only when it saves at least `--prefer` (2) pills' prices, each shared pill beside its host, the user that keeps its group's arrows shortest), and **fanning out** a node that points at many (each of its uses on the board becomes a pill beside it, and what they stand for is made public; never an edge that says `direct`, nor one to a `public: false` shape). Popularity decides first, on a board that isn't good enough as it is (the dial's thresholds: a star of eight arrows that cross nothing is left with its arrows, since pills are for a mess): while it isn't, and a node has at least the dial's `popular` arrows that a move would turn into pills (pointing at it, or leaving it; arrows still drawn, counted afresh after each move), the one with the most is moved, the first by title on a tie (for one node, pointing-at before leaving), whatever its own trial measures (`mostPopular`; a measured gain is noisy enough to call a node with ten importers a loss), and such a move is never taken back. Then the judgment calls, as before: the best measured of the top candidates either way round (`candidates`, scored arrows x spread x (1 - tie), scaled by how badly those arrows do), kept when it beats the margin measured from the layout's noise, until the board is good enough, nothing beats the margin, or the cap (which counts the popular moves, and never holds one back). Last, no arrow runs longer than the dial's `longest` (`tooLong`): a plain arrow over it, or one into a pill others share, is set apart as a pill of its own beside its start (`state.apart`; its end made public) and the board laid out again from where it is, until none is left (each pass sets at least one more edge apart, so the passes end by themselves); `direct` edges and `public: false` ends are left. One dial, `mess` (0 tidy to 1 loose, default 0.1), sets them together: a pill's price, `popular` (round(4 + 10 mess): 5 at 0.1), `longest` (round(1000 + 3000 mess) units: 1300 at 0.1), the cap and the good-enough thresholds; `--cap`, `--margin` and `--popular` override the dial's; at 1, and with `--promote off`, no move is made and no arrow set apart (at 1 a node the digest pins, `public: true`, still has its users' pills: a pin is the digest's, not a move; only `--promote off` leaves those arrows too). The popular moves come in the same order at every setting, the dial saying how far down them the loop goes; the judgment calls after them start from wherever that leaves the board. A board's header is never another's: a subboard called what the digest is keeps `About <title>`, and the digest's own takes ` (digest)` (`buildModel`). Output: `plan.json` (each board's shapes at exact offsets from its header note, its pills, its edges in drawing order, `share` and `host`, `into`, `runs`), `report.json` (each board's moves in order, `mode` `in` or `out`, `popular` with its `arrows` or a judgment call with its costs; `promoted`, `fanned` and `long`; why each board's loop stopped; the public set with a reason for each) and `runs/NN-<board>-<step>.draw`, shapes first (a board's top level, then each depth of frames), then each board's edges: a shared group's host first and the others saying `share: "<host>"`. With `--into`, `runs/00-into.draw` makes the subboard and every shape of the root board is `in` it; compare reads that board as `root`.
- **What is public.** Only shapes the run creates, in their own shape statements (`public: true`, so before any edge through them), and the report names them with why: pinned in the digest, an edge from another board points at it, `via: reference`, promoted, what a fanned-out node's pill stands for, or the end of an arrow that would run too long (`emit.mjs`'s `madePublic`). `public: false` in the digest means never promote it; `direct: true` on an edge means never a pill. The canvas skill carves this out of "making a shape public is the user's call"; a shape that was on a board is never touched: a digest draws a new file's board, a new subboard, or an open board as its own only when the board's file is empty (`canvas boards`' `fileShapes` is 0) or holds nothing titled but the drawing `--replace` takes back (`root_ok`, at `check`, `plan` and `draw`).
- **The gate.** Every run is a dry run first: `compare` holds each shape row's `at` (relative to its board's header) to the plan within a unit, and fails the run on a push (`pushedPast`), an unorderable placement or a pill pushed past a shape; the driver stops before drawing that script, naming the shape, exit 4. A shape the plan creates must come back `created`: one found `unchanged` is a plan drawn before (or a title taken), and fails the run. Pills are held as shapes are: a pill more than a unit off its planned spot fails compare and replay. Then the real run is compared again. A warning that shapes landed outside the window's view is not a failure (a big drawing outgrows the window; the camera is the user's). `verify` replays every saved real result in order (`replay`), checking each planned shape, pill and arrow landed, none was restated, and the file's titles hold them. Neither reads positions from the file: `canvas query` doesn't read where a shape is, so the result rows of the runs are the evidence.
- **Standalone steps.** `digest draw` checks the plan's titles against the file again (`clashes`: a title the plan draws, or the `--into` title, that the file holds stops it before the first script), and refuses a plan with a saved result (`results/NN-....json`): a plan is drawn once, and `plan` starts the results afresh. `digest plan --board` re-runs the title check (quietly unless it finds an error). When a draw stops after something was drawn, the driver says which scripts are on the board and how to take them back, for the target: one undo (Edit > Undo Draw) a script, or delete the subboard `--into` named; for `--new-file`, close the file's window without saving and delete the file. A cycle in `in` is refused by `check`, `plan` and `measure`, naming the titles (`buildModel`).
- **Drawing again in place (`--replace`).** `draw` keeps what a drawing makes in `<out>/drawn.json` (`redraw.mjs`'s `drawnRecord`: the board's file as `canvas boards` has it, and its id for a board with no file yet; the `--into` subboard or null; the first board's header; the titles on that board; every title; and `shapes`, how many the file held once it was drawn, or as far as it got, null while it draws), written before the first real run, so a drawing that stops part way is taken back as far as it got. With `--replace` and a `drawn.json` in the target board's file (`sameFile`: by path; a board with no file by its id and the drawing's header still in the file, since an id is the app's only while it runs), `check` and the clash test keep clear of the file's titles less the drawing's (`minus`). A digest drawn as the board refuses, before anything is deleted, a titled shape the drawing didn't make (`foreign`; titles match as the app tells them apart, spaces folded and case kept) and more shapes than the drawing made (`beyond`: an arrow or an untitled note added since). `draw` shows the board's root first for a digest drawn as the board (its first script goes on the board the window shows), and before any take-back whose shapes are all on the root board when the window shows another (`from_root`: the app deletes no shape that holds the board shown, so a drawing looked into, as the board or `--into`, is still replaced; a subboard on a board inside the file is left to the app's own refusal), then runs `replace.draw` (`replaceScript`: `delete` the subboard, which takes its board, or each shape on the first board the file still holds, their arrows and pills going with them), dry-run then real, one undo step, and, for a digest drawn as the board, holds `fileShapes` to 0 before drawing (a shape moved out of the drawing's boards is caught only here, after the delete: the message says Undo Draw brings the drawing back, as it does when a run stops before anything new is drawn). `verify` reads every title (`titles.all.json`). Without a `drawn.json` in that file, `--replace` changes nothing. **Until a drawing made in place of the last one is whole, the record is of both** (`drawnRecord`'s `over`; the last one's is kept as `drawn.prev.json`): their titles, their headers, what takes either back (`takes`, and `intos`, the subboards among them), how many shapes the file holds as the draw stops (`shapes`) and how many it held just before the take-back (`was`), because the driver tells the user that an undo a script and one more brings the last drawing back, and the next run must know the board for its own either way. `beyond` then allows a file with no more shapes than the part drawn, or with exactly as many as before the take-back, and counts anything else as added (an arrow drawn on either is still refused before anything is deleted); `replaceScript` deletes a shape a drawing put on the root only where it is on the root board (`extract root-titles`: a title one drawing has on the root the other may hold inside a subboard, and deletes on two boards are a script draw refuses), and an `--into` subboard wherever the file holds it. A run that stops with nothing new drawn puts the last record back, a whole drawing's record is its own again, and the record is written whole or not at all (beside itself, then moved). Stopped by hand (Ctrl-C), the draw records and says what is on the board as for any other stop (a `trap` around its loop). A drawing made on a board with no file yet is still known once the board is saved (`sameFile`: its id and its header, or the subboard it went into, whenever the record has no path; two paths that differ are two files). The record lives in `--out`, so a drawing made from another checkout or project isn't known to this one: its board reads as not empty. `draw` numbers each run as it lands (`[n/N] ok ...`). `--board` takes a board's id, file or name, or `front`, resolved once by the tool (`boardField`): a file by its path as given or with its links resolved (the driver hands over both: the app lists the path a board was saved by; `/tmp` is `/private/tmp`), and a file or name two open boards have is refused with their ids. `plan` measures when there is no `measure.json`, and again when the digest is newer than it.
- **The codebase ingestion** (`dogfood/model/ingest`, POSIX sh; [its README](../../dogfood/model/README.md)): nothing is written by hand for a codebase, this one included (it has no `spec.py`; a project may keep one, which only overrides `defaults.py`, and what it leaves out or names that the code lacks is said on standard error, never stopping the run). It asks `digest ready` first, so an app that isn't running or a board that can't take the drawing is said before the minute and a half of reading; reads the code into `model.json` (Swift's three readers, or `scip_read.py` with `--scip`; `--skip-read` keeps the model; a reader also writes `name`, what the code calls itself, which is the board's title; the readers write `model.json.reading`, which takes the model's place only when it is whole, so a read that stops part way never leaves a model with files and none of their uses); makes the digest (`to_digest.py`: bands as ranked frames, by the modules' layer tags ordered by how deep their imports go, else by import depth; modules, and the folders of a module of over 50 files, as subboards whose `text` is their About note; a board's folders as frames; files as notes; imports and uses as edges, weighted by the names used up to 4); then runs `digest all` with `--board front --replace` (or `--board ID --replace`, or `--new-file PATH`) and `--out <PROJECT>/digest.out`. A note's `@[` is written `\@[` (a run of backslashes before it doubled), so a doc that shows a mention reads as text, and a header's mention of a card escapes `]` and `\` in its title (`common.mention`). **Every title is given out once** (`to_digest.py`'s `Titles.claim`), the ones that matter most first: modules, folder boards, bands, files, frames. One another shape has (spaces folded, case aside), or over 80 characters (74 for a card, whose board's header is `About <card>`), gives way to the next it is offered (a band `X (layer)`, a file its whole path, a frame `X (<board>)`), then to a number after it, keeping its end behind an ellipsis when clipped; each is said on standard error and none stops the run, so no codebase's names can fail `check` after the read (a name with half a character in it, a file's that isn't UTF-8, is given U+FFFD there; a folder whose board would be named as a module is gets no board of its own, `defaults.complete`). When `ready` refuses, `ingest` adds what that comes to in its own options (it has no `--into` or `--replace`).
- **Hubs and frames.** An edge that names a frame is dropped with a warning (a frame has no ports), so a frame is never a hub or an end of an edge; subboards and notes can be hubs (D9, narrowed).
- **Known and left.** `canvas measure` runs on the main actor (a `run:` command), so measuring a very large digest holds the window for as long as it takes. A promoted hub is measured without its Public chip, which it will have once drawn, so its `above` and chip width in `plan.json` are the unpromoted ones; positions are still held by the shapes' own rows.

## Testing

- `Tests/CompositionTests/DigestTests.swift` (`digestTests`): the tool's unit tests under jsc (`tool/test/run.js`, which also runs under node; its tests cover the dial, the layout, the measure script and sizes, check, compare, replay, extract and the three fixtures `acme`, `tree` and `flat60` in `tool/test/fixtures`); then `digest all` as an agent runs it, with `canvas` as built (`CANVAS_CLI` = `builtExecutable("CanvasCLI")`) against the test's own `CommandServer` (`CANVAS_SOCKET`), on Acme drawn into a subboard of an open board and again with `--promote off` on another, a 3-level tree, and the flat 60 notes into a new file (`canvas new` through a server whose `show` keeps the board). Each run is held to its plan by the tool's own `verify` over rows read from the editor (every shape and pill within a unit, pills as wide as planned, in their frames, every arrow drawn, no extra pill), to no warning but the out-of-view one, to the public set being exactly the report's, and, for each promoted hub, `canvas query`'s `:edge-to("Hub")` rows being the same promoted and not, and the digest's own edges. Refusals (a title the file has, an unknown kind, a plan made for another target, `--board` without `--into` on a board that isn't empty) and a tampered script that stops the run before it draws (into a subboard, and into a new file, where the advice differs) are held too, and so are the standalone steps: a draw whose title the file has, a plan drawn twice, `plan --board` over a drawing, a missing canvas and a cycle (said on standard error, status 1), canvas found only on the PATH (a copy of the driver in a folder with no `build/canvas`), and a title with "error: " in it passing `check`. The test closes the boards it opens and uses its own socket; `DIGEST_DUMP=1` prints what `digest` said in each run.
- Drawing again in place: the tree drawn as the empty board in front (`--board front --replace`), then again (`replace: took back`, the same shape count, on its plan, no warning), then refused with an arrow the user drew (one shape more than the drawing) and with a note titled as one of the digest's but for its case (nothing taken back either time), and a plan for the board itself refused on a board that isn't empty without `--replace`. The ingestion: `ingest --skip-read` on a two-module model with a spec that leaves out a file and names a module the code lacks (both said, neither stopping it), drawn as the board in front (its header the name the reader found, bands, cards), the digest's ranks and the left-out file's frame, then a rerun drawn in its place (said up front by `ready`), and what stops it before a digest is made: a board holding another drawing (with the way out in `ingest`'s own options), a new file's path taken, an app that isn't running. A second model has awkward names (a module called what a band is, a `]` and a `\` in names, one over 80 characters, paths that differ only by case, an `@[` in a doc and in the repository's name): drawn and verified, each reworded title said, the header's mentions escaped; and a module whose two folder boards differ only by case passes `check`. In the replace test, a drawing in place of the last one stopped part way (a tampered script) is drawn over as it was left, and again after Undo Draw brought the last drawing back (refused first with an arrow the user drew on it); `ready` refuses a `canvas` that doesn't measure and the take-back for a shape the user locked, shows the root first when the window shows a board inside the drawing (the app deletes no shape that holds the board shown), and refuses an `--into` title the file has and a new file in a folder that isn't there. The tool's own tests hold ranked rows, header text and headers that never clash, `redraw.mjs`, and the loop's rules: a popular node promoted whatever its trial measures (by the dial's count, the most arrows first and the first by title on a tie, left with its arrows on a board good enough as it is, never at mess 1), a summary that leaves out the moves taken back, a node that points at many fanned out (its uses pills beside it, their ends public, `direct` and `public: false` left), the longest arrow (set apart as a pill of its own; `direct` kept), an edge set apart leaving a shared pill, the gain rule and the cap for the judgment calls (`--popular` out of the way), and byte-identical output for the same input.
- `canvas measure` and `share:` are held in MeasureTests and DrawShareTests ([command line](command-line.md)).
- A change to `measure`'s answer or to how `draw` places a pill or a frame changes what the tool plans: run `DigestTests` (and `tool/test/run.js` under jsc and node) with it.

## Not built

- Updating a drawing shape by shape: `--replace` takes it back whole and draws it anew, so what the user changed in it goes too.
- A frame as a hub or an end of an edge.
- The layout's tuning (steady landscape boards, layered against stress by eye) and benchmarks.
