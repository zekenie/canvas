# canvas-digest

The canvas-digest skill: a large body of connected information (a codebase, an org, notes, a plan) laid out as boards by a tool outside the app, measured with `canvas measure` and drawn with `canvas draw`; the driver, the tool, the digest format, types in a digest, the plan, the public rule, drawing again in place, and the tests. The codebase ingestion built on it is [ingest](ingest.md)'s.

Related: [ingest](ingest.md) (the codebase ingestion, which draws through this skill), [command line](command-line.md) (`canvas draw`, `share:` on an edge and `canvas measure`, which the skill is built on), [types](types.md) and [relationships](relationships.md) (what a typed digest draws), [references](references.md) (the pills it promotes hubs into), [publishing](publishing.md) (what public means), [queries](queries.md) (what it asks the file for) ([every topic](../../CLAUDE.md#map)).

## Architecture

- **Where the layout lives.** Layout and promotion are the skill's, in `.claude/skills/canvas-digest/tool` (JavaScript, no dependency but ELK, vendored unmodified in `tool/vendor`: elkjs 0.12.0, whose `README.md` says where from, with its EPL-2.0 licence and an entry in `THIRD_PARTY_NOTICES.md`). The app measures (`canvas measure`) and lands shapes (`canvas draw`); `draw` never chooses an arrangement, and nothing in `Sources` knows the skill. The runtime is the system jsc (`/System/Library/Frameworks/JavaScriptCore.framework/Versions/Current/Helpers/jsc`), node as a fallback; the tool is plain ES modules that touch files only through the `io` main.js hands them, so one code base runs in both (jsc cannot make a folder: the driver makes `<out>/runs`, and hands the tool absolute paths, since jsc reads a relative one from where the tool is).
- **The driver, `digest`** (POSIX sh), is the only file that runs `canvas`: `check`, `measure`, `plan`, `draw`, `verify`, `all` and `ready` (whether a draw could start, for a caller with slow work to do first: canvas found, the app answering and both new enough to measure (one note measured: an app or a `canvas` from before `measure` is said here, not after the read), a board fit to be drawn as, the `--into` title free, a new file's path free and its folder there, and, with `--replace`, the take-back as a dry run, so a shape of the last drawing the app won't delete is said now (a window inside a drawing that is the board is shown its root first, as `draw` does); and the build the app says it is (`canvas status`'s `build:`) written to `<out>/app-build`, `unknown` if it says none: the one way a caller that says what drew its boards, as `ingest`'s header line does ([ingest](ingest.md)), learns it, since this driver is the only file that runs `canvas`; its GRAPH needn't exist yet), each taking the digest and a target (`--board <id> --into "Title"`: a new subboard of an open board; `--board <id>` alone: the board itself, which must be empty; or `--new-file <path>`: `canvas new`; `--board front` is the board in front, resolved to its id once, by `canvas boards`). `plan` hands the tool the view the boards are laid out for (`view_for`: `--view WxH`, else the room the target board's window has for a board fit into it, `canvas boards`' `view` ([command line](command-line.md)), read through the tool's `view` command as the plan is made and never kept, since a window is the size it is now; for a new file or no target, the window in front's; nothing with no window, or no canvas found, and the tool then assumes one), and `--ranks`. It finds `canvas` as `$CANVAS_CLI`, else beside itself (the app's, from `Contents/Resources/agents`; `build/canvas` in a checkout of this repository), else PATH, never the current folder's (looked up when it starts, and before the driver's own functions are in play: they are `run_canvas`, `canvas_try` and `canvas_to`, never a name `command -v canvas` would find), and sets `CANVAS_FORMAT=json` and a `--timeout` (120 s) on every call. It never parses JSON in sh: the tool does that (`extract titles|kinds|id|count|errors`, `into`, `clashes`, `check-text`, `runs`, `compare --text`, `replay`); `check` reads the tool's JSON (`extract errors`), never its words. **Errors reach the user:** the driver's own standard error is file descriptor 3 (`exec 3>&2`), and `die`, a tool that fails (`tool` sends jsc's and node's complaints there, and drops jsc's `Exception:` echo on standard output) and a missing canvas write to it, whatever a command's output was redirected to. `tool_to FILE ...` stops the driver when the tool fails. One query lists at most 10000 titles and can't be paged: a file with more titles than it lists is refused (`extract titles`) rather than checked against some.
- **The digest** (`reference/graph.md`): `title`, `text` (the first board's header note), `policy: {mess, promote, ranks}`, `nodes: [{title, kind, in, text, public, rank, source}]` (flat, `in` names the parent; a subboard's `text` is its description, mention text shown in the card's panel and drawn on no canvas (written in a run of its own after every shape has been drawn, since a mention may name a shape of any board; the board has no note for it); `rank` puts a container's ranked children in rows, lowest on top, title order in a row, or in columns, lowest at the left, title order down a column, whatever the arrows ask: a frame alone in its row is stretched to the widest row with what it holds centred, and one alone in its column to the tallest with what it holds at its top, `Layouter.ranked`, no ELK; which way is the view's to say, below, unless `policy.ranks` or `--ranks` says `rows` or `columns`), `edges: [{from, to, weight, text, via, direct}]`; a note may also take `schema`, `relationship`, `is` and `fieldValues`, and an edge `is`, `fieldValues` and `endRule` (**Types**, below). `source` (a path, or `{path, line}`: what the node was made from) is for the maker of the digest and ignored by the layout and the drawing. `check` refuses duplicate folded titles, titles over 80 characters, titles already in the file (one `canvas query`) and the first board's header note's title, kinds `canvas kinds` doesn't list, an unknown `in`, an edge to nothing, and `public: true` on a frame, and what is wrong with the types (below); it warns past 15 shapes in a frame and 150 on a board, for an edge dropped because it names a frame (a frame has no ports), for an untyped edge dropped beside typed ones, and for a type with no `text`.
- **Types** (`tool/lib/types.mjs`; the format and the refusals are in `reference/graph.md#types`). A node with `schema` is a type (a JSON object in the digest, written as `canvas draw`'s quoted string by `lit(JSON.stringify(schema))`), `relationship: true` a relationship type, `is` (a title or a list) a note of those types, `fieldValues` an object written as JSON; an edge's `is` names relationship types. `buildModel` keeps them (`schema`, `relationship`, `is`, `fieldValues` on a node, each with the `...Given` flag `check` reads) and makes of the edges of one pair **one edge to the layout** (weights added) holding an `arrows` list, one a distinct `is` (`isKey`: **a list of types is a set**, so `["R1","R2"]` and `["R2","R1"]` are one arrow, sorted for the key and for `verify` and `replay`; the same type twice is one arrow, its values joined **in a canonical order** (the edges of a typed pair, or of any pair that says `fieldValues` or `endRule`, are sorted by what they say, never by where the digest lists them, so the output is the same whatever the order, and a member two of them give different values is an error from `check` naming both edges, `edges[i]` and `edges[j]`); an arrow keeps the order of types written that sorts first, since `canvas draw` gives the order a meaning (a later type wins where two say the same) and `check` warns when one pair writes one set in two orders); an untyped edge beside typed ones is dropped with a warning (draw answers `ambiguous_edge` for an edge written without `is:` beside two arrows), and an edge between a type and a relationship type is an **end** (`isEndOf`: `edge.end`, forced `direct`, so no move makes it a pill, and left out of `pillTargets`). `typeProblems(model)` is what `check` adds (and `plan` and `measure-script` refuse on, `typedModel` in `cli.mjs`): an `is` that names no type, a relationship type on a note or a plain type on an edge, `is` on a frame, a subboard or a type (a type that builds on a type is not drawn), `relationship` without a `schema` or not a boolean, a `schema` that isn't an object or is on a shape that isn't a note, a `$ref` to `urn:uuid:` (`idRefs`; one inside the schema is fine), `fieldValues` with no `is` or not fitting (`checkValue`, `validateValue` its errors: `type`, `properties`, `required` as an own member, `enum` compared whatever order an object's keys are in, `items`, nested, a null no value, and local `$ref`s (`#/$defs/x`, `#/definitions/x`, any pointer into the type's own schema) followed with a guard against a cycle; not a member the schema doesn't name). A keyword the subset passes over on a value that has one (`anyOf`, `oneOf`, `allOf`, `not`, `if`, `const`, `format`, `pattern`, the bounds, `uniqueItems`, `additionalProperties`, tuple `items`, a `$ref` that names nothing or loops) is a **warning** naming the member and the keyword, once for the type, the member and the keyword (`typeProblems` collects `checkValue`'s `unchecked`), so a pass is never silent, `endRule` that is no `{needed, onlyOne}` of booleans or on an edge that is no end, an end that is a relationship or goes through a reference, and an end whose types are on another board than its relationship type. **Measuring** (`measureScript`) carries each type with its schema, each note with `is` and `fieldValues`, the ends and every typed arrow between notes (`noteTyping`, `arrowTyping`), so a note is sized against the ends the script draws, as one run is: `canvas measure` of that script was held, against a front board with the same titles, other fields and ends (and none), to the same sizes (a script's own types shadow the file's; an `is` can only name a type of the digest, which `check` refuses otherwise), so measuring doesn't depend on the board in front. **The runs** (`buildPlan`): each board's types, relationship types and the ends between them are one script, the run of the deepest frame any of them is in (`typedDepth`, whatever depth each is at; the ends after the shapes), no note of a type in it; the notes of a type are `NN-<board>-notes.draw` of their board, after every board's shapes, because `is:` finds a type anywhere in the file and a note must be created at the size it keeps (a note grows a row for each end of its types, and a type's note too, so an end drawn after them is a size changing after its run; what is drawn *at* a note never changes it: the rows are the ends', one line each); the arrows of relationships, each written with its `is:` and `fieldValues:`, are in the edge runs as ever, one line a typed arrow of a pair (draw reuses the pill the first made for the pair), and `plan.json`'s edges say `is` and `end`. `verify` and `replay` find a typed arrow by `from`, `to` and `is` (`landedRows` says `is` for an arrow; a result row has it). `compare` counts what a typed drawing says by design (`classifyWarning` `typed`: severity `incomplete`, an error with an `attribute`, `is needed`, `should have at most`, `runs from|to`, and a row's `problems`) in `warnings.typed` and `typedMessages`, said in the line and in `verify` and never failing; every other warning (a title near one the board has, say: class `other`) fails nothing and is said too, never only counted: the run's line names the first three (`otherMessages`) and `verify` the first five, with how many more; a push, an order warning, a shape off its box and a missing arrow still do, and so does a row's problem of class `wrong` **at a path** (`warnings.invalid`, in the mismatches): a value that breaks its field's schema, which `check` should have refused (a misfit, a row past Only one and a rule across fields are `wrong` too but have no path, and stay by design). The dry run is where it stops, before the value is drawn.
- **The plan.** `plan` reads `measure.json` (the answer of `canvas measure` to the script `measure-script` writes: every note and subboard and the first board's header, then one `edge A -> T via: reference` per end something points at, so a pill's width is measured, not guessed; the constants the layout places with, `referenceStep`, `defaultGap`, `frameInset`, `smallest.frame` and the gaps, come from its `constants`, with draw's numbers as defaults only when a key is missing) and lays out each board, inner boards first (what is public inside costs less outside). The loop's moves (`moves.mjs`, `promote.mjs`), each of which turns arrows into pills: **promoting** a node many point at (it is made public, and every user of it gets a pill, those in one frame sharing one by preference, a far group splitting off its own shared pill only when it saves at least `--prefer` (2) pills' prices, each shared pill beside its host, the user that keeps its group's arrows shortest), and **fanning out** a node that points at many (each of its uses on the board becomes a pill beside it, and what they stand for is made public; never an edge that says `direct`, nor one to a `public: false` shape). Popularity decides first, on a board that isn't good enough as it is (the dial's thresholds: a star of eight arrows that cross nothing is left with its arrows, since pills are for a mess): while it isn't, and a node has at least the dial's `popular` arrows that a move would turn into pills (pointing at it, or leaving it; arrows still drawn, counted afresh after each move), the one with the most is moved, the first by title on a tie (for one node, pointing-at before leaving), whatever its own trial measures (`mostPopular`; a measured gain is noisy enough to call a node with ten importers a loss), and such a move is never taken back. Then the judgment calls, as before: the best measured of the top candidates either way round (`candidates`, scored arrows x spread x (1 - tie), scaled by how badly those arrows do), kept when it beats the margin measured from the layout's noise, until the board is good enough, nothing beats the margin, or the cap (which counts the popular moves, and never holds one back). Last, no arrow runs longer than the dial's `longest` (`tooLong`): a plain arrow over it, or one into a pill others share, is set apart as a pill of its own beside its start (`state.apart`; its end made public) and the board laid out again from where it is, until none is left (each pass sets at least one more edge apart, so the passes end by themselves); `direct` edges and `public: false` ends are left. One dial, `mess` (0 tidy to 1 loose, default 0.1), sets them together: a pill's price, `popular` (round(4 + 10 mess): 5 at 0.1), `longest` (round(1000 + 3000 mess) units: 1300 at 0.1), the cap and the good-enough thresholds; `--cap`, `--margin` and `--popular` override the dial's; at 1, and with `--promote off`, no move is made and no arrow set apart (at 1 a node the digest pins, `public: true`, still has its users' pills: a pin is the digest's, not a move; only `--promote off` leaves those arrows too). The popular moves come in the same order at every setting, the dial saying how far down them the loop goes; the judgment calls after them start from wherever that leaves the board. Only the first board has a header note, `About <title>`, which takes ` (digest)` when a shape has its title (`buildModel`); a subboard's board has none (`headers` holds the root's alone). Every shape is placed at an exact offset: from the header note for the first board; for a subboard's board from two of its own shapes, because a gap is never negative: of the shapes on the board itself that the earliest run draws (a note that is of a type waits for the types, so those are the last), the widest, which none of them spans left to right, and the tallest, which none spans top to bottom, are drawn first (the first where the app puts a drawing with nothing to hang on, the second against it, whichever of the two can be placed against the other), and every shape after is placed against the first drawn shape it does not span on each axis (`against` in `emit.mjs`: `right of "A" left (gap: x)`, else `left of "A" right (gap: x)`, and `below "B" top (gap: y)`, else `above "B" bottom (gap: y)`; a shape that spans every drawn one on an axis is an error, naming it). The board's origin, where the plan's (0, 0) landed, is read off the two anchors, one for each axis (`anchors`; the header note for the first board). Output: `plan.json` (each board's shapes at exact offsets from its origin, its `anchors`, `described` (run to the cards it writes a description of), its pills, its edges in drawing order, `share` and `host`, `into`, `runs`), `report.json` (each board's moves in order, `mode` `in` or `out`, `popular` with its `arrows` or a judgment call with its costs; `promoted`, `fanned` and `long`; why each board's loop stopped; the public set with a reason for each) and `runs/NN-<board>-<step>.draw`, shapes first (a board's top level, then each depth of frames), then each board's edges: a shared group's host first and the others saying `share: "<host>"`. With `--into`, `runs/00-into.draw` makes the subboard and every shape of the root board is `in` it; compare reads that board as `root`.
- **Laid out for the view.** Every board is laid out to fill the view it will be seen in when it is fit to it (`Layouter.view`, the room the view has for a board: the driver's `--view`, else `DEFAULT_VIEW`, 1440 x 960, which the summary's first line says was assumed; `report.view` has it, `given` or `assumed`). Nothing in the layout is a board's own width over height: **`aspect` everywhere is how far a container is from the shape it is to be** (`offShapeOf`: how many times too wide for it, or too tall; a board's header note counted in, `shapeOf`; and where the view's size is known, how much larger the view would show the same room in its own shape, squared, which is the plain ratio for a board that outgrows the view and 1 for one the view shows whole at its own size, whose shape costs nothing). A board aims at the view's shape, a frame at the same (a look into it fills the view too), and a ranked container's children at their slots'. What a container's layout costs (`ownCostParts`) is its arrows, its shape (`shapeCost`: `SHAPE_WEIGHT` 10 a time off beyond `FREE_SHAPE` 1.1, scaled by its arrows) and the room it leaves empty (`FILL_WEIGHT` 3): the last two together are how small the view shows it. **What a container tries** (`separate`): with arrows among its children, layered with them running down and across and stress as it comes and stretched to the shape (`stretched`: the centers moved apart one way and together the other, which keeps which arrows cross; a warm layout keeps its stretch, `warmStress`'s `k`, and `relax` stretches it further when that costs less, since boxes grow as pills are put beside them), the cheapest kept; a tree down or across; boxes with no arrows packed to the shape (rectpacking's `aspectRatio`). An arrow that runs sideways from a note runs over the pills beside it, so a leaf with a column of pills is two boxes to an arrow (`leafItem`'s `nw`, an edge's `np`: the arrows that end at a pill beside the shape), or across would look free. **Ranked children** (`separateRanked`) run as rows or as columns, whichever the view shows larger (columns only when by 2% or more), chosen once a board on its first layout (`way`: the loop's moves are made for that way) unless the digest or the option says; each child is laid out to the shape of its slot (its share of a row of a board the view's shape, or of a column of one), and how wide the slots are taken to be is tried five ways, the cheapest whole kept. **At the end** the board is laid out from where it is and afresh, and its own container each way a container can be (`force`, the report's `finalWays`), each measured as a whole board is (`evaluate`, arrows over pills and all), and the cheapest kept with what its shape and the room it leaves cost counted in (`ev.shape`): a container's own cost is a guess at that. **Too long is as the view sees it** (`tooLong`: an arrow's run across divided, and its run down multiplied, by the square root of the view's width over height, clamped to 2), so a wide board's arrows aren't set apart for running the way the view is long; and **while they are set apart every shape stays where it is** (`Layouter.hold`: `pushApart` moves only what a grown box now overlaps, and what that overlaps), because a layout made again from a stress layout's own positions is another layout, with other arrows too long, and the passes would never end. The report has each board's `end.size` and `end.aspect`, and each container's `how` (`across`, `stretched`, `rows`, `columns`).
- **Crowded boards.** The search lays every container of a board out again from where it was, hundreds of times, and a warm layout is O(n²) a pass in a container's children (`warmStress`, `pushApart`, `stretched`): a frame of 532 notes took 85 s a layout, and its board would have taken hours (Medusa's admin dashboard, a default lens's folder). So a board with a container of more than `CROWD` (150) children, or more than `CROWDED_BOARD` (1,000) shapes in all (`promote.mjs`, `crowdOf`, decided by sizes alone, so a plan stays the same), is laid out once, afresh, and not searched: `report.stop` `crowded`, `report.crowded` (the container, its children, the board's shapes), every arrow on it drawn as an arrow but those to other boards, which are pills (their hosts the first title, `settle` not run), nothing promoted, fanned out or set apart; and a container past `CROWD` is packed as boxes to its shape (`chooseAlgorithm` gives it `rectpacking`, `layout.mjs`, which owns the number), its arrows drawn over them, since laid out by its arrows a star of hundreds (an index that imports every icon) is a tree as long as a row of them (465 notes, 122,512 units, past the 100,000 `draw` takes); the plan's warnings (`buildReport`, said by the summary) name the board and its frame and say to split it. The rest of the search's end is one closure (`done`), which both ways return through. A board that takes over 10 s to plan is said as it ends (`plan: board "X" (N shapes) took T s; n of N boards laid out`, through `opts.progress`, the plan command's `io.warn`), so a long plan is seen to move. Medusa's round-zero digest (272 boards, 5,533 shapes), which no plan had finished in 40 minutes, plans in 42 s.
- **Spines** (`layout.mjs`: `findSpines`, `spine`, `pillPlan`; the owner's mock B, approved in the app on 2026-10-18). A container (a frame, or a board itself) of two to six leaves (`SPINE_ROWS`, three rows: past them a spine is a strip whatever the view's shape, and the arrows from the far rows to a pill beside the middle one cross the cards between: at eight cards, twelve arrows run over cards), with no frame or ranked child, whose leaves don't point at each other and point at two or more targets in common (each used by two or more of them), is a spine, unless no arrow on a board is to be a pill (`--promote off`, the dial at 1: the Layouter's `spines` option). Every edge of its leaves is a pill (`pillPlan`'s `spined`, whose ends `madePublic` makes public), and it is laid out with no search: its leaves paired into rows by the targets they have in common (the first by title with the one it shares most with, and so on, a leaf that points at nothing after the rest), the first of a row on the left, two columns facing a column of the pills they share, each a box of the spine's own (`free`: its id `\u0003` and its group's key) at the mean of its users' rows, beside a row within a quarter of it, else between two. A pill every leaf that points at something uses is one (`users`); any other is split by the rows (keys `\u0002r<row>`), a part with two users one pill beside its row, a part with one its user's own pill on its outer side (a copy), a left leaf's column on its left (`leftSide`; `unit`'s `nx`, the column's width, puts the note at the right of its box; `from: left` on its edges). `emit` writes each spine pill's first user's edge (by title) with its place, `in` the spine's frame at its offset from the frame's top-left (from the board's origin, for a board that is one), and the other users' with `share: "<host>"`: draw places the stand-in an edge says, as a shape statement's ([command line](command-line.md)). `compare`, `verify` and `replay` hold its pills as any (each to the nearest planned spot). Beside it, a ranked container's slots aim at no wider than `SLOT_MOST` (3) times its own shape, or narrower than a third (`separateRanked`), so a band with little in it is no strip. On this repository the spines are the product band and "Things you do", and the other 66 boards plan as they did.
- **What is public.** Only shapes the run creates, in their own shape statements (`public: true`, so before any edge through them), and the report names them with why: pinned in the digest, an edge from another board points at it, `via: reference`, promoted, what a fanned-out node's pill stands for, or the end of an arrow that would run too long (`emit.mjs`'s `madePublic`). `public: false` in the digest means never promote it; `direct: true` on an edge means never a pill. The canvas skill carves this out of "making a shape public is the user's call"; a shape that was on a board is never touched: a digest draws a new file's board, a new subboard, or an open board as its own only when the board's file is empty (`canvas boards`' `fileShapes` is 0) or holds nothing titled but the drawing `--replace` takes back (`root_ok`, at `check`, `plan` and `draw`).
- **The gate.** Every run is a dry run first: `compare` holds each shape row's `at` (relative to its board's origin, read off its anchors) to the plan within a unit, and a `describe` run's rows to having changed the card they name (a card restated is no shape created: `plan.described`), and fails the run on a push (`pushedPast`), an unorderable placement or a pill pushed past a shape; the driver stops before drawing that script, naming the shape, exit 4. A shape the plan creates must come back `created`: one found `unchanged` is a plan drawn before (or a title taken), and fails the run. Pills are held as shapes are: a pill more than a unit off its planned spot fails compare and replay. Then the real run is compared again. A warning that shapes landed outside the window's view is not a failure (a big drawing outgrows the window; the camera is the user's). `verify` replays every saved real result in order (`replay`), checking each planned shape, pill and arrow landed, none was restated, and the file's titles hold them. Neither reads positions from the file: `canvas query` doesn't read where a shape is, so the result rows of the runs are the evidence.
- **Standalone steps.** `digest draw` checks the plan's titles against the file again (`clashes`: a title the plan draws, or the `--into` title, that the file holds stops it before the first script), and refuses a plan with a saved result (`results/NN-....json`): a plan is drawn once, and `plan` starts the results afresh. `digest plan --board` re-runs the title check (quietly unless it finds an error). When a draw stops after something was drawn, the driver says which scripts are on the board and how to take them back, for the target: one undo (Edit > Undo Draw) a script, or delete the subboard `--into` named; for `--new-file`, close the file's window without saving and delete the file. A cycle in `in` is refused by `check`, `plan` and `measure`, naming the titles (`buildModel`).
- **Drawing again in place (`--replace`).** `draw` keeps what a drawing makes in `<out>/drawn.json` (`redraw.mjs`'s `drawnRecord`: the board's file as `canvas boards` has it, and its id for a board with no file yet; the `--into` subboard or null; the first board's header; the titles on that board; every title; and `shapes`, how many the file held once it was drawn, or as far as it got, null while it draws), written before the first real run, so a drawing that stops part way is taken back as far as it got. With `--replace` and a `drawn.json` in the target board's file (`sameFile`: by path; a board with no file by its id and the drawing's header still in the file, since an id is the app's only while it runs), `check` and the clash test keep clear of the file's titles less the drawing's (`minus`). A digest drawn as the board refuses, before anything is deleted, a titled shape the drawing didn't make (`foreign`; titles match as the app tells them apart, spaces folded and case kept) and more shapes than the drawing made (`beyond`: an arrow or an untitled note added since). `draw` shows the board's root first for a digest drawn as the board (its first script goes on the board the window shows), and before any take-back whose shapes are all on the root board when the window shows another (`from_root`: the app deletes no shape that holds the board shown, so a drawing looked into, as the board or `--into`, is still replaced; a subboard on a board inside the file is left to the app's own refusal), then runs `replace.draw` (`replaceScript`: `delete` the subboard, which takes its board, or each shape on the first board the file still holds, their arrows and pills going with them), dry-run then real, one undo step, and, for a digest drawn as the board, holds `fileShapes` to 0 before drawing (a shape moved out of the drawing's boards is caught only here, after the delete: the message says Undo Draw brings the drawing back, as it does when a run stops before anything new is drawn). `verify` reads every title (`titles.all.json`). Without a `drawn.json` in that file, `--replace` changes nothing. **Until a drawing made in place of the last one is whole, the record is of both** (`drawnRecord`'s `over`; the last one's is kept as `drawn.prev.json`): their titles, their headers, what takes either back (`takes`, and `intos`, the subboards among them), how many shapes the file holds as the draw stops (`shapes`) and how many it held just before the take-back (`was`), because the driver tells the user that an undo a script and one more brings the last drawing back, and the next run must know the board for its own either way. `beyond` then allows a file with no more shapes than the part drawn, or with exactly as many as before the take-back, and counts anything else as added (an arrow drawn on either is still refused before anything is deleted); `replaceScript` deletes a shape a drawing put on the root only where it is on the root board (`extract root-titles`: a title one drawing has on the root the other may hold inside a subboard, and deletes on two boards are a script draw refuses), and an `--into` subboard wherever the file holds it. A run that stops with nothing new drawn puts the last record back, a whole drawing's record is its own again, and the record is written whole or not at all (beside itself, then moved). Stopped by hand (Ctrl-C), the draw records and says what is on the board as for any other stop (a `trap` around its loop). A drawing made on a board with no file yet is still known once the board is saved (`sameFile`: its id and its header, or the subboard it went into, whenever the record has no path; two paths that differ are two files). The record lives in `--out`, so a drawing made from another out isn't known to this one: its board reads as not empty. **With `--records DIR`** the records live in DIR instead, one for each file drawn in, so runs that each have an `--out` of their own (as `ingest`'s do) still know their boards, and a proposal drawn into a new file never replaces the record of the board in front: the run reads the record of its target's file as `<out>/drawn.json` (`select_record`, only with `--replace` and not for `verify`, since nothing else reads a record and a drawing writes to the one its path, or its board's id and header, name: the tool's `record-pick`, `pickRecord`, takes the record with a path that `sameFile` says before a record told by the board's id and header, over the records in DIR; the path needs no query, and the file's titles are asked for only when the path finds none and a record of the board's id could (`record-needs-titles`); of several records of one unsaved board (two digests drawn into it) the one whose header is this run's (`record-header`: the plan's when drawing, else the digest's) is taken, then the newest by the `at` each record has written in it (`drawnRecord`; not file times), then by name; a file in DIR that isn't JSON or has no `titles` list is skipped with one warning naming it (`readRecords`, the tool's `io.warn`, standard error); none for a new file), keeps it there while it draws and writes it back whole or not at all (`keep_record`), and a file with no record yet gets a name from its path (`recordName`, a hash of it) or, with no file yet, from the board's id and the drawing's header. `drawn.prev.json` stays in `--out`: it matters only while a run draws over the last drawing. Without `--records` nothing changes. `draw` numbers each run as it lands (`[n/N] ok ...`). `--board` takes a board's id, file or name, or `front`, resolved once by the tool (`boardField`): a file by its path as given or with its links resolved (the driver hands over both: the app lists the path a board was saved by; `/tmp` is `/private/tmp`), and a file or name two open boards have is refused with their ids. `plan` measures when there is no `measure.json`, and again when the digest is newer than it.
- **The codebase ingestion** (`.claude/skills/canvas-ingest/ingest`) is [ingest](ingest.md)'s: it makes a digest and runs `digest all` with `--records`.
- **Hubs and frames.** An edge that names a frame is dropped with a warning (a frame has no ports), so a frame is never a hub or an end of an edge; subboards and notes can be hubs (D9, narrowed).
- **Known and left.** `canvas measure` runs on the main actor (a `run:` command), so measuring a very large digest holds the window for as long as it takes. A promoted hub is measured without its Public chip, which it will have once drawn, so its `above` and chip width in `plan.json` are the unpromoted ones; positions are still held by the shapes' own rows. The view is the root board's, whichever board the window shows (a drawing made again from inside a subboard is the same drawing): a subboard's board, under the path's pill, has a little less room than that. A drawing is shaped for the window as it was when it was planned, and isn't laid out again when the window changes.

- A frame as a hub or an end of an edge.
- Types that build on types (`is` on a type), a relationship type whose ends are on another board than it, a digest that adds notes to a type of the file (an `is` names a type of the digest), and a typed arrow to a card measured (it is drawn; the measure script leaves it out).

- The layout's tuning by eye (layered against stress) and benchmarks. `longest` is the dial's alone: it doesn't grow with the view.
