# canvas-digest

The canvas-digest skill: a large body of connected information (a codebase, an org, notes, a plan) laid out as boards by a tool outside the app: it reads a graph document, measures it with `canvas measure`, decides where everything goes, and the app draws the result with `canvas apply`. The driver, the tool, the graph document, the plan, pills and private shapes, drawing again in place, and the tests. The codebase ingestion built on it is [ingest](ingest.md)'s.

Related: [ingest](ingest.md) (the codebase ingestion, which makes a graph document and draws it through this skill), [command line](command-line.md) (`canvas apply`, `canvas measure` of a document, `canvas kinds`, `:drawn-by`, which the skill is built on), [types](types.md) and [relationships](relationships.md) (what a typed document draws), [references](references.md) (the pills it cuts links into), [publishing](publishing.md) (what public means), [queries](queries.md) (what it asks the file for) ([every topic](../../CLAUDE.md#map)).

## Architecture

Three layers, each passing the rest through unread. The app owns every rule about shapes (what a kind takes, titles, types, channels, values, names, order of drawing). The render layer, this skill, owns only where things go. Ingest, or any producer, owns what the things are. The tool therefore **names no kind, attribute or channel** (it reads `canvas kinds`: what a kind holds, `shapes` or `board`, whether it is drawable, and the pills that can stand for it, `via`), never looks inside `props`, checks no value and decides no order of drawing. `tool/test/names.js` (`names-lib.mjs`, and a test in `run.js`) fails if any name `canvas kinds` lists is a quoted string literal in `tool/lib/*.mjs`; a build step may run it under jsc or node.

- **The driver** (`.claude/skills/canvas-digest/digest`, sh) is the only thing that runs `canvas`; the tool (JavaScript, run by the system `jsc`, else node) reads and writes files. Commands: `check GRAPH` (`canvas kinds` kept in `OUT/kinds.json`, then the tool's check), `measure GRAPH` (`canvas measure - --tightness` of the document as given, with `--board` and `--on` as apply takes them, so a pill is measured where it is drawn, kept as `OUT/measure.json`, then the `measure:` line and the tool's `tightness` line; the app answers with how alike each link's two notes are, by the embedding model's vectors of their words, and with a key saved in Settings it sends every note's title and text (a repository's code, for ingest) to OpenAI, only the texts it has no vector kept for), `plan GRAPH [--view WxH] [--ranks ..] [--current FILE]` (measures first when there is no measurement or the document is newer; first clears the last run's `drawing.json`, `report.json`, `carried.json` and `measure.carried.json`; then the tool's `cluster` over the graph and that measure (with `--current` and `--changed` when the file has the drawing: a shape a person carried into another container is grouped where it now is), its line printed, writing `OUT/clustered.json` and `clusters.json`, and `carried.json` when it carried something; then the tool's `plan` of the clustered document, writing `OUT/drawing.json` and `report.json`. With nothing carried the plan uses the same measure and nothing is measured a second time. With `carried.json` (a pill is sized from its note's container, and a carried note's is not the document's) the driver measures it, `canvas measure -` with `--board` and `--on` as the first was and no `--tightness` (the groups are found), into `OUT/measure.carried.json`, and plans with that; a failure of that measure stops the driver, saying what canvas said; `drawn-by` and `changed-by` still read the graph), `apply [--dry-run] [--on NAME] [--board ID]` (`canvas apply -` with drawing.json on standard input; the answer in `OUT/results/apply.json`, or `apply.dry.json`; a refusal, exit 1 and `{"error": {..., "refusals": [...]}}` on standard error, is printed by key with the app's message and hint, an edge by its ends, since the app counts edges by drawing.json's list; only a refusal says "nothing was changed", and a timed out apply says the app may still be applying it), `all GRAPH` (check, measure, the current query, plan (cluster included), `apply --dry-run`, apply), `ready` (canvas found, the app answering with a board open, `canvas help apply` known). `--out DIR` (default: the document without `.json`, plus `.out`), `--board ID` (reaches `measure`, the drawing-again query and `apply`), `--timeout S`. Exit 0 done, 1 refused or failed, 2 usage. It warns when the skills are from another build than the app (`build-id`). **When tightness is not there** the driver says why on standard error and goes on, the groups by the links alone (its messages say "clusters", the code's word for a group), each link weighing the same: an app whose `canvas measure` has no `--tightness` (an older one: the error says `has no option --tightness`; `digest: this app's canvas measure doesn't measure tightness (an older one), so the clusters are by the links alone`), and a measure that times out (`reason` `timed_out`; `digest: measuring tightness took longer than --timeout, so the clusters are by the links alone. The vectors that landed are kept: run it again before anything is drawn to use them. Once the file holds the drawing, a redraw keeps what is drawn (it finds the groups again only to weigh the links), so to group it again from the tightness, draw into a new board or file`: the app keeps each vector that landed, so a later run asks only for the rest, and the driver's `--timeout` (default 120) wins over the flag's own 120 s); either way measure is asked again without the flag. Any other failure of the measure, a message that only quotes the word tightness (a note titled so) among them, is `digest: canvas measure failed:` with what canvas said, and is not asked again. An app that answers with the member but says it is `unavailable` (no OpenAI key, a failed request) is the tool's: its `tightness` line says why, and the summary says the groups are by the links alone. Nothing asks before sending: a key saved in Settings is the opt-in.
- **The graph document** (`reference/graph.md`; the contract is the spec's §1). `drawing` (the app's record is by it), top-level `layout` (`placement`, `ranks`), `nodes: [{key, kind, in, props, layout: {rank, pill, placement}}]`, `edges: [{from, to, key?, props, layout: {weight, direct}}]`. The tool reads `key`, `in`, `kind` and `layout`; `props` and an edge's `props` pass through to drawing.json as parsed. Keys are the layout's identity (nodes are sorted by key, so a row keeps key order); titles matter to the tool nowhere and may repeat.
- **The checks** (`check.mjs`, over `model.mjs`'s `readGraph`): structure the layout needs, and nothing the app owns. A key a non-empty string and unique (and not `root` on a node that holds a board: the layout's name for the drawing's own board), a kind `canvas kinds` lists as drawable, `in` naming a node whose kind holds shapes or a board, no cycle in `in`, edge ends naming nodes, the layout hints' types, `layout.pill: true` only on a kind some pill stands for and not on a node that holds shapes. Messages name keys. A refusal the app has (a title, a value, a type, a channel) comes from the app, when it measures or applies.
- **Measure** (`sizes.mjs`). `canvas measure -` answers `nodes[key]` (`size`, `above`, `titleWidth`), `pills` (`for`, `from`: the key of the frame or subboard that holds the other end, null for the top of the drawing's board, with `size`), `edges` (those the app would refuse, by place in the list, with reason, message and hint) and `constants`. `sizesFrom(model, measure)` is what the layout reads: each leaf's size, the room its title takes above it (`above`) and its title's width, each frame's smallest, **title width** (a frame is never narrower than its title) and `above`, the edges the app draws as one arc through a node (`lines`: measure's, each half by the ends of its edge; one the model left out leaves the line out), a pill's width by `pillKey(for, container id)`, the constants (pill height, step and gap, the frame inset, the smallest frame). An edge the app refuses is left out of the layout and of drawing.json, with a warning quoting its message and naming both keys. A node the measurement has no size for is an error naming the key. `tightnessFrom(measure)` reads the `tightness` member `canvas measure - --tightness` adds (how alike each link's two notes are: `model`, `texts`, `asked`, and `pairs` of `a`, `b`, `board`, `tightness`, the centred cosine of the two notes' embedding vectors, centred on the board's mean) into `{by, why, of}`, `of` a Map from the pair's two keys (the lesser first by code unit, sorted here whatever order the app gave) joined by a NUL; `by: null` with `why` where the app has none to give (`{unavailable, reason}`: no key, no model, a failure) or says nothing (an older app).
- **The model** (`model.mjs`). Nodes by key with `holds`, `parent`, `chain`, `board`, `frames`, `container` (`b:root`, `b:<subboard key>`, `f:<frame key>`), `pin` and `never` (`pin` from `layout.pill: true`; `never` from `layout.pill: false` or a kind no pill stands for), `rank`, `placement` (and the document's, `model.placement`); boards (root first, then subboards by depth); edges between one pair are one edge to the layout (weights added, `items`: the document's edges it stands for); `direct` is `layout.direct`, or an end that holds shapes. Left out with a warning (in `model.warnings`, `model.dropped`): the app's refusals, an edge between boards at a shape that holds shapes, an edge between boards to a kind no pill stands for. `forcedTargets`: the far end of an edge between boards, and pinned nodes (the pill targets whatever the cut; the check that throws when a `layout.pill: false` node is reached through a pill uses it).
- **The layout** (`cut.mjs`, `planarity.mjs`, `layout.mjs`, `stars.mjs`, `strips.mjs`, `restore.mjs`, `scene.mjs`, `cost.mjs`, `elk.mjs`, `geom.mjs`): the plan of [docs/plans/board-layout](../../docs/plans/board-layout/README.md), slices 2 and 3, which replaced the mess dial's search (no knob trades crossings for pills). **The cut** (`cut.mjs`'s `cutBoard`, a board at a time): each container's links (each of the board's links lifted to the container that holds both ends, between the children that hold them) are made planar (`planarLinks`: the pairs a link marked direct, a link at a frame, or one into a node no pill may stand for joins are kept whatever, `cuttable`; the rest added the most wanted first: among ranked children the nearer ranks before anything else, the longest spans last; then by weight, then the busier end's degree, then the quieter end's, then key order; and a pair that would make the graph non-planar cut, every link of it a pill beside its start: `planarity.mjs`'s `planarCut`, greedy over the left-right planarity test, `isPlanar`, linear in the graph); then the board is laid out and measured as the drawing will be (`health.mjs`'s `readLayout` and `boardHealth`, on the layout), every crossing and every arrow over a shape naming the plain arrows in it, the links in a conflict that the stars placement could not draw clean cut first (`excusedPairs`), then the link in the most conflicts (ties: the least wanted, `worth` compared member by member: weight, the busier end's degree, the quieter end's; in a document clustered by tightness the least wanted comes first and the most conflicts break the tie, `conflictCuts`' `leastFirst`, since its weights say how alike two notes are) until each is mended, and laid out again from where it was, until clean or nothing cuttable is left (`ROUNDS`, 8); a conflict with no arrow the cut may take (between frames, which are drawn whatever) turns the container in rows that holds its arrow into stars, once (`stuck`, the Layouter's `asStars`, which the report lists), which places its children off each other's arrows, unless the document asks for rows there (`askedPlacement`: the node's `layout.placement` or the document's), when the board is said not clean. Ranked children are laid out a few widths at a time (`separateRanked`), and each attempt's stars state (`starsAt`, `altAt`, `altOf`, `starsNotes`, `starsFinal`) is kept apart and the chosen one's left for the next round; a stars layout's state is set from its result whether it was made or found in the cache. Each container is placed (`chooseAlgorithm`, by every link among its children, drawn or a pill, so a cut never turns stars into rows; one with no arrow left is packed as boxes): **stars** where its links have a cycle (`stars.mjs`'s `starsLayout`: the drawn links as points, by stress (SMACOF, from a spiral) where no two of them cross, else from the links' planar embedding (`planarity.mjs`'s `planarEmbedding`, triangulated, drawn by `planarDrawing`: Tutte's barycentric drawing, in which no two links cross) relaxed toward the stress points only as far as keeps every link uncrossed; then the children put down one at a time, the most linked first, each at the clean spot nearest its neighbours already down, in the direction the points put it from them (no box on another, no arrow over a box, a pill or the room a title takes, none crossing, none through its own or a neighbour's pills), with the arrangement of its pills (below) that its arrows leave free; an arrow no spot lets out is excused (`onExcused`), left out of what clean means there for the cut to take; then compacted (each child moved toward where stress wants it, and each note's pills given a smaller arrangement, only where the container stays clean), unlinked children on a shelf; a drawing more than 2.2 off the view's shape (`OFF_SHAPE`), in a container of up to 12 linked children (`STRETCH_MAX`), is also tried stretched to it; a spine's shared pills are children too, kept 24 from the rest. While the cut loops, the children start where they were (`starsKeep`): those still clean stay and the rest are put down again, and where one lands far from its links (its neighbours' pills grew into the room beside them) every child is put down afresh from the planar drawing, taken when that excuses no more arrows and its area is under 0.8 of the kept one's (`KEEP_WORTH`). On a clean board each stars container is gathered once (`gather`: each child drawn toward the middle, its neighbours or where stress wants it, while the container stays clean), kept when the whole board stays clean and is smaller), **rows** where they have none (ELK layered, down or across, the cheaper by cost.mjs's `ownCost`; a forest as ELK's tree), and `layout.placement` (the document's, or a frame's or a subboard's node's) over it; ELK spaces a rows layout's parts that no arrow joins 64 apart, as it spaces any two boxes (packed inside a frame they may come as close as 40 across, never under 64 down, so none is on the title above another). **Pills** (`strips.mjs`'s `stripAlts`, each leaf's arrangements, `alts`, and which it takes, `altFor`): a leaf's pills stand in short strips beside it, at most 8 in a row or a column (`MAX_ROW`, `MAX_COL`), each joined to its note by a straight line that runs within 8 of none of its other pills. An arrangement is a row below or above the note, a column on its right or left, two sides meeting at a corner, three sides (a U open on the fourth), or all four; a row of more than 8 is staggered layers, the outermost placed first and each inner layer's pills in the gaps its lines leave, the widest pills nearest the middle, each strip at the least distance from the note at which none of its lines runs over a pill; the splits of the pills over the sides are built cheapest first and the smallest kept. In stars, a leaf takes the arrangement its arrows leave free (the sides they leave least); in rows, one on the sides its arrows don't run to; a spine's leaf one that keeps the spine's side clear. A column whose lines may run over its own pills (`column right`, `column left`, `own` counting them) is taken only where no strips fit. Every pill is its link's alone until the cut is done, a spine's shared pills aside. What the layout decides by is the same under jsc and node: it measures and turns with geom.mjs's `len`, `cosd`, `sind` and `atan2d` (square roots and the four operations) and stars with constants, never `Math.hypot`, `cos`, `sin`, `atan2` or `log`, which engines round their own way; the corpus's drawing.json is byte for byte one under both. **Spines** (a frame or board of two to six leaves that don't point at each other and share two or more targets: two columns facing a column of the shared pills, no search), **ranked** children (rows or columns, whichever the view shows larger, `layout.ranks` and `--ranks` over it), **the view** (every container aims at the view's shape; `--view`, else 1440 x 960, said by the summary), and **crowded boards** (a board or a frame holding more than 150 children side by side, or a board of more than 1,000 shapes in all, is cut to planar and laid out once, its `stop` crowded unless it comes out clean all the same; the report's warnings say to split it) are as they were. The report (`cut.mjs`'s) says each board's `links`, `cut` (the planar cut) and `cutFurther`, `rounds`, `stop` (clean, not clean, crowded), `placement`, `algorithms`, `precut` (the links cut between groups before anything was placed), `restored` (the links put back as arrows at the end), `restoredCut` (those of them that were cut between groups) and `sharedByDrawing` (the pills shared at the end), and in `end` its `pills`, `arrows`, `sharedPills` and `sharedLines`; the summary's first line how many pills are shared and how many lines run into them, and a `cut:` line of the totals.
- **Frames laid out with their container** (`layout.mjs`'s `findFlat` and `separateFlat`, `stars.mjs`'s clusters): a frame of two or more notes (no frame, rank or spine in it, no link at the frame itself, rows not asked of it) one of whose members a note beside it links to, in a container placed as stars, is not laid out on its own first: its members are children of the container's stars layout, each pair of them held near (`COHESION`), put down before the rest, one frame after another, each member where it blocks least the ways out the members need to the shapes they link to (`BLOCKED`), and the frame is the box drawn round them (`hulls`), which no other child, and no arrow that ends at none of its members, may come near. In a container with such frames an arrow no spot lets out costs a spot 9,000 units of distance (`FRAME_FAIL`), so the rest is put down round the frames and the board stays small. The cut, the excusal and the check so see the line to the member itself, and a member that a shape beside the frame links to sits on the edge toward it. Each such frame is then settled as a container of its own, its members where stars put them; a board that still ends unclean is laid out again with its frames as boxes. Every other frame is laid out as before, inside first, then as one child of its container. On a redraw a frame is kept as the file has it, its cut the file's (Drawing again in place).
- **Links put back** (`restore.mjs`'s `restoreByDrawing`, at the end of `cutBoard`, before the pills are shared, on a board that is clean and not crowded): the cut decides before the notes are placed, so a link it made a pill often has room for its line on the finished drawing. Each such link (its own pill on the board; not a spine's, not marked direct, not into a frame, not half of a line through a node; one cut between two groups (`layout.cut`) is as eligible as any other, and counted apart, `restoredCut`) is an arrow again, its pill gone, where that arrow, bowed as the app bows a second arrow between two shapes, crosses no line and runs within 8 of no note, title room, frame or pill (its own ends' pills too); where only the pills of up to three other notes are in its way, those notes take another clear arrangement of their pills. The note's other pills are packed smaller where they fit (`repack`). The most wanted links first, as the cut ranks them, and again the shortest first, whichever puts back more; a second sweep tries what the first could not. No note moves. Measured as the app draws it: an arrow in a conflict is given up, and the result is kept only where the board ends clean. `scene.mjs` holds the drawing as obstacles on grids that this pass and sharing ask what is clear.
- **Shared pills** (`share.mjs`'s `shareByDrawing`, at the end of `cutBoard`, on a board that is clean and not crowded): in each container, the notes that use one target (a spine's leaves aside) share a pill wherever the drawing has a spot each of them reaches by a straight line. No note moves and no link is cut, so sharing never costs an arrow. A spot is taken when the pill's box is 16 clear of every note, title room, frame that holds neither end and pill; a note reaches it when its line (every edge it stands for, bowed as the app bows them) runs within 8 of no shape or pill but its ends, its own pills included, crosses no line but those at its ends, and is at most 1,200 long (`MAXLEN`). The candidates are the users' own pills' places, rings round the users and between them, inside the container (inside its frame for a frame's). The targets with the most users go first, each covered by the spot the most of them reach (then the shortest lines) until fewer than two are left; the rest keep their own pills. The first user by title makes the pill (`place.pill`), the others `share` it, and a sharing note's other pills are packed again in the smallest strips that fit, the note where it is (`repack`). The board is measured as the app draws it: a line in a conflict gives its note its own pill back, a pill left with one user goes, and up to three passes run, each on the drawing the last left; the result is kept only where the board ends clean.
- **The plan** (`plan.mjs`, `emit.mjs`). `planGraph(graph, sizes, options, elk)` builds the model, lays out every board (inner boards first), and returns the plan (`buildBoards`: each board's shapes and pills in board coordinates, the layout's own record the tests read), **`drawing`** (`buildDrawing`) and the report. drawing.json is the document as given (every field of every node and edge, in the order given) with `place`: a node's `at` is its box's top-left from its frame's top-left when its `in` is a frame, else from its board's origin, `size` its box's (a frame's the layout's; any other node's the measured size, rounded up); nothing is shifted and a number may be negative. An edge the layout draws through a pill has `place.pill`: the host's own edge (the first edge of the pair) `{at, in?}`, the pill's top-left from its frame's top-left (`in` the frame's key) or the near end's board origin; every other edge of that pair, and every user of a pill someone else makes (a pill shared by notes is made by the first of them by title), `{share: <the host's node key>}`. A pill stands for the `to` end beside the `from` end (an edge between boards is a pill for its end on the other board, beside the end on this one). The makers come before the sharers in the list; every other edge keeps its place in the list. A self edge and an edge with no pill stay unplaced (the app draws an arrow). Edges the model left out are not in it.
- **Health** (`health.mjs`). Every plan measures every board on its drawing, whatever laid it out, so each later layout is judged by the same measure (the owner's ask: [the plan](../../docs/plans/board-layout/README.md)). `healthOf(model, drawing, sizes, {view, ms, bendOf})` reads drawing.json back as the app will get it: each node's box from its place, in its board's coordinates; each pill where its edge places it, as wide as the measurement says for what it stands for and where it is; each edge a line, straight (or bent, `bendOf`: the tool bends none yet), and an edge with no bend that joins two shapes another edge joins already bowed apart from it as the app bows it (`ArrowPairs.swift`: the lowest slot free, 0, +1, -1, ... times 34 units; the app's side goes by the shapes' ids, the check's by their keys). It counts **crossings** (two lines that share no end and cross; arcs sampled), **lines over shapes** (a line within 8 units of a note, card, frame or pill, or of the room its title takes above it, that is none of its ends nor a frame holding one; a note's lines into pills over pills it uses itself, its own and those it shares, are `overOwnPills`, counted apart and failing nothing; the layout keeps them away, strips built clear of a note's other pills and a shared pill placed only where each user's line is clear of them) and **shapes on top** (two overlapping by more than a unit, neither holding the other, or one on the room another's title takes above it: measure's `above`, as wide as its `titleWidth`, else the shape). Beside them: `links` (pairs of nodes on the board an edge joins), `cut` (those with no arrow: all through pills), `pills`, `size` (the shapes with their titles' room and the pills) and `fit` (the zoom a window of the view shows the board whole at, at most 1), and `seconds` (its layout's). A board is `clean` with none of the three, else `not clean`; nothing is refused. `report.boards[b].health` holds each board's, with five `examples` by key; `report.health` the totals and the margin; the summary a line of totals and the five least clean boards (`healthLines`). The constants are `HEALTH`'s (margin 8, overlap 1, an arc's 16 samples, the pair bend 34). Measured with the spike's rules (a line over a shape only inside it, no title's room, the second arrow of a pair straight) it agrees with the spike's own measures board by board on this repository's 71 module boards. A relationship type's two ends that the measurement names as one line (`sizes.lines`) are drawn as the app draws them where both are arrows into the type itself, on one board, their far ends two shapes (`throughLines`): one arc through it, each half the part of the circle through the far ends' middles and the type's away from the other's far end (`geom.mjs`'s `throughBend` and `isStraightThrough`, Arrows' `ArrowThrough` ported), straight where the three are on a line; an arc is sampled a point every 40 units (400 at most), and a board's `size` counts its lines, so an arc that loops off the board shows in `size` and `fit`.
- **Pills and private shapes.** Every shape is public unless a person made it private (`private: true`), and the tool makes nothing public or private: a pill can stand for any shape it draws but a private one, which the tool can't tell (it reads no `props`), so a document that makes a node private keeps it off pills with `layout.pill: false` and draws no edge to it from another board, else `canvas apply` refuses the pill by the node's key ([drawings](drawings.md)). The report names no public list and no reason for one: what became a pill is counted in each board's `cut`, `precut`, `cutFurther` and `restored` (the links the drawing put back as arrows) and in `totals`. A spine's targets and the far ends of edges between boards are pills by the layout. `layout.pill: false` means never a pill target (no link into it is cut), `layout.pill: true` pins one, `layout.direct: true` that an edge is never a pill.
- **Drawing again in place** (the plan's slice 5: `plan.mjs`'s `currentFrom` and `changedFrom`, `cut.mjs`'s `redrawBoard` and `fileCut`, `layout.mjs`'s `keepFrozen`, `stars.mjs`'s `putDown`). A redraw moves a shape only for a reason: the document changed it, something the document changed needs its room, or what a person just changed is on it. `digest all` writes `canvas query ':drawn-by("NAME")' --brief` as `OUT/current.json` and `canvas query ':changed("NAME")' --brief` as `OUT/changed.json`, and `plan --current --changed` starts from them. `:drawn-by` has a row for every shape the drawing made, in world units: a node's `{id, key, at: [[x, y], [w, h]], board, inside, in}` (`in` the key of the drawing's shape that holds it, a row with none on the drawing's board; `inside` not read), a pill's, keyed `pill <the record key of the edge that made it>`, and an arrow's, keyed `edge <record key>`, with no `at` and its `connection` (`from` and `to` its ends through any pill, `via` the pill it runs into); a list or `{rows, absent}`. No rows (the file lacks the drawing) starts the plan afresh; any other failure of the query stops the driver, saying what canvas said, since drawing afresh would move a person's shapes back. `:changed` has a row for each of those shapes a person changed since the drawing last wrote it, `changed` saying how (`moved`, `resized`, `frame`, `board`, then property names); an app that doesn't know the word is said and the plan goes on without it, and any other failure stops the driver as `:drawn-by`'s does. **The cut is the file's** (`fileCut`): an edge whose row has no `via` is an arrow; one whose row runs into a pill goes through it, the edge whose record key the pill's row has making it and the others sharing it, the maker first. Only an edge with no row (a new link) is decided: an arrow where its line is clear, else a share of a pill the file has for that shape, else a pill of its own. The record key is the app's (`DocumentApply.swift`'s `edgeRecordKeys`: an edge's own `key`, else `A -> B`, then each value that tells a pair's arrows apart, then ` #n`), matched by its beginning, so the tool names no attribute. **Every shape stays where the file has it** (`keepFrozen`): each container as the file has it, a frame at its size; what the file lacks (a new note, one the document put in another container) is put down at the clean spot nearest what it links to, with its pills (`putDown`); a longer note grows where it stands, a note with new pills takes another clear arrangement of them where it stands, and what such a note then covers is put down again, as near where it was as is clean; what is put down in a frame is looked for inside the frame's current box first (the spots round the held shapes, the spots touching one at exactly the gap, the frame's top-left corner: the room a person's note left is the note it covers' to take), and, where none there is clean at the stars gap, at the least gap (8, a pill's margin), so a room the file drew tighter than the gap is still room; two notes an arrow joins keep the stars gap (40) even then, between their own boxes, where the arrow runs, and 8 between their footprints, as between any two children; the frame grows only where nothing there is clean even so (a covered note whose pills make it taller than the note it covers was can still make it grow). A new note's spot is scored by its links' weights: each placed neighbour pulls by the weight of its link to the note (`layout.weight`, of the links on the board, drawn as arrows or as pills, so a pill's link weighs what its weight says) over the mean of the note's own links (the cap of 3 on the links as a whole), and where all its links weigh the same, arrows and pills alike, nothing is weighed and the choice is the unweighted one. A shared pill put down again in a frame stays inside the frame (the frame grows right and down for it where it must). Ranked bands are turned only where the file's way is plain and is not the one `--ranks` asks. **What a person changed is held** on the redraw that sees it (`changedFrom`): a shape they moved, resized or carried into another container stays exactly where they put it, at the size they gave it (a note they only moved takes its text's size), never put down again nor pushed by a frame that grows; its pills are set again about it, in the smallest arrangement clear of what the file has, where the shapes it covers, their pills and the lines to them count for nothing (they are put down again, and a covered note's pill under the place its own pill would take is the room the person's note left, the covered note's to take before any frame grows); a shape of the drawing's own that it now covers is put down again (its `moved` why: a person's shape covered it; one that only a frame grown about a person's shape reaches says a frame grew); one carried into another container is drawn in it (`report.carried`). The document's own change wins: a shape the document put in another container goes there, a person's move or not. Two of a person's shapes on each other both stay, and the report names the conflict as theirs. On a later redraw the app no longer says the shape was a person's (`canvas apply` wrote it where they left it), so it is kept as every shape of the file is, in place and moving only for a reason, the least it can; a carried shape goes back to the container the document has it in. **Then mended** (`frozenCuts`): a conflict something this redraw changed is in (a new link's line, a note put down or grown) is mended by cutting the link in most of them, sharing a pill the file has, setting a note's pills again or putting the note down again (never a person's, nor a note the file has on another's room, which someone put there), `ROUNDS` at most; a conflict among shapes as the file has them is the file's, left as it is. A board is laid out afresh only where the file holds none of it (or reading it threw); one the mend can't clear is kept, `stop` not clean, and what is left said. Nothing is put back or shared after: a pill stays a pill. **The groups only weigh the links** (`cluster.mjs`'s `clusterGraph` with `current`, and `changed`; the driver gives `cluster` the same two files as `plan`): `carried` runs first, so a shape a person carried into another container is grouped where it now is, and the groups are then found afresh over that document, with today's tightness, only to weigh and cut its links (`layout.weight`, `layout.cut`). What `clustered.json` holds is the document's own, in its own containers, with only those marks (`layout.cut`, `layout.weight`, `layout.clustered`): the plan carries the shapes itself, so `report.carried` and the summary's `redraw:` line say what was carried. `clusters.json` has `carried` (`[{key, in}]`, `in` the container it was carried to, null the board) when something was, and `cluster` then writes `carried.json`, the document with those shapes there, which the driver measures (above); none carried, no `carried.json`. The cluster line on a redraw says the groups only weigh the links and the file's arrows and pills stay, not that the cut links come back as arrows. They keep, add and move nothing of the file's: `fileCut` leaves every link the file has a row for as the file has it whatever the groups now say, and what it decides of a link is a new one's, above. So an unchanged document redraws with every place as it is, whatever the tightness the app says now (this repository's 72 boards in a few seconds, from the app's own rows). To group a drawn board again from the tightness, it is drawn into a new file (the drawing is found by name in the file as a whole, so a new board of the same file is redrawn in place), since a redraw keeps what is drawn (the canvas-digest skill says so, and so does the driver when the measure times out). The report says per board `kept` (its containers), `afresh`, `moved` (each of the file's notes and frames put elsewhere, `{key, by, why}`), `held`, `carried`, `putDown` and `conflicts`, and the summary's `redraw:` line the totals. A row's `at` is the frame each shape is laid out in (`canvas query`'s, [queries](queries.md)), which `canvas apply` places, so a relationship type's pill, drawn about the middle of a taller box, is read where it is drawn. A pill the plan puts elsewhere than it is, or in another frame, is moved there by `canvas apply` ([drawings](drawings.md)), and an edge the plan draws straight that went through a pill, or the other way round, is drawn anew.
- **Clusters** (`cluster.mjs`, a pure transform of the graph document run before the plan; the driver runs it between measure and plan; the strategy of the board-layout plan's Groups, [docs/plans/board-layout](../../docs/plans/board-layout/README.md), whose spike found it). The code's word for a group is a cluster. `clusterGraph(graph, measure, {kinds, res})` groups each container's shapes by how tightly their links hold them and returns `{graph, report}`. **It adds no shape and moves none**: no frame, no container, and nothing across the board and frame the lens put a shape in; the groups only weigh the links and cut those between groups. On every board with a link between two notes (a *pair*: the links between two notes either way, a shape that holds shapes is no end of one): a pair weighs 0.1 for the board's loosest to 1 for its tightest, by its place in the board's order of tightness (`tightnessFrom`, below: a rank, not the tightness itself), or 1 each where there is none; topology first, so a frame of the document is one item in what holds it, each pair lifted to the container where its ends' containers meet, between the items there that hold them (the note, or the frame it is in), the lifted weights added in pair-key order, and a frame's own notes are grouped inside it; each container's items are grouped by `louvain` (modularity at resolution 1.5, `RESOLUTION` or `opts.res`, a number above 0, where a higher one makes smaller groups; items in key order, a tie to the lower cluster, `1e-12`, 20 levels of 100 passes) so the same document and tightness give the same groups; and a pair between two groups is **cut**: each of its links gets `layout.cut: true`, a pill before anything is placed, unless a link of the pair may not be a pill (`cuttable`: `layout.direct`, or into a node marked `layout.pill: false` or of a kind no pill stands for), which keeps the pair an arrow. A link cut so may come back as an arrow once everything is placed (Links put back). With tightness each pair's links also get the weight the engine's own further cuts, mend and put-back go by (`layout.weight`): the cut pairs 1..49 and the rest 50..100 by tightness rank, the loosest lightest (the spike's formulas, parentheses and all: `Math.round(50 * (i / (n - 1)))` is not `Math.round(50 * i / (n - 1))`, which differs at 2 of 101 ranks, rank 29 among them); without it the lens's own weights stay. The top-level `layout.clustered` is `{by: the embedding model's name}`, or `{by: null, why}` where there was none (no key, an older app: groups by the links alone, each weighing the same, and the summary says so). `report` (`clusters.json`) has `tightness`, `resolution` and `totals` (`boards`, `links`, `cut` and `missing`), and the boards with a pair only, each with `notes`, `links` and `cut` (pairs, not edges: a pair's links are one pair), `clusters` (sizes of the linked notes' groups, largest first), `levels` (each container's items and the group each is in) and `missing` (the pairs the app's answer had no tightness for: they weigh as the middle, 0, so they're counted). On a redraw the groups are found again only to weigh the links (Drawing again in place). A document that has `layout.clustered` is refused (the lens's own document is clustered once); a lens's node may have any key, since the tool makes none. `cluster.mjs` writes no kind, title or text by name.
- **The model's hints for the cut** (`model.mjs`): `layout.cut` on an edge (true or false; refused unless the document has `layout.clustered`, being the tool's own; refused with `layout.direct`; and an edge cut into a node no pill may stand for is refused naming its ends) makes the model edge `precut`; `layout.clustered` at the top must be `{by: string|null, why?: string}`. `planarLinks` takes the precut links out first (a pair keeps the rest of its links and goes when none is left, before anything is counted or ranked: the degree tie-break counts the pairs that are left; a pair that holds a link no pill may stand for, `kept`, stays a pair of those links alone, so a link cut between groups that was lifted into the same pair of children as such a link is still cut and no arrow for that reason; `report.precut` counts every link cut so), and `restoreByDrawing` puts one back like any other where its line is clear (`candidates` has no `precut` guard); a redraw's `fileCut` leaves every link the file has a row for as the file has it, so a new link cut between groups is decided as any new link is (an arrow where its line is clear, else a share of a pill the file has, else a pill of its own). The report's `cut` is the planar cut alone and `precut` those the groups cut, per board and in `totals`, with `restored` and `restoredCut` (those put back that were cut between groups); the summary's `cut:` line gives them, `N of M links made pills: P between groups before anything was placed, C so each board's links are planar and F more where a drawing still crossed or ran over a shape; R of the P between groups and S of the others put back as arrows where the finished drawing had a clear line`.
- **The commands of the tool** (`cli.mjs`, `main.js`): `check`, `check-text`, `cluster` (`cluster GRAPH MEASURE OUTDIR --kinds K [--current C [--changed D]]`: `clustered.json`, the document, in its own containers, with `layout.cut` on the links between groups and `layout.weight` on every link, no shape added or moved, `clusters.json`, `carried.json` (the document with the shapes a person carried into another container there, when there are any, for `canvas measure`), and one line: how many pairs of the linked ones are cut before anything is placed, and by what tightness or why by none), `tightness MEASURE` (what the app said of tightness, one line: how many linked pairs of notes, by which model, how many texts were asked for), `plan`, `name`, `drawn-by` (the query that finds the drawing's shapes, `:drawn-by("NAME")`; once `query`, a word `canvas kinds` lists as an attribute, which the names rule refuses as a literal), `view` (the room `canvas boards` says a board's window has, `WxH`), `count`, `refusals`, `applied`, `extract kinds|errors`; the usage lists them with the cut and the view.

## Not built

- Drawing part of a document: `canvas apply` is all or nothing.
- A view for each board (a subboard's has a little less room); a board laid out again when the window changes.
- A frame as a hub, or at a pill.
- Groups by anything but links and tightness (a title's folder, a person's grouping).
- Grouping a drawn board again in place: a redraw keeps what is drawn and finds the groups again only to weigh the links, so grouping a drawn board anew is drawing it into a new file (a new board of the same file still finds the drawing).
- Dense boards split (the board-layout plan's slice 6, which the owner has not dropped): a board or frame past the crowd is cut to planar, laid out once and reported, not split.
- A cut link's pill beside the end with fewer links, standing for the busier (the plan's): `canvas apply` refuses a pill that stands for an edge's start when both ends are on one board (DocumentApply), so every pill is beside its link's start and a shape that points at many has a column of them.
- A shape a person carried into another container kept there past the redraw that sees it: the app forgets a person's change once `canvas apply` writes it, and a later redraw can't tell their carry from the document's own move, so it draws the shape where the document has it.
- A board whose remaining conflicts are only links that can't be cut, in a container already in stars, laid out another way: it is reported not clean.
- A bend in a pill's line: the app takes none from a document, so every line into a pill is straight, and a note with many pills fans them out wide.
- A pill shared across containers: one is shared only among the notes of one container (a board, or a frame).
