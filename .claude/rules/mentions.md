# Mentions

Mentions: mentionable kinds, mention text and its stored form, scopes, mention edges, `MentionState`, pills on the canvas and in text, the `@` picker and its lines (a candidate and its board), layout by names (an arrow's label), mention text in the panel, what mentions a shape (the quote and Show What Mentions), and mentions' warnings.

## Architecture

- Mentions (platform, a horizontal and a shape trait; what it imports and why: [build](build.md), Who builds on whom) lets text mention shapes, each mention an inline pill: the kind's symbol and the shape's name, no "@" (monochrome on a shape's surface, tinted on a neutral one, `MentionSurface`). A kind opts into being mentioned with `x.mentionable(label:untitled:symbol:detail:tint:following:)` (`registrar.mentionable(K.self, …)` for another plugin's kind, `mentionableEveryShape(where:)`; the `ShapeMentions` point): its name is `label`, else its title (Titles' `registry.title(of:)`, named or derived), else `untitled`, else "Untitled" and the kind's name (`isPlaceholder`: the picker leaves such a shape out, since its kind gives it no name, though a mention of it shows it live; the catalog keeps it in a side table, `MentionCatalog.unnamed`, with no keys and no slot, and `candidates(…listingUnnamed: true)`, with `among:` or `kinds:`, lists it as a member after the named ones (`MentionCandidates.forgave` says whether the matcher's typo pass ran, over the named and the unnamed together, which the typo's tier reads when the other tiers found fewer than `typoPassBelow` shapes of both, so a list that ranks a narrowed `among:` set knows when it must rank the whole one), matched when typed by its placeholder label alone: only a row of notes that fit asks, and `@`, `/move-to` and the reference list do not), each read from the shape alone (`registry.mentionAppearance(of:)`, a `MentionAppearance`, its tint the kind's; the editor's `editor.mentionAppearance(of:)` is the same with the tint the shape has of its own, what a list that shows the shape's symbol takes: the state's resolutions and catalog entries, the reference's row and panel; the drawing a shape's surface does asks no tint, so a frame costs none). The state hears the file's colors changing (`shapeTintsDidChange`): it resolves what's mentioned again, telling the observers of the pills whose tint changed, and reads the catalog's entries again at the next query. Arrows hold mention text too (their label, the kind of Arrows', a product that depends on Mentions: `Arrow.text` is a `MentionText`, its placement `overCanvas`, centered; an arrow isn't mentionable: a mention of one shows a dashed pill, and validation warns), so its pills, `@` picker and slash commands are the editor's of a note's text, found by Find and listed in Neighbors' Connections tab like a note's. A subboard's description is mention text too (`Subboard.description`, Subboards'), edited in its panel's Description tab, where it's the shipped `MentionTextArea` (below), and placed nowhere (no `mentionText`), so no canvas draws it and Find doesn't search it; its mentions are edges like any, listed and quoted in the Connections tab ([subboards](subboards.md)). Shipped: notes (`untitled: { $0.props.text.firstLine ?? FieldValues.name(of: $0) }`: the first line with words, each mention in it "@…", so no name holds another shape's, which would grow as notes that mention each other are written; else, for a note with no title and no words, its values (Types' `FieldValues.name`: [types](types.md#a-note-that-is-one)), so a note with something in it is a named note wherever Mentions names a shape: `@`, `/move-to`, the reference list, Referenced In, the table of contents and an Issues sentence), subboards (`following: .opens`: following a mention of one enters its board, `editor.goInto`, where every other kind's is `goTo`), each in its kind's tint, the core's (`x.tint`, read from `registry.label(of:)`: a note's yellow, `NoteStyle.tint`; a subboard's indigo, `SubboardStyle.border`, the system's, lighter in the dark; a shape that has a color of its own is in that, `editor.ownTint(of:)`, first; a mention's `tint:` says one for a shape, over its kind's, which no shipped kind does), so a kind has one color in the list, the picker, the Connections tab, Find's rows and Jump To's, declared once; the panel's header keeps its symbol neutral. Text holds mentions when its type is `ScopedMentionText<Scope>` (`MentionText` is `<AnyMentionable>`), stored as one JSON string with inline `@[label](shape:UUID)` tokens (in a label `\]` and `\\`; `\@[` is a literal `@[`; backslashes just before one are doubled), so `canvas draw`'s `text: "…"` works (a draw's string spells a backslash `\\`) and an older reader sees text; its `runs` (`MentionRun`: `.text`, `.mention(id, label:)`) are parsed once; equality compares `stored`, so a value read writes back byte for byte, and one made from runs is canonical (ids in uppercase); a string literal and `init(plain:)` are plain text. Its schema is `mentions.text`, a string, which takes no length or pattern (`MentionTextFormat.checkBounds`). The label a mention holds is a snapshot, shown only while its shape isn't live. A mention is a name (`ShapeNaming`), not a binding: deleting its shape writes nothing, its pills show the name they hold, dashed (`MentionResolution.missing`; `.unavailable` for a shape kept aside, not mentionable, or on a board the app can't show), and undoing the deletion makes them live (redoing it, missing again); a copy renames the mentions of shapes copied along, and a cut and paste is a move (Clipboard's), so a mention from outside what moved shows it missing between the cut and the paste and live again once it's pasted, on whatever board. A note's text became `MentionText` in its v3 migration, which escapes what would now read as a mention through a frozen escaper (`MentionTextFormat.escapeLookalikesV1`). What a text may mention is its scope (`MentionScope`): `AnyMentionable`, `Only<Kind>` (a vertical's own kind), and `DeclaredMentionScope`s any plugin declares (`registrar.mentionScope(S.self)`, the `MentionScopes` point) and kinds join (`x.mentionable(in: S.self)`, `registrar.mentionable(K.self, in:)`); a scope limits what the picker offers and says so in the schema (`x-canvas-mentions`), and never refuses a mention that's there; no shipped text is restricted now (a schema card's description was; MentionsTests hold `Only`). Who mentions whom is Topology's: each mention is a `mention` edge (`MentionEdge`, a root) from the shape whose text holds it, slot the property, repeats counted (Mentions' source on the kinds that can name shapes, `forShapes(adopting: .namingShapes)`, the core's capability over `registry.namingKinds`, through `forEachNamingLeaf`). `MentionState` (`editor.mentions`, a service) reads it (`mentions(in:)`, in text order; `mentioners(of:)`, file-wide: the board shown's in document order, then the other boards' in the file's order), Topology's service, looked up as Mentions' is made, taking each commit in before it; it keeps how each shape mentioned anywhere in the file shows now, resolved again for what each change to the edges touched (the mention-typed ends of each change Topology tells it, `topology.follow`, whatever caused it, and a commit's `elsewhere`; a move costs nothing; an undo or redo is such a commit, so a rename undone gives every pill its name back), so a switch of board reads no mention text and resolves nothing, and the catalog the picker searches, which is the whole file's, every mentionable shape with a name on every board the editor can show (walked from the root, each owner asked `registry.ownsShowableBoard`, `canShow`'s rule), read as the editor opens or a file or board is put in place, and kept up to date by each commit, `elsewhere` included, so a switch reads none of it; never transacting; `labels` (`MentionLabels`, `Sendable`, taken in O(1): it shares the state's resolutions until their next change copies them once) is what `plainText` reads for every shape the file mentions, to read off the main actor (`text.plainText { labels.label(of: $0) }` is `plainText(text)`; a query's mention text, through Mentions' `MentionQueriesPlugin` (which gives queries `:mentions` and `:mentioned-by` too), which takes them as a fact of the file, `MentionedNames`: they're a function of the records, so a text search reads only the file), as of the last commit the state heard; a mention names a shape on any board of the file and shows it live (`resolve` looks through `editor.shape(inFile:)`, the canvas through the core's `context.shape(inFile:)`, a render's lookup anywhere in the file; both find only shapes on boards `canShow` allows, so one the file keeps without using is unavailable, never followed), so a rename, a deletion with its board, and their undo show whatever board is shown when they happen (`rowsAffected` names the mentioners of the `elsewhere` the table of contents hands it on going back); following one (`goTo`) shows its board first, one Back step; the picker lists shapes on every board (matches from anywhere, the board shown's first on a tie and with nearness; an empty `@` lists what's near on the board shown, then the boards it's inside, so a subboard is mentioned from inside itself (on the line of a command that names its kinds, then the rest of those, on every board: below), and a shape may mention itself (left out of its own empty `@`'s nearby, and of a typed query's matches while its name, a note's first line, holds the `@query` being typed); `docs/plugin-system.md`, "Mentions across boards"): `observe(_:_:)` tells a view which targets changed, `labelRevision(of:)` observes one target for SwiftUI, `rowsAffected(by:)` names the mentioners whose rows a rename changes (`MentionRows.affected`, with `context.plainText(_:)` in the row: a note's), `candidates(matching:in:for:)` ranks with every list's tiers (FuzzyMatching's `FuzzyMatcher`, over the catalog's folded names) on the folded query ([fuzzy matching](fuzzy-matching.md)'s tiers, the best 50; then recent picks and nearness), over the catalog's shapes the scope admits: for a scope but `AnyMentionable` its **members** (`ScopeMembers`, made at the scope's first ask in one pass and kept up to date as each catalog entry is read, taken out with it), so a scope that admits few, the public shapes a reference names, costs what it admits and an empty query reads a narrow scope's members whole (`MentionRanking.narrowScope`, 512, or an eighth of the catalog) for the nearest, never squares grown over a board; `candidates(matching:in:for:kinds:admitting:)` takes what a slash command asks of the one shape it takes, besides the scope ([slash commands](slash-commands.md)); what `kinds` and `admitting` do is said on it: a shape either refuses counts toward nothing (not the eight that keep the typo pass from running, nor the 50) and a typed query's order is what it was less those; the kinds' members (`MemberSet`, keyed by the set of kinds) are made at the first ask in one pass, some 0.5 ms at 10,000, and the scope is asked of each, so a narrow scope's own members are not the ones ranked then; a rule alone, asked of every shape the squares gather and then of the whole board, took some 4.6 ms at 10,000 to find five subboards; the nearest board is the fewest boards apart, up the file's tree to where the two paths meet and down again, on a tie in the catalog's order, so `/move-to @` inside a subboard lists a subboard on the root with nothing typed; `follow(_:)` goes to a shape on the next scheduler turn (`goTo`, no undo step; ⌘[ comes back), and `hover(_:)`/`endHover(_:)` set `editor.hovered`. What mentions a shape is the file's, read from Topology's edges into it: `isMentioned(_:)` (another shape on any board the editor can show mentions it; its own mention doesn't count; its edges, never a board's), `quote(of:around:)` (a mentioner's text around its first mention of the shape: about 60 characters of it (`MentionStyle.quoteLength`) as plain text with live names around the mention, on one line, cut between words with "…"; nil for a shape that isn't in the file and for one whose text doesn't mention the shape, a pointer, which is no text; read from its record wherever it is, in the board shown and the file read unobserved, `editor.withoutObservingDocument { … }`, the core's, and never kept) and `showWhatMentions(_:)` (on the scheduler's next turn, since a menu in text is being handled by the view it ends: ends editing, then `goTo`s the mentioners, the board shown's first, so it stays if any are here and else shows the first one's board, one Back step; nothing if none). The panel lists what mentions a shape in Neighbors' Connections tab, which Mentions' lights fill (below; [neighbors](neighbors.md)), and Show What Mentions is in the canvas's context menu (an item for the canvas in `MentionsMenuGroup`, order 50, after a kind's own items, shown when a shape the menu is for is mentioned), so a list with Mentions needs `ContextMenusPlugin()`. Drawing: a kind lists where it draws mention text (`x.mentionText { shape in [MentionTextPlacement(text, in: box, style:, lines:, overCanvas:)] }`, the `MentionTexts` point; `x.mentionText { shape, shapes in … }` when where the text is depends on the shapes around it, through the `ShapeContext` (an arrow's label sits on its body, from its kept geometry's `label`), and `registry.mentionTextPlacements(of:in:)` takes the editor's `shapeContext`; `overCanvas` says the text is drawn over the canvas itself and not on the shape's surface, which only Find reads, to wash a hit), its render draws exactly those (`context.drawMentionText`: string drawing, each built string kept by what it says and how each mention shows, `MentionTextMemo`: the 2,048 used last, and never one the frame being drawn has drawn, so it keeps all a frame draws and the next builds none, each frame's end marked by an overlay that draws nothing; a pill's image is never kept as a bitmap, `cacheMode` `.never`; a text that is one pill and nothing else, in fixed lines set from the left (a row's pill), is drawn straight into the context with no image, `MentionPillLayout.draw(in:of:)` where string drawing would put it (`MentionTextLayout.onlyPill`: arithmetic, no layout made; nil for more than one pill, the font's own lines, centered or right-set text, a line taller than the box and a pill wider than it, which string drawing draws as ever), since string drawing draws an attachment's image into a bitmap of its own and then draws that bitmap, each frame, most of what a pill cost (450 in a frame took 14 ms and take 2: [benchmarks](benchmarks.md)); it is named as its shape is now like any mention, looked up and found in the memo at each draw, so a rename shows on the next frame whatever drew it; where the pill lies on whole pixels the two draw the same pixels, and elsewhere string drawing's is its bitmap laid a part of a pixel off, so softer, its label up to a device pixel from where text set on the device's pixels lands (a see-through pill, the shape surface's or a missing one's, may differ by two levels of rounding: an image goes on whole, its parts one by one, which would differ under a context alpha, where no render draws mention text); a pill among words still costs an attachment's image; zoomed out a note is its skeleton, which draws no mention text, so a frame there builds no string and lays out no pill, and the memo trims back to 2,048 at its end), and `editor.mentionPills(of:)` is where each pill is (world units, `isLive`); Find's asking for a range's line rects makes the text's layout and keeps it with the text (`MentionTextMemo.Entry.lineRects`: TextEditing's `StringDrawingLayout` over the string with its pills' stand-ins, per width), so its rects are a lookup; drawing keeps none (`Entry.pills` places the pills with a layout already kept, else with one made for the call and let go, as it did before Find: a layout is a text storage and a layout manager, which the canvas would hold for every text with a pill in it; debug builds' `MentionDrawingCounts.layoutsKept` counts the kept). `MentionLightsPlugin` (Mentions', id `mention-lights`, after Neighbors, Mentions and arrows' lights in the shipped list: [neighbors](neighbors.md)) gives Neighbors mentions' two lights, titled Mentions and Mentioned By (`MentionStyle.mentions`, `mentionedBy`), what a shape's text mentions in teal and what mentions it in lavender (`MentionStyle.mentionsLight`, `mentionedByLight`), their queries written from `MentionEdge.id`; the second's caption, the line under a mentioner's name in the Connections tab, is `quote(of:around:)`; a type's pointer (`field-link`, a child of `mention`) is in both as it is lit, though `mentioners(of:)`, `isMentioned` and `:mentions` read plain `mention` edges only ([types](types.md)); MentionsTests' `mentionLightTests` hold the two queries, their titles, the caption and its refusal without Neighbors. `MentionFindPlugin` (Mentions', after Find and Mentions in the shipped list: [find](find.md)) gives Find every `MentionTexts` placement's text (`forShapes(adopting: .mentionText) { $0.findableTexts("mention text", …) }`, the kinds that list placements: Mentions' capability), each mention its live name (`MentionState.resolve`), a placement's place in the kind's list its field; the placements `overCanvas` are another contribution, "mention text over the canvas", whose hits are washed ([find](find.md)); a hit in a name is its pill's one character, mapped from the text read to the text drawn (`text.reading(spelling:)`, a `MentionReading`: the text with each mention spelled as its reader says, and `drawnRange(of:)`, a spelling or any of it its pill; a type's highlights map the model's words with it too); `affected` is `rowsAffected(by:)`, which Find asks before reading any text. One `MentionTextStyle` (font, color, fixed line height, surface, and the lines' alignment, natural unless a kind says: an arrow's label is centered) is shared by a kind's render and its editor; a pill (`MentionAttachment`, one U+FFFC, which adopts the core's `ReadsAsText` with the name it shows, `writtenLabel`, no "@": a selection across it, which Find's ⌘F seeds its query with, reads as that name) is 17 points tall in 16-point text, so a note's lines keep their 19, and its kind's symbol is centered in a slot an em wide (`MentionStyle.symbolSlot`, as wide as the widest shipped symbol; a wider one is drawn smaller), so a live pill is as wide as its label makes it whatever its kind: text measured from itself alone, where no shape is looked up (`MentionTextStyle.measuredString(_:width:)`: a kind's `DerivedProps`, a note's height, from its text), makes each mention a live pill by the name it holds, as wide as it's drawn while its shape is called that (one drawn missing has no symbol, so it's narrower). Its faces (Selection's; Types' `RelateOffer` is asked before them on a pill in a type's words that names a type it is not yet related to, and takes its single click to open `Relate to <Type>`, keeping the double-click and the hover: [relationships](relationships.md#relating-from-the-words-the-offer)): a click on a pill edits its shape from the pill (`beginEditing(_:at:)` at its center, unless the shape is read-only), a double-click on a live one of a read-only shape goes to it (an editable shape's text view took the click before), and the pointer over a live one hovers what it names, if that's on the board shown; none on a note drawn as a skeleton, zoomed out, where a click selects it, a double-click edits it (a read-only one's is refused, going nowhere) and the pointer hovers it. The editor is `MentionTextView<Scope>` (an `EditingTextView` on TextKit 2: a note's and the panel's `MentionTextArea`'s; `onPointer` hears where the pointer is over it, for a host's own hover, a type note's highlights; How a script names a mention: `MentionTextFormat.resolvingNames(in:_:)` (public, generic over the error its `resolve` closure throws) writes each `@[name]` that isn't already a whole mention as the whole mention of the shape `resolve` gives for the name, in text order, repeats included (its grammar, one with `parse`'s, and its cost, said on it; its output is an array of scalars, a string appended to copying itself whole each time). `registry.mentionAdmission(of:scope:)` asks, from what a text's schema says beside its reference (`x-canvas-mentions`, nil for none), whether the text may mention a shape: `MentionAdmission.admitted`, `.notMentionable`, or `.outsideScope(admits:)` (the kinds the scope admits: a declared scope is found by its title, `joinsScope`); a scope it can't read is none. Mentions' own `MentionTextsPlugin` is where `canvas draw` uses both (the text format for `MentionTextFormat.mediaType`, `describes` `@[Title] mentions`, whose lookup is Draw's `DrawTextContext.shape(called:admitting:)`: [command line](command-line.md)), so a script writes `@[Owner]` and never an id, a title that no shape the text may mention has is refused (`unknown_title`, `ambiguous_title`, or `invalid_value` saying why), and `@[]` is refused; only the hints of `unknown_title` and of `@[]` add how to write `@[` as text (`\\@[` in a script's string), since a title two shapes have, or a shape that can't be mentioned, was meant as a mention and its hint says only how to mend it. `MentionsPlugin` comes right after Titles in the shipped list, and needs Selection (so Keyboard) for its faces and ContextMenus for Show What Mentions.
- A pill's name and a list's line (public, for the plugins on Mentions): `MentionResolution.shownLabel(stored:)` is what a pill reads (the live label, else the stored name, else "Deleted" or "Not available"), and `MentionAttachment` calls it. `MentionChoice` (`MentionChoices.swift`) is a candidate and the name of the board it is on when that isn't the board shown (`MentionState.boardName(ofShape:)`: what Boards calls it, `editor.name(of:root:)`, its owner's title, else its kind's placeholder, "Untitled Subboard", else its kind's name, with "Board" for the root, `MentionStyle.rootBoardName`: Mentions imports Boards for it, so the picker's line says what the path, the table of contents and Find say), and `MentionChoice.items` is the lines a list shows for them (the matched letters, the kind's symbol and tint, the board at the right, "Kind · Board" when two are called alike, spoken "Ann Lee, Note, 1 of 3"); the Reference picker's rows are these (`ReferenceChoice` is `MentionChoice`). `candidates(…among:)` takes the shapes the caller has found (ids): it does what `kinds` does for a set no kind names, so only those of the catalog are ranked, a typed query ranks them alone, and an empty one lists them nearest first on the board shown and then on every other board, as many as a query lists, without asking a rule of every shape on the board (a row's list of the notes it may name passes them). `MentionSurface.outlined` is the pill of a row or a cell that names a note: white, a hairline outline in the text's color at 20%, no symbol, ends fully round, taller than a text pill's and its label as large as the text (`MentionStyle.outlined*`); a pill whose target is gone is dashed as on any surface. It is the style's, so `drawMentionText` and `MentionAttachment` draw it as they draw any.

## Layout by names

- A geometry measured from mention text (an arrow's label) can't read what a mentioned shape is called now (it may be on another board), and a rename writes nothing to the text that mentions it, so a kind opts in with `x.mentionLayout { $0.props.text }` (`MentionLayouts`, `MentionLayout.swift`) and Mentions hands its geometry the names as a layout input, `MentionLayout.names` (`context.mentionNames(of:)`: one name per mention in text order, nil when each is the name the text holds; `MentionTextStyle.measuredString(_:width:names:)` measures with them). `MentionState.refreshLayout` sets it, through `editor.setLayoutInput`, for the shapes of those kinds that mention a target whose resolution a commit changed (`lastAffected`, file-wide, any board), whose text a commit added or changed (a pure move isn't one, so a drag costs nothing here), or that a file opens with (`layOutMentioners`), and takes it back for one removed or a file put in place. It costs the shapes named, a lookup each for kinds that didn't opt in, and the editor works out again only those. A pill drawn missing or unavailable is still measured by the name it holds. Nothing is stored. Notes have the same gap and are left as they are: a note's height is a stored prop derived when its text is edited (`DerivedProps`), so a rename to a longer name may wrap a pill past the note's last line until the note is edited; a rename never changes the stored height. ArrowsTests' `LabelMentionTests` hold the arrow's.
