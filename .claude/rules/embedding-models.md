# Embedding models

Embedding models: the one model the registry lends plugins to turn texts into vectors with, OpenAI's text-embedding-3-large and its key's pane, the vectors it gave kept by text in a file, the text a note is embedded by, and the scripted model tests use.

Related: [language models](language-models.md), [decision models](decision-models.md), [build](build.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Embedding models](../../docs/plugin-system.md#embedding-models).

## Architecture

- EmbeddingModels (an engine beside LanguageModels and DecisionModels; it builds on LanguageModels, for its error's words and the key's file and pane every service shares) lends the registry one model: `registry.embeddings` (and `editor.embeddings`, `editor.embeddingModel`; nil without `EmbeddingModelsPlugin(model:)`), an `Embeddings`, whose one call is `vectors(of: [String]) async throws(EmbeddingModelError) -> EmbeddedTexts` (`model`, a vector for each text in the order asked, and `asked`, how many distinct texts the model was asked for). The model is an `EmbeddingModel`: its `name` (the provider and the model, `"openai/text-embedding-3-large"`: what vectors are kept by), `textsPerRequest` and `embed(_:)`. It knows nothing of what the vectors are used for.
- **`EmbeddingModelError`** is a `failure` and the `provider` it names, worded as a decision model's: `message` is a fragment, never what to do ("No OpenAI key", "OpenAI key rejected", "Rate limited", "OpenAI error 500", a 4xx's first sentence from the service with the key taken out (`LanguageModelError.firstSentence(of:)`), "Can’t reach OpenAI", "Timed out", "Unusable answer"), `isTransient` (Retry) and `needsKey` (Open Settings…). None ever holds the key, or a piece of it.
- **OpenAI** (`OpenAIEmbeddingModel`, the app's): `POST https://api.openai.com/v1/embeddings`, `authorization: Bearer <key>`, `{"encoding_format": "base64", "input": [...], "model": "text-embedding-3-large"}` (sorted keys; no `dimensions`, so the vectors have the model's own 3,072 numbers; base64 is little-endian `Float32`, exact and a quarter the size of decimal text). `name` is `openai/text-embedding-3-large`. It sends up to 256 texts a request, one request after another, in order, and joins the vectors; any request failing fails the call (`Embeddings` asks one chunk at a time, so it keeps the chunks before). Each request is bounded to 60 s in all, `timeout`: the request's idle limit (`URLRequest.timeoutInterval`) and, since the model makes a session of its own for a call when none is given (`boundedSession()`, ephemeral, `timeoutIntervalForRequest` and `timeoutIntervalForResource` both `timeout`, finished with the call), the whole request, so a reply that trickles in is cut off too (the shared session's resource limit is a week); a session given (tests) is the caller's to bound, and `URLProtocol.registerClass` doesn't reach the model's own, so a test gives one that reaches only its stub. It retries nothing, and reads its key at every call from `OpenAIKeyStore.standard` (`~/Library/Application Support/InfiniteCanvas/openai-api-key`), a `KeyFile` as Anthropic's and TypeSafe's are ([language models](language-models.md)). The reply's `data[].index` places each `data[].embedding`; it is an unusable answer unless every index of the request is there exactly once and every vector has one non-zero length and finite numbers. 401 and 403 are a key refused, and the body of one is never read; 429 is rate limited, except one whose `error.code` is `insufficient_quota`, which is the service's words (it is about the quota, not the rate); 503 is overloaded; any other status is the body's `error.message` with the key taken out: the exact key and every run that looks like one (`sk-` and four or more of `A-Za-z0-9_*.-`: OpenAI's refusals quote a masked key, `sk-proj-****abcd`). Never print, log or write the key, and never log a body: nothing in the module prints or logs.
- **What is sent.** Every text embedded leaves the machine for OpenAI, and only with a key saved in Settings: saving it is the opt-in, no prompt comes before a text is sent. What a feature sends is that feature's to say (`canvas measure --tightness`: a document's notes' titles and words, [command line](command-line.md)).
- **`Embeddings`, one for the registry**, held through `EmbeddingEngines` (a keyed point, owner `.embeddingModels`, one contribution, so a second is a conflict, as `DrawEngines` has one). It is not an `EditorService` as DecisionModels' `Decisions` is: `canvas measure` runs with no editor when no board is open, and one memory of vectors must be shared by every command and editor. It drops duplicate texts (first-seen order), looks each up in the memory, and asks the model for the rest **in chunks of `textsPerRequest`**, one `embed` call a chunk, keeping the chunk's vectors (memory, and the file) as it lands: a failure part way, or a cancel, keeps what came and throws, and the next call asks only for the rest. A model that answers another number of vectors than texts, or a vector with no numbers or more than 65,536 (what the file's records can hold), is an unusable answer. Nothing tracks the texts in flight: two calls at once may each ask the model for a text neither has had answered yet (a measure is one-shot: a duplicate request at worst), and a text once kept is never asked for again. Texts are told apart by their UTF-8, never by `String`'s equality (two canonically equal texts are two): the memory's key, and `ScriptedEmbeddingModel`'s vectors, are by bytes.
- **Vectors kept** (`EmbeddingMemory`, not main-actor, `Sendable` through a lock): by the model's name and the SHA-256 of the text's UTF-8 (`key(of:from:)`), in memory and, where it has a file (`EmbeddingMemory.standard()`, `~/Library/Application Support/InfiniteCanvas/embedding-vectors.bin`), in it. A vector of a text by a model never changes, so none is let go: no cap, no expiry (a vector is some 12 KB with the app's model, and the file grows by one a text). The file is read at the first lookup and written after each chunk, both off the main actor (`loadInBackground()`, `saveInBackground()`). Its format is the magic `ICEMBV1\n`, then records: a `UInt32` byte count of the key, the key's UTF-8, a `UInt32` dimension and that many `Float32`, little-endian, the floats as the model sent them. The app and every copy of it share the file and run at once, so a save never truncates and never writes a record in pieces: it appends what was kept since the last save as one `write` of the whole buffer (`O_APPEND`, mode 0600, the magic in front when the file is new), and a file with the wrong magic is replaced by a new one renamed into place. A load checks every record (a key of at most 1,024 bytes, a dimension from 1 to 65,536, its bytes all there) and stops at the first that fails, keeping what it read; a second magic where a record would begin (two copies each made the file new) is passed over; of two records with one key the later wins. A save looks at the file first (mapped, its records' headers only): one that doesn't parse to its end (a process killed mid-write, a full disk) is healed as a file that isn't ours is, replaced by a rename with its whole records and what is in memory (memory's vector winning), never appended to, since a torn record's lengths would swallow what followed and no load would reach it. `keep` refuses what a record can't hold (no numbers, more than 65,536, a key past 1,024 bytes). A failed save keeps what it couldn't write, for the next. Debug builds log which thread read or wrote the file (`fileAccessesOnMainThread`), for a test.
- **`EmbeddingText.of(title:words:)`**, the text a note is embedded by, pure: its title (without a trailing file extension, if it looks like a file name: no whitespace, something before the dot, then a letter and up to seven letters or digits), a dot and a space, its words' first 900 UTF-16 units, the code names in it split into words (a lower-case letter or digit before a capital, the last capital of a run before a capital and a lower-case letter, and backticks and underscores are spaces) and every run of whitespace one space, none at either end; never empty (nothing at all is "."). It is the layout spike's `texts.mjs` character for character, which the vectors it measured were made from (`docs/plans/board-layout`), in JavaScript's terms and not Foundation's: units, not Characters; `\s` is the set `isJavaScriptSpace` lists, not `.whitespacesAndNewlines`; a trailing newline after an extension keeps it. The one deviation: a cut that falls inside a surrogate pair drops the pair's first half, where JavaScript keeps it and sends invalid UTF-16. The extension is the owner's one change to `texts.mjs`, which strips `.swift` only; it changes none of the corpus's 962 texts.
- **The plugin.** `EmbeddingModelsPlugin(model:memory:)` (the memory in memory only unless given one with a file) lends its `Embeddings` through `EmbeddingEngines`. It gives the key's Settings pane (`registrar.settingsPane("OpenAI")`, `OpenAISettingsView.pane`) only when its model is an `OpenAIEmbeddingModel`, over that model's keys, so a registry with any other model has no OpenAI pane and never points at the key's file.
- **The pane** is the language models' `KeySettingsView` over `KeySettings` made for `KeyService.openAI` (`OpenAIKeySettings(keys:model:)`, a typealias and an init: "OpenAI API key", its prompt "Saved" or "Not saved", "Get a key" to platform.openai.com), so it is the Claude pane's key rows (`KeyRows`) in a pane of its own: Save, Remove, and Test, which embeds `OpenAISettingsView.testRequest` (one text, "Test") with the saved key. Save and Remove post `Notification.Name.embeddingModelKeyDidChange` (never another service's). Nothing listens for it: a measure is a one-shot command, so what failed for want of a key is asked again by the next, not by itself, which is DecisionModels' reason for its notice; `KeyService` requires the name all the same. `OpenAISettingsView.showSettings()` opens Settings with the action the Claude pane's sends.
- **Vectors vary.** Live vectors are not bitwise stable between calls or between Macs (the service's own floating point), so what is measured from them can differ a little between runs; the memory keeps the first a text was given, so one Mac is steady, and a feature that must not change under a redraw keeps its own result (canvas-digest's redraw keeps every shape, arrow and pill the file has, and finds the groups again only to weigh the links).
- **The scripted model** (`ScriptedEmbeddingModel`, main-actor, as `ScriptedDecisionModel`): each text answered by its vector (`set(_:for:)`, kept by UTF-8), else `fallback`, else `.server(status: 0, …)`; `requests` (every call's texts), `queue(_:)` (the next call fails), `holdsAnswers` with `release()` and cancelling a held call. `hashing(dimensions:)` answers any text with the first bytes of its SHA-256, each `Float(byte) / 255 - 0.5`: the same for the same text, and otherwise unlike.

## Testing

- EmbeddingModelsTests: OpenAI's request, answers and errors over a `URLProtocol` stub (the body, the bearer key, a batch past 256 as several requests in order, each reply that is not one, each status, the key taken out of a message, masked ones too, a 401's body never read, the network, cancelling, the session a model with none given asks over bounding the whole request), the key (saved 0600 beside the others, the notice and never another's), the pane (Test's one text and what it says, nothing sent with no key, the field focused and Return saving), `EmbeddingText` over `Fixtures/texts.json` (each case's text computed once by texts.mjs's own code in node, with the extension line changed; the one case marked `deviation` is written by hand, since JSON cannot hold a lone surrogate), the memory (the file bit for bit, append only, two memories on one file and a third reading both, corrupt and foreign files, a torn tail healed by the next save and read back with the records after it, the thread), `Embeddings` (only the missing texts, chunks, a failure keeping the chunks before it, a cancel between chunks keeping the first in the file and in a reopened memory, a vector the file can't hold refused, canonically equal texts) and the scripted model and the plugin.
- `ScriptedEmbeddingModel` answers every test; ShippedTesting's `ShippedPlugins` takes `ScriptedEmbeddingModel.hashing()` unless a test passes its own, so no test reaches the network or the user's files.
