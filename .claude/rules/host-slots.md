# Host slots

What a board's window puts around its canvas, and what the app takes from the plugins besides, said by plugins and placed by the host: views over the canvas, the inspector, the window's subtitle, settings panes, tool tips, the welcome board and the commands the app's server runs; CanvasUI's `BoardChrome`, the inspector's rule, and the Settings window.

Related: [build](build.md), [command line](command-line.md), [detail panel](detail-panel.md), [boards](boards.md), [jump to](jump-to.md), [keyboard](keyboard.md), [language models](language-models.md), [find](find.md), [editor](editor.md), [plugins and kinds](plugins-and-kinds.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Host slots](../../docs/plugin-system.md#host-slots).

## Architecture

- **Why it exists.** A plugin can't import the window (CanvasUI), and the app and CanvasUI may import only the foundation and the wire, so neither can hand the other a view. Composition used to join them (`boardChrome`, `detailPanel`, `boardPath`, `coveredTop`, `boardName`, `settings`, `help`, `commands(in:)`, and the welcome board it built); it now only lists plugins. HostSlots (`Sources/HostSlots/HostSlots.swift`, a foundation library on Canvas and CanvasRPC, the one foundation module that imports SwiftUI, since its slots hold views, and the one that imports the wire, whose types the commands are said in) declares what passes between them: seven extension points, each the core's (`owner` is `.core`, so always installed), each conformed in an extension with a `summary`. A plugin contributes from its own `register`, with no plugin value of its own for it (nothing can be missing), and a list without the plugin is a window without its piece. It knows no plugin and no window.
- **The seven slots**, what a plugin says and what the host reads (all `Registry` extensions, public):
  - Views over the canvas (`HostOverlays`, a list in plugin order, a later one over an earlier; the report's `host overlay`): `registrar.hostOverlay(alignment:coveredTop:) { editor, onExit in … }` (`alignment` `.center` and `coveredTop` zero by default). Read as `registry.hostOverlays` (`HostOverlay`: `alignment`, `coveredTop`, `view(for:onExit:)`) and `registry.hostCoveredTop(on:)`, the most any says for a board. Not a `CanvasOverlay`, which the canvas draws into itself in the world. Shipped: Boards' path (`.top`, covering `BoardPath.coveredHeight(on:)`), then Jump To's palette, over it.
  - The inspector (`HostInspectors`, keyed, at most one, a second `RegistryError.conflict`; `host inspector`): `registrar.hostInspector(isRequested:onDismiss:) { editor, onExit in … }` (never requested, and nothing on dismissal, by default). Read as `registry.hostInspector` (`HostInspector`: `isRequested`, `onDismiss`, `view(for:onExit:)`). Shipped: the detail panel (`DetailPanelPlugin`), requested while a takeover is active (`registry.activeDetailTakeover(in:)`), dismissal running that takeover's `onEscape`.
  - The window's subtitle (`WindowSubtitles`, keyed, at most one; `window subtitle`): `registrar.windowSubtitle { editor in … }`, nil for none. Read as `registry.windowSubtitle(for:)`. Shipped: Boards, the board shown's crumb's title, none on the root.
  - Settings panes (`SettingsPanes`, keyed by title, in plugin order; `settings pane Anthropic`): `registrar.settingsPane(title) { … }`, the view made each time the window opens, handed no editor. Read as `registry.settingsPanes` (`SettingsPane`: `title`, `view()`). Shipped: the Anthropic key's, which `LanguageModelsPlugin(model:)` adds only when its model is an `AnthropicModel`, over that model's `keys`, so the pane and the model read one key and a registry built with a test's `ScriptedLanguageModel` has no pane and never points at the key's file.
  - Tool tips (`ToolTips`, keyed, at most one; `tool tips`): `registrar.toolTips { tool, registry in … }`. Read as `registry.toolTip(for:)`, the tool's label without one. Shipped: Keyboard, `registry.help(for:)` ("Note (N)").
  - The welcome board (`WelcomeBoards`, keyed, at most one; `welcome board`): `registrar.welcomeBoard { registry in … }`, a `CanvasDocument` made each time it's asked for (each board opened has shapes of its own), handed the frozen registry so it can leave out what the list can't draw. Read as `registry.welcomeBoard`, what makes one, nil without. Shipped: StickyNotes (`WelcomeBoard`, `Sources/StickyNotes/WelcomeBoard.swift`: `texts`, and `document(texts:linked:)`, six notes and, where the list has the arrow kind, three arrows), so a list without notes has no welcome board.
  - The commands (`HostCommands`, keyed, at most one; `host commands`): `registrar.hostCommands(specs:run:)`, what the command line shows of each command and how to run one by name, both handed the frozen registry (the commands are every plugin's, known only once it's built). Read as `registry.hostCommands`, `(specs, run)`: no specs, and every name `unknown_command`, where no plugin gives any. The one slot said in the wire's types (`CommandSpec`, `JSON`, `RPCError`). Shipped: Automation, over `automationCommands` and `runAutomationCommand` ([command line](command-line.md)).
- **A view a plugin gives** is made for a window's canvas: handed that board's editor and `onExit`, which gives the keyboard back to the canvas (`CanvasFocus.take`), and it follows the editor by itself. A view over the canvas is over the whole of it and takes clicks only where it draws.
- **The window's side** (CanvasUI, which knows no plugin):
  - `BoardChrome(editor:showsInspector:onExit:)` (`Sources/CanvasUI/BoardChrome.swift`), a public view modifier the app applies to its `CanvasRepresentable` after its frame and toolbar: each registered overlay folded onto the canvas with `.overlay(alignment:)`, in plugin order, then, if an inspector is registered, `.inspector(isPresented:)` with it and its toolbar button (Inspector, its tooltip "Show Inspector" or "Hide Inspector": `ChromeStyle`). No inspector registered, no `.inspector`.
  - The inspector's rule (`InspectorRequests`, private, with a `revealed` flag of its own): `isRequested` turning true while the inspector is hidden shows it and notes that; turning false hides it again only if that's what showed it; the person hiding it while it's requested runs `onDismiss`, then `onExit`. Generic over whatever requests it: the window has never heard of Find, whose ⌘F shows a hidden inspector through the detail panel's takeover ([find](find.md), [detail panel](detail-panel.md)). `FindState.revealedInspector` is gone.
  - What the canvas covers: `BoardDocument` sets each board's `editor.coveredTop` to `registry.hostCoveredTop(on:)` (host API, [editor](editor.md)), so a fit leaves the path's pill clear. A headless editor is told nothing and covers nothing, which is why this stays the window's to say and isn't a core point the editor reads.
  - The subtitle: `BoardWindowController` reads `registry.windowSubtitle(for:)` observed, so it follows a switch of board or a rename; with no plugin saying one it reads nothing, and is never read again.
  - `SettingsWindow` (moved here from Composition): `SettingsWindow(registry:)` hosts `registry.settingsPanes` one under another (`SettingsPanesView`), unheaded, since a pane says what it is itself; `init(autosaveName:content:)` hosts any view. Made afresh each time it opens, sized before it goes in.
  - `ToolPicker(editor:)` reads `registry.toolTip(for:)`; it takes no `help:` closure.
  - `BoardConfiguration(registry:content:)` has no `coveredTop` or `boardName`: both come with the registry.
  - `CommandServer.Commands(registry:)` is `registry.hostCommands`, what the server runs beyond its own.
- **The app** (`Sources/InfiniteCanvas/InfiniteCanvasApp.swift`) imports Canvas, CanvasUI, Composition and HostSlots: it builds the registry from `ShippedPlugins`, hands it to `BoardConfiguration`, `SettingsWindow(registry:)` and `CommandServer.Commands(registry:)`, opens `registry.welcomeBoard`'s board the first time it's launched with nothing to open and from Help › Welcome Board (an item it adds only where a plugin gives one), and its `ContentView` is the canvas, the toolbar's `ToolPicker`, and `BoardChrome`. Composition keeps the list, `--ask`'s prompt, and one forward (`anthropicModel`).
- **Adding a slot**: a point here owned by `.core`, its sugar on `PluginRegistrar`, a public reader on `Registry`, and the window's use of it in CanvasUI. Never a function in Composition, and never a plugin's type in CanvasUI.

## Testing

- HostSlotsTests (fixtures only: `Contributor`s of their own, CanvasTesting's tiles and pockets) hold the points: overlays in plugin order with their alignments and what they cover, the most covered per board and none with no overlay; a view made only when the window asks, handed the editor and `onExit`; the inspector (none by default, `isRequested` and `onDismiss` as given, never requested by default, a second a conflict); the subtitle (nil without one, per board, a second a conflict); panes in order, made when asked, a title once; a tool's tip a plugin's or its label, a second a conflict; the welcome board (none by default, made each time it's asked for and not before, handed the built registry, a second a conflict); the commands (no specs and `unknown_command` by default, a contributor's specs read off the built registry and its `run` handed the name, the params and the editor, a second a conflict); and each summary in the report.
- CanvasUITests' `chromeTests` (`ChromeTests.swift`) host a real `CanvasRepresentable` with `BoardChrome` in an unshown window, with fixture overlays (a `Marker` view found by identifier) and a fixture inspector that's requested while an `@Observable` model says: each overlay where its alignment puts it; nothing with no contributions; the inspector shown when requested while hidden and hidden again after, left alone when the person had it shown; hiding it while requested dismissing and giving the keyboard back, and nothing when it isn't requested. `toolPickerTests` hold the tips (a contributor's, and the label without one).
- Each plugin's own tests hold what it gives: BoardsTests' `headingTests` (the path's alignment and covered height, the subtitle following a board shown and a rename), JumpToTests' `paletteTests` (its overlay after Boards'), DetailPanelTests' `takeoverTests` (the inspector requested while a takeover is active, dismissed through its escape), KeyboardTests (the tips), LanguageModelsTests' `pluginTests` (the pane with an Anthropic model over a temporary key store, none with a scripted one), StickyNotesTests (the welcome board: the six texts, three arrows only where the list has the arrow kind, new shapes each time), AutomationTests' `registrationTests` (the server handed every command, the plugin's own and another's, each run by name, an unknown one refused).
- CompositionTests hold the shipped seven (ShippedTests: the two overlays in order, the covered height, the inspector, the subtitle, no pane with the scripted model and the key's with the app's, the toolbar's tips, the welcome board's six notes and three arrows, the commands as the command line lists them, and the report's lines), the Settings window over the registry's panes with a temporary key store (`settingsWindowTests`), and the window's behavior with Find (`findShippedTests`: ⌘F showing a hidden inspector, closing hiding it again, hiding the inspector closing Find). `InspectorHost` applies `BoardChrome` as the app does.
