# Host slots

What a board's window puts around its canvas, and what the app takes from the plugins besides, said by plugins and placed by the host: views over the canvas, the inspector, the window's subtitle, settings panes, tool tips, the Keyboard Shortcuts window's rows, the menu bar's commands and the keys menus show, what Copy as Image draws and the commands the app's server runs; CanvasUI's `BoardChrome`, the inspector's rule, the Settings window, the Keyboard Shortcuts window and the menu bar.

Related: [build](build.md), [command line](command-line.md), [detail panel](detail-panel.md), [boards](boards.md), [jump to](jump-to.md), [keyboard](keyboard.md), [language models](language-models.md), [find](find.md), [editor](editor.md), [plugins and kinds](plugins-and-kinds.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Host slots](../../docs/plugin-system.md#host-slots).

## Architecture

- **Why it exists.** A plugin can't import the window (CanvasUI), and the app and CanvasUI may import only the core, so neither can hand the other a view. A module that imported every plugin, Composition, used to join them (`boardChrome`, `detailPanel`, `boardPath`, `coveredTop`, `boardName`, `settings`, `help` and `commands(in:)`); it's gone, and nothing joins them now. The core (`Sources/Canvas/Plugins/HostSlots.swift`, which imports SwiftUI, since its slots hold views, and the wire, whose types the commands are said in) declares what passes between them: ten extension points, each the core's (`owner` is `.core`, so always installed), each conformed in an extension with a `summary`. A plugin contributes from its own `register`, with no plugin value of its own for it (nothing can be missing), and a list without the plugin is a window without its piece. It knows no plugin and no window.
- **The ten slots**, what a plugin says and what the host reads (all `Registry` extensions, public):
  - Views over the canvas (`HostOverlays`, a list in plugin order, a later one over an earlier; the report's `host overlay`): `registrar.hostOverlay(alignment:coveredTop:) { editor, onExit in … }` (`alignment` `.center` and `coveredTop` zero by default). Read as `registry.hostOverlays` (`HostOverlay`: `alignment`, `coveredTop`, `view(for:onExit:)`) and `registry.hostCoveredTop(on:)`, the most any says for a board. Not a `CanvasOverlay`, which the canvas draws into itself in the world. Shipped: Boards' path (`.top`, covering `BoardPath.coveredHeight(on:)`), then Jump To's palette, over it.
  - The inspector (`HostInspectors`, keyed, at most one, a second `RegistryError.conflict`; `host inspector`): `registrar.hostInspector(isRequested:onDismiss:) { editor, onExit in … }` (never requested, and nothing on dismissal, by default). Read as `registry.hostInspector` (`HostInspector`: `isRequested`, `onDismiss`, `view(for:onExit:)`). Shipped: the detail panel (`DetailPanelPlugin`), requested while a takeover is active (`registry.activeDetailTakeover(in:)`), dismissal running that takeover's `onEscape`.
  - The window's subtitle (`WindowSubtitles`, keyed, at most one; `window subtitle`): `registrar.windowSubtitle { editor in … }`, nil for none. Read as `registry.windowSubtitle(for:)`. Shipped: Boards, the board shown's crumb's title, none on the root.
  - Settings panes (`SettingsPanes`, keyed by title, in plugin order; `settings pane Anthropic`): `registrar.settingsPane(title) { … }`, the view made each time the window opens, handed no editor. Read as `registry.settingsPanes` (`SettingsPane`: `title`, `view()`). Shipped: the Anthropic key's, which `LanguageModelsPlugin(model:)` adds only when its model is an `AnthropicModel`, over that model's `keys`, so the pane and the model read one key and a registry built with a test's `ScriptedLanguageModel` has no pane and never points at the key's file.
  - Tool tips (`ToolTips`, keyed, at most one; `tool tips`): `registrar.toolTips { tool, registry in … }`. Read as `registry.toolTip(for:)`, the tool's label without one. Shipped: Keyboard, `registry.help(for:)` ("Note (N)").
  - The Keyboard Shortcuts window's rows (`KeyboardHelp`, keyed, at most one; `keyboard help`): `registrar.keyboardHelp { registry in … }`, `[KeyboardHelpRow]` (`keys` as they're written, `title`, `place`: `.tool`, `.command(c)`, `.canvas`, `.pointer`, `.text`), read off the built registry. And key hints (`KeyHints`, a list in plugin order; `key hint ⌥ Drag Drag a Copy`): `registrar.keyHint(keys, title, while: .pointer | .text)`, a key no shortcut has, said beside the code that reads it. Read together as `registry.keyboardHelp`, the list's rows then the hints, each row once; none with neither. Shipped: Keyboard's rows (`keyboardHelpRows`) and every plugin's hints ([keyboard](keyboard.md)).
  - The menu bar's commands, and the keys menus show (`MenuKeys`, keyed, at most one; `menu keys`): a command a plugin declares in a section (`registrar.command(… in:placed:…)`, the core's Commands point: [editor](editor.md)) is in the menu bar, read as `registry.menuBarCommands` (`MenuBarCommand`: `command`, `title`, `section`, the `MenuBarSection` it's in, `placement`, its place among the section's items, `menu`, the section's menu as a `MenuPath`, and `key`, a `MenuKey`, in plugin order), which the window arranges with its own items, section by section ([keyboard](keyboard.md), the menu bar); the key an item shows for a command is the plugin's that keeps the keys, `registrar.menuKeys { command, registry in … }` (`MenuKey`: the key equivalent as a menu item takes it and the `Modifiers`, `modifierFlags` for the item), read as `registry.menuKey(of:)`, nil for none, which a context menu's items read too. Shipped: Keyboard, the first key registered to run the command (`KeyChord.menuKey`).
  - What Copy as Image draws (`ImageSources`, keyed, at most one, a second `RegistryError.conflict`; `image source`): `registrar.imageSource(isAvailable:_:)`: `isAvailable: (CanvasEditor) -> Bool`, asked as the menu item is validated, so cheap, and the shapes, `(CanvasEditor) -> [ShapeID]`, those of the board shown to draw, back to front, none for nothing. Read as `registry.imageSource` (`ImageSource`: `isAvailable`, `shapes(for:)`), nil where no plugin says. Shipped: Clipboard, over `editor.canCopyAsImage` and `editor.imageShapes()`: the shapes a copy of the selection would take, or every copyable shape of the board shown with nothing selected ([clipboard](clipboard.md)).
  - The commands (`HostCommands`, keyed, at most one; `host commands`): `registrar.hostCommands(specs:run:)`, what the command line shows of each command and how to run one by name, both handed the frozen registry (the commands are every plugin's, known only once it's built). Read as `registry.hostCommands`, `(specs, run)`: no specs, and every name `unknown_command`, where no plugin gives any. The one slot said in the wire's types (`CommandSpec`, `JSON`, `RPCError`). Shipped: Automation, over `automationCommands` and `runAutomationCommand` ([command line](command-line.md)).
- **A view a plugin gives** is made for a window's canvas: handed that board's editor and `onExit`, which gives the keyboard back to the canvas (`CanvasFocus.take`), and it follows the editor by itself. A view over the canvas is over the whole of it and takes clicks only where it draws.
- **The window's side** (CanvasUI, which knows no plugin):
  - `BoardChrome(editor:showsInspector:onExit:)` (`Sources/CanvasUI/BoardChrome.swift`), a public view modifier the app applies to its `CanvasRepresentable` after its frame and toolbar: each registered overlay folded onto the canvas with `.overlay(alignment:)`, in plugin order, then, if an inspector is registered, `.inspector(isPresented:)` with it and its toolbar button (Inspector, its tooltip "Show Inspector" or "Hide Inspector": `ChromeStyle`). No inspector registered, no `.inspector`.
  - The inspector's rule (`InspectorRequests`, private, with a `revealed` flag of its own): `isRequested` turning true while the inspector is hidden shows it and notes that; turning false hides it again only if that's what showed it; the person hiding it while it's requested runs `onDismiss`, then `onExit`. Generic over whatever requests it: the window has never heard of Find, whose ⌘F shows a hidden inspector through the detail panel's takeover ([find](find.md), [detail panel](detail-panel.md)). `FindState.revealedInspector` is gone.
  - What the canvas covers: `BoardDocument` sets each board's `editor.coveredTop` to `registry.hostCoveredTop(on:)` (host API, [editor](editor.md)), so a fit leaves the path's pill clear. A headless editor is told nothing and covers nothing, which is why this stays the window's to say and isn't a core point the editor reads.
  - The subtitle: `BoardWindowController` reads `registry.windowSubtitle(for:)` observed, so it follows a switch of board or a rename; with no plugin saying one it reads nothing, and is never read again.
  - `SettingsWindow` (moved here from Composition): `SettingsWindow(registry:)` hosts `registry.settingsPanes` one under another (`SettingsPanesView`), unheaded, since a pane says what it is itself; `init(autosaveName:content:)` hosts any view. Made afresh each time it opens, sized before it goes in. It and the Keyboard Shortcuts window are a `SecondaryWindow` (`SecondaryWindow.swift`, an `NSWindow` whose `cancelOperation:` is Close), so Escape and ⌘. close them when nothing inside took the key (P5, P6). The key pane (LanguageModels' `AnthropicSettingsView`) puts the keyboard in its field as it appears (`@FocusState`), makes Save the default action (Return saves), says each status as it changes (`AnthropicKeySettings.announce`, an announcement; tests set it) and gives the status line `statusHelp` as its accessibility hint.
  - `ToolPicker(editor:)` reads `registry.toolTip(for:)`; it takes no `help:` closure. It shows the tool lock on the selected segment ([keyboard](keyboard.md)).
  - The menu bar: `BoardMenus.make(appName:registry:editor:)` (the app's `BoardMenus.install(appName:registry:)`), the window's own items and the commands placed in it, each item carrying its command (`BoardMenus.command(of:)`) and sending `BoardWindowController.runCommand:`, the controller's one action for every command, whose one validation dims an item while `editor.canPerform` says no and while text has the keyboard for a `.whenIdle` command, and retitles it by `editor.menuTitle(of:)`. Edit's Undo, Redo, Cut, Copy, Paste, Delete and Select All are AppKit's own, run on the board as the commands that answer them (`editor.perform(answering:)`): the window's `undo:` and `redo:`, the controller's `cut:`, `copy:` and `paste:`, the canvas's `delete:` and `selectAll:` ([keyboard](keyboard.md)).
  - Panes (P1, P3 of [keyboard navigation](keyboard-navigation.md)). `HostInspector.keyboardEntry` (optional, `registrar.hostInspector(keyboardEntry:)`) is the view the inspector says takes the keyboard now (the detail panel declares the overview's list, else its header's field); View › Focus Inspector (⌥⌘I) and the inspector's turn in the pane cycle give the keyboard to it, else to the topmost list, table or text field, else any control, as before, and when the panel has none at all (after the retries a just-shown inspector needs) to the window's hosting view, so Tab enters the loop: it never stops silently. View › Focus Next Pane (F6) and Focus Previous Pane (⇧F6) are `BoardWindowController`'s (`focusNextPane:`, `focusPreviousPane:`, placed after the inspector tabs) and move the keyboard round the panes shown (`shownPanes()`: the canvas; the inspector while shown and a host inspector exists; the toolbar while it is visible and one of its items' views, or a view in one, takes the keyboard): `currentPane()` reads where the keyboard is by the first responder (a view the window puts over the canvas, the board path or Jump To's field, is the canvas's pane; the hosting view itself, where Focus Inspector's last resort leaves it, the inspector's; nowhere, on the window itself: F6 then goes to the second pane, ⇧F6 to the last), ⇧F6 is the exact inverse, a shape being edited ends first, and the way back to the canvas is `CanvasFocus.take`. Escape in the toolbar, which takes no text, or on the bare hosting view, gives the keyboard back to the canvas (`BoardWindow.escapeToCanvas`, the selection kept), with Caps Lock on too (`Modifiers(event.modifierFlags)`, the four that change a key). Ctrl-F6 is the system's floating-window key and F6 may need fn on a laptop, which is why the items name F6 in the window. The toolbar's item views exist only once the window is on screen, so CompositionTests' `inspectorFocusShippedTests` put a segmented control into the unshown toolbar's item view.
  - `BoardWindowController`'s own items, with no command: Edit › Copy as Image (⇧⌘C, `copyAsImage:`) is dimmed unless `registry.imageSource?.isAvailable` and otherwise draws `source.shapes(for:)` from the board's own file with `BoardPicture(file: editor.file, registry:, board: editor.board, showing:)` (the whole file in the picture's editor, as opening it reads it, so the file's own colors, the types notes are of and what mentions name are there to read, wherever they are; only those shapes drawn, the core's `editor.drawnShapes`, and fitted; a big file costs what opening it does; `picture.inset = ImageCopyStyle.inset`, 32 points of margin in all; `pngData(within: ImageCopyStyle.limit, scale: ImageCopyStyle.scale, appearance:)`: at most 2048 × 2048 points, 2 pixels to a point, in the window's `effectiveAppearance`, the PNG's resolution saying so) and writes the PNG to `BoardConfiguration.imagePasteboard` (`.general` in the app, so `BoardConfiguration(registry:imagePasteboard:content:)`; a test passes its own, as CompositionTests' `configureBoards(pasteboard:)` does, and no test reads or writes the general one); View › Focus Inspector (⌥⌘I, `focusInspector:`, dimmed with no `registry.hostInspector`) shows the inspector (`viewState.showsDetails = true`) and gives the keyboard to `inspectorKeyView()`: of the window content's views that are visible, accept first responder, aren't scroll or clip views and whose middle is outside the canvas's frame (the inspector is the window's content beside the canvas, whatever it holds, and what's over the canvas, the path's crumbs, is inside the frame), a table (`NSTableView`, so the table of contents' list, which the panel shows with nothing selected) first, else a text field or text view (a selected shape's header title, which is above its back button), else any control, the topmost then the leftmost of its kind; it tries again each 16 ms for up to 30 turns while the inspector is just shown and SwiftUI has made no views yet (`InspectorFocusStyle`, `editor.scheduler`). Escape from either gives the keyboard back to the canvas through the panel's `onExit` ([detail panel](detail-panel.md)).
  - `KeyboardShortcutsWindow(registry:menu:autosaveName:)`: Help › Keyboard Shortcuts (⌥⌘/), `registry.keyboardHelp` and the menu bar filed into sections (`KeyboardShortcutSection.sections(menu:rows:)`, [keyboard](keyboard.md)), made afresh each time it opens, as Settings is: its rows read again and its list a new view under an identity per opening (`KeyboardShortcutsView.opening`; a hosting controller keeps its root's state when the root is replaced), so nothing typed last time stays, and the search is given the keyboard again (AppKit does it only as a window is first shown). It opens with a search field focused (`KeyboardShortcutSection.filtered(_:by:)`: `FuzzyMatcher` over a row's title and each of its keys, best first, a section with no match gone); a row is one accessibility element reading "Title, keys" (`Row.spoken`) and a section title is a header; the rows are still generated, never written by hand (P6, P9).
  - `BoardConfiguration(registry:content:)` has no `coveredTop` or `boardName`: both come with the registry.
  - `CommandServer.Commands(registry:)` is `registry.hostCommands`, what the server runs beyond its own.
- **The app** (`Sources/InfiniteCanvas/InfiniteCanvasApp.swift`) imports Canvas and CanvasUI, and no plugin: it builds the registry from the product's list, each plugin made by its name (`Registry(plugins: ShippedList.plugins())`, [build](build.md), What ships), hands it to `BoardConfiguration`, `SettingsWindow(registry:)`, `KeyboardShortcutsWindow(registry:)`, `BoardMenus.install(appName:registry:)` and `CommandServer.Commands(registry:)`, opens a new, empty board when it's launched with nothing to open, and its `ContentView` is the canvas, the toolbar's `ToolPicker`, and `BoardChrome`.
- **Adding a slot**: a point in `HostSlots.swift` owned by `.core`, its sugar on `PluginRegistrar`, a public reader on `Registry`, and the window's use of it in CanvasUI. Never a module that imports both sides, and never a plugin's type in CanvasUI or the app.

## Testing

- CanvasUITests' `KeyboardShortcutsTests` (the search: matches on title and keys, the field focused and named, Escape closes both windows, ⌘. too; SwiftUI builds its accessibility tree only for an assistive app, so the rows' and headings' modifiers are not read in a test, and `spoken` is) and `CardViewTests` (below); LanguageModelsTests' `SettingsViewTests` (the key field has the keyboard, Return saves, a status change is announced).
- CanvasTests' `hostSlotsTests` (`HostSlotsTests.swift`; fixtures only: `Contributor`s of their own, CanvasTesting's tiles and pockets) hold the points: overlays in plugin order with their alignments and what they cover, the most covered per board and none with no overlay; a view made only when the window asks, handed the editor and `onExit`; the inspector (none by default, `isRequested` and `onDismiss` as given, never requested by default, a second a conflict); the subtitle (nil without one, per board, a second a conflict); panes in order, made when asked, a title once; a tool's tip a plugin's or its label, a second a conflict; the Keyboard Shortcuts window's rows (a list's off the built registry, then the hints in plugin order, a row once, none with neither, a second list a conflict) and a command's title; the menu bar's commands and the menu keys slot are CanvasTests' `commandTests` (each command's section, place and key, none without a slot, a second a conflict, what the registry refuses of the sections and places, the report); the commands (no specs and `unknown_command` by default, a contributor's specs read off the built registry and its `run` handed the name, the params and the editor, a second a conflict); and each summary in the report.
- CanvasUITests' `chromeTests` (`ChromeTests.swift`) host a real `CanvasRepresentable` with `BoardChrome` in an unshown window, with fixture overlays (a `Marker` view found by identifier) and a fixture inspector that's requested while an `@Observable` model says: each overlay where its alignment puts it; nothing with no contributions; the inspector shown when requested while hidden and hidden again after, left alone when the person had it shown; hiding it while requested dismissing and giving the keyboard back, and nothing when it isn't requested. `toolPickerTests` hold the tips (a contributor's, and the label without one) and the lock.
- `hostSlotsTests` also hold the image source (asked apart from making the file, handed the board's editor, none without one, a second a conflict); CompositionTests' `copyAsImageShippedTests` (the item on a private pasteboard, `NestedWindow(pasteboard:)`) and `inspectorFocusShippedTests` (a real `BoardWindowController` over the nested file: the list with nothing selected, a selected note's title field and not the back button, a hidden inspector shown first, Escape from both, the menu item) hold the window's own items.
- Each plugin's own tests hold what it gives: BoardsTests' `headingTests` (the path's alignment and covered height, the subtitle following a board shown and a rename), JumpToTests' `paletteTests` (its overlay after Boards'), DetailPanelTests' `takeoverTests` (the inspector requested while a takeover is active, dismissed through its escape), KeyboardTests (the tips), LanguageModelsTests' `pluginTests` (the pane with an Anthropic model over a temporary key store, none with a scripted one), AutomationTests' `registrationTests` (the server handed every command, the plugin's own and another's, each run by name, an unknown one refused).
- CompositionTests hold the shipped slots (ShippedTests: the two overlays in order, the covered height, the inspector, the subtitle, no pane with the scripted model and the key's with the app's, the toolbar's tips, the commands as the command line lists them, and the report's lines), the Settings window over the registry's panes with a temporary key store (`settingsWindowTests`), and the window's behavior with Find (`findShippedTests`: ⌘F showing a hidden inspector, closing hiding it again, hiding the inspector closing Find). `InspectorHost` applies `BoardChrome` as the app does.
