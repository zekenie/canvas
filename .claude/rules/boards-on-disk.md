# Boards on disk

`BoardDocument` and `BoardCodec`: the file formats, migrations and fixtures, what's kept aside, the view memory, saving and autosave.

Related: [boards in a file](boards-in-a-file.md), [properties and schemas](properties-and-schemas.md), [undo](undo.md), [subboards](subboards.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Boards on disk](../../docs/plugin-system.md#boards-on-disk).

## Architecture

- Boards are files, one per board, with the boards inside it (`docs/plugin-system.md`, "Boards on disk"): `BoardDocument` (CanvasUI, an `NSDocument`, autosaved in place) saves `editor.file`, every board of it, with `BoardCodec` (Canvas), and opens one with `replaceFile`; only a board's document writes its file, a new one too (`BoardDocument.newFile(at:)`, `canvas new`'s: a new, empty board saved there as Save As saves one, unedited, its type the app's, closed if the save fails); `openWindow()` opens a board in a window of its own, one of the app's documents, as File › Open does (File › New's, an earlier version's copy, `canvas new`'s). The app is AppKit-run: `InfiniteCanvasApp` sets `BoardDocument.configuration` (the shipped registry, the window's SwiftUI content) and installs `BoardMenus`; the Info.plist that `build.sh` writes exports the `.canvasboard` type (not `.board`: Freeform owns it). Order in the stack is each record's `stackingKey`. A kind's props are versioned by its append-only `static let migrations`: changing how they encode needs a migration and a new fixture in `Tests/CompositionTests/Fixtures/kinds` (never edit a fixture), even a new member with a default (`PropsMigration("name")`, which rewrites nothing). An added property's value is versioned by its own (`PropertyMigration`, over the value's JSON), whatever kinds opt in, with fixtures in `Fixtures/added` (`expectPropertyFixtures`); `PropsMigration.handOver("title", to: TitleProperty.self)` hands a kind's own member over to one. Shapes the app can't use are kept aside (`AnyShapeRecord.isOpaque`) and saved back as they were, each with its own version (`v`), since the envelope lists only the kinds the app writes; a horizontal that goes through every shape skips them. A kind the app no longer has (the schema card, retired for type notes) is such a shape: `Fixtures/files/frames.v5.json` holds one, read kept aside and written back as read but for that version moving onto the card (FramesShippedTests). A record's metadata is saved beside its props (`meta`), members no plugin knows included, and its added values in `added`, by key; those the app can't use (not declared, not opted into, newer, unreadable) in `kept`, with their versions, saved back as they were and listed in `LoadReport.keptValues` (the alert never offers to delete them). A board is written in the oldest format that holds it: 5 when a shape on any board is in a container (its `container`, beside its props, read only from 5; reading drops one not on the shape's own board or in a loop, `LoadReport.Repair.droppedContainer`, and keeps one that can't hold, kept aside or of a kind that holds nothing here, as written), else 4 with any board besides the root (`BoardCodec.encode(CanvasFile)`: `boards`, one flat map by owner id, never nested (Foundation's JSON reader stops at 512 levels), each `{ "shapes" : [...] }`, under the root's `versions`; read only from format 4), else 3 with added values (the envelope's `versions` has `kinds` and, when any, `added`), else 2 with metadata, else 1 (both with `schema`), so an older app refuses what it would save without. `LoadedBoard.file` is every board (`document` its root); reading walks the boards in tree order with one set of ids, so a repeated id is the first holder's, with the board it owns, and keeps the boards it can't show (`LoadReport.keptBoards`, `KeptBoard`: an owner kept aside, of a kind that owns none, inside such a board, unreachable, or an entry that isn't a board, kept verbatim in `CanvasFile.unreadableBoards`), writing them back; `KeptShape` and `KeptValue` name their `board`. The camera on each board, the board left open, and whether the details and the minimap show are remembered per file (`BoardViewMemory`: `View`'s `board` and `boards`, read with `decodeIfPresent`, so an older entry is the root's; saved for the boards the file can still show, `editor.boardCameras`: the one shown and those above it, then those shown most lately, up to `BoardViewMemory.boardLimit`, 50, by `editor.boardsLeft` and the last session's `recent`), never in the file; a file opens on the board left open if it can still show it, through `replaceFile(with:showing:)`, so it's no step back nor an edit, each board with its camera (`rememberedCameras`); the board shown's camera comes back before the window makes its canvas, so the zoom it opens at isn't shown as a change ([drawing](drawing.md)). A board document has no undo manager (`hasUndoManager = false`): it counts its changes by its history's events (`undoHistory.didChange`, host API: a step began, came to nothing, was undone or redone), at once, so undoing to what was saved reads unedited. Every save closes the open step (`breakStep`), so undo returns to exactly what was saved; a periodic autosave during a press, or while a key is held whose repeats are one step (`undoHistory.isKeyHolding`: an arrow key's nudges), gives way (`userCancelled`) and runs once it's let go (`snapshot(implicitlyCancellable:)`). Its window is a `BoardWindow`, which answers Edit › Undo and Redo: the text's own while text has the keyboard (its `textUndo`, the only undo manager text views see, or a field's; forgotten when the text loses the keyboard; after each, the text says it changed, so a note or a field's binding writes it), else the board's `.undo`/`.redo`, named ("Undo Move"); it seals a run of panel writes on a click, a key on a control, or the keyboard moving, and every board's window seals on a click in a window that isn't a board's (the color panel), but not in a board's child window (the `@` picker beside a panel's text, whose pick is part of the typing).
- A shape's stored box is the shape with no layout input: a kind laid out larger than it stores (`LaidOutBox`, [editor](editor.md); a note with rows) never writes the laid-out size, so the codec, the migrations and the fixtures see the box as it was, a preview draws it as stored, and a shape whose rows go is the size it was. Nothing is stored for rows, and a note's kind stays at version 3.
