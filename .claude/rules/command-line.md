# The command line

The `canvas` command line: the wire (CanvasRPC), the CLI, `CommandServer`, Automation's commands (`draw`, `show`, `kinds`), `canvas draw`'s language and the lexicon's points, and the canvas skill that teaches them.

Related: [queries](queries.md), [language models](language-models.md), [properties and schemas](properties-and-schemas.md), [shape references](shape-references.md), [containers](containers.md), [titles](titles.md), [connections](connections.md), [validation](validation.md), [boards in a file](boards-in-a-file.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [The command line](../../docs/plugin-system.md#the-command-line), [draw](../../docs/plugin-system.md#draw).

## Architecture

- The command line (`canvas`, for agents first, people too; `docs/plugin-system.md`, "The command line"): agents never read or write a board's file, only run `canvas`, which asks the running app. The wire is CanvasRPC (layer `wire`: knows no canvas, plugin or AppKit): JSON-RPC 2.0, a message a line, over a Unix-domain socket only this user can reach (`~/Library/Application Support/InfiniteCanvas/canvas.sock`, or `CANVAS_SOCKET`; the app that holds `canvas.sock.lock` listens, so a second app gives up and a crashed one's socket is taken over); `CommandSpec`, a command's description with its params as a JSON Schema, and how params are spelled as arguments (`spec.params(from:)`, `usage()`, `help()`); the blocking `RPCClient` and the `RPCListener`, which answers each request as a main-actor task of its own (its `Handler` is async; `init(path:synchronous:)` wraps one that answers at once), a connection's answers in the order its requests came, and cancels the requests with ids still running once its client hangs up (never notifications). `canvas` is CanvasCLI (layer `cli`: the wire only, never the app) and knows no command but `help`: each run asks the app (`describe`) and makes the commands, their arguments and their help from what it says, so a plugin's command needs nothing of `canvas`, and it refuses an app of another `RPC.protocolVersion`. Results go to standard output (JSON when it isn't a terminal, text for people, `--format`), errors to standard error with a `reason` and a `hint`, and it exits 0 done, 1 the app couldn't, 2 usage, 3 unreachable. The app's end is CanvasUI's `CommandServer`, started by the app: `status`, `boards` and `new` are its own (`boards` lists each open file: its id, name and file, which is in front, whether it's edited, what its window shows, and `shapes`, the board shown's, and `fileShapes`, every board's, `CanvasFile.shapeCount`; `new <file>` makes a new, empty board's file through its document, saved as Save As saves one (`BoardDocument.newFile(at:)`), never as JSON, shows it through the server's `show` (the app's document controller; a test gives its own) and answers as `boards` lists it, refusing a file that's there already (or a folder as written), or that a board open is or another `new` is saving (`file_exists`), a known type's extension (`.txt`, a `UTType` that isn't dynamic; `invalid_params`), any other ending getting `.canvasboard` (`BoardConfiguration.fileExtension`) as the Save panel adds it (`Sprint 3.2` is `Sprint 3.2.canvasboard`), a folder that isn't there (`no_folder`) and a save that fails (`cannot_save`)), and it runs the rest on the board a request names (`--board`: its number, `BoardDocument.number`, its file, or its name) or the one in front, and there on the board inside the file that its window shows (`editor.board`: `boards` names it, `shows` and `showsPath`, root first, as `BoardID`s, and `status` the front one's, `frontmostShows`; no command addresses another yet), so a command's change is an undo step on that board; each command runs in a task kept against its board, and a client gone is answered `cancelled`, a board closed (`BoardDocument.close()`) `board_closed`, at once, the task cancelled and what it returns later dropped (every command, `draw` included, runs a main-actor hop after its request, so one cancelled before it starts never runs). Every other command is Automation's (a language, which the app reaches through Composition's `commands(in:)`, async, as `Registry.runAutomationCommand` is): `registrar.automationCommand("name", "summary", params: P.self, positionals:, examples:) { params, context in … }`, its params a `SchemaDefined` list (each property an option, `fooBar` as `--foo-bar`; `x-value-name` for help), checked and decoded before it runs, its output anything `Encodable`, answered in the turn it's asked in; or, for one that waits (a model, a query), `runAsync:` (write the label out: a trailing closure that doesn't await picks `run:`), its output `Encodable & Sendable`, written as JSON and freed off the main actor (`AutomationCommand.encoded`, `@concurrent`; a `JSON` output, `JSON(_: JSONValue)`, passes through), a long wait looking at `Task.isCancelled`; its errors `AutomationError(_:reason:hint:)` (with `line:`, `column:` and `length:` in characters, `statement:`, `errors:`, and `details:`, whose members join the error's data under names of the command's own, never one of the error's), a board command's changes through `context.board()`'s `transact`. The registry refuses a name `canvas` can't type or that's kept (`RPC.reservedCommandNames`: `describe`, the server's `status`, `boards` and `new`, `canvas`'s `help`), a param named `board` or like `canvas`'s own options, and two commands of one name. A command's options may come before its name (`canvas --board 2 draw - < plan.txt`); text whose schema says `"x-stdin": true` is read from standard input when given as `-`; text whose schema says `"x-path": true` (`new`'s file) is a file named from where `canvas` runs, which it sends whole (`CommandArgument.isPath`, `Invocation.absolute`; an older `canvas` sends it as typed, and `new` refuses a file not named from `/`); an error about a script or a query carries `line`, `column`, `length` and `statement`, which `canvas` prints as `line L, column C: …` with carets under the columns (`Invocation.caret(under:column:length:)`), and several at once `errors` (protocol 2, which a param's `"x-timeout": N` and an error's `column` and `length` keep: an older `canvas` passes over them); a param whose schema says `"x-timeout": N` has `canvas` wait up to N s when it's given (`CommandArgument.waits`: a call waits `--timeout`, else the longest such, else 10 s; help says "(waits up to N s)"); CommandServer adds `board: {id, name, shows, showsPath}` to a board command's object result, as `boards` lists it, read in the command's own job just before it runs (so `draw`, which doesn't wait, names the board it drew on, whatever the person did since the request came); a command that knows better where it worked says `shows` and `showsPath` in a `board` object of its own, which the server completes (a query: the board shown as it took up the file, `QueryResult.shown`, since it may wait for answers to settle or on a model). Automation's own: `draw`, `show` and `kinds`. `draw` reads a script in a language after reladraw's (`THIRD_PARTY_NOTICES.md`), one statement a line: a shape named by its title (a title the board has restates that shape, any other makes one), with attributes by its kind's schema and placements against shapes already named, never coordinates; an edge; a delete; a style. DrawScript reads it (`Script(parsing:)`) and places it (`LayoutProblem.solve()`, its obstacles, every board shape with a solid that the script doesn't move or delete (`ShapeContext.solidBounds(of:)`, the core's rule: its bounds where its geometry is closed, finite and not flat, never a shape kept aside; what a container the script moves holds met where the container takes it, never where it is now, `LayoutProblem.Free.carries`: moved as far as the innermost such container moves and kept clear of by a bound against that container, so containers can trade places in one run, and `board`'s box leaves it out as it leaves out what the script moves), filed once a run in DrawScript's `ObstacleGrid` (boxes only, in paint order, so a plugin that isn't a language places shapes among others the same way, as Moving's `/move-to` and `/move-near` do, [moving](moving.md); Automation's `ObstacleIndex` fills it and keeps each obstacle's shape beside it), and each answer kept, so a draw costs what's near what it places: `./build.sh bench` holds 20 notes pushed along rows of 10,000 shapes to 150 ms); Automation's `Drawing` resolves it against the board shown as the run starts (new shapes from `placement.shape(at:)`, attributes through `registry.shape(_:setting:)`, JSON held to the kind's schema first, `registry.schemaViolations(of:kind:)`, so a member its type hasn't is `invalid_value`, not dropped; a property whose schema says `readOnly` (`Property.readOnly()`) is no attribute (`KindVocabulary.isAttribute`: written, it's `unknown_attribute`, and `kinds` leaves it out), and a string whose `format` is `x-canvas-query` is asked of the query engine once read (`DrawQueries.swift`: `editor.queries?.check`, syntax and vocabulary only, so a bad one is `invalid_value` with the engine's own message and hint and nothing is drawn; without QueriesPlugin it isn't checked; Automation, a language, uses Queries, a surface, and the format names no kind); an object value replaces its whole property; a size the kind derives from what's set, a note's height, is the one it's placed at, and `size:` with a width alone (`300x`, DrawScript's `Size` with no height) builds the shape at that width first and puts what the kind derives in step there whether anything's set or not (`registry.derived(_:)`, the core's), so a note is that wide and as tall as its text there in one run, and any other kind keeps its height; a `size:` under the smallest its kind's placement draws (`Placement.minimumSize`, the one place a kind says it: a frame's 96 × 64, which the Frame tool's drag, resizing and Create Frame read too) is `invalid_value`, as one over 100000 is, with the size to write (a shape restated at the size it is already changes nothing, and goes through); `view` is where the camera is headed, `editor.cameraTarget`, the part of the view the host leaves clear, `unobscuredViewport`, as `--reveal` fits into) and applies it in one `editor.transact("Draw")`, one undo step, marked `byAgent` (deletes, each shape's with every connection bound to it, a subboard's with its boards, said in a warning, unless one holds a locked shape, and a container's (a frame's) letting go of what it holds, the core's; shapes, each after what it's drawn inside, on or in, a restated container before what it holds, and raised above it, or a zone it sits in where it lands (`Solver.isZone`: an obstacle that wholly holds the shape where it already sat, a shape it's placed against at twice that one's area, where it lands and another shape too at twice its own, or the view it's placed against or drawn in; a shape the script places counts as held only when it's there for a reason of its own, `Solver.counted(by:in:)`, so two new shapes never hold each other on an empty note), while writable (`transaction.isReadOnly(_:)`: a shape in a locked frame, or on a locked subboard's board, is read-only), each put down as by hand once every one is where it goes (so none is judged against where a shape the run moves was), one by one, those holding no shapes first, then the containers, new, placed or resized: settled by the in-or-out rule (`transaction.settle`: wholly in or out of a container whose edge it's over, nudged, and said, glided after a real run, `editor.glide`; a container put down taking in what it lands on, also said; a read-only container refusing the run, `read_only`), a container placed elsewhere taking what it holds along (`translate`), which is never in its way (`LayoutProblem.Free.carries`), and a placement against what it takes along `unsupported`, while a container's edge is no zone's to warn about; then edges against `transaction.shapes`; anything wrong, or `--dry-run`, throws out of the body, so nothing commits and no step opens); a real run ends a person's typing only once it's placed, has been applied once and thrown away without an error, and changes that shape, and waits out a drag or a press held (`busy`, `undoHistory.isPressHeld`: what commits during a press is its step's); its result is rows by line and title, never ids, and warnings, among them names (`ShapeNaming`: a note's mentions) of shapes that aren't in the file or are on boards the app can't show, as the result lists them, since a script wrote them. A shape bound (`ShapeReferencing`) to one not on the board is refused. A kind whose title is only derived (none shipped; Titles keeps the API) can't be titled by a script, and is renamed by what it's derived from (`renamed`); a type is a note drawn with `schema:` (Types' added property, an attribute as every added property is), named by its title. It never names a board: it draws on the one what it names is on (a title names a shape on any board of the file the app can show, the board shown's first; a new shape goes on its placements' targets' board, or the one `in "X"` names: the board X holds (a subboard's), or, for X a container on its board (`ShapeContaining`: a frame), that board, the shape kept within X as `inside` keeps one (`LayoutProblem.Free.holder`, `no_room` if it can't be; with no other placement, and not in X already, against its top-left, 40 in, a clause written `in "X"`), and in X once put down, `read_only` for a read-only X (a locked frame, or a subboard whose board is read-only: its own lock, or a lock above it, `"X" is read-only (locked, say), so nothing goes in it`), `unsupported` for one the script draws, `circular` for the shape itself or one it holds; else the board shown), read through the core's `editor.reading(of:)` (`BoardReading`: shapes, a `ShapeContext` and paint order, the view it would be shown with, and `isBoardReadOnly`) and committed with `transact(on:)`, the window staying put (`--reveal` shows it); a board that's read-only (a locked subboard's, and every board under it) takes nothing new: a new shape that would land there, by its placements' targets or on the board shown, is `read_only` (`"N" would go on "Plans"'s board, which is read-only (locked, say)`, `FileNames.named` naming the board, each statement's first problem, found as the run starts, so a dry run says it too, with nothing changed and no step), and so is a new edge (`edge "A" -> "B" would go on …`, found as it's applied, in `connect`); changing or deleting what's on it is refused as any read-only shape's is (`target.isReadOnly`, `transaction.isReadOnly`), and a restatement that changes nothing is `unchanged`; one run is one board (`several_boards`, but for an edge between boards, next), its result's `on` says which, and a delete can't take the board shown or one above it (`board_shown`). `canvas show "<title>"` or `--root` (Automation's) moves the window. What it doesn't own comes from four Automation points, at most one contribution each (`DrawTextFormats`, one for each media type), filled by DrawLexicon (AutomationTests fill them with fixtures of their own): `DrawNames` (`registrar.drawNames`: `TitleNamesPlugin`), `DrawEdges` (`registrar.drawEdges`: `PortEdgesPlugin`, whose `sides` lists none for a kind draw can't name, neither a naming property nor a derived title, `registry.drawCanName`, since an edge names its ends; the connector's connections made by name, on a channel picked from the port table as a drag would, `registry.connectionChannel(from:fromSide:to:toSide:)`, or `channel: none`; an edge's other attributes are the edge kind's, an arrow's `text:` and `labelPosition:` among them, read by its schema as a shape's are and set on what `make` returns, which is made again over it to refuse one that says otherwise than the edge as written, an arrow's heads), `DrawChecks` (`registrar.drawChecks`: `ValidationChecksPlugin`) and `DrawTextFormats` (`registrar.drawTextFormat(mediaType:describes:write:)`: `MentionTextsPlugin`, for mention text; a string whose schema says `contentMediaType` of the format's media type, wherever it is in a value (`DrawTexts.swift`: an attribute's, a style's, an edge's own, a string inside an object or a list, found by walking the value beside the property's schema, `$ref`s followed, and only for the properties that can hold one, `KindVocabulary.textKeys`), is handed to `write` as the script wrote it, with a `DrawTextContext` (the registry; the string's schema as declared, `$ref` unfollowed, so an annotation beside it reads; and `shape(called:admitting:)`, which finds the shape a title names, among those `admitting` takes, a nil admitting and a string saying why not, as a clause after its kind: the script's own shapes first, one drawn further down too, and one renamed to the title (`title: "New"`, the old title too); else the board the run draws on; else the board the window shows; else any other board the app can show (those last two are `FileNames.beyond`, which finds an edge's end on another board too); `ambiguous_title` for two or more in one place, `unknown_title` for none, with `Suggestions.closest`, or for one only the script's deletes have (`names "X", which this script deletes`), `invalid_value` for one called that and none taken, said as the format's clause) and keeps what it gives back; a refusal is the statement's, on its line, `"Plan": text: …` (`(from style x)`; an edge's, `edge "A" -> "B": text: …`); the file's names, `FileNames`, are read when a lookup first asks and shared with `Drawing.board(for:in:)`, so a script whose texts name nothing reads none, `AutomationPlugin.fileNamesRead` in debug builds, and a title in a text never decides which board the run draws on; `canvas kinds` says what a format takes after the type of a property it writes, `text (@[Title] mentions)`, `KindVocabulary.compactType`); without one, titles are `no_names`, edges `no_edges`, text kept as written, and checks only the schemas' bounds. `kinds` is the language's vocabulary (each kind's drawability, names, size, its `smallest` where its placement says one, what its shapes hold for `in` to name, `holds`: `board` or `shapes`, attributes with compact types, edge channels by side; `--schema`). `query` and `query-vocabulary` are QueryCommands' (a language on Automation, Queries, QueryTranslation and the wire, which declares no point: `QueryCommandsPlugin()`, and `--ask` is a call to `editor.queryTranslator` whose `QueryTranslationError` it says as an `AutomationError`, reasons, messages and hints unchanged): `canvas query <query>|- [--ask <question>|-] [--limit <number>] [--count] [--brief] [--fields <attribute>]…` is a board command (`runAsync:`) answered about the whole file, taking exactly one of a query and `--ask` (up to 2,000 characters, `x-timeout` 60), and not both `--brief` and `--fields` (`invalid_params`); its answer is `{board, query (canonical), count, rows, warnings?}` (`board` where it ran: `shows` and `showsPath`, the board shown as it took up the file, which the server completes with the file's `id` and `name`), `asked` with `--ask`, no rows for `--count`, built member by member as JSON off the main actor (`QueryOutput.json`, the result consumed and freed there, never through `JSONEncoder`); a refusal carries its reason, message, hint, `line`, `column`, `length` and `statement`, the line as sent, whole, so the caret lands on what's wrong (at most 200 characters around it, `QueryOutput.quoted`, `QueryError.located(in:quoting:)`), and `errors`. `canvas query-vocabulary` (app scope) is `{vocabulary (the <vocabulary> block), kinds [{kind, label, naming, holdsBoard, attributes}], edgeTypes [{type, under?, summary?}], words [{word, takes, summary, example, from}]}` (`naming`, not `titles`, which is Titles' plugin id); without `QueriesPlugin` both answer `no_queries` (`registry.answersQueries`). The languages are taught by the canvas skill (`.claude/skills/canvas`), whose every `draw` and `draw-error` block, and every `query` and `query-error` block (a CSS comment first: `/* matches: "Title", (kind) */`, `/* count: N */` or `/* reason: … */`; each must leave the file equal, not edited, no undo step; `reference/query.md`, marked `<!-- board: query-story -->` on its first line, runs on the story file, `QueryStory.document(windowed: false)`, and `reference/references.md`, marked `<!-- board: reference-story -->`, on `QueryReferenceStory` ("Services": a public note, a reference to it, two channel-less arrows into the reference; CompositionTests, whose test holds the page's `via` snippet to what `canvas query` answers); a file's first line `<!-- board: <name> -->` names its board among `skillStories`, each the board of exactly one file, and a file with none runs on a new board), CompositionTests' SkillTests runs through `canvas` as built, holding its tables of kinds to `canvas kinds`, query.md's words and edge types to `canvas query-vocabulary` and its blocks to the design's table of every construct (`StoryQuery.table`), and SKILL.md's description to 1,024 characters; its `query-prompt.md` carries `QueryPrompt.system` byte for byte, which QueryPromptTests hold (`scripts/query-prompts/copy_prompt.py` rewrites it): a change to either language, its messages, the shipped kinds, words or edge types, or the prompt changes the skill too. After a timeout `canvas` hangs up, which cancels what looks for it (a query, `--ask`); the app may still have run what it was sent (`timed_out`'s hint says check first).
- Edges through stand-ins (`DrawStandIns.swift`, `DrawBoard.swift`; guide, "draw"): an arrow can't leave its board, so an edge between shapes on two boards goes into a stand-in (Topology's, [topology](topology.md): a reference) for the end on the other, a new shape of the run put beside the end on the board the run draws on. Which end: the one off the run's board, either end. Which board (`Drawing.board(for:in:)`, read by `BoardClaims`): such an edge claims a board softly with an end some maker admits and hard with one none does; the run draws on the first hard claim, else the board of the first such edge's start (`via:`'s start claims hard, `delete edge`'s ends as an edge's), and each needs one end on it, else `several_boards` (the hint, `Drawing.standInHint`: only a shape a kind admits can be stood for, ask the user: `public:` is theirs); `Drawing` reads stand-ins only for a script with an edge or a delete, and the board's claims only for one with an edge, so none costs a script with neither anything. Two edges claim otherwise. One **drawn through a stand-in already** (an arrow on one of its two boards between the end there and a direct stand-in for exactly the other: `Drawing.edgeMatches`, the one matcher, static, given the board's document, its arrows and `registry.standIns`) claims that board hard, the start's first, and its other end claims nothing, whether it can be stood for still or not, so a run again, a `via:` over it and `delete edge` find it where the stand-in is, rather than draw a second stand-in on the other board; each board's arrows are read once a run, and only for an edge between boards (`AutomationPlugin.boardConnectionsRead`, debug builds). One that joins **a shape the script draws** (a title no board has: it's on the board the run draws on, so it claims none) to a shape the file has claims for that end as an end of an edge between boards does: softly if a maker admits it (with nothing else to say the run goes to its board and the edge is straight there, as it always did), else hard, its title asked about in the hint. The stand-in is a `ShapeItem` (`standsFor`) placed as a new shape right of the start where that stays, left of the end where that does, or on the side `from:` or `to:` names for the end that stays, and where it clashes with a free box nothing orders it against it yields (`LayoutProblem.Free.implied`, `Solver.yielding`: DrawScript, never `unordered`), its push saying to name a side (and a push it takes others along on names the side for it); those beside one shape on one side are a list of their own, `LayoutProblem.impliedListStep` (16) apart (`Solver.findLists` keys implied boxes apart, and lists by what placements say, not their text: never with a box the script wrote, which stays where its placement puts it while they give way past it, where once it was taken into their list and off its centering), and a list moves as one (`Solver.listHolds`: each member held across from the one before where the first solve has it; and as free as all its members are, `Solver.freedom`, so a later member can't drag its head off a centering); beside a shape the run doesn't move, a stand-in joins the column a run before left on that side (`Drawing.columnEnd`: of the direct stand-ins an arrow on the board joins to it, `connected(to:)`, the board's arrows indexed by end once a run, those wholly that side of it, in line as a list lines them, on the nearest line whose stand-ins reach across from its middle, so one dragged off elsewhere isn't beside it), `impliedListStep` past its lowest (its topmost, above it), in line with it, its placements said in words (`Clause.written(_:naming:gap:)`: `below the reference to "Auth" (gap: 16)`), unless the run moves that end too; a side named for the end stood for is the stand-in's own (PortEdges' `checkStandInSides`: `top` for a reference is `invalid_value`). Its channel is picked as a drag from the shape stood for would (`EdgeRequest.fromStandsFor`, `toStandsFor`; Connections' `standingFor:` lookups). Matching (`edgeMatches`): an arrow between one end and a stand-in whose record stands for exactly the other, by `.shapes` (a `.provided` one never), is the edge, on one board too, so a run again is `unchanged` and makes no second stand-in, and `routeEdge` looks for one through a stand-in before it decides the kind or whether the end admits it, so what's drawn is the edge whatever can be stood for now; `via:` over an arrow drawn straight, or through one for the start, is `invalid_value` (`the edge "A" -> "B" is drawn straight to "B"`, hint: `delete edge` it above the line). Deletes: `delete edge` takes the matching arrows, and `delete "X"` every connection bound to X; then each direct stand-in at the other end of one (`standIn(at:in:)`, as `edgeMatches` reads them, so never a query's) that the run leaves with no arrow, a loose one counted, goes too, since it has no title for a script to delete it by (`standInsEmptied`, `retireEmptiedStandIns`, one pass over the board's arrows; a read-only one is `read_only`, `the reference that delete "X" leaves with no arrow is read-only (locked, say), so it can't be deleted`, and nothing is deleted); a stand-in for X with arrows from elsewhere stays. An edge's row has `via` (the kind; `unchanged` and `deleted` rows too, a `delete "X"`'s among them, which name the shape a stand-in stands for, `end(_:in:)`), the stand-in a row of its own on its statement's line, before the edge's when `created` (`kind`, `at`), after its arrows' when `deleted` (`kind`); one transaction, one undo step, `byAgent`.

## Testing

- For the command line, never use the app's socket: tests listen on their own (`temporarySocketPath()`, TestKit). The app answers on the main actor, so a test that's the client too asks off the main thread (`offMain`) or runs `canvas` as built (`run(builtExecutable("CanvasCLI"), arguments)`), both of which turn the main run loop until the answer comes. CanvasCLITests hold `canvas` to an app of their own (`FakeApp`: its errors' carets, `x-timeout`'s waits, `x-path`'s files sent whole); CompositionTests' CommandLineTests run it against `CommandServer` on real boards (`canvas new` on a server whose `show` keeps what it shows, `Opened`: the file the codec writes, its board as `boards` lists it and drawn on by its id, a dotted name, two at once for one file, `no_board`'s hint, and each refusal, a save into a folder that can't be written among them, which opens nothing and leaves no board open) (and a `Lingering` board command on a server of its own: a board closed under it answered `board_closed`, and a timed-out `canvas` cancelling it).
