# The command line

The `canvas` command line: the wire (CanvasRPC), the CLI, `CommandServer`, Automation's commands (`draw`, `rehearse`, which draws several scripts on a copy of the file, `show`, `kinds`, `measure`, which reads a board's types, and `capture`, which takes a picture of a board), Draw (platform, an engine), the engine under `canvas draw`, with its language and its points (`is:`, a note's values joined member by member, what each shape's values still need), and the canvas skill that teaches them.

Related: [queries](queries.md), [adornments](adornments.md), [language models](language-models.md), [properties and schemas](properties-and-schemas.md), [shape references](shape-references.md), [containers](containers.md), [titles](titles.md), [connections](connections.md), [validation](validation.md), [boards in a file](boards-in-a-file.md), [digest](digest.md) (the skill built on `canvas measure` and `share:`), [types](types.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [The command line](../../docs/plugin-system.md#the-command-line), [draw](../../docs/plugin-system.md#draw).

## Architecture

- The command line (`canvas`, for agents first, people too; `docs/plugin-system.md`, "The command line"): agents never read or write a board's file, only run `canvas`, which asks the running app. The wire is CanvasRPC (layer `wire`: knows no canvas, plugin or AppKit): JSON-RPC 2.0, a message a line, over a Unix-domain socket only this user can reach (`~/Library/Application Support/InfiniteCanvas/canvas.sock`, or `CANVAS_SOCKET`; the app that holds `canvas.sock.lock` listens, so a second app gives up and a crashed one's socket is taken over); `CommandSpec`, a command's description with its params as a JSON Schema, and how params are spelled as arguments (`spec.params(from:)`, `usage()`, `help()`); the blocking `RPCClient` and the `RPCListener`, which answers each request as a main-actor task of its own (its `Handler` is async; `init(path:synchronous:)` wraps one that answers at once), a connection's answers in the order its requests came, and cancels the requests with ids still running once its client hangs up (never notifications); and holds an activity of the process's for each request from its line read to its answer written (`Answering`: `ProcessInfo.beginActivity`, user-initiated, idle system sleep still allowed), so macOS doesn't nap the app while a client waits: an app whose windows can't be seen is napped (App Nap: its threads at a low priority, its timers put off) and stays napped while it works, an app an agent drives is in the background as a rule, behind the terminal or the app the agent runs in, and napped it answered six times slower (2026-11-05, a worktree's build hidden on a socket of its own with this repository's ingest open, 13,577 shapes: `canvas apply --dry-run` of that drawing, every verdict `unchanged`, 21 to 25 s napped and 4.2 s holding the activity, an unchanged `ingest` 74 s and 28 s; the main thread at priority 4 napped, 28 while it answers, and 4 again within half a second of the answer). One a request, so requests answered at once hold one each (the app's server answers a query while another waits), each ended however its request ends (an answer, an error, a line that isn't a request, a client gone, `canvas` timing out among them; a notification's once it has run), and none outlives its answer, a cancelled command running on included, so the app naps again when idle (`RPCListener.activitiesHeld`, debug builds, counts them). `canvas` is CanvasCLI (layer `cli`: the wire only, never the app) and knows no command but `help` and `install` (below, the bullet after this one): each other run asks the app (`describe`) and makes the commands, their arguments and their help from what it says, so a plugin's command needs nothing of `canvas`, and it refuses an app of another `RPC.protocolVersion`. Results go to standard output (JSON when it isn't a terminal, text for people, `--format`), errors to standard error with a `reason` and a `hint`, and it exits 0 done, 1 the app couldn't, 2 usage, 3 unreachable. The app's end is CanvasUI's `CommandServer`, started by the app: `status` (which says `build`, the app's build id: below), `boards` and `new` are its own (`boards` lists each open file: its id, name and file, which is in front, whether it's edited, what its window shows, `shapes`, the board shown's, `fileShapes`, every board's, `CanvasFile.shapeCount`, and `view`, the room its window has for a board fit into it, `[width, height]` in points (`CommandServer.fitRoom(of:)`: what a first visit fits the root board's shapes into, the part of the view the window's chrome leaves clear (its title bar's row, and the sidebar and the inspector while they show: `coveredEdges`) less `CanvasEditor.firstVisitInset` on every side, and the same whichever board of the file the window shows, so a tool that asks twice plans the same; left out while the window has no size), which is what a tool that lays a board out shapes it for ([digest](digest.md)); `new <file>` makes a new, empty board's file through its document, saved as Save As saves one (`BoardDocument.newFile(at:)`), never as JSON, shows it through the server's `show` (the app's document controller; a test gives its own) and answers as `boards` lists it, refusing a file that's there already (or a folder as written), or that a board open is or another `new` is saving (`file_exists`), a known type's extension (`.txt`, a `UTType` that isn't dynamic; `invalid_params`), any other ending getting `.canvasboard` (`BoardConfiguration.fileExtension`) as the Save panel adds it (`Sprint 3.2` is `Sprint 3.2.canvasboard`), a folder that isn't there (`no_folder`) and a save that fails (`cannot_save`)), and it runs the rest on the board a request names (`--board`: its number, `BoardDocument.number`, its file, or its name) or the one in front, and there on the board inside the file that its window shows (`editor.board`: `boards` names it, `shows` and `showsPath`, root first, as `BoardID`s, and `status` the front one's, `frontmostShows`; no command addresses another yet), so a command's change is an undo step on that board; each command runs in a task kept against its board, and a client gone is answered `cancelled`, a board closed (`BoardDocument.close()`) `board_closed`, at once, the task cancelled and what it returns later dropped (every command, `draw` included, runs a main-actor hop after its request, so one cancelled before it starts never runs). Every other command is Automation's (platform, for agents, which the app's server reaches through the host's slot for commands, [host slots](host-slots.md): `AutomationPlugin` fills it, `registrar.hostCommands`, with `automationCommands` and `runAutomationCommand`, and the app starts its server on `CommandServer.Commands(registry:)`, `registry.hostCommands`, async, as `Registry.runAutomationCommand` is): `registrar.automationCommand("name", "summary", params: P.self, positionals:, examples:) { params, context in … }`, its params a `SchemaDefined` list (each property an option, `fooBar` as `--foo-bar`; `x-value-name` for help), checked and decoded before it runs, its output anything `Encodable`, answered in the turn it's asked in; or, for one that waits (a model, a query), `runAsync:` (write the label out: a trailing closure that doesn't await picks `run:`), its output `Encodable & Sendable`, written as JSON and freed off the main actor (`AutomationCommand.encoded`, `@concurrent`; a `JSON` output passes through, and what the core writes is one: its `JSONValue` is the wire's `JSON`), a long wait looking at `Task.isCancelled`; its errors `AutomationError(_:reason:hint:)` (with `line:`, `column:` and `length:` in characters, `statement:`, `errors:`, and `details:`, whose members join the error's data under names of the command's own, never one of the error's), a board command's changes through `context.board()`'s `transact`. The registry refuses a name `canvas` can't type or that's kept (`RPC.reservedCommandNames`: `describe`, the server's `status`, `boards` and `new`, `canvas`'s `help` and `install`), a param named `board` or like `canvas`'s own options, and two commands of one name. A command's options may come before its name (`canvas --board 2 draw - < plan.txt`); text whose schema says `"x-stdin": true` is read from standard input when given as `-`; text whose schema says `"x-path": true` (`new`'s file) is a file named from where `canvas` runs, which it sends whole (`CommandArgument.isPath`, `Invocation.absolute`; an older `canvas` sends it as typed, and `new` refuses a file not named from `/`); an error about a script or a query carries `line`, `column`, `length` and `statement`, which `canvas` prints as `line L, column C: …` with carets under the columns (`Invocation.caret(under:column:length:)`), and several at once `errors` (protocol 2, which a param's `"x-timeout": N` and an error's `column` and `length` keep: an older `canvas` passes over them); a param whose schema says `"x-timeout": N` has `canvas` wait up to N s when it's given (`CommandArgument.waits`: a call waits `--timeout`, else the longest such, else `RPC.defaultWait`, 10 s; help says "(waits up to N s)"; `canvas query` is refused `too_slow` at 8 s, `QueryBudget.commandDeadline`, whatever the file, before that runs out: [queries](queries.md)); CommandServer adds `board: {id, name, shows, showsPath}` to a board command's object result, as `boards` lists it, read in the command's own job just before it runs (so `draw`, which doesn't wait, names the board it drew on, whatever the person did since the request came); a command that knows better where it worked says `shows` and `showsPath` in a `board` object of its own, which the server completes (a query: the board shown as it took up the file, `QueryResult.shown`, since it may wait for answers to settle or on a model). Automation's own: `draw`, `show`, `kinds` and `measure` (below, after the stand-ins), `rehearse` and `capture` (their own bullets, below), and `apply`, a program's document drawn by key on every board in one step, with `measure` of a document (and its `--on`, the board apply will draw it on) and `draw --drawing NAME`, which joins a run to a drawing ([drawings](drawings.md)); the engine of the first, third and fourth is Draw, an engine (`Sources/Draw`: `draw(script:dryRun:reveal:program:in:)`, `measure(script:program:in:namesBeyond:)` and `kinds(named:schema:in:)`, throwing `DrawError`, which says the six fields of an error a script has and no wire code), and each command resolves its board, calls Draw, and says a `DrawError` as the wire's `AutomationError` (`AutomationError.init(_: DrawError)`, nested `errors` too; `DrawParams`, `MeasureParams` and `ListKinds` are Automation's, in `Params.swift`). `draw` reads a script in a language after reladraw's (`THIRD_PARTY_NOTICES.md`), one statement a line: a shape named by its title (a title the board has restates that shape, any other makes one; a shape with no title is named by its id, ids as names, below), with attributes by its kind's schema and placements against shapes already named, never coordinates; an edge; a delete; a group or an ungroup (below); a style. DrawScript reads it (`Script(parsing:)`) and places it (`LayoutProblem.solve()`, its obstacles, every board shape with a solid that the script doesn't move or delete (`ShapeContext.solidBounds(of:)`, the core's rule: its bounds where its geometry is closed, finite and not flat, never a shape kept aside; what a container the script moves holds met where the container takes it, never where it is now, `LayoutProblem.Free.carries`: moved as far as the innermost such container moves and kept clear of by a bound against that container, so containers can trade places in one run, and `board`'s box leaves it out as it leaves out what the script moves), filed once a run in DrawScript's `ObstacleGrid` (boxes only, in paint order, so a plugin that speaks no wire places shapes among others the same way, as Moving's `/move-to` and `/move-near` do, [moving](moving.md); Draw's `ObstacleIndex` fills it and keeps each obstacle's shape beside it), and each answer kept, so a draw costs what's near what it places: `./build.sh bench` holds 20 notes pushed along rows of 10,000 shapes to 150 ms); Draw's `Drawing` resolves it against the board shown as the run starts (new shapes from `placement.shape(at:)`, attributes through `registry.shape(_:setting:)`, JSON held to the kind's schema first, `registry.schemaViolations(of:kind:)`, so a member its type hasn't is `invalid_value`, not dropped; a property whose schema says `readOnly` (`Property.readOnly()`) is no attribute (`KindVocabulary.isAttribute`: written, it's `unknown_attribute`, and `kinds` leaves it out), and a string whose `format` is `x-canvas-query` is asked of the query engine once read (`DrawQueries.swift`: `editor.queries?.checkStored`, syntax and vocabulary, and no word that reads the editor (`:selected`, `:current-board`: `query: “:selected” can’t be used here.`), since the query is stored to run later, so a bad one is `invalid_value` with the engine's own message and hint and nothing is drawn; without QueriesPlugin it isn't checked; Draw uses Queries, and the format names no kind); an object value replaces its whole property; a size the kind derives from what's set, a note's height, is the one it's placed at, and `size:` with a width alone (`300x`, DrawScript's `Size` with no height) builds the shape at that width first and puts what the kind derives in step there whether anything's set or not (`registry.derived(_:)`, the core's), so a note is that wide and as tall as its text there in one run, and any other kind keeps its height; a whole `size:` (`300x200`) is given as a resize by hand gives a frame (`registry.sized(_:to:giving: .both, in:)`, the core's `CustomSizing`), so a note keeps the height as the least it is (typing never takes it under) and is as tall as its words past it, never cut off, and any other kind is that size; a `size:` under the smallest its kind's placement draws (`Placement.minimumSize`, the one place a kind says it: a frame's 96 × 64, which the Frame tool's drag, resizing and Create Frame read too) is `invalid_value`, as one over 100000 is, with the size to write (a shape restated at the size it is already changes nothing, and goes through); `view` is where the camera is headed, `editor.cameraTarget`, the part of the view the host leaves clear, `unobscuredViewport`, as `--reveal` fits into; `origin` is the board's (0, 0), a fixed box with no size, `PlaceWord.origin` and `Target.Box.origin`, which ties a shape to the board as `board` and `view` do and is no obstacle and no zone: what a layout worked out elsewhere is placed from, with no shape drawn to measure from, as canvas-digest places every board ([digest](digest.md))) and applies it in one `editor.transact("Draw")`, one undo step, marked `byAgent` (deletes, each shape's with every connection bound to it, a subboard's with its boards, said in a warning, unless one holds a locked shape, and a container's (a frame's) letting go of what it holds, the core's; shapes, each after what it's drawn inside, on or in, a restated container before what it holds, and raised above it, or a zone it sits in where it lands (`Solver.isZone`: an obstacle that wholly holds the shape where it already sat, a shape it's placed against at twice that one's area, where it lands and another shape too at twice its own, or the view it's placed against or drawn in; a shape the script places counts as held only when it's there for a reason of its own, `Solver.counted(by:in:)`, so two new shapes never hold each other on an empty note), while writable (`transaction.isReadOnly(_:)`: a shape in a locked frame, or on a locked subboard's board, is read-only), each put down as by hand once every one is where it goes (so none is judged against where a shape the run moves was), one by one, those holding no shapes first, then the containers, new, placed or resized: settled by the in-or-out rule (`transaction.settle`: wholly in or out of a container whose edge it's over, nudged, and said, glided after a real run, `editor.glide`; a container put down taking in what it lands on, also said; a read-only container refusing the run, `read_only`), a container placed elsewhere taking what it holds along (`translate`), which is never in its way (`LayoutProblem.Free.carries`), and a placement against what it takes along `unsupported`, while a container's edge is no zone's to warn about; and the edges against `transaction.shapes`, made before that put-down so it judges by a transaction that holds them (`Drawing.layOut()` laid the same arrows in for the rooms); anything wrong, or `--dry-run`, throws out of the body, so nothing commits and no step opens); a real run ends a person's typing only once it's placed, has been applied once and thrown away without an error, and changes that shape, and waits out a drag or a press held (`busy`, `undoHistory.isPressHeld`: what commits during a press is its step's); its result is rows by line and title, with the id of each shape the file has (`id`, below), and warnings, among them names (`ShapeNaming`: a note's mentions) of shapes that aren't in the file or are on boards the app can't show, as the result lists them, since a script wrote them. A shape bound (`ShapeReferencing`) to one not on the board is refused. A kind whose title is only derived (none shipped; Titles keeps the API) can't be titled by a script, and is renamed by what it's derived from (`renamed`); a type is a note drawn with `schema:` (Types' added property, an attribute as every added property is), named by its title. It never names a board: it draws on the one what it names is on (a title names a shape on any board of the file the app can show, the board shown's first; a new shape goes on its placements' targets' board, or the one `in "X"` names: the board X holds (a subboard's), or, for X a container on its board (`ShapeContaining`: a frame), that board, the shape kept within X as `inside` keeps one (`LayoutProblem.Free.holder`, `no_room` if it can't be, except that a shape placed by a lone direction (`right of`, `left of`: centered on its target across; `above`, `below`: along) that would cross X's inner edge only on the axis the direction leaves free is slid along that axis until it is inside, keeping its side of the target, and a warning says so (`"n2" was slid down to stay inside "f1"`: the solver's `Solver.slide`, which holds the centering from one side only and `LayoutSolution.slides`); it stays `no_room` when the shape can't fit X on that axis at all; with no other placement, and not in X already, against its top-left, 40 in, a clause written `in "X"`), and in X once put down, `read_only` for a read-only X (a locked frame, or a subboard whose board is read-only: its own lock, or a lock above it, `"X" is read-only (locked, say), so nothing goes in it`), `unsupported` for one the script draws, `circular` for the shape itself or one it holds; else the board shown), read through the core's `editor.reading(of:)` (`BoardReading`: shapes, a `ShapeContext` and paint order, the view it would be shown with, and `isBoardReadOnly`) and committed with `transact(on:)`, the window staying put (`--reveal` shows it); a board that's read-only (a locked subboard's, and every board under it) takes nothing new: a new shape that would land there, by its placements' targets or on the board shown, is `read_only` (`"N" would go on "Plans"'s board, which is read-only (locked, say)`, `FileNames.named` naming the board, each statement's first problem, found as the run starts, so a dry run says it too, with nothing changed and no step), and so is a new edge (`edge "A" -> "B" would go on …`, found as it's applied, in `connect`); changing or deleting what's on it is refused as any read-only shape's is (`target.isReadOnly`, `transaction.isReadOnly`), and a restatement that changes nothing is `unchanged`; one run is one board (`several_boards`, but for an edge between boards, next), its result's `on` says which, and a delete can't take the board shown or one above it (`board_shown`). `canvas show <name>` or `--root` (Automation's) moves the window; the name is a title, or an id or a path as a script writes one (below, Paths as names). What it doesn't own comes from Draw's points (seven here; two more, for a property's values and a run's reports, are under Types in draw, below), at most one contribution each (`DrawTextFormats`, one for each media type), filled by the plugins that own each meaning (AutomationTests fill them with fixtures of their own): `DrawNames` (`registrar.drawNames`: `TitleNamesPlugin`), `DrawLabels` (`registrar.drawLabels`: `MentionTextsPlugin`, what a shape with no title is called for the pill an edge to it on another board puts beside the other end: what Mentions calls it, its first line or its values), `DrawEdges` (`registrar.drawEdges`: `PortEdgesPlugin`, whose `sides` lists none for a kind draw can't name, neither a naming property nor a derived title, `registry.drawCanName`, since an edge names its ends (a reference drawn by its query, named by its id, is an end all the same, on its own ports: every channel on its left and right, so an edge into one is on the other end's first); the connector's connections made by name, on a channel picked from the port table as a drag would, `registry.connectionChannel(from:fromSide:to:toSide:)`, or `channel: none`, and never between a container and a shape it holds (`cannot_connect`, `"Sprint 3" can't be connected to "Fix the login", which it holds`, on any channel or none: Connections' `mayConnect`); an edge's other attributes are the edge kind's, an arrow's `text:` and `labelPosition:` among them, read by its schema as a shape's are and set on what `make` returns, which is made again over it to refuse one that says otherwise than the edge as written, an arrow's heads), `DrawEdgeIdentities` (`registrar.drawEdgeIdentity(_:)`, one plugin a property key: Types' `TypeNamesPlugin` names `is`, the edge kind's property that tells two arrows of a pair apart, below), `DrawChecks` (`registrar.drawChecks(touched:rest:)`: `ValidationChecksPlugin`; a string whose schema says `contentMediaType` of the format's media type, wherever it is in a value (`DrawTexts.swift`: an attribute's, a style's, an edge's own, a string inside an object or a list, found by walking the value beside the property's schema, `$ref`s followed, and only for the properties that can hold one, `KindVocabulary.textKeys`), is handed to `write` as the script wrote it, with a `DrawTextContext` (the registry; else the board the run draws on; else the board the window shows; else any other board the app can show (those last two are `FileNames.beyond`, which finds an edge's end on another board too); `ambiguous_title` for two or more in one place, `unknown_title` for none, with `Suggestions.closest`, or for one only the script's deletes have (`names "X", which this script deletes`), `invalid_value` for one called that and none taken, said as the format's clause) and keeps what it gives back; a refusal is the statement's, on its line, `"Plan": text: …` (`(from style x)`; an edge's, `edge "A" -> "B": text: …`); the file's names, `FileNames`, are read when a lookup first asks and shared with `Drawing.board(for:in:)`, so a script whose texts name nothing reads none, `DrawPlugin.fileNamesRead` in debug builds, and a title in a text never decides which board the run draws on; `canvas kinds` says what a format takes after the type of a property it writes, `text (@[Title] mentions)`, `KindVocabulary.compactType`); without one, titles are `no_names`, edges `no_edges`, groups `no_groups`, text kept as written, and checks only the schemas' bounds. `kinds` is the language's vocabulary (each kind's drawability, names, size, its `smallest` where its placement says one, what its shapes hold for `in` to name, `holds`: `board` or `shapes`, attributes with compact types, edge channels by side, and `via`, the pills that can stand for one of it, each with what it `needs` of the shape first: the makers of Topology's stand-ins (`registry.standIns`) that `fulfil` a blank shape of the kind, `needs` their own words, `public` for a reference, so a tool asks the app which kinds a pill stands for rather than keeping a list; left out for a kind none can; `--schema`). `query` and `query-vocabulary` are QueryCommands' (platform, for agents, on Automation, Queries, QueryTranslation and the wire, which declares no point: `QueryCommandsPlugin()`, and `--ask` is a call to `editor.queryTranslator` whose `QueryTranslationError` it says as an `AutomationError`, reasons, messages and hints unchanged): `canvas query <query>|- [--ask <question>|-] [--limit <number>] [--count] [--brief] [--fields <attribute>]…` is a board command (`runAsync:`) answered about the whole file, taking exactly one of a query and `--ask` (up to 2,000 characters, `x-timeout` 60), and not both `--brief` and `--fields` (`invalid_params`); its answer is `{board, query (canonical), count, rows, warnings?}` (`board` where it ran: `shows` and `showsPath`, the board shown as it took up the file, which the server completes with the file's `id` and `name`), `asked` with `--ask`, no rows for `--count`, built member by member as JSON off the main actor (`QueryOutput.json`, the result consumed and freed there, never through `JSONEncoder`); - A shape has two sizes in a run (`ShapeItem`): `size`, which `complete` works out and the run writes and compares (`moved`, `unchanged`, "settle again" go by it), and `room`, the frame its kind lays it out in once drawn, which is `size` for a kind laid out as it stores (`LaidOutBox`, [editor](editor.md)). `Drawing.layOut()`, at the end of `Drawing.init` (after the errors are found, so every record is complete, and so `measure` gets it too), asks the editor's context for each shape, `base.layingOut(with: items.map(\.record) + provisionalConnections(), removing: deleted)` (`base` is `target.shapes`, a measure's `namesBeyond.shapeContext`), so the script's own shapes are read as the file's (a type and its instance, a stretch and the gauge it names drawn together), the connections the run draws are laid in beside them, and a board shape the script doesn't restate is read as it is, but for what it deletes, shapes and their connections (`deleted`), which are not there (a stretch restated after its gauge is deleted is the size it will be). `provisionalConnections()` makes each edge's arrow as `connect` will, by the one function (`connection(for:matches:beside:edging:kind:in:shapes:)`, over a document of the edge's two ends alone, matches found as `connect` finds them): a make that fails contributes nothing and says nothing (`connect` throws what it throws, where it does today), an arrow the run leaves as it is is not laid in, and each is kept on its `EdgeItem` for a debug check in `connect` that the arrow drawn is the one laid in but for its id. The arrow of a pair's next edge is bent beside the arrows already joining the pair (`EdgeRequest.beside`, which the maker reads from the document it is given), so the laid-out arrows are made over the ends plus the arrows beside: the board's of the pair the run does not delete, then the run's own earlier ones as they were laid out (their own ids, which `freeSlot` reads the stored bend of), and `connect` holds the same list as the committed arrows' ids; an edge that reconnects a drawn arrow adds none. So a note whose room depends on an end the same script draws, a type's instance beside the relationship type and its ends ([relationships](relationships.md)), is laid out with the row the end gives it, and `at` is the frame the board has a moment later. `apply` makes the edges before it settles (`transaction.settle` judges by a transaction that holds them), and the reports, the checks and the warnings read one context taken after the last write. A board shape the script does not restate keeps the size it had before the run (a run that draws an end and places a shape below an untouched note of that type places it against the note's size before the row), as it does for a type restated with a new field. `DrawLayout` places `room` (a shape that stays is `placed` at its origin with `room`; the free boxes, the corners on an outline, "where it already is" and "resized where it is" go by it and by `context.frame(of:)` of the board shape) and writes `size` (`record.box` is the placed origin at the stored size); `DrawCommit`'s rows report `at` as the origin the transaction leaves at `room` (not `transaction.shapes.frame(of:)`: a note the script restates as it is, whose type the same script changes, is untouched by the transaction, which would give the size before, and the row would disagree with `measure`), and "was over the edge" is judged at `room` from the origin before and after settling. A shape grown by a type is not settled again (`DrawCommit:95` asks whether the statement resized it). `transaction.settle` asks the transaction, which lays out afresh what the run added or wrote, over the run's records as inserted: the same answer. - <a id="capture"></a>**`capture`** (`Capture.swift`, a board command, `run:`): `canvas capture <file> [--shape <name>]… [--zoom <percent>] [--in <name> | --root] [--size <width,height>] [--scale <n>] [--dark]` writes a PNG of a board as the canvas draws it, with nothing selected, drawn apart from the window by the core's `BoardPicture` ([Quick Look](quick-look.md)) from the board's own file (`editor.file`, as Edit › Copy as Image draws, so a file's colors, its types and what mentions name are there to read): nothing on any board changes and no step opens, and the window doesn't move and needn't be in view. What it pictures (`CaptureSubject`): the board `--in` names (a subboard's, by its title through Draw's `FileNames.container(called:boards: true)`, as `show` finds one, by `#<id>`, or by a path, `FileNames.container(named:boards:board:)`) or `--root` (not both: `invalid_params`), else the board of the first `--shape`, else the board the window shows; a `--shape` is a title, found as a script's is (Draw's public `FileNames.shape(called:on:)`: the board shown's first, then the only other board that has one, `ambiguous_title` for two, whose hint says to write the path or the id, `unknown_title` with the titles like it; on the board already decided alone, `several_boards` for a shape elsewhere), `#<id>` for any shape on a board the app can show, an arrow's too (`unknown_id` otherwise; `#` and no id is a title, whose refusal says an id's form), or a path (`"Payments" > "Checkout"`, `#<id> > "Checkout"`, `board > "Checkout"`, found by `FileNames.shape(path:on:)`; a value that starts with `"`, with `#` and an id or a `>`, or with `board` and a `>` is read as a script's name, `ShapeName.isScriptSpelling` and `ShapeName(parsing:)`, a name that doesn't parse `invalid_params`, anything else a bare title as before; `board` there is the board the window shows); with nothing that names shapes a title is `no_names`. With shapes the picture is about them (`picture.focus`, with `CaptureStyle.shapesInset`, 100 in all, what `draw --reveal` leaves), fitted no closer than 100%, everything around them drawn; `--zoom` (1 to 800, percent) centers it on them, or on the whole board, at that zoom (`picture.zoom`). Its size is `--size` (16 points a side or more), else, for the whole board fitted, `picture.size(within: CaptureStyle.limit)` (as big as the board at 100%, at most 1600 × 1200 points), else `CaptureStyle.view` (1200 × 800); `--scale` (1 to 4) is pixels to a point, at most 8,192 pixels a side; light unless `--dark`. The file (`x-path`, so `canvas` sends it whole; `x-timeout` 30 s, since the picture's editor reads the whole file, as opening it does, and builds its cards' previews) gets `.png` unless it ends in it, is refused for another type's extension, a folder, and a folder that isn't there (`no_folder`), and is written atomically over one there (`cannot_save` when it can't be). An empty board is `empty_board`. Its answer: `board` (`shows` and `showsPath` of the board pictured, which the server completes), `file`, `width` and `height` in pixels, `zoom` in percent (to a tenth), `region` (the part of the board in it, `[[x, y], [width, height]]` in world units, as a draw's `at`: `BoardPicture.framing(in:)`), and `warnings` where the zoom draws skeletons (`Framing.drawsSkeletons`: no words) or what it's about isn't all in the picture (`Framing.about` outside `region`). The canvas skill teaches it (SKILL.md, Looking at the board).
