# The command line

The `canvas` command line: the wire (CanvasRPC), the CLI, `CommandServer`, Automation's commands (`draw`, `show`, `kinds`), `canvas draw`'s language and the lexicon's points, and the canvas skill that teaches them.

Related: [queries](queries.md), [language models](language-models.md), [properties and schemas](properties-and-schemas.md), [shape references](shape-references.md), [containers](containers.md), [titles](titles.md), [connections](connections.md), [validation](validation.md), [boards in a file](boards-in-a-file.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [The command line](../../docs/plugin-system.md#the-command-line), [draw](../../docs/plugin-system.md#draw).

## Architecture

- The command line (`canvas`, for agents first, people too; `docs/plugin-system.md`, "The command line"): agents never read or write a board's file, only run `canvas`, which asks the running app. The wire is CanvasRPC (layer `wire`: knows no canvas, plugin or AppKit): JSON-RPC 2.0, a message a line, over a Unix-domain socket only this user can reach (`~/Library/Application Support/InfiniteCanvas/canvas.sock`, or `CANVAS_SOCKET`; the app that holds `canvas.sock.lock` listens, so a second app gives up and a crashed one's socket is taken over); `CommandSpec`, a command's description with its params as a JSON Schema, and how params are spelled as arguments (`spec.params(from:)`, `usage()`, `help()`); the blocking `RPCClient` and the `RPCListener`, which answers each request as a main-actor task of its own (its `Handler` is async; `init(path:synchronous:)` wraps one that answers at once), a connection's answers in the order its requests came, and cancels the requests with ids still running once its client hangs up (never notifications). `canvas` is CanvasCLI (layer `cli`: the wire only, never the app) and knows no command but `help`: each run asks the app (`describe`) and makes the commands, their arguments and their help from what it says, so a plugin's command needs nothing of `canvas`, and it refuses an app of another `RPC.protocolVersion`. Results go to standard output (JSON when it isn't a terminal, text for people, `--format`), errors to standard error with a `reason` and a `hint`, and it exits 0 done, 1 the app couldn't, 2 usage, 3 unreachable. The app's end is CanvasUI's `CommandServer`, started by the app: `status` and `boards` are its own, and it runs the rest on the board a request names (`--board`: its number, `BoardDocument.number`, its file, or its name) or the one in front, and there on the board inside the file that its window shows (`editor.board`: `boards` names it, `shows` and `showsPath`, root first, as `BoardID`s, and `status` the front one's, `frontmostShows`; no command addresses another yet), so a command's change is an undo step on that board; each command runs in a task kept against its board, and a client gone is answered `cancelled`, a board closed (`BoardDocument.close()`) `board_closed`, at once, the task cancelled and what it returns later dropped (every command, `draw` included, runs a main-actor hop after its request, so one cancelled before it starts never runs). Every other command is Automation's (a language, which the app reaches through Composition's `commands(in:)`, async, as `Registry.runAutomationCommand` is): `registrar.automationCommand("name", "summary", params: P.self, positionals:, examples:) { params, context in … }`, its params a `SchemaDefined` list (each property an option, `fooBar` as `--foo-bar`; `x-value-name` for help), checked and decoded before it runs, its output anything `Encodable`, answered in the turn it's asked in; or, for one that waits (a model, a query), `runAsync:` (write the label out: a trailing closure that doesn't await picks `run:`), its output `Encodable & Sendable`, written as JSON and freed off the main actor (`AutomationCommand.encoded`, `@concurrent`; a `JSON` output, `JSON(_: JSONValue)`, passes through), a long wait looking at `Task.isCancelled`; its errors `AutomationError(_:reason:hint:)` (with `line:`, `column:` and `length:` in characters, `statement:`, `errors:`, and `details:`, whose members join the error's data under names of the command's own, never one of the error's), a board command's changes through `context.board()`'s `transact`. The registry refuses a name `canvas` can't type or that's kept (`RPC.reservedCommandNames`: `describe`, the server's `status` and `boards`, `canvas`'s `help`), a param named `board` or like `canvas`'s own options, and two commands of one name. A command's options may come before its name (`canvas --board 2 draw - < plan.txt`); text whose schema says `"x-stdin": true` is read from standard input when given as `-`; an error about a script or a query carries `line`, `column`, `length` and `statement`, which `canvas` prints as `line L, column C: …` with carets under the columns (`Invocation.caret(under:column:length:)`), and several at once `errors` (protocol 2, which a param's `"x-timeout": N` and an error's `column` and `length` keep: an older `canvas` passes over them); a param whose schema says `"x-timeout": N` has `canvas` wait up to N s when it's given (`CommandArgument.waits`: a call waits `--timeout`, else the longest such, else 10 s; help says "(waits up to N s)"); CommandServer adds `board: {id, name, shows, showsPath}` to a board command's object result, as `boards` lists it, read in the command's own job just before it runs (so `draw`, which doesn't wait, names the board it drew on, whatever the person did since the request came); a command that knows better where it worked says `shows` and `showsPath` in a `board` object of its own, which the server completes (a query: the board shown as it took up the file, `QueryResult.shown`, since it may wait its turn or on a model). Automation's own: `draw`, `show` and `kinds`. `draw` reads a script in a language after reladraw's (`THIRD_PARTY_NOTICES.md`), one statement a line: a shape named by its title (a title the board has restates that shape, any other makes one), with attributes by its kind's schema and placements against shapes already named, never coordinates; an edge; a delete; a style. DrawScript reads it (`Script(parsing:)`) and places it (`LayoutProblem.solve()`, its obstacles, every board shape with a solid that the script doesn't move or delete (`ShapeContext.solidBounds(of:)`, the core's rule: its bounds where its geometry is closed, finite and not flat, never a shape kept aside), filed once a run in DrawScript's `ObstacleGrid` (boxes only, in paint order, so a plugin that isn't a language places shapes among others the same way, as Moving's `/move-to` and `/move-near` do, [moving](moving.md); Automation's `ObstacleIndex` fills it and keeps each obstacle's shape beside it), and each answer kept, so a draw costs what's near what it places: `./build.sh bench` holds 20 notes pushed along rows of 10,000 shapes to 150 ms); Automation's `Drawing` resolves it against the board shown as the run starts (new shapes from `placement.shape(at:)`, attributes through `registry.shape(_:setting:)`, JSON held to the kind's schema first, `registry.schemaViolations(of:kind:)`, so a member its type hasn't is `invalid_value`, not dropped; a property whose schema says `readOnly` (`Property.readOnly()`) is no attribute (`KindVocabulary.isAttribute`: written, it's `unknown_attribute`, and `kinds` leaves it out), and a string whose `format` is `x-canvas-query` is asked of the query engine once read (`DrawQueries.swift`: `editor.queries?.check`, syntax and vocabulary only, so a bad one is `invalid_value` with the engine's own message and hint and nothing is drawn; without QueriesPlugin it isn't checked; Automation, a language, uses Queries, a surface, and the format names no kind); an object value replaces its whole property; a size the kind derives from what's set, a schema card's height or a note's, is the one it's placed at; `view` is where the camera is headed, `editor.cameraTarget`, the part of the view the host leaves clear, `unobscuredViewport`, as `--reveal` fits into) and applies it in one `editor.transact("Draw")`, one undo step, marked `byAgent` (deletes, each shape's with every connection bound to it, a subboard's with its boards, said in a warning, unless one holds a locked shape, and a container's (a frame's) letting go of what it holds, the core's; shapes, each after what it's drawn inside, on or in, a restated container before what it holds, and raised above it, or a zone it sits in where it lands (`Solver.isZone`: an obstacle that wholly holds the shape where it already sat, a shape it's placed against at twice that one's area, where it lands and another shape too at twice its own, or the view it's placed against or drawn in; a shape the script places counts as held only when it's there for a reason of its own, `Solver.counted(by:in:)`, so two new shapes never hold each other on an empty note), while writable (`registry.isReadOnly(_:in:)`: a shape in a locked frame is read-only), each put down as by hand, one by one, new, placed or resized: settled by the in-or-out rule (`transaction.settle`: wholly in or out of a container whose edge it's over, nudged, and said, glided after a real run, `editor.glide`; a container put down taking in what it lands on, also said; a read-only container refusing the run, `read_only`), a container placed elsewhere taking what it holds along (`translate`), which is never in its way (`LayoutProblem.Free.carries`), and a placement against what it takes along `unsupported`, while a container's edge is no zone's to warn about; then edges against `transaction.shapes`; anything wrong, or `--dry-run`, throws out of the body, so nothing commits and no step opens); a real run ends a person's typing only once it's placed, has been applied once and thrown away without an error, and changes that shape, and waits out a drag or a press held (`busy`, `undoHistory.isPressHeld`: what commits during a press is its step's); its result is rows by line and title, never ids, and warnings, among them names (`ShapeNaming`: a note's mentions) of shapes that aren't in the file or are on boards the app can't show, as the result lists them, since a script wrote them. A shape bound (`ShapeReferencing`) to one not on the board is refused. A kind whose title is only derived (a schema card's) can't be titled by a script, and is renamed by what it's derived from (`renamed`). It never names a board: it draws on the one what it names is on (a title names a shape on any board of the file the app can show, the board shown's first; a new shape goes on its placements' targets' board, or the one `in "X"` names: the board X holds (a subboard's), or, for X a container on its board (`ShapeContaining`: a frame), that board, the shape kept within X as `inside` keeps one (`LayoutProblem.Free.holder`, `no_room` if it can't be; with no other placement, and not in X already, against its top-left, 40 in, a clause written `in "X"`), and in X once put down, `read_only` for a read-only X, `unsupported` for one the script draws, `circular` for the shape itself or one it holds; else the board shown), read through the core's `editor.reading(of:)` (`BoardReading`: shapes, a `ShapeContext` and paint order, and the view it would be shown with) and committed with `transact(on:)`, the window staying put (`--reveal` shows it); one run is one board (`several_boards`), its result's `on` says which, and a delete can't take the board shown or one above it (`board_shown`). `canvas show "<title>"` or `--root` (Automation's) moves the window. What it doesn't own comes from three Automation points, at most one contribution each, filled by DrawLexicon (AutomationTests fill them with fixtures of their own): `DrawNames` (`registrar.drawNames`: `TitleNamesPlugin`), `DrawEdges` (`registrar.drawEdges`: `PortEdgesPlugin`, whose `sides` lists none for a kind draw can't name, neither a naming property nor a derived title, `registry.drawCanName`, since an edge names its ends; the connector's connections made by name, on a channel picked from the port table as a drag would, `registry.connectionChannel(from:fromSide:to:toSide:)`, or `channel: none`; an edge's other attributes are the edge kind's, an arrow's `text:` and `labelPosition:` among them, read by its schema as a shape's are and set on what `make` returns, which is made again over it to refuse one that says otherwise than the edge as written, an arrow's heads) and `DrawChecks` (`registrar.drawChecks`: `ValidationChecksPlugin`); without one, titles are `no_names`, edges `no_edges`, and checks only the schemas' bounds. `kinds` is the language's vocabulary (each kind's drawability, names, size, what its shapes hold for `in` to name, `holds`: `board` or `shapes`, attributes with compact types, edge channels by side; `--schema`). `query` and `query-vocabulary` are QueryCommands' (a language on Automation, Queries, QueryTranslation and the wire, which declares no point: `QueryCommandsPlugin()`, and `--ask` is a call to `editor.queryTranslator` whose `QueryTranslationError` it says as an `AutomationError`, reasons, messages and hints unchanged): `canvas query <query>|- [--ask <question>|-] [--limit <number>] [--count] [--brief] [--fields <attribute>]…` is a board command (`runAsync:`) answered about the whole file, taking exactly one of a query and `--ask` (up to 2,000 characters, `x-timeout` 60), and not both `--brief` and `--fields` (`invalid_params`); its answer is `{board, query (canonical), count, rows, warnings?}` (`board` where it ran: `shows` and `showsPath`, the board shown as it took up the file, which the server completes with the file's `id` and `name`), `asked` with `--ask`, no rows for `--count`, built member by member as JSON off the main actor (`QueryOutput.json`, the result consumed and freed there, never through `JSONEncoder`); a refusal carries its reason, message, hint, `line`, `column`, `length` and `statement`, the line as sent, whole, so the caret lands on what's wrong (at most 200 characters around it, `QueryOutput.quoted`, `QueryError.located(in:quoting:)`), and `errors`. `canvas query-vocabulary` (app scope) is `{vocabulary (the <vocabulary> block), kinds [{kind, label, naming, holdsBoard, attributes}], edgeTypes [{type, under?, summary?}], words [{word, takes, summary, example, from}]}` (`naming`, not `titles`, which is Titles' plugin id); without `QueriesPlugin` both answer `no_queries` (`registry.answersQueries`). The languages are taught by the canvas skill (`.claude/skills/canvas`), whose every `draw` and `draw-error` block, and every `query` and `query-error` block (a CSS comment first: `/* matches: "Title", (kind) */`, `/* count: N */` or `/* reason: … */`; each must leave the file equal, not edited, no undo step; `reference/query.md`, marked `<!-- board: query-story -->` on its first line, runs on the story file, `QueryStory.document(windowed: false)`, and `reference/references.md`, marked `<!-- board: reference-story -->`, on `QueryReferenceStory` ("Services": a public note, a reference to it, two channel-less arrows into the reference; CompositionTests, whose test holds the page's `via` snippet to what `canvas query` answers); a file's first line `<!-- board: <name> -->` names its board among `skillStories`, each the board of exactly one file, and a file with none runs on a new board), CompositionTests' SkillTests runs through `canvas` as built, holding its tables of kinds to `canvas kinds`, query.md's words and edge types to `canvas query-vocabulary` and its blocks to the design's table of every construct (`StoryQuery.table`), and SKILL.md's description to 1,024 characters; its `query-prompt.md` carries `QueryPrompt.system` byte for byte, which QueryPromptTests hold (`scripts/query-prompts/copy_prompt.py` rewrites it): a change to either language, its messages, the shipped kinds, words or edge types, or the prompt changes the skill too. After a timeout `canvas` hangs up, which cancels what looks for it (a query, `--ask`); the app may still have run what it was sent (`timed_out`'s hint says check first).

## Testing

- For the command line, never use the app's socket: tests listen on their own (`temporarySocketPath()`, TestKit). The app answers on the main actor, so a test that's the client too asks off the main thread (`offMain`) or runs `canvas` as built (`run(builtExecutable("CanvasCLI"), arguments)`), both of which turn the main run loop until the answer comes. CanvasCLITests hold `canvas` to an app of their own (`FakeApp`: its errors' carets, `x-timeout`'s waits); CompositionTests' CommandLineTests run it against `CommandServer` on real boards (and a `Lingering` board command on a server of its own: a board closed under it answered `board_closed`, and a timed-out `canvas` cancelling it). In-process, a test awaits `runAutomationCommand` or `commands.run` with TestKit's `awaitResult`; CanvasRPCTests' "Answering later" hold order on a connection, connections apart, a hang-up's cancelling and `x-timeout` with a `Holds` listener and a `RawConnection`; AutomationTests' "Commands that answer later" hold `run:` in one turn, `runAsync:`'s output written and freed off the main actor (`ThreadLog`), a `JSON` output passed through, and an error's data (its details never over its own members).
- DrawScriptTests hold the language and the solver over a stand-in for Automation (`Support.swift`: a board of titled rects and fixture words), and `ObstacleGrid` to what going through every obstacle says (a fixed run of boxes and areas, cell edges, boxes too big or too far out to file, each answer kept).
- For `canvas draw`, AutomationTests use fixtures only (tiles, cards, discs, links, and a pin that binds and names; `"tile"` or `"link"` may be written there, never a shipped id), with test plugins in DrawLexicon's place (`DrawSupport.swift`: `namesPlugin`, `edgesPlugin`, `checksPlugin`, `drawEditor`, `drawn`, `refused`), undo and a file of boards among them (`DrawFileTests.swift`); TitleNamesTests, PortEdgesTests (channels of their own) and ValidationChecksTests hold each of DrawLexicon's plugins over fixtures; CompositionTests run `draw` through `canvas` as built (CommandLineTests, DrawContentsTests, DrawBoardsTests: subboards, undo and schema cards, whose model a draw never asks), and SkillTests runs every example in the skill, each file's blocks in order on a fresh 1440 × 900 board (a `draw` block must succeed and push nothing aside; a `draw-error` block, as a dry run, fail with the reason on its first line, `// reason: <reason>`; a `query` or `query-error` block must answer or be refused as its first line's comment says, and change nothing, `reference/query.md`'s on the story file; `SKILL_DUMP=1` prints what each said), and holds the skill's tables of kinds (size, attributes, channels by side) to `canvas kinds`.
