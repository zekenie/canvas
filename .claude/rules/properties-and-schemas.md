# Properties and schemas

A kind's props as a list of properties (`SchemaDefined`), the JSON Schemas made from them, `KindSchema`, and added properties, which a plugin adds to the kinds that opt in.

Related: [plugins and kinds](plugins-and-kinds.md), [boards on disk](boards-on-disk.md), [shape references](shape-references.md), [validation](validation.md), [titles](titles.md), [command line](command-line.md), [queries](queries.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Properties](../../docs/plugin-system.md#properties).

## A kind's properties and its schema

- A kind's props, and any struct stored in them, are a list of properties (`SchemaDefined`): `static let properties = Properties<StickyNote>(title: "Sticky note") { Property("frame", \.frame).required(); Property("text", \.text).description("…") }`, with `init()` giving the defaults. The list is the type's `Codable` (a member missing from a board reads as its default; a `required()` one has none) and its JSON Schema (2020-12): each property's type from its member's (`SchemaDescribed`: the core's geometry and `ShapeID` as `core.*` definitions, `SchemaCases` for a string enum, a nested struct in place or, with `definition:`, shared and named after its module, `canvastesting.memo-note`), its default, and what its modifiers add (`PropertyModifiers`: `minimum`, `maxLength`, `pattern`, `examples`, `keywords` for any other). A type that codes itself by hand writes `schema(in:)` by hand (`ArrowTerminal`). The registry describes every kind's and added property's schema as it's built, and refuses a list of any struct those reach that misses a stored member (a board wouldn't save it), names a non-member or has a key path that isn't its member (a computed view), lists one twice, writes one member twice, has an optional that's required or defaults to non-nil, or holds optionals in a collection (nor may an added property's value); the first problem is the one reported, a property value's against its declarer; and two types under one definition name, or a struct that holds itself with no name. `registry.schema(for: kind)` is the kind's whole schema, its added properties included, and marked `x-canvas-board` for a `BoardOwning` kind. `registry.schemaViolations(of: shape)` checks a shape against it (its own and added properties as one object, `record.propertiesJSON`, through a fast `JSONValueEncoder`; each kind's schema compiled as the registry is built, `SchemaValidator`, which checks any JSON against any schema, strings code point for code point and patterns as ECMA-262 reads them; and a schema it couldn't check, a `$ref` to nowhere or back to itself before going into the value, a pattern ICU can't read, refuses the plugin list, a kind's or an added property's): typed props always have the schema's shape, so what breaks it are bounds (`maxLength`, `minimum`) and numbers that aren't finite. A bound is a guideline, never a refusal: Validation warns about each violation. Agents get the schemas from the command line (`canvas kinds --schema`). Text reads a kind's schema through the core's `KindSchema` (`Sendable`, holding the schema's JSON and no registry, so it reads anywhere, following its `$ref`s): which properties hold a place (`holdsPlace`: the core's rect or point, or what holds one), what each property's values are (`shape(of:)`, a `KindSchema.PropertyShape`), what each takes said briefly (`compactType(of:)`, `canvas kinds`' and a query's vocabulary's words), and a literal read as the property's JSON (`value(ofLiteral:quoted:for:)`, `forItemOf:` for a list's item), refused with a `KindSchema.Refusal` that holds no words, which each command says in its own (`draw` through Automation's `KindVocabulary`, a query through its resolution); so `canvas draw` and `canvas query` read a value alike.

- `SchemaValidator(schema) { uri in … }` (`resources:`) follows a `$ref` to a schema outside the schema (a `urn:uuid:…`, with or without a `#/…` fragment): its resolver is asked the ref's part before the first `#`, verbatim (no `$id` resolution, `$id` stays an annotation), once per URI; the fragment is walked in that resource, whose own `#/…` refs are to itself; nodes are filed under `uri + pointer`, so loops across resources are marked as within one. A schema the resolver lacks is a problem (`the $ref at P, U, can't be found`) and a value meeting it "can’t be checked"; with no resolver, an outside `$ref` is `isn't in the schema` as before. The resolver is non-escaping and not kept (the validator stays `Sendable`: a caller compiles off the main actor from a snapshot), and `validator.resources` lists the URIs asked, found or not, in the order met, for a caller to drop its validators on. The core knows nothing of what the schemas are. `SchemaResolverTests` (CanvasTests) resolve against a dictionary of schema objects, with no registry.

## Added properties

- Added properties are what a plugin adds to the kinds that opt in: something the shapes know that their kind doesn't declare (a title). The type is the key: `enum TitleProperty {}` with `extension TitleProperty: ShapeProperty { static let key: PropertyKey = "title"; static var defaultValue: String? { nil } }` (a nil default: only the shapes it's set on have one), and `static var keywords: PropertyKeywords<Value>` for what its schema says beyond its type (Titles' title: `.minLength(1).maxLength(80)`), and `static func isNone(_:)` for a value that's no value at all (Titles' blank title), which no shape holds: a shape set to one, or read from a board with one, holds nil, or the default for a property that has one (which can't be none). A value a board writes as null, added, kept or handed over, is none too. Its owner declares it (`registrar.declare(P.self)`); a kind opts in through the owner's sugar (`ShapeRegistrar.optIn(to:)`, as `note.title()` does), `registrar.optIn(Kind.self, to:)` for another plugin's kind, or `optInEveryShape(to:where:)`. The registry refuses an opt-in to a property nobody declares, a key declared twice, a kind opted in twice, and a key that's one of the kind's own property names; its report lists `property title` and `property title → sticky-note`. Read and write `shape[P.self]` (`record[P.self]`), in a transaction like the props; a write the shape can't hold (its kind doesn't opt in, nil for a property with a default, a value kept aside) is dropped. A placement sets one on what it places with `.setting(P.self, to:)`. Defaults are filled where shapes enter an editor (inserted or placed, `CanvasEditor.init` and `replaceFile` on every board, `replaceDocument`, a board read; `registry.fillingDefaults`); filling never marks a board edited by itself. In a kind's schema each one is a property marked `x-canvas-owner`. What a shape knows is a property; what a plugin keeps about a shape (the one it was copied from) is `ShapeMeta`, never a property.
