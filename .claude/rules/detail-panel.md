# The detail panel

The detail panel: sections, tabs and status lines, headers, bindings, read-only shapes, text boxes, and the code editor with its completions.

Related: [fuzzy matching](fuzzy-matching.md), [table of contents](table-of-contents.md), [text editing](text-editing.md), [titles](titles.md), [validation](validation.md), [mentions](mentions.md), [boards](boards.md), [schema cards](schema-cards.md), [locking](locking.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [The detail panel](../../docs/plugin-system.md#the-detail-panel).

## Architecture

- The detail panel (DetailPanel, a surface) lays out a header, tabs, sections and a footer; plugins fill them with `x.details { DetailSection("…", in: SomeTab.self) { $x in … } }` and `detailStatusForEveryShape`: status lines, the shape's state rather than its settings, in the footer, or with `in: SomeTab.self` in a tab that shows only while the shape has lines there (Validation's Issues tab, `ValidationDetailsPlugin`), and whose title in the strip follows its worst line's symbol while that warns or errs (`layout.alert(in:)`). A tab is a type (`DetailTab`) any plugin may declare, in order bands: 0 a kind's own, 50 a horizontal's feature tab, 100 `StyleTab`, 300 a tab of the shape's state that comes and goes (Issues, Mentions' Mentioned In). A section of such state says when it shows with `.shownWhile { shape, context in … }` (Mentioned In's: while the shape `isMentioned`), asked on every commit beside the status lines, whatever the commit changed, so it reads a service's cached state, O(1), and only the sections that have one are asked (found once per kind); a tab shows only while it has a section shown or status lines, and the shape's panel draws again only when its record, whether it can change, its status lines or the sections `shownWhile` hides change (`panelsDrawn`, debug builds, counts it drawn). `registrar.detailsForEveryShape(where:) { DetailSection<AnyShapeRecord> … }` puts sections on every shape a `where` picks (asked as the panel is laid out), over the whole record (`ShapeBinding<AnyShapeRecord>.record`), beside `detailsForEveryBox`. `DetailCheckbox(_:isOn:)` (a label-hidden `Toggle` and a `Text` that toggles on click, `smallSpacing` apart) is a `LabeledContent` row's checkbox that reads "Label [] Title" on macOS 14 and 15; `DetailShapeRow(symbol:tint:name:detail:lines:dimmed:)` is a list row for a shape on `DetailStyle`'s own internal metrics (status icon column, 11 pt name, 10 pt secondary detail and up to two lines, `dimmed` dims the whole row), both in `ListRows.swift` (DetailPanelTests' ListRowTests). A horizontal's feature is opt-in sugar on `ShapeRegistrar` that contributes to its own point and calls `details`, so opting in brings its tab (`x.opensBoard(…)`, Boards' Board tab). An added property's sections are over its value: `x.details(of: P.self) { DetailSection(…) { $value in … } }`, or on `PluginRegistrar` for every shape that has it; a kind's own sections and header read added values through `$x.shape`, the whole record (`$note.shape[TitleProperty.self]`), and bind one, nil while the shape has none, with `$x[P.self]` (a `Binding<P.Value?>`, as `TitleHeader($x)` does; the bindings one `$x` makes of its added properties read back the last write through any of them; on a kind that doesn't opt in, it reads nil and drops writes, and `$x.holds(P.self)` says which, so `TitleHeader($x)` on a kind that doesn't opt into titles stops a debug build). `DetailCommandButton(title, systemImage:, command:)` runs a registered command (`editor.perform`), dimmed while `editor.canPerform` says no: the panel's counterpart of a menu item (it reads the editor from the panel's environment, `\.detailEditor`). A number being typed is committed in `boardWillChange` (`DraftTracker.commit`), so it lands on its shape before another board is shown. Sections write only through `$x.field` or `$x.update` (one transaction each, on the live shape, which the binding reads back until the panel redraws; a field's writes, one after another, are one undo step, and `$x.update(\.field) { … }` runs with them for a field written through a method, as the schema card's `setTitle`), bind the narrowest key path, and use `LabeledContent` and DetailPanel's primitives, never their own layout or fonts: among them `DetailTextArea` (with `placeholder:`, and `onCommit:`, which makes Return commit, ⇧↩ a new line, and the keyboard leaving commit too, a turn later if the view left the window with it, so a commit captures its service weakly), `DetailCodeEditor` (code typed as keyed: monospaced, every substitution, automatic completion, prediction and Writing Tools off; lines never wrap; as tall as its lines, from `DetailStyle.codeEditorHeight`, a text area's 76, to what the panel shows; ⌘↩ and the keyboard leaving commit; `coloring:` names its runs, `DetailCodeSpan`, and the panel colors them, red only for `.invalid`; `completions:`, a `DetailCodeCompleting`, says what can be typed at the caret, UTF-16 in, a `DetailCodeCompletions` out: the `range` a pick replaces, which holds the caret, the `query` typed so far, and every candidate as offered, unfiltered, each a `DetailCodeCompletion`, its `label`, `detail`, `insert`, the `selection` within it a pick leaves, `reopens` and `isRelevant`; ⌃Space, and AppKit's `complete:` (⌥⎋, F5), opens it in the app's one caret list (TextEditing's) while the text can be written and something's offered, else nothing, no beep: under what's typed, each label in the code's font, matched in its semibold, its detail after it, VoiceOver saying both, ranked with `FuzzyMatcher` (FuzzyMatching's, as every list ranks) (nothing typed: as offered; else by tier, then `isRelevant`, then as offered; what doesn't match left out); while it's open ↑ ↓ ⌃P ⌃N and Page Up and Down move, Return, Enter and Tab pick, Escape, ⌘., ⌃Space, ⌥⎋ and F5 close it, ⌘↩ closes it and commits, and the rest is the text's; it asks again after every keystroke and move of the caret, and closes once nothing's listed, the caret leaves the place it opened for (the range starts elsewhere), the text is shown from outside or can't be written, the keyboard or the window goes, the window resigns key, or what's typed scrolls out of view; a pick is `insertText` over the range between two `breakUndoCoalescing()`, one step of the text's undo that the box writes as typing, and one that `reopens` opens it again; `onCompleting:` hears it open and close (a pick that opens it again, not at all), for what waits on the person's choosing (the schema card's sync); without `completions`, F5 does nothing and ⌥⎋ leaves the panel: code gets no dictionary words), `.detailUpdating(_:)` (read-only and dimmed while something else writes the box; the words go on a status line where the person is, never over the text), and `DetailStatusLine` (a tone's symbol or, `isBusy`, a spinner, one width so the text doesn't move, then the text, which takes no tone and can be selected and copied (a line whose selected text has the keyboard as it goes hands it back to the canvas), with `DetailStatusAction` buttons under it). Text that isn't a string edits in a `DetailTextBox(value, height:placeholder:onCommit:make:)`, a box as a text area's (the panel's own, `DetailCodeEditor` and a `DetailTextArea` with `onCommit:`, are boxes over `PlainTextView`, on TextKit 1 as they always were; a `DetailTextArea` without `onCommit:` is still SwiftUI's `TextEditor`), over the view `make` returns: a subclass of `EditingTextView` (TextEditing's: [text editing](text-editing.md)) that adopts `DetailTextContent` (`value`, which the box writes to the binding on every change, and `show(_:)`, which the box calls only when the binding changed from outside, an undo or another plugin's write: the storage alone, never `didChangeText`, since the board may be applying a step, and then the box drops typing's undo), set in `DetailStyle.textFont` (the panel's text, 11 pt), as Mentions' `MentionTextArea` is. The panel's root hears Escape before the view does, and lets it through only to a view holding keys, and ⌥⎋ to a view that `offersCompletions` (a code editor with completions it can write), list or not; ⌘. with no list open goes on up and leaves the panel from its root (`onExitCommand`). Disabled (a read-only shape's section, `detailUpdating`), a box is read-only and dimmed by its view (`showEnabled(false)`), never by SwiftUI, which would take every click over it: its text is still selected and copied, and its clicks land (a pill followed), but it never commits (`onCommit`): nothing was written. A section reaches a service of its plugin's with `$x.service(S.self)` (the schema card's `SchemaSync`), never the editor, and `$x.shapeID` is the shape a binding writes, whatever its value. A read-only shape's panel (a locked one, or one in a locked frame) shows everything with its sections' controls and its header disabled (`registry.isReadOnly(_:in:)`, asked on every commit where the panel's root reads the shape's record, O(the shape's depth), and handed to the shape's panel, which never reads the document and draws again only when it changes: a container locked or unlocked, the shape joining or leaving one), but a section's that changes nothing of the shape (`DetailSection(…).enabledWhileReadOnly()`: Boards' Open, Mentions' Mentioned In); Back, the tabs and collapsing still work. The header is a view made from the shape's binding too, `x.details(header: { $x in DetailHeader("…") }) { … }`: a `DetailHeader`, or a view of the kind's own built on `DetailHeaderLabel` (with `DetailHeaderField` for a title renamed in place; `isEditable: false` shows it as text at full strength, for a title that can't be written just now), so every header looks alike; the panel hands it the kind's name and symbol through the environment, and tests read it back with `layout.header` or `layout.header(as:)`. Keep the sugar's closure types unannotated, and never name `Transaction` in a file that imports SwiftUI. The app places `ShippedPlugins.detailPanel(editor:onExit:rootName:)` in an `.inspector`, with `onExit` set to `CanvasFocus.take` (CanvasUI), which gives the keyboard back to the canvas.
- The panel's takeover slot (`DetailPanelView(editor:onExit:overview:takeover:)`, a `DetailTakeover`: `isActive: (CanvasEditor) -> Bool`, `onEscape`, and the content view; nil by default): while `isActive` holds it shows the content in place of everything else, "No Details" and every selection branch included, with the panel's environment, frame and width as ever. `isActive` is read in the body, so it reads observable state and the panel redraws only when it flips. Escape and ⌘. in the panel run `onEscape`, then `onExit`, while it's active (a text view holding keys hears Escape before either, as ever). Composition fills it with Find's panel (`FindPanel`, while `editor.find?.isActive`; `onEscape` closes Find: [find](find.md)): the panel never learns what it shows. A takeover turning active over a shape's panel removes that panel as it stands, so a number field's uncommitted draft is dropped: one that can start while a field is being typed in should end the edit first.

## Testing

- For the detail panel, check layouts and writes headlessly (`editor.detailPanel?.layout(for:)`, a tab's status lines with `layout.statuses(in:)`, the footer's with `statuses(for:)`, `editor.shapeBinding`, `editor.propertyBinding(id, P.self)`). For its views, host `DetailPanelView` in an `NSHostingView` in an unshown `NSWindow`, beside the canvas when focus matters (DetailPanelTests; `Tests/CompositionTests/InspectorTests.swift` uses the app's own wiring), with the real `TaskScheduler`; `panelsDrawn` (debug builds) counts a shape's panel drawn, so a test holds a commit to drawing it again only when what it shows changes (ReadOnlyTests: a shape in a frozen corral, two corrals down). CanvasTesting drives the window: `window.spin { condition }` runs the main run loop until the state a test expects arrives (and fails the test after 2 s), `window.settle()` runs it a few turns where there's nothing to wait for, and `focus`, `type`, `press`, `pressCommandPeriod` (the menus' turn, then the window's, which sends `cancelOperation:` up the responder chain) and `mouse` send input. Call `canvas.mouseDown` directly (`sendEvent` mouse-downs don't reach views in an unshown window). A click in the panel goes where the window's hit test from its top view lands (`PanelWindow.hit(_:in:)` and `clickThroughWindow(at:in:)`, MentionsTests' `MentionPanel` likewise): SwiftUI takes the clicks over what it disables, which a view's own `mouseDown` called directly never meets. Once there's a step back, the header has a back button, an `NSButton` in the panel's top 44 points, and a kind renamed in its header has a text field there, so tests that count the panel's buttons, checkboxes or fields leave the header out (`isInPanelHeader`). Render the panel standalone: in the app's `.inspector` it doesn't draw offscreen. DetailPanelTests hold a plugin's text box with a fixture view (`KeyedTextView`, an `EditingTextView` whose value wraps a string, with a settable `holdsKeys`, logging its commands, `didChangeText`s and `show`s; a view that doesn't hold keys never hears Escape in the panel, whose root takes it first), and `shownWhile` with a service of their own (`Watchers`); `PanelWindow(inBoardWindow:)` hosts the panel in a `BoardWindow` for Edit › Undo. A code editor's completions (Code completions) are the `CodeBoxesPlugin`'s code editor completing fruit (`fruitCompletions`: a basket that reopens, a cherry whose count a pick selects, a word after an x whose range is elsewhere; `codeCompleting` logs what `onCompleting` hears) and `BareCodePlugin`'s with none, read through the text view's `caretListWindow`, with ⌃Space pressed as `press(" ", code: 49, modifiers: .control)`, ⌥⎋ and F5 likewise; SchemasTests' `panelCompletionTests` hold the card's, and CompositionTests' `boardWindowTests` the app's menus leaving ⌃Space to the text, ⌘↩ with the list open committing, and a mouse pick joining the typing's step (the list made the board window's child first, as showing it would).
- The takeover slot is tested in `Tests/DetailPanelTests/TakeoverTests.swift` (`PanelWindow(…, takeover:)`: it outranks a selection, the overview and No Details; Escape and ⌘. in its field run `onEscape`, then `onExit`; inactive, the panel is as before).
