# Queries

Queries: the query language, what a query sees, where it runs, what plugins add to it, `canvas query`, `query-vocabulary` and `--ask`.

Related: [topology](topology.md) (stand-ins, the edge views and settling the engine reads), [command line](command-line.md), [language models](language-models.md), [titles](titles.md), [mentions](mentions.md), [validation](validation.md), [boards](boards.md), [selection](selection.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Queries](../../docs/plugin-system.md#queries), [query](../../docs/plugin-system.md#query).

## Architecture

- Queries (a surface on Topology, the engine any plugin may run: the language agents write is `canvas query` and the lexicon's words; `docs/plugin-system.md`, "Queries") finds the shapes of a file a query matches. The language is QueryLanguage's (a foundation module that knows no canvas, registry or plugin: `SelectorList(parsing:)`, a tree whose parts know their places, `QuerySpan`s in characters of the query as sent, and `canonical`, the one form it prints, which an answer says ran), CSS's where CSS has a meaning: a compound is at most one head (a kind, `*`, a title in quotes, a kind with a title right after it, `sticky-note"Checkout"`, the kind's shapes with that title, refused as a title head is, or `#` and an id) and tests with no space (`[a]`, `[a=v]`, `^= $= *= ~= |=`, `< <= > >=`, `i` and `s`; `:not`, `:is`, `:where`, `:has`), a space is inside at any depth, `>` directly inside (a container's own shapes, an owner's board's in no container), a comma either; its own words (`Word`) are those, `:inside`, `:top-level`, `:current-board`, the edge words (`:edge-to`, `:edge-from`, `:connected-to`, one edge either way, `:downstream-of`, `:upstream-of`, `:component-of`, any number either way, `:starts-at`, `:ends-at` (the connections, shapes that carry an edge in slot "", that start and end at a shape), `:start-of`, `:end-of` (the shapes where such a connection starts and ends), `:between`, each taking edge types after a comma, `a|b`, `only t` for a type alone, a type taking in those under it), `:dangling` and `:contains("x")`; `QueryLimits`: 8,192 characters, 1,024 in a string, 32 levels, 256 compounds, 20 problems said. It refuses, never passes over, each refusal saying where, with the one like it and a hint, most often the query to write: `empty_query`, `syntax`, `stray_space` (a compound after a space starts with a head), `too_long`, `too_complex`, `unsupported` (`+ ~ ||`, `:nth-*`, `:root`, `:hover`, a combinator in `:has`, whose hint nests `:has(> …)`; `.Name`, whose hint is the word that finds a type's shapes, `:is-a("Name")`, when a relation is declared `namesTypes` and a shape is titled so, else `:contains("Name")`, a plain refusal that says neither "class" nor "schemas"), `not_built` (where shapes sit; the words people invent that are planned), `not_an_id` and `bad_argument` (what the text shows, QueryLanguage's, stopping at the first, as are the words people invent, `KnownInventions`: `:parent-of`, `:source-of`, `:neighbor-of` (the old `:connected-to`), `:near`, the spatial ones `not_built`); `unknown_kind`, `unknown_attribute` (the words people write in brackets, `[kind=…]`, `[board=…]`, with what to write), `unknown_pseudo_class`, `unknown_edge_type`, `invalid_value`, `unsupported_operator`, `cannot_contain` (a container side that can only be kinds whose shapes hold no shapes, `containerKinds`), `no_names`, and `not_built` for an attribute that holds a place or `=` on an object (what the app hasn't, Queries' resolution, every independent one at once), and `[class=…]`, `unsupported` as `.Name` is; and a title or id no shape has (`unknown_title`, `unknown_id`), rather than answering none (a title standing for an anchor whose edges point at shapes that aren't there hints the `:dangling` that finds their carriers). The canvas skill teaches it (`reference/query.md`). A query ranges over every shape on every board the app can show, none kept aside, in file order (the root's shapes in no container back to front, each container followed at once by what it holds and each owner by its board's shapes: the snapshot's `forEachShape(inFileOrder:)`, `fileOrderKey(of:)`), so without `TopologyPlugin` every query is `no_topology`; containment is Topology's one tree, boards and containers alike (`A B` and `:inside` at any depth, `:has`, `:top-level` inside nothing: on the top board in no container, `:current-board` the board shown, in a container or not; each candidate's ancestors are its container's, `container(of:on:)`, then its board's, each container's and each board's worked out once); titles are the names point's, folded, case and all, named or derived; attributes are the kinds' schemas' properties, own and added (read with `KindSchema`), but those that hold a place, with the names point's word (`title`), each test typed by its schema (a quoted number is a number, a lone day a UTC day, `i` on text and choices, `~=` a list's item, an absent true|false its default else false, `[a]` a value that says something, `[a=""]` on text, choices, dates and titles no value, absent or empty, `!=` is `:not(=)`; with no kind named, each kind reads the literal its own way); `[a.b.c]` (`AttributeTest.path`, identifier members, QueryLanguage's) goes inside an attribute whose schema is an object or any JSON (`pathTest`; any other is `unknown_attribute`, "is text, so it has no members"), untyped: a `PathTest` (`.path` comparison, Queries) is typed by the JSON found at the members on each shape, string by the text operators and `i`, number by `=` and the orderings when the literal reads as a decimal number (an ordering with one that doesn't is `invalid_value`, with `i` `unsupported_operator`), a boolean by `true`/`false`, `~=` an array's item or a string's word, any other sort matching nothing, and a member that is missing, null, or inside a non-object is no value (`[a.b]` false, `[a.b=""]` true, `!=` their `:not`); text reads through its media type's format (mention text as plain text, live names); a row's `inside` names the shapes it's inside, outermost first: boards as Boards names them, containers by their names, else their kinds' labels. Its points, each filled by QueryLexicon (Queries knows no plugin; QueriesTests fill them with words of their own): `QueryNames` (`registrar.queryNames(attribute:source:named:derived:fold:)`, at most one: `TitleQueriesPlugin`, `.derived` for a kind both named and derived, `named` read off the record anywhere), `QueryBoardNames` (`queryBoardNames(placeholder:)`, at most one: `BoardQueriesPlugin`, `registry.boardPlaceholder(of:)`), `QueryWords` (by word, never the language's or a known invention: `queryPseudoClass(_:_:example:prepare:seeds:matches:onMain:)`, whose `prepare` runs in the turn the query takes up the file, `matches` anywhere, `.yes`, `.no` or `.onMain`, and `onMain` in slices with a `QueryMainContext`; and every word and text format says what it reads (`QueryReads`, `.file` or `.editor`): the form above, whose `prepare` takes a `QueryPreparation` (the editor), reads the editor, and the form with `reads: .file` takes a `QueryFilePreparation` (`snapshot`, Topology's in the request's view, and `registry`, never the editor, and no `onMain`) so the claim is compiler-held; what a plugin keeps that is a function of the records alone reaches a file word as a fact of the file, a type adopting `QueryFileFact` (`current(in:)`, on the main actor in the capture's turn, O(1)) read by `fact(_:)`, the claim made once where the fact type is declared; a relation reads the file; `queryRelation(_:_:example:reads:transitive:namesTypes:prepare:seeds:related:)` (`.fileRelation`, `reads: .file`), a relation answered from a `QueryFileFact` instead of edges: `related(shape, prepared)` lists the shapes a shape is related to directly, `seeds` every shape that has any, and `transitive` follows them through each other; the evaluation reads it forward once per query and word (`reversedRelations`) and works backward from the anchors, breadth first, each shape once, so a cycle ends where it began (a shape in one is related to itself), a plan that holds it is `readsEdges` (it waits for answers still arriving, as an edge word does) and `readsOnlyTheFile`, and it can start a compound as a one-step edge word does; `namesTypes: true` (at most one word) is the word `.Name` is refused toward (`HintPremise.Claim.typeWord`, settled by `Hints` once a shape is titled so); `querySelection(_:_:example:selected:)`, the person's selection, at most one, which `--ask` sends; `queryRelation(_:_:example:types:direction:)` over exactly some declared edge types; shipped: `MentionQueriesPlugin`'s relations `:mentions` and `:mentioned-by`, over `MentionEdge.id` alone, `ValidationQueriesPlugin`'s `:invalid` and `:warned`, `SelectionQueriesPlugin`'s `:selected`), `QueryTextFormats` (by media type, `queryTextFormat(mediaType:describes:prepare:read:)`, and the same with `reads: .file`: `MentionQueriesPlugin`'s reads the file, through `MentionState.labels` as the fact `MentionedNames`, so `[text*=…]` and `:contains` are `readsOnlyTheFile`) and `QueryEngines` (`QueriesPlugin`'s mark, `registry.answersQueries`); report lines `query names`, `query board names`, `query word :x`, `query text <type>`, `query engine`. `editor.queries` (a `QueryState`, nil without `QueriesPlugin`): `vocabulary` (a `QueryVocabulary`, `Sendable`, made on the first query, also from a registry alone, each word's `readsEditor`, `textForStoredQueries`, the `<vocabulary>` block with those words left out, for a query stored to be run later ([language models](language-models.md): `translate`), each kind's `holdsShapes`, whether shapes can be inside its shapes, `containerKinds`, and `holdsBoard`, whether by a board of their own; its `text` is the `<vocabulary>` block, "holds a board of shapes" or "holds shapes"), `check(_:)` (a `Sendable` `QueryPlan`, `description` a tree, and `editorWords`, the words in it that read the editor in the order the query uses them, `readsOnlyTheFile`, `editorWords` empty, and `readsEdges`, an edge word in it), `matches([QueryMatchRequest(text, edges:limit:admitting:)])` (the ids-only batch, `[Result<QueryMatches, QueryError>]` in order: each text checked once however many requests carry it (`checks`: a query asked in two views), over the edge types read once, one capture, one snapshot of Topology in each view asked for, every request evaluated in one `Evaluation` that shares the walk, the title index and the names memo, so a derived name is asked of the main actor once per batch; `admitting` asked off the main actor of each match before `limit`; `QueryMatches`: `canonical`, `ids`, `count` of all admitted, `revision`; no rows built, a refusal one request's, a cancellation every request's), `checkNames(_:)` (the names pass `run` makes, `unknown_title`, `unknown_id`, `cannot_contain`, and nothing else; nothing taken up for a plan that names no shape), `run(QueryRequest(text, limit:countOnly:properties:edges:settle:))` (`edges`, an `EdgeView`, `.resolved` unless it says: the view of Topology's edges the query's edge words and a row's connection see, `capture` taking `topology.snapshot(request.edges)`; `settle`, a `Duration?`: a plan that `readsEdges` waits, before it takes up the file and holding up no other query, while `topology.isSettling`, at most that long, and never past the deadline (`QueryBudget.settleWait`, 2 s, which `canvas query` and `--ask`'s query pass), then runs with a `pending` warning if answers are still arriving; a `QueryResult`: `query`, `count`, `rows` in file order, `QueryRow`s of id, kind, title, board, inside, properties as they read, cut at 500 unless named, connection and editing (a connection that went through a stand-in in the request's view says `via`, a `QueryVia` of the stand-in at each end that was one, and `more`, its other `QueryPair`s: `from` and `to` are the first pair in file order; both nil as drawn, and written by `QueryOutput` member by member), `warnings` `limited`, `editing`, `no_title_match`, `pending`, `shown` and `shownPath`, the board shown as it took up the file, and `timings`), `titles(for:limit:)` and `whereThePersonIs(selectedLimit:)`. The main actor reads and resolves it (some 0.02 ms) and takes up the file in one turn, O(1) (`withoutObservingDocument { editor.file }`, `topology.snapshot(request.edges)`, the board shown and its path, the revision, the shape being typed into, then each word's and text format's `prepare`); a detached `@concurrent` evaluation answers it off the main actor, a set at a time (a compound's tests cheapest first; a one-step edge word with fewer than 1,024 anchors starts from their edges), over that snapshot, handed over whole (`Handover`) and freed there (some 24 ms for every note's text at 10,000 shapes); what only the main actor can say (a derived name, an `onMain` verdict) is asked in slices (`MainFacts`), each a main-actor job of 2 ms of thread CPU plus at most the record that crosses it (the clock read after the first record, every 16 while the pace leaves room before 1.5 ms, then after every record), the next asked for only once the last has answered (a query's own: other queries' slices take their places among them), about the shape as the app has it then (its live record and board; one gone since has no name and fails the word), so derived titles and validity can be newer than the rest of an answer, never older, and no main-actor code is handed a record the app has since replaced; the answer is written as JSON off the main actor too. `:invalid` and `:warned` take Validation's `cachedResult(for:)` only on the board shown with nothing committed since the query started, else run the kind's rules over the live board (`context.shapes(on:)`), so a query never makes Validation read a board. Queries on one editor run at once: each takes up the file as soon as it's asked and is answered alongside the others, over a snapshot of its own, none waiting for another; `QueryBudget.deadline` (8 s, under `canvas`'s 10) is a scheduled action on `editor.scheduler`, armed before a query waits for answers to settle (`too_slow`: the settle wait counts against it, so a query that waited 2 s has 6 s of evaluation, and a slow one is refused with its hint rather than dying as `canvas`'s client timeout); the caller's cancellation reaches the evaluation (`cancelled`, looked for every 256 shapes and before each slice), and stops that query alone, as its deadline does; an editor gone is `board_closed` (`QueryState` and `MainFacts` hold it weakly). Zero upkeep: no `documentDidChange`, `boardDidChange` overridden with nothing, and nothing kept past a query but the vocabulary (a snapshot held makes a commit copy each table it changes once, however many are held, so queries at once cost it no more than one, and none outlives its query; `liveSnapshots` is 0 whenever none runs). Debug counters: `liveSnapshots`, `captures`, `checks`, `mainSlices`, `recordsEncoded`, `derivedTitlesAsked`, `verdictsAsked`, `universeWalks`, `seededFromAnchors`. The engine knows no stand-in kind: standing in is Topology's mechanism (`EdgeForwarding`), and what these views, the batch and `reads` give a plugin that keeps answers is generic. `canvas query`, `query-vocabulary` and `--ask` are QueryCommands' ([the command line](command-line.md) and [language models](language-models.md)). The shipped list has `QueriesPlugin(), TitleQueriesPlugin(), BoardQueriesPlugin(), MentionQueriesPlugin(), ValidationQueriesPlugin(), SelectionQueriesPlugin()` (QueryLexicon's) after DrawLexicon's, then `QueryCommandsPlugin()` (`QueryTranslationPlugin(prompt: QueryPrompt.system, referenceRule: QueryPrompt.referenceRule)` follows `QueriesPlugin()`: the translator is [language models](language-models.md)' English-to-query, `editor.queryTranslator`, which `--ask` calls and the app may too); each of QueryLexicon's needs `QueriesPlugin()` and its concern's plugin (`MentionQueriesPlugin` is refused without Mentions, whose edge type it follows; the others find nothing without theirs).

## Testing

- For queries, QueryLanguageTests use fixture words only (card, box, disc; rank, status, due; wire, hot-wire, pipe; the unknown words glows and stacked): trees and spans, the canonical form (a fixed point), every refusal (reason, message, hint, offset, length, line, column), the limits at their edges, the words and the inventions, and seeded fuzz (generated trees round-trip; random edits never crash, reprint as their canonical form, keep every span inside the text). QueriesTests use fixtures only (PathTests: chores that hold `facts`, an object of any JSON, an added property, and `meta`; FileRelationTests: `:descends-from(S)` and `:sprung-from(S)` over `Lines`, a service's parents as a `QueryFileFact`): CanvasTesting's `Chore` (`ChoresPlugin`: kind `chore`, labelled "Task", every schema type, and the added `Flagged`, key `flag`), pockets, tiles and links graded as wires, a `caption` names point, board names, the words `:starred` (seeded), `:heavy` (off the main actor, counted by `Tally`), `:audited` (on it, `MainCalls`) and `:wired-to(S)`, and a `text/x-shout` format (`queryPlugins`; `shelf()`, `hiddenShelf()`, `yard()`, CanvasTesting's corrals captioned on boards and pockets, containers nested two boards down, `choresHarness`, `storyHarness` with `citesPlugin`, `pickedPlugin` and `faultyPlugin`, `wiresHarness`, `danglingHarness`); `answer`, `matched`, `refusedAnswer` and `expectMatches` run a query through `awaitResult`, which turns the main run loop for its slices, and `plan(_:on:)` reads a plan (`description`). What runs where is held by `QueryState`'s debug counters (`liveSnapshots`, `captures`, `checks`, `mainSlices`, `recordsEncoded`, `derivedTitlesAsked`, `verdictsAsked`, `universeWalks`, `seededFromAnchors`) and `threadsPlugin` (names, a text format's `read` and a word's `matches`, each off the main thread); `SlowWord`, with `burn(_:)`, makes a record cost what a test says: a slice's bound and its costliest record, one slice queued at a time, a run-loop `Timer` firing between slices (the run loop's sources run between them, not only queue order), cancellation mid-slice, the deadline reached with `h.wait(8_000)` inside a slice on the `ManualScheduler`, queries at once (a quick query, and a batch, taking up the file and answering while a slow one is mid-slices, each over a snapshot of its own; a cancelled one, or one out of time, stopping alone), and a closed file (an editor held only in a box a word empties); a word whose `prepare` commits lands a commit in the turn the query takes up the file (attributes the capture's, a derived name the live record's). QueryLexicon's tests use fixtures only: TitleQueriesTests title CanvasTesting's kinds as TitleNamesTests do; BoardQueriesTests a `drawer`, which opens its board, and a `crate`, which doesn't (and titled corrals between them, `cellarHarness()`, named in `inside` where the path names none); MentionQueriesTests a `scribble` of mention text and a `strand` edge type the words ignore; ValidationQueriesTests card and tag rules that count their runs (never Validation made to read a board); SelectionQueriesTests a `:shifting` word; BoardQueriesTests and MentionQueriesTests name shapes with a names contribution of their own over `TitleProperty`. Stand-ins, batches, reads and settling are fixtures too (QueriesTests' StandIns.swift: a `Proxy` standing for the shapes its record cites, a `Lens` for what was provided with `topology.provide`, `relay()`, wires into them, and `fileReadsPlugin`: a `reads: .file` word, `:linked`, and text format, hushes): `edgeViewTests`, `connectionViaTests`, `matchesBatchTests`, `checkNamesTests`, `readsTests` (and a fact of the file: `glossaryPlugin`'s `GlossaryFact`, a service's value read by a file format) and `settleTests` (a `Working` source of busy work on `topology.keepsSettling`, the `ManualScheduler` ending the wait, and the deadline counting it: 2 s of waiting then an evaluation that runs to 8 s in all is refused `too_slow`, a millisecond short answers); QueryCommandsTests' StandInTests write `via` and `more` and wait; CompositionTests' QueryShippedTests pin what each shipped word reads, and MentionQueriesTests that mention text reads only the file and answers as it did. QueryTranslationTests hold the translator (`editor.queryTranslator`) on fixture chores and a `ScriptedLanguageModel` without the command line: how an answer is read (`AskAnswer.parse`), what it answers and asked, each failure's `reason` and `message`, no model or no queries, and the deadline in a model call; and `translate` (TranslateTests, over captioned chores, a `:picked` selection word and a scripted model): the canonical query returned and nothing run, a wrong title and a word that reads the editor each repaired once and refused twice an unusable answer, the 40 s mark, the 55 s deadline, a cancelled task, the `.reference` request (no selection, no word that reads the editor, the rule line) against the `.person` one, and each failure as `ask`'s. QueryPromptTests hold the shipped rule line and the filtered vocabulary for `.reference`. QueryCommandsTests run the commands as the server does (`start`, `finish`, `run`, `answered`, `refused`) over chores, pockets and links (and corrals, for `holdsShapes` and `inside`), captions naming them, "Untitled Pocket" boards and a `Desk` (`:picked`, the selection word; `:slow`, asked on the main actor), with a `ScriptedLanguageModel` (`queue`, `holdsAnswers`, `requests`), the deadline and the repair mark reached with `h.wait(…)` on the `ManualScheduler` (from inside `:slow`, or `onPicked` for the request's assembly), and `QueryOutput.lastBuiltOnMainThread` (debug builds) says where an answer was built. CompositionTests hold the shipped pieces on the story file, `QueryStory` (the design's "Roadmap": ids `00000000-0000-4000-8000-0000000000NN` by letter, `ids("C, Y")`, `fileOrder`, `file(in:)`, `harness(pasteboard:model:)`, `document(windowed:)`; never mend V's JSON, `{"type": "object" "title": "Invoice"}`: a card's reading as an object is kept by id for the whole process, so V would be titled in every story after; mend a copy): "Query story"; QueryShippedTests (`StoryQuery.table`, the design's table of every construct, row for row: shapes in file order, count, canonical form, reasons); QueryCommandLineTests (`canvas` as built against `CommandServer` on the story in a `BoardDocument`: `configureQueryBoards(pasteboard:model:)`, `startQueryServer(for:)`, which holds the board weakly so a closed file's editor can be seen to go, and `RunningCanvas`, a `canvas` left running, a held `--ask`, while the test does something else); BoardsTests' `:current-board` across a switch; QueryPromptTests (each of `runnableExamples` answered on the story, each of `illustrativeExamples` refused there with its reason, every query after "→" listed, nothing query-shaped left out of the lists, every `:word` the language's, a shipped plugin's or one the prompt says not to invent, the kinds, edge types and words it assumes the shipped vocabulary's, and the skill's `query-prompt.md` equal byte for byte, which `scripts/query-prompts/copy_prompt.py` rewrites: a prompt change lists each new query-like example in one of the two lists); "Query eval board" (`QueryEvalBoard`, 59 shapes on six boards); and "Query prompt, live" (each case's reference query, offline; with `QUERY_LIVE=1`, the model itself: `QUERY_LIVE=1 TEST_FILTER="Query prompt, live" build/debug/CompositionTests/CompositionTests`, with `QUERY_RUNS`, `QUERY_MODEL`, `QUERY_EFFORT`, `QUERY_CASES`, `QUERY_JOBS` and `QUERY_EVAL_OUT=<round>`; a run the API fails asked again up to 4 times, a timeout not; `scripts/query-prompts/README.md`). BenchmarkTests' Query benchmarks: `cpu {}` sums a command's main-actor jobs without polling the run loop, and `FrameDriver` times each frame from the first fire of a strict main-queue dispatch timer it answers. The owners' readers are held where they live: CanvasTests' KindSchemaTests (every CanvasTesting kind's compact types and the properties that hold a place, with `Gauge` and the `Latch` added property, each refusal and hand-written `$ref`s, read on a detached task; draw's words stay AutomationTests', SkillTests' and CommandLineTests'), MentionsTests' LabelsTests, ValidationTests' CachedResultTests (counting rule runs, with a service that hears each commit before the engine), LanguageModelsTests' UnwrapTests and the request body's `model` and `effort`, and BoardsTests' "A board's placeholder".
