# Queries

Queries: the query language, what a query sees, where it runs, what plugins add to it (`:invalid`, `:warned`, `:incomplete`, `:is-a`, `:misfit`, a path into a note's values, what `--ask` is told of the file's types and which shapes are of each), `canvas query`, `query-vocabulary`, `--ask`, and `/query`, the command bar's question.

Related: [topology](topology.md) (stand-ins, the edge views and settling the engine reads), [command line](command-line.md), [language models](language-models.md), [titles](titles.md), [mentions](mentions.md), [validation](validation.md), [boards](boards.md), [selection](selection.md), [types](types.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Queries](../../docs/plugin-system.md#queries), [query](../../docs/plugin-system.md#query).

## Architecture

- Queries (platform, an engine, on Selection and Topology, the engine any plugin may run: the language agents write is `canvas query` and the words their owners give; `docs/plugin-system.md`, "Queries") finds the shapes of a file a query matches. The language is QueryLanguage's (a core module that knows no canvas, registry or plugin: `SelectorList(parsing:)`, a tree whose parts know their places, `QuerySpan`s in characters of the query as sent, and `canonical`, the one form it prints, which an answer says ran), CSS's where CSS has a meaning: a compound is at most one head (a kind, `*`, a title in quotes, a kind with a title right after it, `sticky-note"Checkout"`, the kind's shapes with that title, refused as a title head is, or `#` and an id) and tests with no space (`[a]`, `[a=v]`, `^= $= *= ~= |=`, `< <= > >=`, `i` and `s`; `:not`, `:is`, `:where`, `:has`), a space is inside at any depth, `>` directly inside (a container's own shapes, an owner's board's in no container), a comma either; its own words (`Word`) are those, `:inside`, `:top-level`, `:current-board`, the edge words (`:edge-to`, `:edge-from`, `:connected-to`, one edge either way, `:downstream-of`, `:upstream-of`, `:component-of`, any number either way, `:starts-at`, `:ends-at` (the connections, shapes that carry an edge in slot "", that start and end at a shape), `:start-of`, `:end-of` (the shapes where such a connection starts and ends), `:between`, each taking edge types after a comma, `a|b`, `only t` for a type alone, a type taking in those under it), `:dangling` and `:contains("x")`; `QueryLimits`: 8,192 characters, 1,024 in a string, 32 levels, 256 compounds, 20 problems said. It refuses, never passes over, each refusal saying where, with the one like it and a hint, most often the query to write: `empty_query`, `syntax`, `stray_space` (a compound after a space starts with a head), `too_long`, `too_complex`, `unsupported` (`+ ~ ||`, `:nth-*`, `:root`, `:hover`, a combinator in `:has`, whose hint nests `:has(> …)`; `.Name`, whose hint is the word that finds a type's shapes, `:is-a("Name")`, when a relation is declared `namesTypes` and a shape is titled so, else `:contains("Name")`, a plain refusal that says neither "class" nor "schemas"), `not_built` (where shapes sit; the words people invent that are planned), `not_an_id` and `bad_argument` (what the text shows, QueryLanguage's, stopping at the first, as are the words people invent, `KnownInventions`: `:parent-of`, `:source-of`, `:neighbor-of` (the old `:connected-to`), `:near`, the spatial ones `not_built`); `unknown_kind`, `unknown_attribute` (the words people write in brackets, `[kind=…]`, `[board=…]`, with what to write), `unknown_pseudo_class`, `unknown_edge_type`, `invalid_value`, `unsupported_operator`, `cannot_contain` (a container side that can only be kinds whose shapes hold no shapes, `containerKinds`), `no_names`, and `not_built` for an attribute that holds a place or `=` on an object (what the app hasn't, Queries' resolution, every independent one at once), and `[class=…]`, `unsupported` as `.Name` is; and a title or id no shape has (`unknown_title`, `unknown_id`), rather than answering none (a title standing for an anchor whose edges point at shapes that aren't there hints the `:dangling` that finds their carriers). The canvas skill teaches it (`reference/query.md`). A query ranges over every shape on every board the app can show, none kept aside, in file order (the root's shapes in no container back to front, each container followed at once by what it holds and each owner by its board's shapes: the snapshot's `forEachShape(inFileOrder:)`, `fileOrderKey(of:)`), so without `TopologyPlugin` every query is `no_topology`; containment is Topology's one tree, boards and containers alike (`A B` and `:inside` at any depth, `:has`, `:top-level` inside nothing: on the top board in no container, `:current-board` the board shown, in a container or not; each candidate's ancestors are its container's, `container(of:on:)`, then its board's, each container's and each board's worked out once); titles are the names point's, folded, case and all, named or derived; attributes are the kinds' schemas' properties, own and added (read with `KindSchema`), but those that hold a place, with the names point's word (`title`), each test typed by its schema (a quoted number is a number, a lone day a UTC day, `i` on text and choices, `~=` a list's item, an absent true|false its default else false, `[a]` a value that says something, `[a=""]` on text, choices, dates and titles no value, absent or empty, `!=` is `:not(=)`; with no kind named, each kind reads the literal its own way); `[a.b.c]` (`AttributeTest.path`, identifier members, QueryLanguage's) goes inside an attribute whose schema is an object or any JSON (`pathTest`; any other is `unknown_attribute`, "is text, so it has no members"), untyped: a `PathTest` (`.path` comparison, Queries) walks the members on each shape (`reached(in:)`), a list met at any step or at the end giving each of its items, lists in lists too, and holds when any value reached does, each typed by the JSON found: string by the text operators and `i`, number by `=` and the orderings when the literal reads as a decimal number, a date string by the orderings when the literal reads as a date or date-time (`QueryDates`, tried only when it is no number: a day is its whole UTC day, `TypedTest.ordering`, the rule a date attribute's orderings share; a string that is no date matches no ordering, `=` stays text) (an ordering with a literal that is neither is `invalid_value`, `"Oct 1" isn't a number or a date`, with `i` `unsupported_operator`), a boolean by `true`/`false`, `~=` a string's word or, on an item of a list, a number's or boolean's value, any other sort matching nothing, and a member that is missing, null, or inside something that is neither an object nor a list is no value (`[a.b]` holds when any value reached says something, `[a.b=""]` when none does, `!=` the `:not` of `=`); text reads through its media type's format (mention text as plain text, live names); a row's `inside` names the shapes it's inside, outermost first: boards as Boards names them, containers by their names, else their kinds' labels. Its points, each filled by the module that owns the meaning (Titles, Boards, Mentions and Validation, and Queries itself for the selection, Selection being below it; Queries knows no shape trait; QueriesTests fill them with words of their own): `QueryNames` (`registrar.queryNames(attribute:source:named:derived:fold:)`, at most one: `TitleQueriesPlugin`, `.derived` for a kind both named and derived, `named` read off the record anywhere), `QueryBoardNames` (`queryBoardNames(placeholder:)`, at most one: `BoardQueriesPlugin`, `registry.boardPlaceholder(of:)`), `QueryWords` (by word, never the language's or a known invention: `queryPseudoClass(_:_:example:prepare:seeds:matches:onMain:problems:)`, whose `prepare` runs in the turn the query takes up the file, `matches` anywhere, `.yes`, `.no` or `.onMain`, `onMain` in slices with a `QueryMainContext`, and `problems` (`[ShapeProblem]`, the form with an editor only), what a row it matched has to answer for, asked in the same kind of slices of only the rows returned (`MainFacts.problems`, after the rows are made: `Evaluation.listProblems`, for the words the plan names that have one, in the order of their names, each shape's problems once however many words give them; none for `countOnly`, `limit`'s rows for a limited query; `problemsAsked`) and set on each row that has any; and every word and text format says what it reads (`QueryReads`, `.file` or `.editor`): the form above, whose `prepare` takes a `QueryPreparation` (the editor), reads the editor, and the form with `reads: .file` takes a `QueryFilePreparation` (`snapshot`, Topology's in the request's view, and `registry`, never the editor, and no `onMain`) so the claim is compiler-held; what a plugin keeps that is a function of the records alone reaches a file word as a fact of the file, a type adopting `QueryFileFact` (`current(in:)`, on the main actor in the capture's turn, O(1)) read by `fact(_:)`, the claim made once where the fact type is declared; a relation reads the file; `queryRelation(_:_:example:reads:transitive:namesTypes:prepare:seeds:related:)` (`.fileRelation`, `reads: .file`), a relation answered from a `QueryFileFact` instead of edges: `related(shape, prepared)` lists the shapes a shape is related to directly, `seeds` every shape that has any, and `transitive` follows them through each other; the evaluation reads it forward once per query and word (`reversedRelations`) and works backward from the anchors, breadth first, each shape once, so a cycle ends where it began (a shape in one is related to itself), a plan that holds it is `readsEdges` (it waits for answers still arriving, as an edge word does) and `readsOnlyTheFile`, and it can start a compound as a one-step edge word does; `namesTypes: true` (at most one word) is the word `.Name` is refused toward (`HintPremise.Claim.typeWord`, settled by `Hints` once a shape is titled so); `querySelection(_:_:example:selected:)`, the person's selection, at most one, which `--ask` sends; `queryRelation(_:_:example:types:direction:)` over exactly some declared edge types; shipped: `MentionQueriesPlugin`'s relations `:mentions` and `:mentioned-by`, over `MentionEdge.id` alone, `ValidationQueriesPlugin`'s `:invalid` (its rows list each error as a `problem`, `class` `wrong`, a field's with its `path`) and `:warned` (each warning, `class` `warning`), `SelectionQueriesPlugin`'s `:selected`, `GroupQueriesPlugin`'s `:grouped-with` (a `reads: .file` relation, Grouping's: [grouping](grouping.md))), `QueryAskFacts` (`registrar.queryAskFact(tag:_:)`, one plugin a tag, report line `ask fact fields`: a block `--ask` sends about the file after `<titles>` under the tag, `text(editor, question)` on the main actor, asked once a question by `QueryTranslator.inputs(for:)` in the registry's order and kept for a second try, left out when empty; `check` refuses a tag that is no lower-case word or one of the request's own, `AskFacts.reservedTags`, which are `AskFacts.Tag`'s cases, `AskRequest.Tag` the same; shipped: `TypeQueriesPlugin`'s `<fields>`, `<instances>` (which shapes are of each type, by title, and `Of no type:` the titled notes of none, so a note of no type is told apart from one that is) and `<connections>` (how arrows join the file's shapes, a line for each pair of ends: `Person → Company: 2 Employment arrows`), [types](types.md); Queries and QueryTranslation know no field), `QueryPathChecks` (`registrar.queryPathCheck(attribute:_:)`, one plugin an attribute, report line `query path fieldValues`: `check(members, editor)` on the main actor says the first member of a path a query tests (`QueryPlan.paths`, noted as `pathTest` resolves it) that no shape of the file can hold, a `QueryPathUnknown(index:known:)`; `QueryState.run` asks each distinct path once and appends `unknown_field` to the result's warnings, its message `No type in the file has fieldValues.stauts.` and `Did you mean fieldValues.status?` when a known member is near (`Suggestions.closest`); a batch and `translate` ask nothing; shipped: `TypeQueriesPlugin` over `FileFields`, [types](types.md)) and `QueryTextFormats` (by media type, `queryTextFormat(mediaType:describes:prepare:read:)`, and the same with `reads: .file`: `MentionQueriesPlugin`'s reads the file, through `MentionState.labels` as the fact `MentionedNames`, so `[text*=…]` and `:contains` are `readsOnlyTheFile`) and `QueryEngines` (`QueriesPlugin`'s mark, `registry.answersQueries`); report lines `query names`, `query board names`, `query word :x`, `query text <type>`, `query engine`. `editor.queries` (a `QueryState`, nil without `QueriesPlugin`): `vocabulary` (a `QueryVocabulary`, `Sendable`, made on the first query, also from a registry alone, each word's `readsEditor`, `textForStoredQueries`, the `<vocabulary>` block with those words left out, for a query stored to be run later ([language models](language-models.md): `translate`), each kind's `holdsShapes`, whether shapes can be inside its shapes, `containerKinds`, and `holdsBoard`, whether by a board of their own; its `text` is the `<vocabulary>` block, "holds a board of shapes" or "holds shapes"), `check(_:)` (a `Sendable` `QueryPlan`, `description` a tree, and `editorWords`, the words in it that read the editor in the order the query uses them, `readsOnlyTheFile`, `editorWords` empty, `readsEdges`, an edge word in it, and `usesScope`, a word bound per request (below), which `check(_:binding:)` refuses unless bound), `checkStored(_:binding:)` (`check` for a query stored to run later, refused `unsupported` for the first word that reads the editor, `QueryError.cantBeUsed`, “`:selected`” can’t be used here., hint `A stored query reads only the file, never who is looking or what is selected.`: the one gate a reference's answers, draft and warning, the translator's stored answers and `canvas draw`'s `x-canvas-query` check go through), `matches([QueryMatchRequest(text, scope:edges:limit:admitting:holdingBack:)])` (the ids-only batch, `limit` at least 1 and held to no number, `QueryMatchRequest.every` its default: every match, as a reference that stands for all of them asks, and the lights a hover shows and a shape's lists, `[Result<QueryMatches, QueryError>]` in order: each text checked once however many requests carry it (`checks`: a query asked in two views), over the edge types read once, one capture, one snapshot of Topology in each view asked for, every request evaluated in one `Evaluation` that shares the walk, the title index and the names memo, so a derived name is asked of the main actor once per batch; `admitting` asked off the main actor of each match before `limit`, and `holdingBack` of each it turned away; `QueryMatches`: `canonical`, `ids`, `count` of all admitted, `heldBack`, how many of those turned away `holdingBack` took (what a step of the caller's could admit: References' count of what isn't public), `revision`; no rows built, a refusal one request's, a cancellation every request's), `checkNames(_:)` (the names pass `run` makes, `unknown_title`, `unknown_id`, `cannot_contain`, and nothing else; nothing taken up for a plan that names no shape), `run(QueryRequest(text, limit:countOnly:properties:edges:settle:))` (`limit` at least 1, `QueryBudget.rows` (100) unless it says, and held to no most: `QueryRequest.every` lists every row, and `canvas query --limit` takes any number) (`edges`, an `EdgeView`, `.resolved` unless it says: the view of Topology's edges the query's edge words and a row's connection see, `capture` taking `topology.snapshot(request.edges)`; `settle`, a `Duration?`: a plan that `waitsForAnswers` (it `readsEdges`, or holds a word that says it waits as edges do, `queryPseudoClass(…, settles: true)`, `PlanUses.settles`: Validation's three) waits, before it takes up the file and holding up no other query, at most that long, and never past the deadline (`QueryBudget.settleWait`, 2 s, which `canvas query` and `--ask`'s query pass): one that holds a word that waits while `topology.isSettling`, one that only reads edges while `topology.isSettlingEdges` (a source of no edges, a rule's verdicts, holds up no query of edges: `SettleWait`, `.everything` or `.edges`); then it runs with a `pending` warning if answers are still arriving (`QueryWarning.pending(_:ofEdges:)`, of edges with the stand-ins unanswered counted when only edges were waited for, else uncounted, `Answers are still arriving`); a `QueryResult`: `query`, `count`, `rows` in file order, `QueryRow`s of id (which names the shape in a later query, `#<id>`, and in a later `canvas draw` if it has no title: [command line](command-line.md), ids as names), kind, title, board, inside, properties as they read, cut at 500 unless named, connection, editing and `problems` (a connection that went through a stand-in in the request's view says `via`, a `QueryVia` of the stand-in at each end that was one, and `more`, its other `QueryPair`s: `from` and `to` are the first pair in file order; both nil as drawn, and written by `QueryOutput` member by member), `warnings` `limited`, `editing`, `no_title_match`, `pending`, `unknown_field`, `shown` and `shownPath`, the board shown as it took up the file, and `timings`), `titles(for:limit:)` and `whereThePersonIs(selectedLimit:)`. The main actor reads and resolves it (some 0.02 ms) and takes up the file in one turn, O(1) (`withoutObservingDocument { editor.file }`, `topology.snapshot(request.edges)`, the board shown and its path, the revision, the shape being typed into, then each word's and text format's `prepare`); a detached `@concurrent` evaluation answers it off the main actor, a set at a time (a compound's tests cheapest first; a one-step edge word with fewer than 1,024 anchors starts from their edges), over that snapshot, handed over whole (`Handover`) and freed there (some 24 ms for every note's text at 10,000 shapes); what only the main actor can say (a derived name, an `onMain` verdict) is asked in slices (`MainFacts`), each a main-actor job of 2 ms of thread CPU plus at most the record that crosses it (the clock read after the first record, every 16 while the pace leaves room before 1.5 ms, then after every record), the next asked for only once the last has answered (a query's own: other queries' slices take their places among them), about the shape as the app has it then (its live record and board; one gone since has no name and fails the word), so derived titles and validity can be newer than the rest of an answer, never older, and no main-actor code is handed a record the app has since replaced; the answer is written as JSON off the main actor too. `:invalid` and `:warned` take Validation's `cachedResult(for:)` only on the board shown with nothing committed since the query started, else run the kind's rules over the live board (`context.shapes(on:)`), so a query never makes Validation read a board. Queries on one editor run at once: each takes up the file as soon as it's asked and is answered alongside the others, over a snapshot of its own, none waiting for another; a query's deadline is a scheduled action on `editor.scheduler`, armed before a query waits for answers to settle (`too_slow`, its message saying the whole seconds: the settle wait counts against it, so a query that waited 2 s has 6 s of evaluation, and a slow one is refused with its hint rather than dying as `canvas`'s client timeout). The file sets it, as the query starts (`QueryBudget.deadline(forShapes:)` of `file.shapeCount`, O(1), every board's): 8 s (`QueryBudget.deadline`) for a file of up to 10,000 shapes (`deadlineFrom`) and 50 µs (`deadlinePerShape`) more for each shape past that, 12.5 s at 100,000 (a walk of every shape off the main actor is some 3 µs of each), counted from when the query started or the main actor last answered a slice it asked for (`MainFacts.onSlice`, `QueryRun.answered`), so it is a time without a sign of life, not a total: a query that the main actor serves, a slice a frame between the frames of a drag (`:invalid` over 200,000 shapes, a drag's frames at 60 a second in between, takes 4,000 slices and more than a minute), is not refused, and one that runs on without an answer is; a request may also cap the total (`QueryRequest.deadline`), and `canvas query` does, for `QueryBudget.commandDeadline`, `RPC.defaultWait` (the 10 s `canvas` waits when nothing says otherwise, one constant for both) less 2 s, so its refusal arrives before the client gives up whatever the file (the message says the seconds that ran out); the caller's cancellation reaches the evaluation (`cancelled`, looked for every 256 shapes and before each slice), and stops that query alone, as its deadline does; an editor gone is `board_closed` (`QueryState` and `MainFacts` hold it weakly). Zero upkeep: no `documentDidChange`, `boardDidChange` overridden with nothing, and nothing kept past a query but the vocabulary (a snapshot held makes a commit copy each table it changes once, however many are held, so queries at once cost it no more than one, and none outlives its query; `liveSnapshots` is 0 whenever none runs). Debug counters: `liveSnapshots`, `captures`, `checks`, `mainSlices`, `recordsEncoded`, `derivedTitlesAsked`, `verdictsAsked`, `universeWalks`, `seededFromAnchors`. The engine knows no stand-in kind: standing in is Topology's mechanism (`EdgeForwarding`), and what these views, the batch and `reads` give a plugin that keeps answers is generic. `canvas query`, `query-vocabulary` and `--ask` are QueryCommands' ([the command line](command-line.md) and [language models](language-models.md)). The shipped list has `QueriesPlugin(), TitleQueriesPlugin(), BoardQueriesPlugin(), MentionQueriesPlugin(), ValidationQueriesPlugin(), TypeQueriesPlugin(), SelectionQueriesPlugin()` (`TypeQueriesPlugin` adds `:is-a(S)`, the word `namesTypes` points `.Name` at, reads a type in `is` as its title, and adds `:misfit` (below); `ValidationQueriesPlugin` adds `:invalid`, `:warned` and `:incomplete`, each a shape with an issue of one of Validation's three levels, read the same way (Validation's cache while it is current, else the rules over the shape's board as the app has it), an `.onMain` word reading the editor, asked of every shape of the file in slices, whose `problems` list that level's issues (`:invalid`'s, `class` `wrong`; `:warned`'s, `class` `warning`, a language rule's its sentence; `:incomplete`'s, `class` `needed`, what a shape still needs, a field's with its path or a relationship row's name), and each says it waits for answers still arriving (`settles: true`), as a rule may answer later than its commit: `:incomplete` is not an error, so a shape can be both `:incomplete` and `:invalid`, and the summary, `it still needs something`, is true of any rule's issue of that level (Types' rule says a field its types need left empty, a needed yes or no never counting, and a Needed relationship row left empty: [types](types.md#checks)); `--ask`'s prompt teaches `:incomplete` beside `:invalid` and a request's vocabulary, which is generated, lists: [types](types.md); its prompt example, the story's Person, Employee card and Ann, and the skill's rows are held by QueryPromptTests, QueryShippedTests and SkillTests) (the last six their owners', the last of them Queries' own, Selection being below it) after draw's words, then `QueryCommandsPlugin()` (`QueryTranslationPlugin()` follows `QueriesPlugin()`, made with the product's text files, `Shipped/ask-prompt.txt`, `ask-rule.txt`, `ask-bound.txt` and `ask-accepts.txt`: the translator is [language models](language-models.md)' English-to-query, `editor.queryTranslator`, which `--ask` calls and the app may too); each of the six owners' needs `QueriesPlugin()` and its owner's plugin (`MentionQueriesPlugin` is refused without Mentions, whose edge type it follows; the others find nothing without theirs).
- `/query <question>` (QueryTranslation's `QuerySlashPlugin`, QuerySlash.swift, id `query-slash`, shipped after `QueryCommandsPlugin()`; the owner's ask of 2026-10-25): the command bar's question, a command about the bar's target as a whole ([slash commands](slash-commands.md): `SelectionSlashCommand`, offered on several shapes selected or on every shape with none, never one shape nor a shape's text; `argument` "question", `waiting` "Interpreting…", `InterpretationWords.interpreting`). Its task (`QuerySlash.answer`, holding the translator and the engine, which hold the editor weakly, and the editor weakly) translates the words (`translate(_:about:)`: `.person` with nothing selected, as `--ask` asks; `.selection` on a selection, whose `<board>` adds that the question picks out some of the selected shapes and only those the query matches are kept, since `/query` narrows a selection: "the ones with a beta fish" with three students selected is those of the three; a pill in the words is the name it shows in quotes), finds every match (`matches`, `QueryMatchRequest.every`, `admitting` the selection's shapes on a selection), and selects them with `editor.goTo`: those on the board shown if any are, else those on the first board in the file's order that has some, which it shows (as following a mention does, one step back); VoiceOver hears `4 shapes selected`, and `, 5 more on other boards` where the selection can't hold them all (`QuerySlashStyle`). None found is `.failed("No matches")`; the model's failures are the words every host of words says (`InterpretationStatus(_:)`'s `words`: "Unavailable" with no model or engine, "Not signed in", "Key rejected", the model's own words, a deadline "Timed out", "No query for these words" for a question a query can't ask, "Unusable answer", "No shape is called Task" for one the engine refused for a title no shape has: `QueryError.unknownTitle`, Retry mending it once the shape exists); cancelled (the bar closed, the line edited), it says and selects nothing. QueryTranslationTests' `querySlashTests` hold it headless (captioned chores, a pocket's board, a scripted model).
- `ShapeProblem` (Queries' `QueryResult.swift`, `Sendable, Hashable, Encodable`: `field` (a field's name, or `from` or `to` for an end of an arrow of a relationship type, or a relationship row's name), `path` (a JSON Pointer), `class`, `message`) is something a shape's values still need or have wrong, as a result lists it: `canvas draw`'s rows carry them as `problems` (Draw's `DrawReports`; [command line](command-line.md)), and so do the rows of a query that names `:invalid` or `:incomplete`, both Validation's words (`:incomplete` also lists a note with a Needed relationship row left empty, its `problems` saying the row's name and `layer is needed`, `class` `needed`) (`QueryRow.problems`, written by `QueryOutput.row`).

- `:misfit` (Types' `TypeQueriesPlugin`, `Engines/TypeQueries.swift`): an arrow whose ends do not fit its relationship type, a `reads: .file` word over `RelationshipFacts: QueryFileFact { graph }` (`editor.relationships.graph`, taken in O(1) in the turn the query takes up the file, with the kinds that relate and the kinds that are pills), seeded by the shapes that list types, judged off the main actor by `MisfitFacts.isMisfit`: the arrow's connection edge(s) in the snapshot (the request's view), each end alone, `.note` for the shape it is or the one shape a pill resolves to, unjudged for a pill the snapshot leaves as it was (not admitted, stands for nothing), for ends that differ across several edges (a pill that finds several shapes) and for a shape the file cannot show, and `graph.fit(of:from:to:)?.isMisfit` for each marked type in the arrow's `is`: the one `fit` the check on an arrow calls, so the app's verdict, Validation's kept issues and `:misfit` are the same set (`relationshipAgreementTests` holds it after every step of its typed seeded runs). An arrow with no connection (an end free) has no verdict. - A reach (`QueryReach.swift`, `Evaluation.reaches`, `QueryState.reaches(_:)`): what a one-step query leads to from a shape, and from there, until nothing new is found, for a hover's lights (Neighbors' reach mode; the engine knows no light or edge type). `QueryReachRequest(step:between:start:edges:strength:)` carries a light's own query and between, written with `:scope` (`light.query(":scope")`, `light.between?(":scope")`), and, if the caller has one, a `strength(hop, share)` it measures a candidate by (the engine knows no 60%: Neighbors passes `ReachStyle.strength`); `reaches(_:)` answers a batch as `matches` does (one capture, one evaluation off the main actor, each text checked once, a refusal one request's: the texts, `unknown_id` for a start no shape has; cancellation, the deadline and a closed file the batch's). An arrow within a hop, back to an earlier one or to the start is not followed, so a cycle ends where it began and the start is never in the answer. `between` is evaluated for each shape stepped from, and each connection it finds (an edge in the empty slot touching that shape) is **travelled** when it runs from hop d-1 to hop d (`carriers`, with `carrierHops` and `carrierShares`, the far end's; the strongest of them, if found more than once: by `strength`, a tie or none going to the nearest hop, then the greatest share) and **spared** when it runs between two shapes of the reach or from one to the start and isn't (`spared`, each with both ends' hop and share, so a caller can fade it by the weaker, one a connection: the run whose weaker end is the strongest, if it has several; never one that is also travelled). A travelled connection whose far end, as its carrier emitted it, was a stand-in for the shape it leads to (`Edge.literalSource` and `literalTarget`, which the resolved view's forwarded edges keep: no second snapshot in the literal view is needed) adds that stand-in to `ids` at the hop and share of what it stands for (the strongest, if it stands for several, as a carrier is), unless the reach met it already: the pill the reach goes into is in the answer, a pill that only stands for a reached shape elsewhere is not, and a stand-in at the near end isn't either. A walk that starts at a stand-in (a pill hovered) takes its first step in the literal view as well as the one asked for, where the pill's own arrows are its own, so their far ends are hop 1 as a one-hop ask of both views finds them (the original it stands for is hop 1 too if the step names the edge to it), and goes on from there in the asked view; the capture takes the literal view for it whenever the request reads the resolved one (O(1)). A step that is one transitive relation of `:scope` alone (`:is-a(:scope)`, any `queryRelation(… transitive: true …)`) is evaluated once, from the start: all it finds is at hop 1 and none is expanded (expanding what is already found finds nothing new), the between of the start only; anything around it (`note:is-a(:scope)`) is walked. `ids` is nearest hop first and in no order within a hop; `hops`, `ways` and `shares` are aligned with it. No shortest-path counts, no fast path off the plan: every step is the plan evaluated. Debug builds count `QueryState.reachSteps`, the steps evaluated.
