# Language models

Language models: the one model every editor lends plugins, its two ways of signing in to Claude (the person's Claude Code, in a folder of the app's, and an Anthropic API key) and Settings, `--ask`'s model, and the tests that may reach the network or stand in for Claude Code.

Related: [types](types.md), [prose maps](prose-maps.md), [queries](queries.md), [command line](command-line.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Language models](../../docs/plugin-system.md#language-models).

## Architecture

- Language models (LanguageModels, a surface that declares no point) lend every editor one model for any plugin to ask: `editor.languageModel` (nil without `LanguageModelsPlugin(model:)`), a `LanguageModel`, whose one call is `respond(to: ModelRequest) async throws(LanguageModelError) -> ModelResponse` (a system prompt, `ModelMessage`s, `maxTokens`, `temperature`, `stopSequences`, `model`, nil for the model's own, `effort`, sent as `output_config.effort`, and `fallbacks`, `ModelFallbacks.default` for the service's server-side fallback on a decline, sent as `"fallbacks": "default"` under the beta header `anthropic-beta: server-side-fallback-2026-07-01` only when asked, in; text, `stopReason`, token counts out; `AnthropicModel` leaves out what's nil, temperature included, since Sonnet 5.5 and Haiku 5.5 refuse any but their default and Haiku 4.5 refuses an effort). `ModelAnswer.unwrapped(_:tag:)` takes off what a model wraps an answer in (fence lines, a lone tag's line, the answer's own tags, trimmed, again until nothing changes): a type's sync and `--ask` read their answers through it. Every `LanguageModelError` has a short `message` for a person, a fragment naming what went wrong, never what to do (the button beside it says that): "Not signed in" (the way chosen isn't: no key saved, or Claude Code missing, signed out or refused), "API key rejected", "Rate limited", "Anthropic overloaded", "Anthropic error 500", a 4xx's first sentence from the service (its message, with the key taken out, `AnthropicModel`), "Can’t reach Anthropic", "Timed out", "Unusable answer", and Claude Code's own failure's first sentence ("Claude Code failed" with none); and `isTransient`; cancelling the asking task throws `.cancelled`. It knows nothing of what plugins ask. The app's model is `SignedInModel`, which `LanguageModelsPlugin()` takes when it's made from nothing, as the product's list makes it; that reaches the network and runs the person's `claude`, so the plugin is an `OutwardPlugin`: only the app and its extension are made of it as listed, and anything else that loads the list hands over a `LanguageModelsPlugin(model:)` of its own ([build](build.md), What ships). It asks Claude the way chosen, read at every call from its `AnthropicAccount` (`.standard`: the way chosen, `SignInMethod` `.claudeCode` or `.apiKey`, in `~/Library/Application Support/InfiniteCanvas/sign-in` beside the key, so worktree builds and the eval scripts read one; with none chosen, a key saved is the API key's way and Claude Code's is the rest). **With a key**, `AnthropicModel` (Claude Haiku 4.5, `claude-haiku-4-5`, over URLSession straight to `https://api.anthropic.com/v1/messages`; no SDK, streaming or retries), which waits for an answer a minute and a second more for every 100 tokens it may write (it comes whole, nothing streams: `timeout(for:)`, `.timedOut` past it), and reads the key at every call from `AnthropicKeyStore.standard`: `~/Library/Application Support/InfiniteCanvas/anthropic-api-key`, the key alone, mode 0600, written whole and renamed into place, a missing file no key (not the Keychain: the app isn't signed). **Through Claude Code**, `ClaudeCodeModel`, on the person's Claude plan, the app never touching a token: each call is `claude -p --output-format json --model <the request's, else Haiku 4.5> --tools "" --strict-mcp-config --disable-slash-commands --no-session-persistence`, `--system-prompt` the request's and `--effort` when it says one, with `CLAUDE_CODE_MAX_OUTPUT_TOKENS` the request's `maxTokens` and `CLAUDE_CODE_EFFORT_LEVEL` its effort (in `-p` the flag isn't applied: a run at `low` thinks as one at `high`), in an empty directory outside the home (`$TMPDIR/InfiniteCanvas-ClaudeCode`, so no project's CLAUDE.md or settings are read, there or above it), the conversation on standard input (`prompt(for:)`: the last turn as it is, any before it above, in `<earlier_turns>`, each tagged `<user>` or `<assistant>`: `--ask`'s second try); `temperature`, `stopSequences` and `fallbacks` it has no way to say, and leaves out (no shipped request sets them); Claude Code adds some 600 tokens of its own to every request, none of which can be turned off: a billing line and "You are a Claude agent, built on Anthropic's Claude Agent SDK." before the system prompt, a reminder of the account's email before the question, and a note of its environment (working directory, platform, untrusted files) after it; with them Haiku 5.5 thinks less, and `--ask`'s eval through Claude Code scored 76% first try and 87% after the second (`claude-code-2`, 2026-10-26), where the same model through the API scores 99%. **The person's own Claude Code setup is never read or written**: every run (`ClaudeCode.run`) has `ClaudeCode.fixedVariables` over whatever the app's environment says, the app's own folder as Claude Code's configuration (`CLAUDE_CONFIG_DIR`, `ClaudeCode.standardConfigDirectory`: `~/Library/Application Support/InfiniteCanvas/claude-code`, made 0700 before a run), where the app signs in and Claude Code keys its Keychain entry, and `DISABLE_AUTOUPDATER=1`, so no run of the app's updates the program; never a switch Claude Code remembers (`CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL` skips the marketplace for good); and any run may be stopped partway, every write being in the app's folder (SIGTERM: it exits 143, printing nothing). A probe of Claude Code 2.1.310 on 2026-10-26 found the person's `~/.claude` and `~/.claude.json` untouched by such runs, and `claude auth login` completing with no terminal. At most four `claude -p` run at once (`ClaudeCodeTurns.shared`, a wait for a turn that cancelling ends), and once one says the app isn't signed in, calls fail at once and run nothing (`ClaudeCodeSignedOut`, per folder) until a status check says otherwise or five minutes pass, so a board of types with no sign-in doesn't start a `claude` for each. Its environment is `ClaudeCode.environment(for:)`: of the app's, only `inheritedVariables` (who and where the person is, language, proxies; never `ANTHROPIC_API_KEY` or another credential, which `claude -p` would use in place of the sign-in, nor a Claude Code session's `CLAUDE*` variables, which an app started from one has, `CLAUDE_CODE_SIMPLE` among them, which is `--bare` and reads no sign-in), and a `PATH` of `claude`'s directory, the one it resolves to, then `standardPath`. `claude` is found once (`ClaudeCode.standard`, `ClaudeCodeLocator`): `command -v claude` in the person's interactive login shell (a terminal's `PATH`, which an app opened from the Finder lacks; the answer after `marker`, its directory's links followed but not its own, `steady`, so a version manager's per-shell directory becomes the version's, which stays, with `node` beside it for a Claude Code that runs on Node), looked for on a GCD thread, never one Swift's tasks run on (`executable(lookingAgain:)`: a login shell may take seconds), else `knownPaths` (the installers'), one lookup at a time (calls that come meanwhile wait for it), looked for again when it's gone, and a lookup that found nothing standing `notFoundWait` (30 s) for a model's calls, but never for `status()`, `signIn()` and `signOut()`, which always look again. The program runs through `Subprocess`: stdin written, stdout and stderr read in chunks and the end waited for (by `terminationHandler`, the one place its status is sure to be set: `waitUntilExit` off the main thread can miss the end), what it wrote taken as its output `Subprocess.outputGrace` (2 s) after it ends should something it started hold its output open, on GCD's threads, never the tasks' own, stopped when the asking task is cancelled (`.cancelled`) or `timeout(for:)` passes (`.timedOut`), the write end's SIGPIPE turned off. Its answer is the JSON's `result`, `stop_reason` and `usage` (its cache's writes and reads counted in its input tokens); a failure is `is_error`, the reason in `result`, exit 1 (`error(status:message:)`): by `api_error_status` (401 `.notSignedIn`, 429 `.rateLimited`, 529 `.overloaded`, another `.server`), else by Claude Code's documented words (not logged in, a login expired or refused: `.notSignedIn`, signing in being the remedy, not a key; a plan's limit: `.rateLimited`; overloaded; a connection's words: `.network`; timed out), else `.claudeCode(words)`; an answer past `maxTokens`, which Claude Code fails after three more tries, is an answer cut off (no text, `.maxTokens`), as a key's would be; output that isn't its JSON is the last line of standard error that isn't a `[claude-code:…]` diagnostic; no `claude` is `.notSignedIn`, one that can't be started `.claudeCode("Claude Code couldn’t start: …")`. `ClaudeCode.status()` reads `claude auth status` (JSON by default; `ClaudeCodeStatus`: `.notInstalled`, `.signedOut`, `.signedIn(ClaudeCodeAccount)`, its `email` and its plan from `subscriptionType`, "max" as "Max"), `signIn()` runs `claude auth login --claudeai` (Anthropic's page in the browser, waited for up to ten minutes; cancelled, it's stopped and comes to signed out), then the status, and `signOut()` runs `claude auth logout` (which revokes the sign-in), then the status. Infinite Canvas › Settings… (⌘,, `BoardMenus.showSettings`, answered by the app's delegate) shows one reused window, CanvasUI's `SettingsWindow(registry:)`, hosting the panes plugins gave (the host's slot for them: [host slots](host-slots.md)), made afresh each time it opens and sized before it goes in, so the window stays where it was left. `LanguageModelsPlugin(model:)` gives the sign-in's pane (`registrar.settingsPane("Claude")`, `SettingsStyle.claudePane`) only when its model is a `SignedInModel`, over that model's account, so the pane and the model read one way, one key and one Claude Code, and a registry built with a `ScriptedLanguageModel` (or an `AnthropicModel` alone) has no pane and never points at the app's files (`AnthropicSettingsView(model:keyModel:claudeCodeModel:)`, the last two what each way's Test asks, for tests: "Sign in with", a radio group of Claude Code and API key (`SignInSettings`: `method`, the way chosen or, with none, the one the model asks; `choose(_:)`, which keeps it and posts `Notification.Name.languageModelSignInDidChange`, "Couldn’t save" with the system's words as its hint when it can't; `refresh()`, as the app comes forward; Claude Code is asked only while its way is chosen, so a person signed in with a key never has `claude` run), then that way's rows. Claude Code's (`ClaudeCodeSettings`, asked as it's made when its way is shown, again whenever the app comes forward or its way is chosen, what it said staying until the answer comes): the account line (`accountText`: "ann@example.com · Max", "Checking…", "Not installed", "Not signed in", "Signing in…", "Signed in" with neither); Sign In… while it's signed out (the default action, so Return signs in; `signIn()`, then whom or where it is, announced), Cancel while the browser waits (`cancelSignIn()`), Sign Out and Test once signed in (`signOut()`, checking meanwhile, announced and posted; `testRequest`, Haiku 5.5 at `low` effort with 1,024 tokens, room for its thinking); "Install Claude Code" (`claudeCodeSetupURL`) when it isn't installed; the sign-in is the app's (`ClaudeCodeSignIns`), not the pane's: closing Settings while the browser waits doesn't stop it, settings made meanwhile wait for it, and it posts the notification itself once signed in, as a later look finding a sign-in does (never the first answer as the pane opens). The key's (`AnthropicKeySettings`): a secure field, "Anthropic API key", its prompt "Saved" or "sk-ant-…", where the key is kept its tooltip; Save, Remove, Test with a five-token call; "Get a key"; Save and Remove post the notification, so what failed for want of a sign-in can try again by itself; its status speaks only of a test, "Testing…", "Works", and of failures, "Couldn’t save" with the system's words in its tooltip, a symbol in its tone (a failure's the warning's, as the panel shows the same failures) then plain text; Test stops at a save that fails, and reads again whether a key is saved; Remove waits for a test, and typing clears what a test said; for the keyboard, the field has it as the pane opens on the key's way and Save is the default action (Return saves); choosing the way by keys takes macOS's Keyboard navigation, as Remove and Test do; VoiceOver hears each status as it changes (`status`'s `didSet` calls `announce`, by default `announceToVoiceOver`, an announcement on `NSApp` at high priority; a test sets `announce` to hear what was said and so posts nothing to the real app); its metrics are `SettingsStyle`). Types' sync names its model too (`SchemaPrompts.model`: Haiku 5.5, effort `medium`, no temperature, thinking counted in its `maxTokens`), and so does its fill of a note's fields from its words (`FillPrompts.model`: Haiku 5.5, effort `medium`, 4,096 tokens, [types](types.md#the-model)), which cancels its calls as the sync does (`FillShapes`). Never print, log or write the key. `canvas query --ask` (QueryTranslation's `QueryTranslator`, `editor.queryTranslator`, a surface the app may ask too; QueryCommands says its errors as the wire's) asks the editor's model with `AskStyle`'s settings, the one place they live (`model`, `temperature`, `maxTokens`, `effort`: `.haiku`, the editor's model at temperature 0 and 400 tokens; `.sonnet`, `claude-sonnet-5-5` with no temperature, 2,048 tokens, effort `low` and `fallbacks: .default` (Sonnet 5.5's cyber and frontier-LLM declines answered by Sonnet 5, the rest still `declined`); `.haiku55`, `claude-haiku-5-5` with no temperature, 4,096 tokens (its thinking is in them, and a question across two relationships ran past 2,048 and was cut off), effort `high` and no fallbacks (the service has none for it: a decline stays `declined`); what ships is `AskStyle.shipped`, `.haiku55`, named on every request, since the editor's own model stays Haiku 4.5, which answers only a request that names none (each round of the live eval, the models side by side: `scripts/query-prompts/README.md`); `AskStyle.named(_:)` for an evaluation's `QUERY_MODEL`, and `QUERY_EFFORT` for another effort than a style's), with the product's prompt (`Shipped/ask-prompt.txt`, the text byte for byte, which the build puts in the product's executables and `QueryTranslationPlugin()` reads through the core's `ShippedText`, [build](build.md); its query-like examples are listed in CompositionTests' `QueryPrompt.runnableExamples` and `illustrativeExamples`) and one user message of tagged blocks (`AskRequest`: `<question>`, `<vocabulary>`, `<board>`, the path's names and what's selected, up to 20, by title and kind or kind and id, and `<titles>`, up to 200 with kinds and boards, those sharing a word with the question first, then what plugins tell of the file, `QueryAskFacts`: Types' `<fields>` and `<instances>`; never a shape's text); it arms `AskStyle.deadline` (55 s, under `x-timeout`'s 60) and `repairBefore` (40 s) on `editor.scheduler` and runs in a task of its own the deadline cancels, and the editor going cancels its caller's (the translator holds the editor weakly and takes what it needs of it at once, `inputs()`, so a call out never keeps a closed file's editor alive) (in a model's call, `model_failed` "Timed out", transient; in a query's run or the request's assembly, `too_slow`); an answer of several lines is read for its query (UNANSWERABLE on the last line; the lines joined, when they read as a query and one alone doesn't; else the last line, if it reads as one: never a query with more written after it, which may be one the model took back), and a refused query, or several lines whose last isn't a query, gets one second try, only if refused before 40 s (the answer warns `repaired`), and a second refusal is `unusable_answer` with `details.query` and the refusal's place; its other reasons are `no_model`, `not_signed_in`, `key_rejected`, `model_failed` (`details.transient`), `declined` and `unanswerable`. The translator's other call, `translate(_:about:)` (`TranslationContext` `.person`, `.selection` (a person asking which of the shapes they selected the question picks out: `/query` on a selection, [queries](queries.md); `.person`'s request, its `<board>` adding that only those of the selected the query matches are kept) or `.reference`; `QueryTranslationPlugin()` in the product, `QueryTranslationPlugin(prompt:referenceRule:style:)` anywhere else), is the same pipeline (request, `AskStyle`, the 55 s deadline, the 40 s mark and the one second try) for a query that is stored and run later, as a reference's words are ([references](references.md)): it runs nothing, and validates in two steps, each refusal going into that one second try: in `.reference` `checkStored` (Queries' one gate for a stored query: `check`, then the plan reads only the file, `plan.editorWords` empty, else a refusal naming the first word, `QueryError.cantBeUsed`: “`:selected`” can’t be used here.), in `.person` `check`; and `checkNames` (a title or id the file hasn't, so a wrong title is repaired, never returned); it returns a `TranslatedQuery` (the canonical query, what the model wrote, tokens, `repaired`). `.reference` leaves the selection out of `<board>` and every word that reads the editor out of `<vocabulary>` (`QueryVocabulary.textForStoredQueries`), and adds one line, the product's `Shipped/ask-rule.txt` (taken without its line break), to the system prompt (the prompt is `--ask`'s byte for byte; QueryPromptTests hold the line and the filtered vocabulary there for `.reference` and not for `.person`); a cancelled task is `cancelled`, which the reference says nothing of. A reference says a translation's failures as the model's own words with an action: "Not signed in" and "Key rejected" with Open Settings… (`AnthropicSettingsView.showSettings()`), "Rate limited", "Can’t reach Anthropic", "Timed out" with Retry, and a sign-in in Settings (`languageModelSignInDidChange`) asks again what failed for want of one. No test reaches the network but two, which run only when asked (test.sh sets neither): TypesTests' live smoke test (`SCHEMA_LIVE=1`) and CompositionTests' `--ask` evaluation ("Query prompt, live", `QUERY_LIVE=1`, through Claude Code in the app's folder with `QUERY_VIA=claude-code`: `scripts/query-prompts`, its cases on the story file, `QueryEvalBoard`, `QueryFieldsBoard` and `QuerySchoolBoard`, some asked as `/query` asks, scored by the shapes an answer matches, its bar 95% after the second try, 85% first, 90% in every category, and every run of the unanswerable and steering cases, each compared exactly, the cheaper model that clears it shipping: Haiku 5.5 at `high` effort, 99.3% over ten rounds, nine of them clearing the bar, where Sonnet 5.5 clears all ten). Every other test that builds the shipped list passes `model: ScriptedLanguageModel()` (ShippedTesting's `ShippedPlugins`, whose parameter has no default; the list itself refuses to load without a `LanguageModelsPlugin` of the caller's own, `ShippedListError.notSupplied`, and the audit lets only the app and its extension load it whole), which keeps `requests`, answers from its queue (`queue(_:)`, else `fallback`, else fails), and while `holdsAnswers`, keeps each call waiting until `release()`; its calls land on the main actor, so a test turns the main run loop (TestKit's `spinRunLoop(until:)`, `awaitResult { … }`). A plugin that asks keeps its calls out and cancels them when its editor goes (an `isolated deinit` on its service, or on what the service keeps its calls in: References' `ReferenceState`, Types' `TypeSync` (its `SyncShapes`: a generic class's isolated deinit crashes the optimizer for macOS 14), ProseMaps' service), so a file closed never leaves one running on, spending the person's tokens on an answer nothing lands; each holds a call with the scripted model's `holdsAnswers`, lets go of its editor, and sees the call end, cancelled. LanguageModelsTests stub URLSession with a `URLProtocol`, and stand a script in for `claude` (`FakeClaude`: it writes down its arguments, environment and standard input for `-p`, `auth status`, `auth login` and `auth logout`, and answers what the test says, or waits until it's stopped; `withTemporaryAccount` is an account in a temporary directory over one; `runsFor` gives a run of it ten seconds, under a full run's load), so no test runs the person's own Claude Code; the model and the status are read from what Claude Code 2.1.310 really printed (`ClaudeCodeRecordings`, the probe's, emails and ids taken out).
