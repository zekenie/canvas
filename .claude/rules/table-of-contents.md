# The table of contents

The table of contents: rows and marks, nesting, what's listed, hover, rows read from more than their shape, and another board's outline.

Related: [detail panel](detail-panel.md), [selection](selection.md), [validation](validation.md), [locking](locking.md), [titles](titles.md), [mentions](mentions.md), [boards](boards.md), [containers](containers.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [The table of contents](../../docs/plugin-system.md#the-table-of-contents), [Another board's outline](../../docs/plugin-system.md#another-boards-outline).

## Architecture

- The table of contents (TableOfContents, a surface) is a native `List` in the right-hand panel, with data-canvas's TOC contract: `x.contentsRow(when:nestedUnder:) { ContentsLabel(title, placeholder:, systemImage:, color:, badge:) }`, and `registrar.contentsRow(P.self)` for another plugin's kind. The list owns the row's chrome; a row reads only its own shape (unless it names what else it reads, below), and uses `ContentsLabel` so rows from different plugins look alike (its text its tooltip, `label.help`, up to 200 characters, cut between words with "…", none for a placeholder). `registrar.contentsMarkForEveryShape(where:) { shape, context in ContentsMark(symbol:color:help:) }` puts a mark at a row's trailing end from any plugin, a dot or, with `symbol`, an SF Symbol, on the kinds `where` picks (a `ContentsKind`, asked once per kind, as an adornment's `where`: `$0.holds(LockedProperty.self)`) (Validation's `ValidationContentsPlugin`: a red or orange dot for a shape with issues, its tooltip the issues; Locking: a lock on a locked shape's row). A mark is part of the row, made with it, so one read from more than its shape names, with `affected:`, the shapes each commit may change the marks of (Validation's `dependents(of:)`): their marks are read again, and their rows replaced only if the marks changed. A row's view reads only its `ShapeRow`, never the document: the list makes every row's view on each redraw. A kind without a row gets its label and symbol (`registry.label(of:)`: what the kind declares, `x.label(_:systemImage:)`, one per kind, as the arrow does, since no tool places one; else its placing tool's; else its id; the label a placeholder, dimmed until a shape is named, where another plugin names the kind's rows with `contentsTitle`), and `x.contentsRow(when:nestedUnder:)` with no builder keeps that row. `x.contentsTitle { … }` (`ContentsTitles`) names a kind's rows from another plugin without replacing them: a name that isn't blank takes the place of a `ContentsLabel`'s title, keeping its symbol and badge (Titles names rows this way). Rows are in document order; a row nests under the shape its kind names (`nestedUnder`), else under the container its shape is in (a frame: the core's `registry.container(of:in:)`, read from its record), only while that shape is listed, so rows nest as deep as containers do. Arrows nest under the shape they start from. Each row with rows under it has a disclosure triangle of its own (`ContentsTree`, a `DisclosureGroup` a row, bound to `ContentsState.isExpanded(_:)`, observed per row): a container's row starts expanded (`entry.startsExpanded`: what it holds is on the board shown), every other collapsed (a note's arrows, a subboard's board), and a row keeps what the person turns it to (`setExpanded(_:_:)`), by shape, whatever's listed: Show All, its rows replaced, another board shown and back. A shape that owns a board (a `BoardOwning` kind's, not kept aside: `entry.nestedBoard`, nothing to opt into) opens onto that board's rows (`outline(of:)`, no marks), before those nested under it, with no disclosure triangle while the board has no shapes; read only once it's expanded (`BoardRows`, behind `ListedRows`, a collection with a `@MainActor` conformance: SwiftUI's outline asks every row for its nested rows' collection on every update, but for what's in it only once expanded), so a collapsed subboard costs its row; selecting one goes there (`editor.goTo`, its board shown, one step back; several, the board of the one listed first; not when a selection adds rows of the board shown too, a ⇧-click's range), its primary action `goInto`, and the pointer on one hovers nothing; a crumb's menu's rows open the same way. `ContentsState` keeps each shape's row and where it's listed (`ContentsListing`, per scope), and redoes only those of the shapes each commit's `ChangeSet` names but those it only moved (`ChangeSet.moved`), whose rows stay, the same objects (a row, `when`, `nestedUnder` and a name say what a shape is, never where it is), and whose marks the next read reads again (the commit only notes which moved, one set's upkeep a drag event, whatever it carries): a read after a drag makes no row, a frame dragged with all it holds neither; joining or leaving a container changes the shape's record, so its row is made again and placed under its new container. Selecting on the canvas lists just the selection; selecting rows selects and zooms to their shapes (Selection's `editor.reveal`) without changing what's listed (`editor.selectionRevision` tells the two apart). It lists the board shown, and keeps each board's rows and listing for the boards shown last (a `BoardStash`, taken back while the board's revision is unchanged, so going back makes no row: `rowsMade`, debug builds, counts rows made); a switch drops a pinned scope. The header is "Board", or whatever the placer's `heading:` closure names (`TableOfContentsView(editor:onExit:heading:)`, a `ContentsHeading`: title, symbol, and an `up` command offered as a button while `canPerform`, an arrow turning up, since a chevron in a list reads as collapsing, called `upTitle` with `upHelp` its tooltip), so the list never learns what a board is. A double-click or Return on one row opens its shape as Return on the canvas does, through Selection's `editor.open` (`ContentsState.open(_:)`, `.contextMenu(forSelectionType:primaryAction:)`); in the app's panel, picking one row shows its shape's panel in the list's place and gives the canvas the keyboard, so Return opens it there and a double-click doesn't reach the list. A change of what's listed replaces the rows, and so does a commit that brings rows in at more than one place (`ContentsListing.isScattered`, counted in `ContentsState.replacements`; the list's `.id(ContentsListID(board:scope:replacements:))`, so another board's rows too), bringing the new ones in as one run: rows coming in at several places at once make AppKit, whose table sizes a `List`'s rows, log "a reentrant operation in its NSTableView delegate" (a future assert), in a list of any length (replaced rows keep their disclosure, a container's open), as it still does when a list first shows 200 rows or more. A row that goes (replaced, say) lets go only of a hover the pointer on it set (`hover(_:)`), never one the canvas set; a switch of board lets go of it. Hover is shared: the pointer on a row sets Selection's `editor.hovered`, which the canvas outlines faintly, and a shape hovered on the canvas tints its row (`isHovered`), in the selection highlight's place; a selected shape shows neither. A row's tint observes only its own shape's hover (`editor.isHovered`) and, while that shape is hovered, the selection, so a hover redraws the row it leaves and the row it reaches: rows that read `editor.hovered` would all be redrawn on every hover change. It's the detail panel's overview: `DetailPanelView(editor:onExit:overview:)` shows the overview with nothing selected, and under the header of several; Composition's `detailPanel(editor:onExit:rootName:)` passes `TableOfContentsView`, so neither horizontal knows the other. Another board's rows (`docs/plugin-system.md`, "Another board's outline") are `ContentsState.outline(of: board)`: those `entries` would list there with nothing selected, less their marks (the board shown's), whichever board is shown, made on the first read and kept while the board's revision is unchanged and it's on the path to the board shown, the rows of kinds with `affected` made again on a read after a commit that did more than move shapes (their answers are the board shown's; `ChangeSet.onlyMoves`, internal, names nothing anew) and kept unless their labels changed; `ContentsOutline(editor:board:highlighted:maxHeight:onPick:)` shows them in a small panel (the path's crumb menus): 24-point rows as their kinds draw them, lazily, nested ones behind a disclosure triangle, a container's open from the start (the panel's own, each time it shows), `highlighted` tinted as a hovered row is, a click `onPick`, opening at the top (scrolling a lazy stack to a far row lays out the rows before it).

## Rows read from more than their shape

- A table-of-contents row read from more than its shape (an untitled note's text with the live names of the shapes it mentions): `x.contentsRow(when:nestedUnder:affected:) { shape, context in ContentsLabel(…) }` (`registrar.contentsRow(P.self, affected:)` for another plugin's kind), whose builder gets the shape and a `ContentsContext` (services) and returns a `ContentsLabel`, and whose `affected: { changes, context in … }` names the shapes each commit may change the rows of without changing them. `ContentsState` makes those rows again on the next read and replaces a row (so the list redraws it) only if its label changed (title, placeholder, symbol, color and badge), as marks' `affected` does; a read before it hears a commit makes every kept row of such a kind again. `affected` runs on every commit, listed or not, so it must cost O(changed): a service keeps who reads what, per shape (AffectedRowTests' `RefIndex`). A row may read a shape on any board (`editor.file.record`): `affected` looks at `changes.elsewhere` too (what a commit did beyond its board: a subboard's deletion, `transact(on:)`), and going back to a board as it was left hands it what changed on the others meanwhile, as `elsewhere`, so those rows are made again and the rest taken back (AffectedBoardsTests). `when`, `nestedUnder` and `contentsTitle` work as for any row.

## Testing

- For the table of contents, read `editor.tableOfContents?.entries` headlessly (each row's text, symbol and badge through `entry.label`, its marks through `entry.marks`, the board under it through `entry.nestedBoard` and `outline(of:)`, whether it starts expanded through `entry.startsExpanded`), and drive `select(_:)`, `showAll()`, `hover(_:)`, `endHover(_:)` and `setExpanded(_:_:)` (read back with `isExpanded(_:)`); shapes nest in CanvasTesting's corrals (`editor.put(_:in:)`; ContainerTests, with a seeded run of joins, leaves, drags, deletions, undo and redo held to listing afresh). `rowsRedrawn` (debug builds) counts how often the list has asked a row for its view, so a test holds a change to redrawing the rows it changes (HoverTests), and `rowsMade` how many rows it has made (BoardTests: going back to a board makes none). Headless, `open(_:)` is a row's primary action; in a window, `pressReturn()` with the list focused runs it (a synthesized double-click doesn't reach the list). SwiftUI's hover doesn't answer synthesized events, so check a row's tint by rendering the list with `snapshot(view)` (CanvasTesting; highlights draw, a source list's vibrant text may not). In a window, its list is an `NSOutlineView` whose first row is the header, a group row (TableOfContentsTests; `ContentsWindow.isExpandable(_:)`, `isExpanded(_:)`, `expand(_:)` and `collapse(_:)` read and turn a row's disclosure triangle, and `selectRowIndexes` reaches the list's selection as a click does, NestedBoardTests). AppKit's warnings go only to standard error: `standardError(during:)` (CanvasTesting) returns what was logged, so a test can check a list's update logged no `tableReentrancyWarning`. A shape's panel can hold lists too, so CompositionTests tell them apart with `isTableOfContents` (`Tests/CompositionTests/ContentsPanelTests.swift`), and InspectorTests' `tables` leave it out.
