# Context menus

Context menus: a shape's items and groups, the canvas's items, and what a right-click or a Control-click does.

Related: [selection](selection.md), [clipboard](clipboard.md), [locking](locking.md), [mentions](mentions.md), [boards](boards.md), [transform](transform.md), [slash commands](slash-commands.md), [colors](colors.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Context menus](../../docs/plugin-system.md#context-menus).

## Architecture

- Context menus (ContextMenus, platform, a horizontal in the window) follow the same pattern: `x.contextMenu { MenuItem("…", in: SomeGroup.self, when: { … }) { $0.field = … } }`, `registrar.contextMenu(P.self)` for another plugin's kind, `x.contextMenu(of: P.self) { … }` over an added property's value (on `PluginRegistrar`, every shape that has it), `contextMenuForEveryShape(where:)` (`where` picks kinds by their definition, so by capability; Reordering's Arrange submenu leaves out `PaintOrderAnchored` kinds). A group is a type (`MenuGroup`) in the tabs' order bands, with separators between groups; a horizontal's opt-in sugar calls `contextMenu` too, so opting in brings its items (Boards' Open). `when` leaves an item out (prefer it to `isEnabled`, which dims); nothing left, and the right-click does nothing. Items that aren't one shape's (Cut, Copy, Paste; Show What Mentions, since whether a shape is mentioned is what Mentions' state knows, not the shape; Turn into …, which a transform's target brings, since what a shape can turn into is what the registry knows: Transform's `TransformMenuGroup`, order 60, between Mentions' 50 and the clipboard's 100, [transform](transform.md); Create Frame, which Frames brings for any shapes a frame can hold, in `FramesMenuGroup`, order 70, [frames](frames.md)) are the canvas's: `registrar.contextMenuForCanvas { MenuItem("…", when: { $0.editor… }) { ids, editor in … } }`, over the menu's `MenuSubject` (its shapes, `point`, where it was asked for, in world units, which the `edit` form, handed the subject, reads, and the editor), asked once per menu, in every menu after the shapes' own, and alone on empty canvas; `when` asks the subject, never `canPerform`, since the menu's shapes become the selection only once it's made. ContextMenus has two of its own, `StateMenuGroup` (order 300, ContextMenus' own, so horizontals share it without importing each other): Grouping's Group and Ungroup ([grouping](grouping.md)), Locking's Lock and Unlock, Types' Is a ▸ and Colors' Color ▸ (a selection whose shapes all have colors: [colors](colors.md)), in one group, no line between. Selection's commands, in `SelectionMenuGroup` (order 400, last, after Lock): Delete in every shape's menu, running `.delete` on them (a locked one shakes, as with the key), and Select All on empty canvas while the board has shapes, running `.selectAll`; so with Selection installed only an empty board with nothing to paste has no menu. The menu is for the selection: a right-click on an unselected shape selects it, or the group it's in, whole, as a click would (`editor.selectionUnit(of:)`, Selection's: [selection](selection.md)) (only if it has a menu), and with several shapes an item shows when every one shows it (same group and id). An item for the canvas may be made when the menu opens, from the file rather than the registry: `MenuItems(in: Group.self, id: "…") { subject in … }` (inside `contextMenuForCanvas`), whose closure is a `MenuBuilder` over the subject, asked once per menu, before anything resolves, and whose entries take its place (itself claimed by group and id at registration: a second claim is a `conflict`). An id met twice at a level shows once, the first staying (a made entry also loses to an earlier registered one, and a kind's own item with its group and id takes its place, as for any item for the canvas); a result with nothing shown leaves no separator and, on an empty canvas with nothing else, no menu. `MenuItem`'s `perform` form takes `stepName:` for an item whose title only makes sense in its submenu (the undo group is named by it). The core only lends `registrar.menuForSecondaryClick`, which ContextMenus claims (and `registrar.menuForSelection`, below); `CanvasView.menu(for:)` asks it. A Control-click with no menu reaches the tool as a press with `pointer.isControlClick`: the select tool ignores it, and every other tool takes it as a press with ⌃ held (the hand tool pans), so ContextMenus answers Control-clicks only in the select tool.
- An item can run a command, so it can have a key: `MenuItem(command: .x, in: Group.self, when: { … })` (an optional `title:`, else the command's, `registry.title(of:)`; its `id` is the title, else the command's name; `isEnabled:` and `isChecked:` as any item's) runs `editor.perform(command)` on the selection, which the menu's shapes are by the time it runs (a right-click makes them the selection before the menu opens, [selection](selection.md); `perform` asks the command's own `isEnabled:`, which reads the selection, so `when` and `isEnabled:` still go by the subject, since the items are made before the selection is). The menu item shows the command's first key (Keyboard's `registry.shortcut(forCommand:)`) as its key equivalent, for display (`KeyChord.menuKey`, `menuModifiers`: Delete is Backspace's character, `\u{8}`, to a menu; a popup's key equivalents act only while it's open, and the keys themselves are the canvas's and the menu bar's), and an item that names a command shows only while a plugin claims it (`registry.claims`), so an unclaimed one is left out, in a submenu too. ContextMenus imports Keyboard for that. The shipped ones: Delete and Select All (ContextMenus'), Cut, Copy and Duplicate (Clipboard's), Group and Ungroup (Grouping's), Lock and Unlock (Locking's, two items with titles of their own that run the one `.toggleLock`, ⇧L), Create Frame (Frames', `.createFrame`, ⇧⌘F) and Arrange ▸ Bring to Front, Bring Forward, Send Backward and Send to Back (Reordering's). An item whose action isn't just the command's can stand for it: `MenuItem("Paste", command: .paste, …) { subject in … }` (the `edit` and `perform` forms take `command:`) keeps its action, shows the key and is left out of the selection's menu, as the command is: Clipboard's Paste lands centered on the click (`subject.point`, nil in the selection's menu, where it would paste as ⌘V does, though the menu bar has it).
- The selection's menu: `registrar.menuForSelection { editor, commands in … }` (the core's point beside `menuForSecondaryClick`, at most one plugin, ContextMenus; `editor.menuForSelection(omitting:)`, host API) is the menu of the selected shapes with no click, for a menu bar's Shape menu (CanvasUI's `ShapeMenu`, between Edit and Arrange: [keyboard](keyboard.md)). `ContextMenuState.menuForSelection(omitting:)` makes the same entries a right-click on the selection would (`entries(for:at:)`, `MenuSubject.point` nil: an item that goes by where the click was leaves itself out, as Types' `Relate to <Type>` does), less every item whose command is in `omitting` (the ones a menu bar item runs: `BoardWindowController.menuCommands`' values; a submenu left with nothing goes, and a group left with nothing leaves no line), and each item that runs a command is dimmed as the command is (`editor.canPerform`: the selection is the menu's, so unlike a right-click's it can be asked); choosing one ends editing first (`editor.endEditing()`), as a right-click does when it opens. Nil with nothing selected (not even the canvas's items, Select All and Paste, which the menu bar has) and when nothing is left.
- Types adds `Relate to <Type>` to the canvas's menu on a pill in a type's words that names a type it is not yet related to (`MenuItems(in: ShapeMenuGroup, id: "relate")` over `subject.point`, one selected shape, none at a skeleton's zoom): the item the click on the pill opens, its step "New Relationship Type" ([relationships](relationships.md#relating-from-the-words-the-offer)).
- Types adds `Needed` and `Only one` to the canvas's menu in the state group, beside Lock and Is a ▸, while every selected shape is an arrow that is an end of a relationship type (`MenuItems(in: StateMenuGroup, id: "end-rule")`, `relationships.end(_:)`): each checked when every selected end has the rule, a pick gives it to the ends that don't or takes it from all, in the one step `Make Needed`, `Make Optional`, `Allow Only One` or `Allow Several` (`editor.setEndRule`; a locked end is refused and shakes while the rest change). An arrow's line can be hit only by a real arrow: a test fixture arrow with no box is reached through a selection of two ([types](types.md), [relationships](relationships.md#setting-the-rule)).
- A menu a canvas button opens, rather than a right-click (a chip's, a list at an arrow), is the core's `editor.popUpMenu(_:below:highlighting:)` ([editor](editor.md)): `highlighting` names the one item the menu opens on, so Return picks it; the host pops it up as `menu.popUp(positioning: item, at:in:)`, and that AppKit highlights a positioned item is unchecked until the app is seen (the call reaching the host with the item is what CanvasUITests' `MenuPopUpTests` hold). A right-click's menu (`CanvasView.menu(for:)`) is not this.

## Testing

- ContextMenusTests' `commandItemsTests` hold the items that run a command (titled by it or by their own title, the key they show, run on the selection a right-click made, Delete and Select All among them, `when` and the command's own rule, an unclaimed command's item left out, an item with its own action standing for a command) and `selectionMenuForBarTests` the selection's menu (the same items as a right-click's and in its order, no point, nothing for nothing selected, items left out by command with their lines and submenus, dimmed by `canPerform`, editing ended on a pick, the report); CompositionTests' `shapeMenuShippedTests` the Shape menu over the shipped list ([keyboard](keyboard.md)).
- ContextMenusTests' `DynamicItemsTests` hold `MenuItems` (asked once per menu with the subject, in place after the shapes' own, made again each time, an empty result showing nothing, duplicates, `when` and `isEnabled`, a kind's own item taking its place, the undo group and `stepName:` naming it, the registration key's conflict and `ownerNotInstalled`, the report).
- For context menus, `h.secondaryClick(at:)` returns the `NSMenu` (or nil); read it with `menu.outline` and run an item with `menu.choose("Status", "Done")`. Nothing goes on screen.
