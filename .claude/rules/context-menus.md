# Context menus

Context menus: a shape's items and groups, the canvas's items, and what a right-click or a Control-click does.

Related: [selection](selection.md), [clipboard](clipboard.md), [locking](locking.md), [mentions](mentions.md), [boards](boards.md), [transform](transform.md), [slash commands](slash-commands.md), [colors](colors.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Context menus](../../docs/plugin-system.md#context-menus).

## Architecture

- Context menus (ContextMenus, platform, a horizontal in the window) follow the same pattern: `x.contextMenu { MenuItem("…", in: SomeGroup.self, when: { … }) { $0.field = … } }`, `registrar.contextMenu(P.self)` for another plugin's kind, `x.contextMenu(of: P.self) { … }` over an added property's value (on `PluginRegistrar`, the shapes of every kind that holds it: its scope, `.holding`), and a scope's, over the record: `registrar.forShapes(adopting: .restackable) { $0.contextMenu { … } }` (or `forShapes(holding:)`, `forEveryShape`: [plugins and kinds](plugins-and-kinds.md)), which the registry resolves to the kinds it reaches; `ShapeContextMenus` refuses an item for every kind with no scope (its `scope`, `.scoped`), a kind's own item takes the place of a scope's with its group and id, and two scopes that reach one kind can't both claim one (Reordering's Arrange submenu is on the kinds painted in document order, its capability `.restackable`, which leaves out `PaintOrderAnchored` kinds: `ShapeContextMenus → every shape painted in document order`). A group is a type (`MenuGroup`) whose `order` says where it goes among a menu's groups, as a tab's does (an `Order`, [plugins and kinds](plugins-and-kinds.md): by default where it first appears; `ShapeMenuGroup`, a kind's own items and an item's group when it names none, `.first`; a feature's `.after(ShapeMenuGroup.self)`; a submenu's groups in the order it lists them; the report names the groups a contribution's items are in with their orders, `CanvasContextMenu in StateMenuGroup before SelectionMenuGroup → every shape holding locked`, and the registry refuses groups placed beside each other in a circle), with separators between groups; a horizontal's opt-in sugar calls `contextMenu` too, so opting in brings its items (Boards' Open). `when` leaves an item out (prefer it to `isEnabled`, which dims); nothing left, and the right-click does nothing. Items that aren't one shape's (Cut, Copy, Paste; Show What Mentions, since whether a shape is mentioned is what Mentions' state knows, not the shape; Turn into …, which a transform's target brings, since what a shape can turn into is what the registry knows: Transform's `TransformMenuGroup`, `.after(ActionsMenuGroup.self)`, after Mentions' and before the clipboard's, [transform](transform.md); Create Frame, which Frames brings for any shapes a frame can hold, in `FramesMenuGroup`, `.after(TransformMenuGroup.self)`, [frames](frames.md)) are the canvas's: `registrar.contextMenuForCanvas { MenuItem("…", when: { $0.editor… }) { ids, editor in … } }`, over the menu's `MenuSubject` (the core's `CommandSubject`, what a command acts on: its shapes, `point`, where it was asked for, in world units, which a command and the `edit` form, handed the subject, read, and the editor), asked once per menu, in every menu after the shapes' own, and alone on empty canvas; `when` asks the subject, never `canPerform`, since the menu's shapes become the selection only once it's made. A scope's items for the canvas (`registrar.forShapes(holding: P.self) { $0.contextMenuForCanvas { … } }`) are only in a menu whose every shape is of a kind the scope reaches (`registry.reaches(_:_:)`, the core's), so never on empty canvas, and keep their place in plugin order among the rest: a feature's items for a selection, which run its commands or are made as the menu opens (Locking's Lock and Unlock, Types' Is a ▸ and Colors' Color ▸; the report's `CanvasContextMenu → every shape holding locked`); a scope's item claims its group and id on each kind it reaches, so one that every menu has too is a `conflict`. Publishing's Make Public and Make Private are every menu's, not a scope's: on a mix, some of kinds that can't be made public or private, their commands pick out the shapes that can ([publishing](publishing.md)). Groups that can't name each other are placed against groups ContextMenus gives: `ActionsMenuGroup` (`.after(ShapeMenuGroup.self)`), which no item is in (the registry refuses one, `invalid`), so, having no turn of its own, it comes after every group that is right after a kind's own (what a feature says of the shapes, Mentions' Show What Mentions), and what acts on the shapes is placed after it (Transform's Turn into …, then Frames' Create Frame), which Mentions and Transform, not knowing each other, couldn't say themselves. ContextMenus has two of its own that items are in, `StateMenuGroup` (`.before(SelectionMenuGroup.self)`, ContextMenus' own, so horizontals share it without importing each other): Grouping's Group and Ungroup ([grouping](grouping.md)), Locking's Lock and Unlock, Types' Is a ▸ and Colors' Color ▸ (a selection whose shapes all have colors: [colors](colors.md)), in one group, no line between. Selection's commands, in `SelectionMenuGroup` (`.last`, after Lock): Delete in every shape's menu, running `.delete` on them (a locked one shakes, as with the key), and Select All on empty canvas while the board has shapes, running `.selectAll`; so with Selection installed only an empty board with nothing to paste has no menu. The menu is for the selection: a right-click on a selected shape, or on empty space inside the selection's bounds (Selection's `isInSelectionBounds`: a selected frame's empty inside too), is the selection's menu; a right-click on an unselected shape selects it, or the group it's in, whole, as a click would (`editor.selectionUnit(of:)`, Selection's: [selection](selection.md)) (only if it has a menu), and with several shapes an item shows when every one shows it (same group and id). An item for the canvas may be made when the menu opens, from the file rather than the registry: `MenuItems(in: Group.self, id: "…") { subject in … }` (inside `contextMenuForCanvas`), whose closure is a `MenuBuilder` over the subject, asked once per menu, before anything resolves, and whose entries take its place (itself claimed by group and id at registration: a second claim is a `conflict`). An id met twice at a level shows once, the first staying (a made entry also loses to an earlier registered one, and a kind's own item with its group and id takes its place, as for any item for the canvas); a result with nothing shown leaves no separator and, on an empty canvas with nothing else, no menu. `MenuItem`'s `perform` form takes `stepName:` for an item whose title only makes sense in its submenu (the undo group is named by it). The core only lends `registrar.menuForSecondaryClick`, which ContextMenus claims (and `registrar.menuForSelection`, below); `CanvasView.menu(for:)` asks it. A Control-click with no menu reaches the tool as a press with `pointer.isControlClick`: the select tool ignores it, and every other tool takes it as a press with ⌃ held (the hand tool pans), so ContextMenus answers Control-clicks only in the select tool.
- An item can run a command a plugin declared (`registrar.command`, [editor](editor.md)), so it has the command's one rule and its key: `MenuItem(command: .group, in: StateMenuGroup.self)` shows while the command can act on the menu's shapes and click (its rule, asked of the subject, `editor.canPerform(_:on:at:)`; never the command's moment, since the menu ends editing as it opens and is never asked mid-press), `when:` leaving it out besides (Select All, on empty canvas only), and with `dims: true` it shows wherever `when` says, dimmed while the command can't act (Go to Original, Make Public and Make Private); chosen, it runs the command on the menu's shapes and click (`editor.perform(_:on:at:)`), in one step named by the item, whatever the selection is by then. It is titled as the command is (`registry.title(of:)`) unless `title:` says otherwise, its `id` is the title, else the command's name, and it shows the key a menu shows for the command (`registry.menuKey(of:)`, the host's slot Keyboard fills: Delete is Backspace's character, `\u{8}`, to a menu; a popup's key equivalents act only while it's open, and the keys themselves are the canvas's and the menu bar's), so ContextMenus imports no Keyboard; an item that names a command shows only while a plugin claims it (`registry.claims`), so an unclaimed one is left out, in a submenu too. A command that goes by where the menu was asked for reads the subject's `point` (Clipboard's Paste lands centered on the click, and as ⌘V does with none, as in the selection's menu, which leaves it out since the menu bar has Paste). The shipped ones: Delete and Select All (ContextMenus'), Open (Boards', on a board-owning kind's shapes: Selection's `.openSelection` titled Open, ⌘↓), Cut, Copy, Duplicate and Paste (Clipboard's), Group and Ungroup (Grouping's), Lock and Unlock (Locking's two commands, ⇧L running whichever can), Make Public and Make Private (Publishing's), Go to Original (References'), Create Frame (Frames', `.createFrame`, ⇧⌘F), Connect and Connect To… (`ConnectMenuPlugin`'s, Connections' `.connect`: Connect on two shapes, Connect To…, the picker's, on one while the picker is installed and the shape can be connected to something) and Arrange ▸ Bring to Front, Bring Forward, Send Backward and Send to Back (Reordering's, whose slash commands on the same kinds, `/bring-to-front`, `/send-to-back`, `/bring-in-front-of` and `/send-behind`, are [slash commands](slash-commands.md)').
- A kit switches both points (`ShapeContextMenus` and `CanvasContextMenu` are `KitSwitched`, [kits](kits.md)): `ContextMenuState` reads them through the editor (a kind's items kept by the kits they were gathered for), so while a plugin's kit is off in the file its items are in no menu, the Shape menu's included, and an item that runs a command shows only while a plugin claims the command in the file (`editor.claims`), `dims: true` or not.
- The selection's menu: `registrar.menuForSelection { editor, commands, popped in … }` (the core's point beside `menuForSecondaryClick`, at most one plugin, ContextMenus; `editor.menuForSelection(omitting:)`, host API; `popped` is true for `editor.menuForPoppedSelection()`, the menu a key, the Menu key and VoiceOver's Show Menu pop under the selection, which leaves out Show Context Menu, as it would only open itself again) is the menu of the selected shapes with no click, for a menu bar's Shape menu (CanvasUI's `ShapeMenu`, between Edit and Arrange: [keyboard](keyboard.md)). `ContextMenuState.menuForSelection(omitting:)` makes the same entries a right-click on the selection would (`entries(for:at:)`, `MenuSubject.point` nil: an item that goes by where the click was leaves itself out, as Types' `Relate to <Type>` does), less every item whose command is in `omitting` (the ones a menu bar item runs, which the menu bar's Shape menu finds as the bar is made; left out before their rules are asked; a submenu left with nothing goes, and a group left with nothing leaves no line), and each item that runs a command is dimmed while the command can't run there (its rule, asked as the item is made, and its moment, `CommandMoment.allows`: the selection is the menu's, and a shape being edited dims what runs `.whenIdle`); choosing one ends editing first (`editor.endEditing()`), as a right-click does when it opens. Nil with nothing selected (not even the canvas's items, Select All and Paste, which the menu bar has) and when nothing is left. Show Context Menu (`.showContextMenu`, Shape menu only: its item is `when: { $0.point == nil }`, ⌃↩ and the Menu key, `.whenIdle`, off with nothing selected) pops that menu, less itself, under `editor.selectionBounds` through `popUpMenu(_:below:highlighting:)` with the first enabled item highlighted (`CanvasEditor.showContextMenuForSelection()`); the menu has no click, so items that go by where the click was leave themselves out. `CanvasView.menu(for:)` answers an event that is no mouse event (VoiceOver's Show Menu) with the selection's menu (`menuForSelection(omitting: [])`, nil with nothing selected).
- Types adds `Relate to <Type>` to the canvas's menu on a pill in a type's words that names a type it is not yet related to (`MenuItems(in: ShapeMenuGroup, id: "relate")` over `subject.point`, one selected shape, none at a skeleton's zoom): the item the click on the pill opens, its step "New Relationship Type" ([relationships](relationships.md#relating-from-the-words-the-offer)).
- Types adds `Needed` and `Only one` to the canvas's menu in the state group, beside Lock and Is a ▸, while every selected shape is an arrow that is an end of a relationship type (`MenuItems(in: StateMenuGroup, id: "end-rule")`, `relationships.end(_:)`): each checked when every selected end has the rule, a pick gives it to the ends that don't or takes it from all, in the one step `Make Needed`, `Make Optional`, `Allow Only One` or `Allow Several` (`editor.setEndRule`; a locked end is refused and shakes while the rest change). An arrow's line can be hit only by a real arrow: a test fixture arrow with no box is reached through a selection of two ([types](types.md), [relationships](relationships.md#setting-the-rule)).
- A menu a canvas button opens, rather than a right-click (a chip's, a list at an arrow), is the core's `editor.popUpMenu(_:below:highlighting:)` ([editor](editor.md)): `highlighting` names the one item the menu opens on, so Return picks it; the host pops it up as `menu.popUp(positioning: item, at:in:)`, and that AppKit highlights a positioned item is unchecked until the app is seen (the call reaching the host with the item is what CanvasUITests' `MenuPopUpTests` hold). A right-click's menu (`CanvasView.menu(for:)`) is not this.

## Testing

- ContextMenusTests' `commandItemsTests` hold the items that run a command (titled by it or by their own title, the key they show, shown by the command's rule over the menu's shapes, `when` besides, `dims`, run on the menu's shapes whatever the selection is by then, Delete and Select All among them, an unclaimed command's item left out, a command given the click's point and, in the selection's menu, none) and `selectionMenuForBarTests` the selection's menu (the same items as a right-click's and in its order, no point, nothing for nothing selected, items left out by command with their lines and submenus, shown by the rule alike and dimmed by `canPerform` while a shape is edited, editing ended on a pick, the report); `showMenuTests` Show Context Menu (both keys, the rect, off with nothing selected, only in the Shape menu, the keys free); CompositionTests' `shapeMenuShippedTests` the Shape menu over the shipped list ([keyboard](keyboard.md)).
- ContextMenusTests' `DynamicItemsTests` hold `MenuItems` (asked once per menu with the subject, in place after the shapes' own, made again each time, an empty result showing nothing, duplicates, `when` and `isEnabled`, a kind's own item taking its place, the undo group and `stepName:` naming it, the registration key's conflict and `ownerNotInstalled`, the report).
- ContextMenusTests' `contributionTests` hold a scope's items (by a capability, the property's items as `.holding`, a kind's own over a scope's, conflicts in one scope and in two that reach one kind) and a scope's items for the canvas (only in a menu whose every shape it reaches, in plugin order among every menu's, never on empty canvas, its group and id claimed on each kind it reaches, the report's line).
- For context menus, `h.secondaryClick(at:)` returns the `NSMenu` (or nil); read it with `menu.outline` and run an item with `menu.choose("Status", "Done")`. Nothing goes on screen.
