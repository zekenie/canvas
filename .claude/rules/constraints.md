# Constraints

Constraints: what a place accepts. A container (a frame, a subboard for the board it owns) and the root board hold constraints, each a few words and the stored query they became, and every shape within a constraint's reach must match it: where a list is kept (an added property kinds opt into, the root's file value, one codec), the lists a container has from elsewhere (`InheritedConstraints`) and the shapes that keep a list their own way (`ConstraintHolders`), the one writer (which binds a query's titles to the shapes they name), the index (one standing query a distinct query, judged by the shapes a constraint named so a rename changes nothing, the breakers of each place, what each commit costs), refusing what's moved in (the core's admission), making what's placed fit (the core's placement fit), and the rule (an error, Move Out, Show Constraint, the walk's scope). On this are the faces: the funnel chip, the board's funnel (the pill over the canvas and its popover), the Rules tab's sections, `/constrain`, `/unconstrain` and the menus. Types gives a type's lists to the containers of it (`TypeConstraintsPlugin`, [types](types.md)).

Related: [host slots](host-slots.md), [detail panel](detail-panel.md), [boards](boards.md), [types](types.md), [containers](containers.md), [queries](queries.md), [validation](validation.md), [topology](topology.md), [editor](editor.md), [properties and schemas](properties-and-schemas.md), [colors](colors.md), [language rules](language-rules.md), [placing](placing.md), [boards on disk](boards-on-disk.md), [plugins and kinds](plugins-and-kinds.md) ([every topic](../../CLAUDE.md#map)).

## Architecture

- Constraints (platform, a horizontal and a shape trait: on Canvas, DetailPanel, Draw, Palette, Queries, QueryLanguage, Selection, Titles, Topology and Validation; plugin id `constraints`) knows no kind and imports no Types. `ConstraintsPlugin` declares the property and the file value, makes the index (`ConstraintIndex`, `editor.constraintIndex`) and the writer (`ConstraintWriter`, `editor.constraintWriter`), and answers the core's `admission` and `placementFit`; `ConstraintValidationPlugin` (id `constraint-validation`), a plugin value of its own after it and Validation, is the rule and the walk's scope, so a list without Validation leaves them out. It needs Queries (the standing queries, `fit`) and Topology (the one containment tree); without either it judges and fits nothing. All four plugin values ship (`ConstraintsPlugin`, `ConstraintValidationPlugin`, `ConstraintFacesPlugin`, `TypeConstraintsPlugin`, one after another in `Package.swift`, before `/query`'s: after the queries, the translator, Topology, Validation, the panel, the menus, the bar, the adornments, Types (whose chips the funnel follows) and LanguageRules (whose Rules-tab section a type's constraints follow); so `/constrain` comes before `/query` in the bar), and the kinds that opt in with `constrainable()` are Frames' frame and Subboards' subboard ([frames](frames.md), [subboards](subboards.md)). Words and steps are `ConstraintsStyle`'s, the reach's two names among them (`directlyInside`, `anywhereInside`, nonisolated: `ConstraintReach.schemaTitle` reads them, and the panel's pop-up will), and the refusal every query gets in a list with no Queries (`noQueries`, `unsupported`).
- **The faces** (`ConstraintFacesPlugin`, id `constraint-faces`, a plugin value of its own after Constraints, Validation, the detail panel, the adornments, the context menus, the slash commands and the query translation, so a list without them leaves it out; listed after the plugin that gives a container its types, whose chips come first) are below: the funnel chip, the panel, the commands, the menus. Constraints now depends on Adornments, ContextMenus, SlashCommands and QueryTranslation as well, and still on no Types. Words are `ConstraintsStyle`'s (the chip's, the panel's, the commands', the menus').
- **A constraint** (`Constraint`, `SchemaDefined`, definition `constraints.constraint`): `says` (the words, folded to one line), `query` (the stored query, trimmed; nil, never empty, for words not interpreted: it checks nothing and refuses nothing), `reach` (`ConstraintReach`: `children`, the default, a missing member's, or `descendants`) and `names` (`[String: ShapeID]`, the shapes the titles in the query named when it was written, by the head as the query writes it: below). JSON `{"says": "only tasks", "query": ":is-a(\"Task\")", "reach": "children", "names": {"Task": "7C1E…"}}`, `names` left out while empty (so a constraint with none is written as it always was) and read leniently (anything that isn't an object of ids is none; an entry whose id doesn't read is dropped; a constraint with no query has none), coded by hand in `Constraint` (the listed property makes the schema). Named by its value everywhere (the writer, the index, an issue's source), never by its place in a list, so what lands later for one finds it or nothing. **A list** (`ConstraintList`, the one codec): read leniently (a member that isn't a constraint, has no words, or equals one before it, by its words, is dropped, never the list: a list holds each words once, whatever their reach or query), written in order with each member's keys sorted (the board encoder's), as an array; and as the text a person reads in a type's schema (`ConstraintList.jsonText`, the one writer for it: `Constraint`'s `members` says which members it has and when they're left out, and the codec and the text both write that, the text in the order `says`, `query`, `reach`, `names`, spaced as typed, `names`' keys sorted, slashes unescaped; `codecTests` round-trips every member). A list names shapes (`extension ConstraintList: ShapeNaming`, a leaf coded by hand, the registry can't look inside), so a container's own list is walked and a copy of a frame or subboard pasted with the shapes its constraints name holds the copies' ids, as `is` does (`TypeLink`), and a name of a shape not copied stays; a pasted list whose ids the file lacks is judged by its titles as written (the fallback below). It makes frames and subboards `registry.namingKinds`.
- **Where lists are kept**: a container's own, `ConstraintsProperty` (key `constraints`, an added property, `unlisted()`: no language lists it; none until one is added, an empty list none; `record.ownConstraints`), which a kind opts into with `x.constrainable()` (`registrar.constrainable(K.self)` for another plugin's kind): the opt-in and one contribution to `ConstrainableKinds` (keyed, one a kind, the report's `constrainable → frame`), whose `check` refuses a kind that neither holds shapes (`ShapeContaining`) nor owns a board (`BoardOwning`), since a constraint is a place's; `registry.isConstrainable(kind)`. The root's, `RootConstraintsProperty` (key `constraints`, a file value, the root being no shape). The value is at version 1 for both (`ConstraintList.migrations`, one step that rewrites nothing: "a constraint holds the shapes its query's titles named", since `names` is a new member of the value, an optional that encodes nothing when empty; [boards on disk](boards-on-disk.md)'s rule for an added property's and a file value's new member, which asks a step and a fixture for the new version): fixtures `Fixtures/added/constraints.v0.json` and `v1.json` (a constraint with names), `Fixtures/file/constraints.v0.json` and `v1.json`, held by ConstraintsTests' `codecTests` and, now that Constraints ships, by PersistenceTests with every shipped property. The v0 fixtures are never edited.
- **Places and reach.** A frame F's place is `.container(F)`; a subboard S's is its board's top level, `.board(B)`; the root's is the root's top level. The index keys each by its holder (`ConstraintTarget`: `.shape(F)`, `.shape(S)`, `.root`; `ConstraintTarget(_: ShapePlace)`). `children` reaches the shapes directly in the place (in F directly; on B in no container), `descendants` every shape under it in Topology's one containment tree, boards included (the root's: the file). A shape is under each of its ancestors (`topology.ancestors(of:)`, nearest first) and then the root: depth 0 is the place it's directly in, so a shape in a frame on S's board is at depth 1 under S and only S's `descendants` constraints reach it. Only shapes with a box are judged (arrows never), a place's holder is never inside itself, and a holder of the point below has no place.
- **A place's constraints** (`PlacedConstraint`: `place`, `origin` (`ConstraintOrigin`: `.own`, or `.inherited(holder)` for a list given from elsewhere) and the constraint; the key of everything below): the lists it has from elsewhere, each source in the order given, then its own, each once (`constraints(of:)`, a row each). It is judged by each constraint value once, where it first comes (`Place.judged`, `judged(of:)`): the same words from a type and the type it builds on, or from a type and the place's own list, are one issue, from the first source, and the repeat has no breakers; with the first gone, the next judges.
- **The two points.** `InheritedConstraints` (`.scoped`, unkeyed, mirroring Colors' `InheritedColors`): `forShapes(holding: P.self) { $0.inheritedConstraints({ id, editor in [ConstraintSource] }, readers: { holder, editor in Set<ShapeID> }) }` (`readers` is optional: of a holder, the containers that read through it as the file has them, for `canvas draw` to reach the members of a place that has no list of its own yet, which no table keeps), asked of shapes of a constrainable kind, as a shape is first read and again whenever a commit writes it (a frame retyped), and of a holder as it is (`sources(of:)` for a shape that is no place: a type note's, the types it is built on, so one point reaches containers and holders alike); a `ConstraintSource` is the shape that holds the list (`holder`, to go to), the `swatch` its pill is drawn in (a Palette `Swatch`, as Validation's `IssueScopeChip` is; none: a plain pill) and the constraints; what the holder is called is no part of it, so a rename changes nothing the container is given: the panel and the menu read the holder's title as it is (`editor.constraintSourceName(of:)`, its Titles' title or "Untitled", observed, so a view that shows it draws again on a rename). When what it gives changes with no commit to the shape (a type's list written), the giver calls `editor.constraintIndex?.inheritedConstraintsDidChange(of: ids)`: those shapes are asked again once the change being delivered has settled (at once outside one), so a giver may call it from its own hook. `ConstraintHolders` (`.scoped`, keyed, one a kind): shapes that keep a list their own way and are no place (a type note keeps `$constraints` in its schema: Types' `TypeConstraintsPlugin`, which gives both points and is listed after LanguageRules' `RuleDetailsPlugin`, so the holder's Rules-tab section follows the type's English rules, [types](types.md)): `scope.constraintHolder(read:write:name:reason:)`, `read` the list (nil for a shape of the kind that holds none now: a note that isn't a type), `write` it within a transaction it's handed (false for nothing written), `name` what each of its places is called ("each sprint": the noun is the holder's; `editor.constraintPlaces(of:)`), which Constraints composes the section's heading from (`ConstraintsStyle.inside`, "Inside each sprint", `editor.constraintHeading(of:)`) and tells the model (`.accepting(holder:)`), so no module parses another's heading, and `reason` (optional) why it can't take a list now (a type whose schema isn't JSON yet: "Schema isn't JSON yet."), short, which `ConstraintWriter.refusal(of:)` gives where a refusal is said: the bar for `/constrain`, the panel's line under the add box while the words wait there, and VoiceOver (Constraints' own "Can't add a constraint to Sprint." where the holder has none).
- **The writer** (`ConstraintWriter`, `ConstraintWriter.swift`): the one way a list changes, a target being `.shape(id)` (the holder's list where its kind has one and the shape holds one now, else its own property where its kind is constrainable) or `.root`. `constraints(of:)` reads it (nil where there's none to write). `add(_:to:)` ("Add Constraint", false for one with the words of one there), `remove(_:from:)` ("Remove Constraint"), `removeAll(from:)` ("Remove Constraints"), `replace(_:with:in:)` (words, query and reach at once: what an interpretation lands; "Change Constraint"; one equal to the new one elsewhere goes, as a list holds each once), `setReach(_:of:in:)` and `setQuery(_:of:in:)` (both "Change Constraint"). Each is one step, false and no step for what changes nothing, and a read-only shape is refused before any transaction (`refuseChanges`: it shakes, and `write` says `.refused`, which a box that holds words keeps them for; the Bool writers say false). **It binds**: a constraint it writes with a query its list didn't have (one whose query the list already holds, as `setReach` or new words for the same query, is left as it is; a new constraint with the query of a bound one takes its names, of an unbound one stays unbound) and no names, gets `names` from `queries.bindNames(in: query)` as the file is then (add, replace, `setQuery`, `edit`: the panel's add box and query box, `/constrain`'s landing, an interpretation landing, a holder's list through `ConstraintHolders.write`, the root's file value, with no code in Types: `jsonText` writes `names` among a constraint's members); one it leaves as it was keeps its own, so a write to another constraint binds nothing again. A change that keeps a constraint's query keeps its names (`setReach`, `replace` with the query as it was, `setQuery` with the same text); `setQuery(_:of:in:rebinding: true)` is what a person writing the query in the box does: bound again as written (a title the box showed for a shape the constraint named, and the person left alone, keeps that shape even if another is called the same now), so a title a shape was renamed from names what it names now. A write finds its constraint by value, else by its words, query and reach (a caller that built the value without the names finds the one the writer bound). **A holder that won't take a list** (`write` false for a list that should have changed: a type whose schema isn't JSON yet) is `ConstraintEdit.refused` (`tryAdd`, `tryReplace`, `attempt(_:in:_:)`; `written` and `unchanged` the rest; the Bool writers say false): the writer shakes the holder (`refuseChanges`) and announces why (`refusal(of:)`: the holder's `reason`, else "Can't add a constraint to Sprint.", `ConstraintsStyle.cantAdd(to:)`, the holder by its title, else its kind), once, with no step. `edit(_:in:_:)` changes a list inside a transaction it's handed, for several targets in one step (`/constrain` on a selection), passing a read-only one over (false, `.unchanged` from `attempt`) for its caller to refuse; the static `adding`, `removing` and `replacing` are the changes by value it and the steps share.
- **The index** (`ConstraintIndex`, an `EditorService`, `@Observable`, its state `@ObservationIgnored` and observed by key as `RuleChecks` is). **It judges by identity**: what it stands and fits for a constraint is `text(of:)`, its query as written while it names no shape, else the `.ids` form (`queries.named(query, by: names, as: .ids)`: each bound title written as its shape's id while the shape is in the file, else the title as written), kept once a constraint with names (`judging`, with its users and the places that have it) and found by the ids it names (`binders`); every lookup of an answer, a refusal, a state, a fit, `judge(only:)` and the whole-file narrowing goes by it. A rename is no commit it reads: the id is the same text, so nothing is asked again (the standing query's plan reads no title). The text changes only when a bound shape comes or goes: a commit that adds, removes or moves onto another board a shape in `binders` (a lookup per such id, nothing on any other commit); `watched`, the ids views show, only grows (a commit's cost is its changes' size, not its) reads those constraints again (`rebind`): its places move to the query that is the text now, the new one held before the old is let go of, and the members of just the places that have the constraint are judged by it (`placesWalked` per place; `constraintsRebound` counts them, debug builds). A shape deleted is judged by the title as written, by id again once it is back; a file put in place reads every place afresh. Constraints equal but for their names (bound at two times) are one issue (`distinct` goes by words, query and reach). It keeps each constrained place (`Place`: its own list, its sources, the placed constraints, and each constraint's breakers), what each shape breaks (`broken`), and one standing query per distinct non-empty query (`Held`: the `StandingQuery`, or the `QueryError` `stand` refused it with, and its users), stood as a list gains a constraint with that query and stopped when the last goes; a refused one checks nothing and refuses nothing, and is tried again (`checkStored`) only when a commit could undo it: the file's edge types (`queries.presentEdgeTypes`) are not what they were when it was last asked (`QueryError.readsEdgeTypes`: an `unknown_edge_type`; any commit, on another board too), or a commit added, removed or rewrote a shape the refusal names (`QueryError.shapesNamed`, from the refusal's data: a `cannot_contain` of a container named by id whose kind holds none, `Held.named`); every other refusal is of the registry's words, which no commit changes, so a commit costs it nothing: one that reads now is stood and judges the members of the places that use it. It's built as it's made (every shape of a constrainable kind on a board the app can show, read once, and the root's) and again when a document or a file is put in place.
  - **What each commit costs** (`documentDidChange`, the first round, so whatever reads the index as services take the commit in reads it current; [editor](editor.md)'s delivery). A commit that only moved shapes on their board, nothing. A shape written (added, changed beyond moving, or touched elsewhere) of a constrainable kind: its lists read again (its own, and its sources from the point), and nothing more unless they changed; one turned into a kind that isn't constrainable is a place gone. A list that changed holds what it gained before it lets go of what it lost (`read`), so a constraint changed but for its query (its reach, its words: `setReach`, a `replace`, their undo) keeps its standing query and the answers it has, asking no whole file again; it lets go of the shapes that broke what it lost and judges the members within reach of what it gained by those answers (`judgeMembers`: `topology.children(of:)` or `descendants(of:)`; the root's top level, its shapes in no container, or the file), costing those members; and a written place's breakers are named, as its title is in their issues. The root's list, when `ChangeSet.fileValues` names it. A shape that came into another place (added, on another board, or its `container` changed: a container change is a change, never a move) or left the file: judged where it is now (`judge`, by `committedChain`: its ancestors and the root, O(its depth)), and, when any constraint reaches anywhere inside (`deep`, a count), what it carries (`topology.descendants(of:)`), so a container moved carries its shapes into what reaches them; a shape gone breaks nothing. A shape moved within its place, a list unchanged, a commit of shapes no place holds: nothing walked, and no set of what the commit wrote built (`forEachWritten` goes through them as they are; the set of the shapes it wrote beyond where they are, `unheardWritten`, is built the first time a shape is judged while the commit is heard, once: a 50,000-shape edit in a file with no constrained places builds none). Debug counters `shapesJudged`, `placesWalked`, `constraintsRebound`, `constraintsRead` and `writtenSetsBuilt`.
  - **Verdicts and pending answers.** A shape breaks a constraint when its standing query's last answer is no (`!matches.contains`). While its answer is still to come (`isPending`, or the commit being heard wrote it beyond its box and container, and the queries, which hear it as it settles, haven't yet: `unheard`, let go in `onceSettled`), it keeps the verdict it had (none for one new to the place) and waits (`Held.awaiting`), so a ring doesn't blink while a query asks again, a whole-file ask included; the next thing that query says (`onChange`: the flipped shapes and the waiting ones) judges them by it (`judge(_:only:)`). So a shape new to a place breaks nothing until its answer lands. A few flips (what a commit wrote, at most `flipsJudgedAlone`, 32) are each judged; more (a whole file answered: a query's first answer, a file put in place, an edge change its plan reads) only those within reach of a place whose constraints use that query, and those breaking one now (`judgeable`), so a first answer of `:not(tile)` over 5,000 shapes costs the places' members; the root's anywhere-inside reach is the file, and then every flip is judged.
  - **Telling.** What changed for the commit being heard is the rule's `affected` (`changed(by:)`, by revision: Validation asks it in the second round); what changes otherwise (an answer landing, a given list heard changed) is `validation.recheck` at once. The root's name is in its breakers' issues and a rename is no commit: the index watches `editor.rootName` (`withObservationTracking`, told as it's about to change) and rechecks the root's breakers then (Validation checks them when next read, by the new name), and again a turn later as it arms the watch again. Observers: `constraints(of:)`, `sources(of:)`, `breakers(of:)` (a place's, or one constraint's) are observed by the place, `breaches(of:)` by the shape, told as they change. A holder's `sources(of:)` (a shape that is no place: a type note) is read with the document unobserved and observed by the holder's own key alone, which `inheritedConstraintsDidChange(of:)` tells (a holder is told, not read: no table keeps it), so its section is told by what gives it lists and by no other commit (not an unrelated retitle, nor a drag's every move). A file put in place (`replaceFile`, a revert, a reload) tells every holder `sources(of:)` was asked of that the file still has (the index keeps them, `asked`, observation ignored; `tellHolders`, once every service has settled the change, as `readInherited` waits: what gives a holder its lists, Types, hears the file in a round after the index's, so telling at the index's own round would be read stale) and lets go of the ones it has none of; the places are read again by `rebuild` and need no telling.
  - **Settling.** It keeps Topology settling while a standing query it holds is asking (`keepsSettling(edges: false, feedsChecks: true)`, `isBusy`: the one source whose answers Draw's report of a run waits for), and says `settleSourceChanged()` as each settles or stops, so `:invalid` and whatever waits for verdicts waits for its answers ([topology](topology.md)).
  - **What the faces read** (P8): `constraints(of:)` (each `PlacedConstraint` with its origin), `sources(of:)` (swatches and holders; for a holder, the point's as it is now), `state(of:)` (`ConstraintQueryState`: `.notInterpreted`, `.refused(QueryError)`, `.standing`), `standingQuery(of:)`, `breakers(of:)` (the chip's count, Not accepted), `breaches(of:)` (a shape's, the place it's directly in first, each place's in order), `has(_:)`, `name(of:)` (a place as the rule names it), `isBusy`/`isSettled`.
- **Refusing** (`judge`, `ConstraintAdmission.swift`, the answer to `registrar.admission`). For each arrival that is moved (`!isNew`: a shape made here always goes in), the places it enters: from `arrival.to` up through the transaction's reading (`ReadingPlaces`: a record's container, of a kind that holds shapes, on its board, else its board's owner; Topology's answers would be of the file before), each place's constraints with its own list as the transaction has it and its sources as kept. A `children` constraint applies at depth 0, unless the arrival's `from` has the same holder as the place it's judged at (a frame turned into a subboard keeps its id and moves what it held from `.container(frame)` onto `.board(owned by frame)`: the holder is the same, so what it held is no arrival, flagged there as it was and the turn refused for none); a `descendants` one when its place isn't among those the shape was under as committed (`from`'s holder and its ancestors, and the root; a nil `from`, a cut's paste, is under none). A `descendants` constraint also judges what the arrival carries (`carried`, as the transaction has it, and what the boards it and they own hold, as committed). A judged shape is refused on an answer of no: its standing query's, or, while the query asks it again (an edit does, at every keystroke, so a note typed in a `/move-to` line is one), the last it had (`StandingQuery.lastAnswer(for:)`, `standingAnswer`), the same in a try and in a commit, so the drag's hint, the table of contents, `/move-to`'s picker, Move To ▸ and the drop agree, and a shape edited and dragged at once into a place that refused it is refused; with none ever (new to the file or to the query, its first answer not landed, a file put in place, a refused query, words not interpreted) it goes in, and so does one whose record the transaction changed beyond its box and container (`AnyShapeRecord.isSame(asIgnoringPlace:)` against the committed record: its answer is of what it was). A shape back in the file from where nothing says (a cut's, pasted) has left its queries: it's judged by what they last answered as it left (`remember`, kept by the commit that removed it, with the last answer a query that was asking it again had, at most `goneLimit`, 4,096, past which the older half is let go of, and a shape forgotten comes back in; debug builds let a test lower it, while it comes back as it went). The refusal shakes the place's frame or subboard (the root's: none, so the arrivals shake) and says the first constraint broken, "Backlog accepts only tasks." (`ConstraintsStyle.accepts`, the place by `name(of:)`); the core announces it for a real refusal only. Leaving is never asked; undo and redo never reach here. A drag's hint costs its arrivals' places a container change. The table of contents' drops, `/move-to`'s picker and Move To ▸ ask the same try (`editor.admits(_:on:into:)`, Moving's `Drop`), so a place that would refuse the shapes is not highlighted, listed or offered, as a locked frame isn't; the list's `drop(on:)` says it moved them only if the mover did (`ContentsMoves`' move answers whether), so a shape the try let in for want of any answer, refused by the commit once one landed, is no drop. A rehearsal asks the same (`canvas apply` and `canvas rehearse` draw on `editor.rehearsal()`, whose clock is stopped, so its queries never answer): `rehearsalDidBegin(from:in:)` gives the index the source's, and a shape the rehearsal holds as the source does (`sourceAnswer`: the same record, place aside) is judged by the source's answer, so a move into a place that refuses is refused there as in the live editor (`cannot_contain`, naming the node) and a shape the rehearsal made is new, going in. A dropped ⌥-drag that is refused takes its copies away (Selection's `CopyDraggingSession`), the press coming to nothing.
- **Fitting** (`fit`, the answer to `registrar.placementFit`). For each constraint that reaches the placed shape's place (directly for `children`; from any place at or above it for `descendants`), the outermost place first and at each its sources (in order) before its own, `queries.fit(record, toMatch: text(of: constraint), kindIsOpen:)` (the id form: `:is-a(#id)`, which a type's writer reads as the type by id, so a renamed type is the one a shape is made) over what the call before wrote. An open kind is spent by the first constraint that names the kind the shape is once that call is done (`kinds(namedBy:)`: the subjects' kind heads, through `:is` and `:where`), whether it turned the shape into that kind or the shape was of it already, so a later constraint never turns it out of a kind an earlier one asked for (a tile placed open into "only tiles", "only cards" stays a tile); one that names only kinds it can't be made into leaves it open. Words not interpreted and queries the index doesn't hold standing (refused) are passed over. Nil when nothing was written. The core asks only for person-made placements (never paste, duplicate or draw), and a shape that still doesn't fit goes in and is flagged.
- **The rule** (`ConstraintValidationPlugin`, `ConstraintValidation.swift`): on every kind with a box (`forShapes(adopting: .box)`: a constraint is a place's and any shape with a box can be in a place, so this is what being a box means, as Moving's commands are, never a feature kinds opt into), `ignoringMoves: true` (a container change is a change). It reads the index (`context.service`, else `committedService`): an `.error` for each constraint the shape breaks, "<place> accepts <words>.", the place by its holder's title (Titles' `registry.title(of:)`), else "This " and its kind's label for a container ("This frame"), "This board" for a board's top level, and the root by `editor.rootName` or "This board". In a run's check before it commits (a reading not committed), it climbs the reading and answers only for a shape the run left as it was, so what the run wrote is judged once its answers land, and `canvas draw` says it then: a real run waits for the file's answers and asks the check again over the committed file (`laterIssues`, [command line](command-line.md#a-real-run-waits-for-the-answers)), so a shape it wrote or looked at that breaks a constraint is a warning on its statement's line (a dry run and `rehearse` can't: nothing commits).
