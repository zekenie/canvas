# TextEditing

TextEditing, the core library under every editable text: `EditingTextView`, how the app checks the spelling of what's typed (`Spelling`), and the app's one caret list (`CaretList`, `CaretListWindow`).

Related: [fuzzy matching](fuzzy-matching.md), [mentions](mentions.md), [slash commands](slash-commands.md), [detail panel](detail-panel.md), [editing](editing.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [TextEditing](../../docs/plugin-system.md#textediting).

## Architecture

- TextEditing (a core module that depends on no other of the project's, so it knows no canvas, registry, plugin or panel; `docs/plugin-system.md`, "TextEditing") is the text under every editable text in the app (and `StringDrawingLayout`, where string drawing, `draw(with:options: .usesLineFragmentOrigin)`, puts a string's characters in a box: an offscreen `NSLayoutManager` with the 10.2 typesetter, lines stacked as string drawing stacks them, at least `minimumLineHeight`, `lines(fitting:)`, and `lineRects(of:height:)`, a rect a line per range, across from where a selection of it would be, `enumerateEnclosingRects`, since `boundingRect(forGlyphRange:)` misplaces part of a centered line with that typesetter, down from string drawing's lines; laid out once as it's made, so one kept per text and width makes a range a lookup: Mentions' memo keeps one per text for its pills and Find, Connections one per label) (a note's editor, an arrow's label, the detail panel's boxes) and the one list shown at a caret. `EditingTextView` is an open `NSTextView` with what a host needs and `TextEditor` doesn't give, which a plugin subclasses for text of its own (the panel's `DetailTextContent`s, Mentions' `MentionTextView`): `onCommit`, `commitsOnReturn`, `onExit`, `onLeave` (the keyboard leaving, whatever for), `onKeyDown` (asked of each key first, before the view's own keys and AppKit's bindings, unless the view `holdsKeys` or is composing marked text: true keeps the key, so a host takes a key with no subclass; a note's editor's ⇧↩ and Tab) and `placeholder` do nothing until set, so without them it's a plain text view, and `commitsOnLeaving` off leaves only ⌘↩ to `onCommit`, as a note's editor on the canvas, whose ⌘↩ ends editing; `commitsWhileReadOnly` lets ⌘↩ commit read-only text, for a commit that only ends editing (a type note's words while the model writes them); it draws its placeholder in `drawBackground`, since AppKit gives a class that overrides `draw(_:)` TextKit 1, in the view's font or else `TextEditingStyle.placeholderFont` (the system's, 11 pt); `highlights` (`TextHighlight`: an `NSRange` and a fill) are drawn there too, under the text, as rounded rects a mention's pill tall that reach 2 points past the text, a rect a line (`frames(of:)`, TextKit 2 only, as the caret's frame is), and are let go of when the view is made read-only, so an owner marks text with nothing for a host to forward; `showEnabled(_:)` dims it, by default by its text's color, the label's or the secondary label's. Set, `spelling` (`Spelling`: Edit › Spelling and Grammar's three settings, one for every text that's words and kept in the user defaults, Check Spelling While Typing on until it's turned off, Check Grammar With Spelling off until it's turned on, Correct Spelling Automatically as System Settings has it until it's turned either way) checks the words typed as the app does (`.app`: a note's editor, an arrow's label's, the header's title field's editor, the panel's `DetailTextArea` and `MentionTextArea`): the view follows the settings as they change (each change setting that one alone, so what a caret list turned off stays off), its own toggles (the menu bar's, sent to the text with the keyboard, and its context menu's) change them for every follower at once, each turning over what the view shows, and the words it's told to ignore (Ignore Spelling, kept by AppKit in a spell document of the view's own, which an override of `spellCheckerDocumentTag` doesn't change for its checking: an ignored word came back underlined at the next check, so it's never overridden) come back to the settings as the keyboard leaves it or it leaves its window, and go into each follower's document as it starts following, before its text is checked (`Spelling.ignoredWords`, until the app quits), since an editor on the canvas is made for one editing; nil (code, Find's and Jump To's fields, a reference's search), it checks as AppKit has a text view check, marking no words as they're typed. A subclass that shows a list at its caret keeps its window, `caretListWindow` (a `MentionTextView`'s `@` picker or slash commands' list, a code editor's completions), and `EditingTextView` does the rest for every such list alike: while one's open it `holdsKeys`, so the list's commands (`CaretList.perform`) are the list's, before the delegate's turn (through the window's `pickHighlighted()` and `closeList()`, which run the owner's), and Return and Escape are never `onCommit`'s nor `onExit`'s, while ⌘↩, where the text commits, closes the list and commits, as with none; the keyboard leaving, the view leaving its window and its being made read-only close it; what's left to the subclass is when it opens, what it lists and what a pick puts in (a subclass may `holdsKeys` for something else too). ⌘., which the window sends up the responder chain as `cancelOperation:`, closes an open list (the view's `cancelOperation(_:)`, answered only while one is open, so with none it goes on up the chain as though the view weren't there). Tests read a list through `caretListWindow`. Such a list is the app's one caret list, whatever text it's over (Mentions' `@` picker; slash commands' list; a code editor's completions): `CaretList`, the model, headless (`CaretListRow`s: headers, items and one empty state; a `CaretListItem` is a title with its `matched` characters semibold, in an optional `font`, an optional symbol and `tint` before it, a `trailingSymbol` after it, a `detail` at the trailing end (its `detailMatched` characters, `Character` ranges of the detail, semibold too, its `detailDimmed` ones fainter, neither said), which takes what the title leaves, or `TextEditingStyle.caretListDetailShare` of the row where both are long, `chip` (a color: the symbol and title are drawn in a capsule of it, in `chipInk`, white unless the item says another (a yellow chip takes black), `TextEditingStyle.caretListChipHeight` 20 tall (less 4 than the row where it is shorter), 12-point text with the matched characters semibold, the symbol 10-point semibold inside it, 8 points in from its ends; the highlight is then the accent at 0.15 behind the capsule, not the accent with white text; the detail and trailing symbol are as for any row; spoken as ever; a row without one is drawn as before; hit testing and keys are unchanged), `separated` (a line one point thick across the top of its row, drawn under the highlight: what sets a last row of another kind, the words a reference's list ends with, off from the rest), and what VoiceOver says, `spoken`, the title and detail by default; the first item highlighted, ↑ ↓ wrapping and a page, `rowsShown`, stopping at the ends; `perform(_:)` takes the text view's commands: ↑ ↓ ⌃P ⌃N, Page Up and Down, Return and Tab pick, but not with nothing highlighted, Escape, ⌥⎋ and F5 close), sized by its owner's `CaretListMetrics` (width, row height, rows shown, offset below the anchor; its look is `TextEditingStyle`'s), and shown in a `CaretListWindow(list, accessibilityLabel:over:anchor:pick:close:post:)`, a borderless child window that never takes the keyboard (not deferred: a click's events name it, shown or not, and a board's window leaves clicks in its children alone, so a pick with the mouse is part of the typing), placed under the anchor range's `firstRect` (its rows' text under the anchor's start, above the line where there's no room below, on screen), or, made with `anchorRect:` (a closure giving a rect in screen coordinates, nil to stay put), centered under that rect at its metrics' width (Jump To's palette, whose field is the text view: it follows the view's ancestors and closes when the window resigns key, but never for the anchor leaving the text), following every ancestor's frame and bounds, asking its owner to `close` once the anchor leaves the text's visible rect (a range anchor only) or the window resigns key, and telling VoiceOver through `post` (Mentions routes it through `MentionAccessibility`); its owner calls `listDidChange()` after each change and `dismiss()` as it closes, and decides when it opens and closes, what the query is and what a pick inserts. A list over text that its own substitutions would rewrite (an `@query`, a `/name`) takes them as it opens, turns them off while it's open and puts them back as they were once it closes: `CaretListSubstitutions` (spelling correction, text replacement, smart quotes and smart dashes: `init(of: view)` takes the view's, `off` is all four off, `apply(to:)` sets a view's). Every list ranks typed text with one matcher, FuzzyMatching's `FuzzyMatcher`, not TextEditing's ([fuzzy matching](fuzzy-matching.md)); TextEditing stays free of it.

- Types' `RowField` is a one-line `EditingTextView` (TextKit 2, so `placeSelection` and `caretFrame` work) for the value of a row: a container that never wraps (a clip view slides it), the substitutions off (`CaretListSubstitutions.off`), `commitsOnLeaving` off, and its keys (`insertTab:`, `insertBacktab:`, `moveUp:`, `moveDown:`, `insertNewline:`, `cancelOperation:`) handed to the rows editor. A line break is held as one space carrying an attribute (`RowField.lineBreak`), `typingAttributes` pinned so nothing typed takes it ([types](types.md)).

## Testing

- For text editing, TextEditingTests (the caret list's Suite, Caret lists, and Caret list chip rows: the capsule's color and height, white text, the symbol inside it, the pale highlight against the accent of a row without a chip, in both appearances, read back beside a swatch of the color drawn in the same capture, since the window's bitmap has a color space of its own; over TestKit and CanvasTesting alone) hold the model headlessly (the matcher's tests are FuzzyMatchingTests'), the window over a plain `EditingTextView` in an unshown window (`ListedText`), where it's placed but never ordered in: read its `frame`, and call the rows view's mouse methods for a click, and a subclass's list's keys and closing, `EditingTextView`'s (`ListingTextView`); a list under a rect of its own is read the same way (centered on it at its width, below it or above, on screen, following a moved rect, never closing for the text scrolling away), and a detail's matched characters are drawn semibold and its dimmed ones fainter, neither said. Its String drawing layout suite holds `StringDrawingLayout`'s rects to the ink string drawing leaves, left-aligned and centered, a range over two lines, one past the box, an empty one. Its Highlights suite holds `frames(of:)` (a rect a line, centered, padded, none for a range that isn't in the text), the redraw when they change and the fill drawn in the view's coordinates. Caret lists hold `onKeyDown` over `ListingTextView` (asked first, true keeping Tab, false letting Return type, not asked while a list holds the keys). Its Spelling suite holds `Spelling` over a defaults suite of its own, never the app's (`Spelling(defaults:)`, removed after): its defaults, a view without settings checking as AppKit has it with toggles of its own, a toggle changing the settings for every follower and kept for the next launch, a change setting that one alone (correction a caret list turned off stays off), Edit › Spelling and Grammar's marks, a view that stops following, and a word one follower was told to ignore taken in as the keyboard leaves it or it leaves its window, then ignored in followers there already and made after, never in a text without settings or following others; never `learnWord`, which writes the person's own dictionary. Each host's editor following `Spelling.app` is held in its own tests (StickyNotesTests, ArrowsTests, DetailPanelTests, MentionsTests), and the menu's items going to the text with the keyboard (a note's, the title's field editor), none on the canvas, in CompositionTests' BoardWindowTests; no test toggles `.app`, which would write the test's own defaults. The view with a box's value and keys is held where the box is, DetailPanelTests'.
