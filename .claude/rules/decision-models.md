# Decision models

Decision models: the one model every editor lends plugins to ask yes-or-no questions of a state, each answered with a probability; TypeSafe's Jev and its key, a language model asked in words, the scripted model tests use, and the prototype's evaluations.

Related: [language models](language-models.md), [host slots](host-slots.md), [build](build.md) ([every topic](../../CLAUDE.md#map)).

In the guide, `docs/plugin-system.md`: [Decision models](../../docs/plugin-system.md#decision-models).

## Architecture

- DecisionModels (an engine beside LanguageModels, which it builds on; it declares no point) lends every editor one model: `editor.decisionModel` (nil without `DecisionModelsPlugin(model:)`), a `DecisionModel`, whose one call is `decide(_: DecisionRequest) async throws(DecisionModelError) -> DecisionAnswers`. A request is a `state` (any JSON), a `preface` every question shares (said once; a model that takes questions one at a time reads it before each: `request.text(of:)`) and `DecisionQuestion`s (`id`, what it `asks`, and what its `yes` and `no` mean in a few words, "Yes" and "No" by default). The answers are `model` (the version that answered: an answer kept is kept under it), `yes` (each question's probability of yes by its id; one the model left unanswered isn't there) and `usage`. A model's `cutoffs` (`DecisionCutoffs`, `.standard` a yes at 0.7 and above and a no at 0.3 and below, where Jev's and Haiku's answers to rules separated on the prototype's boards) turn a probability into a `DecisionVerdict` (`yes`, `no`, `unsure`). It knows nothing of what plugins ask (rules are LanguageRules').
- `DecisionModelError` is a `failure` and the `provider` it names: `message` says whose, in a fragment, never what to do ("No TypeSafe key", "TypeSafe key rejected", "Rate limited", "TypeSafe overloaded", "TypeSafe error 500", a 4xx's first sentence from the service with the key taken out, `LanguageModelError.firstSentence(of:)`, "Can’t reach TypeSafe", "Timed out", "Unusable answer"); `isTransient` (Retry) and `needsKey` (no key or one refused: Open Settings…). `init(_:of:)` says a `LanguageModelError` as a provider's.
- **Jev** (`JevModel`, the app's): `POST https://api.typesafe.ai/v1/systemone`, `authorization: Bearer <key>`, `{"state", "model": "jev-latest", "questions": {id: {"type": "noul", "instructions": preface + "\n" + asks, "criteria": {"true": yes, "false": no}}}}`; the reply's `answers[id].noul` are the probabilities (one not a number from 0 to 1, or no `answers`, is an unusable answer), `model` the version ("jev-1.14.0"), `usage.input_tokens`. 401 and 403 are a key refused, 429 rate limited, 503 and 529 overloaded; the error body's `error.message`, `error`, `detail` or `message` is the service's words. It waits 30 s, retries nothing, and reads its key at every call from `TypeSafeKeyStore.standard` (`~/Library/Application Support/InfiniteCanvas/typesafe-api-key`), a `KeyFile` as Anthropic's store is ([language models](language-models.md)). Never print, log or write the key.
- **Answers kept** (`DecisionMemory`): what a model answered, by its `name` (the model asked: `jev-latest`, `claude-haiku-5-5`, `scripted`) and a SHA-256 of the whole request (state, preface and questions as one line of JSON, sorted keys), kept the day it was given (`today`, the user's calendar day; a plugin whose answers may change from day to day says the day in its state), in memory and, where it has a file, written whole and renamed into place a second after the last answer and as the editor goes (`save()`, a failure kept to try again; another day's answers let go as one is kept). Plugins ask through `editor.decisions` (`Decisions`, the service: `model`, `memory`, `decide(_:)`, which answers what the model answered today from memory and asks the model the rest, a failure kept by nothing), never the model itself; `editor.decisionModel` is `decisions?.model`.
- **The plugin.** `DecisionModelsPlugin()`, as the product's list makes it, takes `JevModel(keys: .standard)` and the app's memory (`DecisionMemory.standard()`, `~/Library/Application Support/InfiniteCanvas/decision-answers.json`), which reach the network and the user's files, so it is an `OutwardPlugin` ([build](build.md), What ships): anything but the app and its extension hands over `DecisionModelsPlugin(model:memory:)` of its own, its memory in memory only unless given one with a file. It lists right after LanguageModels. It gives the key's Settings pane (`registrar.settingsPane("TypeSafe")`, `TypeSafeSettingsView.pane`) only when its model is a `JevModel`, over that model's keys, so a registry with any other model has no TypeSafe pane and never points at the key's file.
- **The pane** is the language models' `KeySettingsView` over `KeySettings` made for `KeyService.typeSafe` (`TypeSafeKeySettings(keys:model:)`, a typealias and an init: "TypeSafe API key", its prompt "Saved" or "Not saved", "Get a key" to typesafe.ai), so it is the Claude pane's key rows (`KeyRows`) in a pane of its own: Save, Remove, and Test, which asks `TypeSafeSettingsView.testRequest` (one question) of the model with the saved key; Save and Remove post `Notification.Name.decisionModelKeyDidChange` (never the language model's), so what failed for want of a key can ask again by itself. Under the Claude pane, its field doesn't take the keyboard as the window opens (the window's first pane does: `settingsPaneTakesFocus`, [host slots](host-slots.md)), and Tab goes down to it. `TypeSafeSettingsView.showSettings()` opens Settings with the action the Claude pane's sends.
- **A language model, asked in words** (`LanguageDecisionModel(model:modelID:effort:maxTokens:)`, Haiku 5.5, effort `medium`, 2,048 tokens): its `system` prompt and one user message (`message(for:)`: the state as `prettyText` in `<state>`, the preface, then the questions numbered in `<questions>`, each followed by `Answer "<yes>" or "<no>".`, then the answer's form), read from the last JSON object in its answer: a question's yes words 1, its no words 0, "unsure" 0.5, without case, the space around them or a closing period; other words leave it out, no object is an unusable answer. Words, not "yes" and "no": asked whether something fails, Haiku's "yes" was read as "it holds" (the prototype's round 1). Its failures are Anthropic's. It ships in the module, not the list: it proves the seam isn't shaped around Jev.
- **What asks it.** LanguageRules' checks ([language rules](language-rules.md)), and `canvas decide` (DecisionCommands: one yes-or-no question of every shape a query finds, each with its state as a rule sees it, the rows by how likely a yes; nothing stored, [command line](command-line.md)).
- **The evaluations** (`scripts/language-rules`, each script a task, `eval:rules` and the `eval:rules:` tasks; never run by `./test.sh`: they need the app, the network and both keys): the prototype's boards (Cars, Votes, Listings), what a rule sees built from them (`context.py`), Jev's and Haiku's answers scored against labels (`evals.py`, `score.py`), the chips' translation (`chips_eval.py`) and the Haiku adapter's prompt (`decide_eval.py`, which reads the Swift's `system`, model and effort and writes `message(for:)` as the Swift does, over a round's Jev requests), and a trial at scale (`house.py`: the whole 118th House and its votes on the 16 bills, a board per state and a subboard per district, drawn into the app with `canvas draw` and checked there, scored against Voteview's labels, beside Cars and Listings). Its README holds each round's findings.

## Testing

- DecisionModelsTests: Jev's request, answers and errors over a `URLProtocol` stub (the body, the bearer key, a missing answer, an unusable reply, each status, the network, cancelling a call that hangs), the language model's request and its words read, the scripted model (its queue, `answerAll`, held and released, cancelled while held), the cutoffs, the plugin (the editor's model, its registry line, Jev's pane and none for other models) and the TypeSafe pane (the key saved 0600, the decision model's notice and never the language model's, Test's one question and what it says, the field focused and Return saving).
- `ScriptedDecisionModel` answers every test: ShippedTesting's `ShippedPlugins` takes one unless a test passes its own (`decisionModel:`), so no test reaches TypeSafe. CompositionTests' ShippedTests hold the list refusing to load without a decision model's plugin, the editor's model the one passed, the app's Jev with the standard key, and both panes with the app's models; `settingsWindowTests` hold the two panes, the first focused and Tab going down to the second.
